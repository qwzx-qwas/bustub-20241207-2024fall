# 共享进程与故障工具

供 [旧回归](../legacy_raft/README.md) 和 [当前验收测试](../storage_acceptance/README.md) 复用，全部是测试侧代码。

- `raft_process_harness.sh`：启动、重启、发送信号、核对 wait 状态、清理本轮拥有的进程。
- `raft_message_proxy.py`：默认保留旧场景的丢消息和快照录制/重放；可选 `--observe --node-id N` 提供新套件需要的规则代次确认、阻断记录、日志/快照摘要，不录制快照正文。
- `raft_drop_response_proxy.py`：只转发一次正式请求，取得已提交响应后记录并丢弃它，制造真实客户端未知结果。

观察模式下每个节点间的入口都经过代理。规则 ACK 在旧转发动作结束后发布，新转发按新规则决定；ACK 不宣称已经清空服务器内部收到的消息，因此隔离验证另发一个全新身份请求。故障生效还须实际阻断记录，恢复还须正式业务验证。

这些工具不修改生产协议或磁盘状态，不提供生产专用测试接口。进程终止不模拟主机断电。
