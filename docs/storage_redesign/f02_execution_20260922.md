# S1 / F02 执行与测试设计审查

日期：2026-09-22。[当轮方案与 prompt](modules/object-io.md#65-s1-当轮执行范围用户授权后落定) · [总方案测试约束](README.md#15-每次新增或修改测试后的强制设计审查)

## 1. 范围与实现审查

用户授权“执行 F02 方案和测试”。基准 `2f06f6f42548ec49c53040315f8410b7aea48a27` 加本轮工作区改动；源码快照/哈希才标识实际被测版本。

当轮为单设备 `IOExecutor`：可信已解析范围、显式预算、按实际对齐分配的批次缓冲、有界并行、成员结果及 Flush 依赖、失败收尾、正常排空。F01 定位读写实现保持原样。S2/S6 的对象寻址、S8/S9 正式业务接入、F35 协议/业务阶段 worker、节点级统一预算与状态未实现。

实现复用 F00 `StorageByteRange`、F01 `BlockDevice` 及原生产 CMake 目标。当前 Channel 没有容量限制/关闭拒绝及结果预算，旧 DiskScheduler 仍被业务使用，因此不为复用名字而修改它或引入没有生产用途的泛型队列框架。新类的公开接口对应本轮明确授权的消费者边界，尚无 SQL/Raft 调用者，如实留待后续接入。

参考 [RocksDB 异步 IO](https://rocksdb.org/blog/2022/10/07/asynchronous-io-in-rocksdb.html) 重叠独立 IO 等待的思路；本项目使用 worker/F01 定位 IO，没有引入 RocksDB、协程或预读实现。边界与差异见 F02 §6.5。

## 2. 测试全景

以下 6 项均为真实文件/F01/F02 组件 **integration**，不冒充三节点 E2E 或新性能基线。测试侧 `--wrap` 暂停/观察/注入，正常分支继续调用真实系统函数；没有生产 hook。最终只按模块压缩归档，不注册 CTest。

| 测试（均前缀 IOExecutorTest） | invariant / 防止的具体 bug |
| --- | --- |
| ParallelMembersDoNotSkipBarrierHoles | 后续成员先完成不能跳过前面未完成项；独立工作可推进；Flush 依赖全部成功写入 |
| BudgetIncludesPreparedRunningAndRetainedResults | 准备/在途/保留结果都占预算；分配异常释放预留；不能只限制队列或泄漏额度 |
| RejectionNeverStartsIOOrStealsPreparedBuffers | 非法范围、冲突、错误所有者、重复提交和关闭拒绝不能误下发/丢所有权 |
| PartialFailureDrainsRunningIOAndSkipsUnstartedMembers | 部分失败后等待真实在途 IO 结束，未派发项不执行；不提前归还或假成功 |
| FlushFailureIsNotDurableAndDoesNotLoseLaterWork | 写成功与 durable 分开；刷新错误传出，worker 不崩溃或遗失之后的独立工作 |
| DroppingHandleDoesNotCancelIOAndShutdownDrains | 超时/销毁观察句柄不取消已接受 IO；关闭能排空，缓冲不被提前释放 |

## 3. 逐项：目标 → 输入 → 执行 → Oracle → 失败含义

共同 setup：每例独立临时目录/文件；直接 statx 查询约束，unit 是内存/偏移对齐的最小公倍数，容量 256 unit、最多 64 MiB。初始内容由字节位置及固定 seed 生成，通过独立 POSIX 写入并同步。Oracle 绕过 F01/F02，读取完整物理文件并对照输入计算的镜像，检查范围外邻居和长度。不用生产读写互相验证偏移。

### 3.1 ParallelMembersDoNotSkipBarrierHoles

- **目标/输入**：两个 worker，三个独立不同正文写入，暂停第一个 pwrite，让后两个先结束；另加一个独立真实读作为推进证据。实际能力决定缓冲/长度，不全用固定 4 KiB。
- **路径**：TryPrepare/填缓冲 → TrySubmit → 调度队列 → F01/pwrite → 成员完成 → 本批 Flush；测试只在系统调用边界暂停，正常动作仍由生产执行。随后经 F02 读取同样三个范围。
- **Oracle**：前项未放行时独立读已经结束，原批仍 Executing/未终结、不能访问结果缓冲且没有 Flush。放行后成功、写入 durable 标志、真实同步成功，以及独立完整镜像匹配；读结果按输入成员顺序匹配，并检查批次/每项读取均报告成功、完整字节数且无异常。
- **失败含义**：隐藏串行、按最大完成号跳洞、提前释放、漏 Flush、成员串位或读写寻址错误。状态检查对应公开依赖承诺，不绑定某个私有锁/线程 ID。正常文件同步不证明物理掉电。

### 3.2 BudgetIncludesPreparedRunningAndRetainedResults

- **目标/输入**：明确两个成员的数量上限；同一批分别在 Prepared、暂停执行及完成后仍持有时尝试增加真实请求。另一个 executor 以实际含 padding 的两个 unit 为字节额度，数量额度更大，区分两种限制。
- **路径**：正式 Prepare/Submit/Wait/句柄释放；字节测试再在生产 malloc 边界模拟一次 ENOMEM，随后重新申请同样容量。
- **Oracle**：从显式配置和请求大小独立推导 Accepted/Full；释放后接受；异常后完整额度可再使用。没有读取私有计数，也没有让 oracle 调用生产预算算法。生产返回的缓冲仍按设备实际对齐核对。
- **失败含义**：遗漏准备/保留结果记账、只管数量不管字节、重复计费、分配失败泄漏预留。malloc 注入验证本项目的回滚责任，不测试标准库分配器本身；该边界是模拟，未制造机器真实 OOM。

### 3.3 RejectionNeverStartsIOOrStealsPreparedBuffers

- **目标/输入**：非空越界/不对齐/批内读写冲突范围；已填真实正文的批次误交另一个 executor；同一批重复投递；准备后正常关闭再投递。
- **路径**：正式准入、所有者及阶段检查。保留一条真实成功写入，避免“全部拒绝”也能通过。
- **Oracle**：负面阶段无设备调用且完整原镜像不变；跨 executor 拒绝后缓冲可读、仍 Prepared；一次有效提交只改变独立预期区间；关闭拒绝不执行另一份已准备正文。
- **失败含义**：准入保护缺失、所有权错误、重复执行、关闭后继续接纳。范围算术本身归 F00；这里检查整批准入不能在发现坏成员前已写出其他内容。

### 3.4 PartialFailureDrainsRunningIOAndSkipsUnstartedMembers

- **目标/输入**：第一项 3 unit 写入先真实写 1 unit、后模拟 EIO；第二项在另一 worker 中暂停；第三项尚未开始。注入 EIO 前保证第二项已经进入，排除偶然调度。
- **路径**：生产短 IO 处理 → F02 异常归并/Draining → 独立读验证空闲 worker 仍可推进 → 放行第二项 → 最终失败。
- **Oracle**：未放行不能访问缓冲或终结；第一项失败且进度为 1 unit、异常保留原范围/EIO，第二项成功、第三项 NotStarted，无 Flush。完整镜像只改变可证明执行过的两个区域；观察无额外重试。
- **失败含义**：把部分失败当成功、丢进度、失败后继续派发、提前归还工作缓冲/终结，或设备写自动重试。受控 EIO 不额外改变字节只是本注入的语义，不能推广到真实 Direct 失败区域。

### 3.5 FlushFailureIsNotDurableAndDoesNotLoseLaterWork

- **目标/输入**：一批真实非空写入，刷新模拟 EIO；之后另一位置的新批次正常写入/刷新。
- **路径**：F02 → F01 WriteAt/Flush → 错误结果 → 同一 executor 接受后续独立工作。
- **Oracle**：首批成员写入成功，但批次 Failed、writes_durable 为 false、独立 flush_error 为 EIO；后批成功且实际同步；独立镜像核对两份正文，无自动重复写。
- **失败含义**：把写出当 durable、吞刷新错误、worker 异常退出或错误串到下一批。正文可读只证明这次受控注入的内容，不证明失败已回滚或 durable。

### 3.6 DroppingHandleDoesNotCancelIOAndShutdownDrains

- **目标/输入**：单 worker、两个写入成员，暂停第一项；一次 WaitFor 返回未完成后销毁批次观察句柄，随后在另一线程 Shutdown。
- **路径**：正式句柄生命周期、队列/worker 所有权、实际写入和 Flush、关闭线程汇合；没有持测试全局锁执行 Shutdown。
- **Oracle**：句柄放弃后容量仍满；暂停未释放时关闭不能完成；放行后关闭返回、两项正文及同步完成、之后请求被拒。独立完整镜像及 ASan/泄漏检查补充缓冲生命周期证据。
- **失败含义**：将放弃等待当取消、提前释放缓冲/预算、关闭丢队列或依赖外部消费结果而卡死。释放门的 RAII 放在 future 之后声明，异常退出先开门再析构等待 future，避免重复 F01 测试曾有的问题。

## 5. 重复与价值

- 3.1 和 F01 的独立镜像核对方法相同，新增保护为 F02 的调度、乱序完成和批次屏障；不复制完整 F01 对齐/系统调用重试矩阵。
- 3.1/3.4 都暂停成员，前者验证正常成功的依赖，后者验证失败后的在途收尾和未开始项，错误模式不同。
- 3.2 同时覆盖数量/字节及生命周期，未按每个计数 getter 建测试；分配异常是释放责任的独立边界。
- 3.3 的重复/跨 executor/关闭拒绝保护批次身份，不复刻纯算术；3.6 的句柄放弃/关闭保护实际 IO 所有权，与普通拒绝不同。
- 3.5 与 3.1 都执行 Flush，新增的是异步错误不能变成 durable、不能终止 worker。F01 的同步异常测试不能替代。
- 原 C/P 和课程测试仍不经过 F02，不能算等价覆盖。全部为阶段验证，结束后仅压缩；不再维护另一套性能场景。

## 6. 最小 mutation 与杀伤力

| 故意改坏点 | 能发现的用例/依据 | 实际证据 |
| --- | --- | --- |
| worker 不调用 Flush，但仍标成功 | 3.1 实际同步观察，不靠普通读回 | 指定断言失败，退出 1 |
| 忽略当前已用成员/字节，仅检查单批大小 | 3.2 满额时的新非空请求必须拒绝 | 指定断言失败，退出 1 |
| 成员异常不置失败标志 | 3.4 不允许派发后续项或成功/Flush | 指定断言失败，退出 1 |
| Flush 错误也标 durable/成功 | 3.5 错误、阶段与持久化独立断言 | 指定断言失败，退出 1 |
| 真实读回字节正确，但将成功读取报告为 Failed | 3.1 正向检查读取结果/字节数；不能只看正文 | 指定断言失败，退出 1 |
| 只因最后编号完成就进入 Flush | 3.1 前项被确定性暂停、独立读确保完成事件已经处理 | 静态推演；若改坏造成 UAF，不能仅把检测器崩溃当指定断言捕获 |
| 分配失败不退预算 | 3.2 ENOMEM 后同样容量无法再申请 | 正常注入分支实测，变异静态推演 |
| 丢弃句柄就销毁在途缓冲/取消已接受任务 | 3.6 最终镜像、完整工作、容量及检测器 | 正常生命周期实测，变异静态推演 |

mutation 只改工作区外副本。要求指定用例断言失败且退出 1；编译失败、超时或检测器启动故障单独记录，不算命中。

## 7. 稳定性与清理

固定内容、无随机 seed 漂移、每例独立文件。跨线程观察通过测试侧 mutex/CV 同步，不 sleep。5 秒等待/60 秒进程上限只限制挂起，不是吞吐或延迟指标。暂停门都有异常退出释放；future 析构与 executor Shutdown 之前释放门。注入变量只在无竞争时或互斥锁下更新；malloc 注入 thread_local，只影响指定准备调用。

Direct/statx 不支持时本轮验收失败并报告环境，不能换 Buffered 当通过。Linux WSL 文件不证明裸设备或掉电；有限 worker 调度和 ASan/UBSan 不穷尽数据竞争。临时 no-PIE/检测器设置不改变生产 CMake 默认。对未知的设备永久阻塞不承诺强制关闭。

沿用 F01 已证实支持 LeakSanitizer 的沙箱外环境执行，未关闭泄漏检测，也未重复制造已知 ptrace 启动故障。没有改变生产默认构建参数来迁就测试。测试 runner 记录精确命令、配置、退出码和超时，源码匹配漂移时停止变异；变异只在临时副本，正常对象来自 CMake。runner 没有生产测试 API、独立 oracle 副本或常驻注册，按 §4–§8 一并复审。

### 10.1 发现并修正：runner 可以把零用例误报为六项通过

**P2，测试工具缺陷。** 旧归档 `run_stage.py` 第 56–62 行直接继承环境，运行后只检查退出码，并固定打印六项通过。实际设置 `GTEST_FILTER=IOExecutorTest.NoSuchCase` 后，GoogleTest 日志和 XML 均为 **0 项**，脚本仍退出 0 并打印 `6 stage checks passed.`。原归档 XML 确实包含六个完成且成功的用例，因此原次执行有效；缺陷在于以后复跑可能假通过。

修正仅位于阶段 runner：

- 子进程隔离外部 `GTEST_*` 配置，显式选择本模块场景、运行一次、不打乱顺序；记录被隔离的配置名称。
- 开始前删除旧 XML，避免误读陈旧证据。
- 退出码为 0 后，再用本模块约定的六个名称核验 XML；必须全部出现一次、实际运行并完成，无失败、跳过或禁用，才报告通过。名称清单独立于生产实现，不通过解析被测代码生成。

真实复验同时带入不存在的过滤条件、零次重复和分片配置，仍完整执行六项、全部通过；ASan/UBSan/LeakSanitizer 保持开启。原五个隔离 mutation 重新执行，均由指定用例断言发现。对 runner 的一次性自检还确认：拒绝实际零项 XML、缺项、跳过、重复名称及失败记录，接受原来的完整成功 XML。这些是**测试工具判定的验证**，不另计为 F02 的六项组件覆盖，也不建立常驻工具测试套件。
