# S13.3 单客户端请求与结果窗口

2026-10-09，用户授权实施。延续 S13.2b/F35，不新增会话服务、去重日志、执行器或回收器。

## 1. 协议与顺序

- 原 WRITE 帧、V2 CommandBatch 和 V2 会话快照继续可读；新窗口 WRITE 和 ACK/CLOSE 使用显式新帧。旧客户端的拒绝不消耗请求号。启用新窗口前升级参与复制/恢复的节点；不承诺旧二进制读取V3，不静默降级。
- 窗口会话由新 client_id 的 request=1 建立；禁止在旧会话上静默升级，禁止降级后重新执行。
- 建立新窗口的首个请求串行准入，保证批次校验/Apply间不会超发全局会话名额；其后跨会话仍走既有流水线。
- 同客户端最多保留 8 条未确认结果；节点现有请求数、输入/命令字节预算继续限制在途工作。新窗口会话（包括关闭墓碑）最多 4096 个；单条结果正文最多 512 字节错误描述加固定字段，不能无限保存结果。
- 同客户端依请求号 Prepare，上一条发布后才准备下一条；不同客户端继续依表/键登记并行。重复身份查有序索引，不遍历历史。
- 乱序请求只占有界在途位置，缺号时不持业务依赖。资源无法保证缺号请求前进时，返回暂时拒绝让客户端重试，不永久占着窗口等待。首轮缺号直接返回 GAP；请求已连续排队时允许后续进入，实际 Prepare 仍排队。
- 仅明确的 SQL 业务错误写成最终拒绝记录并消耗编号；未知异常、IO 错误和持久化不明确不能伪装成业务拒绝。新结果区分 COMMITTED 和 DURABLE_REJECTED。
- SQL 输入边界明确处理同条 INSERT 的重复主键、NULL 主键和不受支持的索引定义；前两者复用已提取的主键集合，后者复用现有纯定义校验。不将整个 Prepare 的普通异常统一转成业务拒绝，恢复及已提交命令的校验仍保持严格。
- 未准入的容量拒绝、GAP、WINDOW_FULL 不消耗请求号；只有带持久收据的 DURABLE_REJECTED 才是占号的终局拒绝。客户端不能把一般 REJECTED 当成已持久化结果来确认。

## 2. 确认与关闭

客户端维护原始 SQL、身份和连续已消费边界。先在客户端保存“不再重试此前未知请求”的承诺，再发 ACK；不是把见到的最大编号当确认。库仍是无状态 Send，调用方负责持久保存这些信息，CLI 显式传入，不自动生成新身份掩盖未知请求。

WRITE 可带 ack_through；独立 ACK 复用同一 Raft COMMAND_BATCH 控制封装。ACK 幂等，只允许确认已完成的连续前缀；Apply 后删除结果并留下退休边界。即使结果窗口满，单独的控制任务仍可使用保留的任务/内存进展额度。确认和业务写入分成可独立重试的提交，绝不先清内存后持久化。

CLOSE 必须确认全部已完成结果且没有该客户端在途业务。提交后保留小墓碑，旧身份永不重用；不按本地 TTL 删除身份。关闭/确认不消耗业务请求号，RPC request_id 只用于响应关联。重复 ACK/CLOSE 安全。

## 3. 唯一所有者与恢复

Node 的在途索引、依赖登记和等待者只在内存中；实际任务退出后释放。SessionTable 是请求完成/结果/退休边界/关闭状态的唯一持久逻辑事实。V3 CommandBatch 和 V3 会话快照携带扩展信息；纯旧会话仍可编码 V2。A checkpoint、canonical/shared/incremental snapshot 复用 SessionSnapshotCodec，无第二份会话地址表。

窗口会话固定结果上限；遗留会话维持既有单结果行为，不编造此前结果。确认后的迟到请求返回已退休，不执行；未确认的同号不同正文拒绝。切主通过原当前任期 NOOP/Apply 屏障接续，未知结果仍用原身份查。

## 4. 实施及验收

先审顺序、锁/任务寿命、拒绝类别、确认发布和恢复逻辑，再补测试。不得只对实现内部容器写镜像断言。复用原 SessionTable/codec/FSM/真实三节点 TCP 测试和共同 C/P；新增窗口能力放 F35 单一归档，更新后删除旧同名版本。

重点：同客户端多请求、重发早期结果、正文不符、缺号、终局拒绝后继续；结果满后 ACK 能推进；ACK 后迟到不重放；关闭、切主、重启、快照后的结果/业务一致。窗口功能通过不等于最终性能、所有 F26/S12 尾项或真实掉电验收完成。
