# S11 / F25 快照 DATA 压缩与锁外交接

已完成本轮范围（2026-10-07）。[实际改动、实测及八项审查](s11_compression_execution_20261007.md)；不把 F35/S13 全部标为完成。

## 1. 范围与关系

日志可追赶时仍补日志；必须快照时沿用全量/增量选择。压缩只缩小节点间 DATA 正文，REUSE 仍为逻辑范围描述。本地 checkpoint、对象映射、Journal、Manifest 格式和快照身份不因此改变。接收端解压后进入已有 StageChunk、PrepareSnapshot、发布及 Install，同一候选只构造一次。

此前关于持锁的说明需区分：TcpTransport 的 connect/read/write 已在节点锁外；快照分块正文读取、构造和安装此前在协议调用内。本轮将发送正文读取/压缩及接收解压交给有界 worker。OfferDelta 的格式头探测/元数据差异规划、StageChunk、数据库安装仍按原串行路径执行，完整存储/Apply 异步化归 F35/S13。

## 2. 协议与选择

1. 先发扩展 Offer，目标必填、基础可选；回复确认支持 LZ4，并独立说明基础是否可用。无基础也能压缩全量。
2. 未确认能力时先退回已有 Offer（有基础时），再回旧全量原文。新增 RPC 类型承载扩展字段，原消息字节不改。错误基础或解码损坏仍报错，不伪装不支持。
3. 原始块上限沿用 64 KiB；独立 LZ4 block，无跨块字典。新增算法、原始长度和协商身份；压缩长度复用 Blob 长度。offset/next_offset/done 全按原始字节。
4. 首轮至少 4 KiB 才尝试，计入新增描述后节省至少 12.5% 才发送压缩正文，其余走旧 Raw。与增量 20% 筛选是两个决策，不改变设备对齐。
5. 接收限制输入和解压后大小，要求实际长度严格相等，复用 RPC CRC 和快照/候选验证，不新增重复 SHA。通用 RPC 编解码器只编解码字段，不压缩或解压，避免重复编码时反复计算。
6. 算法先采用 LZ4 默认；用相同真实快照 DATA 样本比较 Raw、LZ4、Zstd level 1/fast 的字节、编码/解码 CPU 和延迟。局部测量不替代原 C/P E2E 基线，也不把上游吞吐当本项目结论。

## 3. 有界任务、寿命与关闭

Raft 单线程决策 → TrySubmit 可靠接收任务及完成槽 → worker 锁外执行 → Raft Tick/Receive 消费完成 → 核对任期、peer、请求和固定目标 → 缓存并发送。

每 peer 最多一个待生成/待确认块；接收端最多一个解压任务。两条 worker、总计四个排队或执行中的任务，覆盖当前三节点并限制已取消的迟到任务。队满保留现有传输 pending，下一次驱动重试；不持节点锁等待入队、线程启动或完成。尚未认领（队满 pending）和已经执行的正文任务，都不能抑制正常心跳。完成存在任务自身 future，不经过可能满而丢弃的完成队列。旧任务即使失去调用方，也持有输入 lease，真实 IO 退出后才释放。

发送成功后缓存编码块，重传不重读/重压缩。后台不直接访问 Raft 可变状态或 SnapshotStore 可变清单；只持不可变输入和已确定差异计划。接收完成重新经过任期/会话/过期检查，再做 Stage，不提前 ACK。错误返回对应请求失败；失败不能污染已发布状态。节点销毁先停止接纳并排空 worker，再销毁 Store 和底层存储。socket 等待仍由既有 transport 承担。

### 3.1 与现有模块复用及重复工作约束

| 组件 | 持有的任务及责任 | 与其他队列的关系 |
| --- | --- | --- |
| RaftNode / F35 当前局部接入 | 传输状态、任期/会话、pending 和完成消费 | 协议决定能否使用结果，不执行压缩 |
| SnapshotTasks（F25 私有实现） | 固定快照输入的正文读取、压缩/解压 | 两 worker / 四任务；会调用下层 IO，不占用设备 worker 等待自身依赖 |
| F02 IOExecutor | 对齐设备 IO、批次及 Flush、缓冲许可 | 继续复用；不复制为一套快照设备 IO |
| F19 ObjectTransactionPipeline | 对象事务的规划、提交与发布 | 继续复用接收存储路径，不作为通用 CPU 任务池 |
| TcpRaftTransport | 已编码帧的排队和 socket 发送 | 入队时校验并编码一次，发送线程复用该帧；接收保留一次完整规范编码检查 |

这些是上下游职责，不因都有队列而合并。当前没有可直接复用的有界通用 CPU 执行器；SnapshotTasks 保持内部实现，不新增公共调度服务。S13 若需要通用执行能力，应评估抽取现有任务原语，不能并排再造同职责快照 worker。

接收完成槽只保存任期、请求、会话和目标身份；压缩正文由解压任务持有，不额外在身份槽复制。重传复用已压缩正文；TCP 帧复用仅限本次入队至发送，不宣称跨重传全部零拷贝。校验合并必须保留 CRC、长度、字段合法性和规范表示检查。

## 4. 顺序、参考与审查

顺序：协议及生命周期 → 生产编码/worker/Raft 接入 → 从逻辑审查协商、资源、过期任务和错误 → 复用真实节点/SQL/恢复场景补测试 → 实测及八项审查 → 单一 F25 包归档。

- [LZ4 v1.10.0 API](https://github.com/lz4/lz4/blob/v1.10.0/lib/lz4.h)：有界输出与安全解码；本项目用独立块，传输层持有长度/算法，并判断净收益。固定版本源码与许可证纳入第三方目录。
- [etcd/raft](https://github.com/etcd-io/raft/blob/main/README.md)：协议决策与外部 IO 分离；内化为 F25 任务/完成交接，不把 worker 的完成等同 Raft 提交，不迁入 etcd 整套 runtime。
- [Zstd](https://github.com/facebook/zstd)：速度与压缩率可调；作为相同正文的比较对象，CPU 优先是本轮初始取舍，网络较慢时可能需要不同选择。
