# S12 / F32 按需元数据缓存与 CLOCK-Pro（2026-10-08，本轮已完成）

本协议落实近期讨论，优先于各模块早期“当前页全部驻留”“保留 A LRU-K”“快照关闭后仍可查询”等描述。归属 F32，协作 F08/F09/F26/F31/F30；不新增缓存服务、线程池或持久格式。

## 1. 已确认的范围

- A 的默认替换策略从 LRU-K 改为 CLOCK-Pro；B 的新按需缓存共用策略代码，各自独立状态与预算。移除失去生产用途的 K 参数和旧中转路径；课程替换器测试仍是历史算法验证，不作为新生产策略证据。
- CLOCK-Pro 保留冷热分类、引用位、三个扫描位置和有界非驻留历史；冷热目标自适应，不固定六四/七三。环位置界定测试期，不逐页设定时器。策略只推荐候选，所有者核对版本/pin/IO/可重读性后执行淘汰。命中直接由缓存槽位标记引用，不增加页号哈希查找；ghost 索引仅在缺页接纳时查询，不持有正文/翻译访问权。
- A 复用 FrameArena、FrameHeader、TranslationDirectory/PathCache 和原 IO 寿命。B 复用 MetadataPager、F05/F02/F01，保持固定元数据区域，不通过对象映射递归读取自己。
- B 的描述保存 page_id/generation/LSN，正文可以缺席；同页同版本加载合并，等待设备不持全局缓存锁。最终页仍保存精确版本时才可淘汰。写回覆盖固定槽位前，把仍被旧视图需要的旧正文固定在 RAM；脏页、唯一旧版不可丢弃。查询使用正文持有者，不能从裸引用访问已淘汰正文。
- 普通 B 视图只在原引擎打开期间允许开始查询；Close 拒绝新查询并排空已接纳查询/IO。已复制结果有效，旧视图不能转接重开实例。此选择已获用户确认。

## 2. 写回与恢复

提交准备阶段收集实际修改页和预备发布所需节点；Journal durable 后才发布并登记待写回。每个物理页位置最多一个 pending 节点，保存最新已提交版本。写回器提取一批独立页、固定发送版本，经 F02 写入与 Flush；成功仅确认实际发送版本，期间较新提交仍在队列。失败保留待处理状态，同一位置的 IO 按序，不以较旧完成清掉新脏状态。队列在 RAM，恢复按重放结果重建，不能用它代替 Journal。

B 的 checkpoint 写回和恢复校验继续复用原格式与 CheckDiskPage。加载验证身份、generation、LSN 和 CRC；恢复流式读取可重读正文，不将全部冷页永久驻留。重放出的脏页必要时有界写回，避免有效历史仅因冷页总量超过正文缓存而无法打开。F30 绕过缓存读取实际持久字节，保持现有写回/扫描互斥。

## 3. 资源和同步

现有 max_live_pages 继续限制真实正文总数，包含私有/旧读者/在途正文；它不再要求大于所有持久页数。描述与 CLOCK-Pro 节点/ghost 有独立实际 RAM 计账，归 F31；虚拟翻译空间不按正文重复计算。必要工作继续使用已有进展额度；长旧视图或大事务仍可能暂时阻止推进，不能丢弃版本或无限等待。

CLOCK-Pro 节点和历史容量预先有界；命中只写局部引用位，结构调整使用短锁，不持策略锁调用缓存所有者或等待 IO。缓存所有者校验候选身份，淘汰失败不得把仍驻留正文误记 ghost。A 历史按目录实例内页号，B 按页版本身份；帧编号不充当长期页身份。ghost 不阻止翻译组 MADV_DONTNEED 或 Data 回收。

## 4. 执行与验证

先审逻辑再写测试：检查版本覆盖/加载交接、并发首次加载、候选失效、发布后无分配、较旧写回完成、关闭排空和恢复。复用正式对象事务及现有门控设备，独立正文模型作 oracle；测试源码不依赖 production hook/getter。

必要验证：B 持久工作集超过正文容量的读取、旧视图与写回、重启；A 真实页访问/淘汰/失败/并发；CLOCK-Pro 的冷热迁移、历史有界及无候选退让；原 F30 与对象/节点回归。性能采用相同总预算，含策略元数据，报告实际设备读/CPU/延迟，不能以组件测试声称完成原 C/P 或四模式性能评测。

每次修改测试必须按主方案 §1.5 八项审查；阶段源码/结果按 F32 各只保留最终压缩包，删中间产物、替换旧包。遵守 §1.7：先逻辑分析，避免防御性兜底掩盖真实错误。

参考：CLOCK-Pro 原论文 https://www.usenix.org/legacy/events/usenix05/tech/general/full_papers/jiang/jiang.pdf ；Pebble v1.1.5 的冷热/测试环 https://github.com/cockroachdb/pebble/blob/v1.1.5/internal/cache/clockpro.go 。工程采用有限扫描以适配数据库 pin，不以策略近似放宽数据正确性。

## 5. 实现时进一步明确的交接

- CLOCK-Pro 每次候选搜索最多处理 `8 × 帧容量` 个节点。冷页均被 pin 时继续推进热手，冷热目标不能让可淘汰热页无法到达。B 遇到仍有正文持有者的候选，本次搜索临时排除，结束后恢复资格；所用槽号工作表预先按缓存容量计账，不能不停返回同一阻塞页。
- A 同页竞争加载失去发布资格是 Retry，不是容量不足。即使获胜映射在下一次查询前又被淘汰，失去资格的一方仍重新查找；真正无资源仍明确返回不足。预取可跳过该提示。未增加重试线程、睡眠轮询或隐藏 IO 错误。
- B 页位置锁在加载、覆盖及 Flush 间保留；全局缓存锁仅保护描述/驻留交接。覆盖先持有旧正文，IO 拒绝前不改变其可重读资格，接纳后撤销资格；无论失败与否，旧视图不读可能被部分覆盖的位置。
- Open 从 checkpoint 流式读取、校验；重放一个完整 WAL 批次后按每批一页写回已提交恢复状态，使后续重放可回收冷正文。周期首改 FULL 和既有 checkpoint 恢复计划保证已覆盖页由 WAL 恢复；未写回的旧读者版本不跨进程保留。恢复不等于只读操作，不能将写失败伪报为成功打开。
- 保留描述不等于驻留正文：描述与页版本目录仍随持久页数/旧视图增长。F31 的计账不宣称等于进程 RSS；STL/共享指针控制块、返回值及操作系统附加成本仍需观测。旧视图过长或事务过大能触发明确背压，释放后可推进。
- 旧课程算法源码由对应课程测试单独编译；生产库只编译 CLOCK-Pro。移除 LRU-K 的生产专用 Candidate/RecordPinnedAccess 扩展、K 参数与 benchmark 开关，没有双策略常驻。

执行与每次测试设计审查见 [F32 执行记录](s12_cache_execution_20261008.md)。本轮机制结果不能替代 SS/RS/PL/GT、原 C/P、设备掉电或不同机器性能比较。


## 6. 2026-10-09 复审补充

页正文额度从临时分配交给 shared_ptr 删除器后，只能由后者归还；控制块分配失败仍会执行删除器，不能在外层再次减计数。见 [复审与测试判据](s12_cache_execution_20261008.md#9-2026-10-09-再次审查所有权交接与历史判据)。CLOCK-Pro 的阶段验证区分相同完整页身份的历史命中与页号/generation/LSN 改变，不靠新增内部 getter 验证；策略性能仍沿共同评测计划。

同日再次复审落实既有独立 oracle 要求：旧视图、写失败和热页正文以提交前输入判断，不能仅以首次 Get 的返回值作为 expected；合并加载保留一次必要扫描与真实 IO 门控，删除重复预热。三个 benchmark 改为直接依赖 AccessType。范围、11 项复验及 66 项同源证据的沿用依据见 [审查 §10](s12_cache_execution_20261008.md#10-2026-10-09-再次复审预期正文必须来自独立输入)。
