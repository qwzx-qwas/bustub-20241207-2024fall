本轮接续 F32，总方案与 F34 原“待确认”提议已获用户执行授权。主责 F34，配合 F09/F10/F22/F31/F32；沿用原测试内容和组件，不新建存储、缓存、队列或回收模块。S13、原地 RMW、页式图索引不在本轮范围。

## 1. 生产入口

- bustub-node 增加 --storage-config FILE；配置为版本 1 的 UTF-8 key=value 文本，空行及 # 注释允许，字段显式、未知/重复/遗漏项报错。相对设备路径以配置文件目录解释。
- --storage-action initialize 是明确初始化动作，成功后退出；默认 open 只打开已初始化设备。initialize 仅面向预先准备的空设备/定容文件，不创建、truncate 或清空已有设备。复用 Bootstrap/NodeStorage/RaftObjectStorage 的 Create；初始化失败不自动覆盖或重建；仅对确定未接纳的 space 申请暂时繁忙退让。
- 布局由 create.capacity/metadata/journal/data 字段提供，仅用于初始化；Open 使用磁盘引导布局。持久身份、Journal 几何、分配单位、Raft 段大小与原格式核对；内存/IO 参数走原组件验证。运行配置不是第二份持久目录。
- 首版初始化建立新对象存储的第一个空间（space=1），随后建立 Raft 控制根、绑定 node/group/voters；配置不能在初始化途中被工具偷偷改写。非空/不完整初始化须明确诊断，不能 Open 失败后重建。
- CLI 对设备 inode 持有排他的非阻塞文件锁，覆盖初始化、正常服务和关闭寿命；只阻止本工具协作的重复打开，不声称能阻止任意外部写者。A/B 仍独立，A 帧和 B 工作正文等共享节点 ResourceBudget。
- Direct 为正式设备路径，对齐实时查询；配置中的页/分配/Journal 单位是声明的几何，由原组件校验，不假定设备要求始终是 4 KiB。

## 2. 逻辑审查发现的生产交接

现有节点打开 B 后没有周期调用 B 的 Writeback/Checkpoint。仅增加 CLI 将无法保证脏正文及 Journal 长期推进。本轮将 B 维护接到既有 ObjectTransactionPipeline 的 GC 执行角色：每轮先有界写回一批，再按明确的轮次间隔 checkpoint；其后继续 Store/范围回收/扫描。已接纳维护使用既有进展额度；没有新维护线程。配置为零保持既有局部组件的手工维护语义；正式部署显式启用。

提交在 `MetadataCommitBusy` 后不能只等周期维护：Store 维护可能正在同步等这次提交，关闭也会先停止周期工作。因此，启用自动 B 维护的部署允许提交角色调用**同一个 B 写回器**推进最多 `metadata_writeback_pages` 页，再重试尚未接纳的元数据发布；写回门控仍归 B，已有写回/checkpoint 占用时退让。这里不做周期 GC、不另发 checkpoint、不重做已完成的 Data IO；真实写回错误上报并结束请求。手工维护部署（页数为零）维持原约定。该规则同时避免正常 Store 回调自等和关闭排空失去进展来源，不需要延长全部后台任务寿命或新增线程。

B 页 IO 准入统一复用 F02 的既有容量计算（包括当前资源类别、名额、缓冲及实际内存对齐开销）：单批本身超过总容量返回明确的 `ResourceUnavailable`，不作为可重试 Busy；能放下但名额/缓冲暂被占用时返回 `MetadataCommitBusy`。换入、写回、B 校验和 checkpoint 恢复读取共用同一内部入口，停止及实际提交后的 IO/Flush 错误仍沿原错误链处理。不能把所有 F02 Full 都直接重试，也不能因临时 Full 把自动维护升级为节点故障。

同一规则接续到 checkpoint 的 Journal 提交，不能只修页写回：B 普通提交与 checkpoint 共用准入分类，Journal Full 为 Busy，NoSpace 为明确资源不足，Stopped/Faulted 为不可用。F07 在实际准备前复用 F02 容量计算，联合计算本批所有段写请求、实际对齐开销及独立 Flush 的一个名额；单批不可能容纳抛既有 `RequestTooLarge`，不消耗游标或返回可重试 Full。暂满退出 checkpoint 时释放其提交门控，后续按原维护节奏重试；已经提交后的失败仍沿原持久化结果处理。

checkpoint 复用 F10 的门控、逐批写回、根发布、PayloadRef 保留与日志裁剪。无新提交时不反复生成相同恢复点。checkpoint 仍可能暂停 B 提交，不能宣称全程无阻塞；本轮观测成本，S13 不因此提前实现。暂时繁忙让出，真实损坏/IO 错误沿原错误链报告。

## 3. 运维观测与空间口径

增加显式 storage STATUS 请求（frame type 5），在既有响应 payload 中返回带版本的对象存储 JSON 摘要；普通 STATUS 的空正文及旧 frame type 保持不变，旧客户端仍可查询普通状态。新运维请求对旧服务不承诺兼容。提供 Data 可分配/已提交/预留/隔离容量、B 正文/页描述数量/换入淘汰及扫描进展，读取不等待设备 IO，不在节点协议锁下扫描位图。观测是正常运维能力，测试只消费正式接口；不暴露可修改内部状态。

Data 统计取自唯一分配器位图，不建立第二份分配事实；元数据/Journal 是固定保留区域，与 Data 实际占用分别表达。预分配文件的长度及 st_blocks 仅为宿主占用，不能用来证明内部空间回收。采样缺失要报告，不能补零或沿用旧值伪装正常。

## 6. 本轮实现的维护参数

`transactions.metadata_writeback_pages` 是单批 B 页数；`metadata_checkpoint_rounds` 是维护轮次间隔，轮次间隔沿用 `gc_interval_ms`。正常节点示例每轮最多 32 页、每 100 轮 checkpoint。它不是每个提交 checkpoint，也不是已证明最优的频率。无新提交则跳过重复发布。回收、校验仍各取有界工作，检查点内部按原协议逐批写完候选，可能比单轮写回耗时更长。

新运维接口是所有者的只读使用量快照，没有新状态真相或缓存。B 描述数是已建立的页槽描述（可能含准备过而未发布的高水位），live_bodies 包含工作/旧视图保留正文，不能相减并称为精确冷页数。load/eviction 只在实际换入/淘汰处更新，命中不额外计数。

正式 C1 暴露了原 S7 交接缺口：B checkpoint 的临时 `MetadataCommitBusy` 曾被已接纳对象事务直接作为 NotCommitted 返回，随后同步 Raft 持久化路径停止。现在提交角色保留已经持久的数据依赖，仅重试尚未获准的元数据发布；不重做 Data IO，不把不明确/真实错误一律重试。公开运维响应同时保留致命错误原因，避免仅返回无原因的 UNAVAILABLE。

长追赶进一步暴露了同类但不同的入口：F28 克隆工作区直接分配新 space，没有经过 S7 提交队列。ObjectPageStorage::Create 及 CLI 初始化对尚未接纳的 space 分配补上 MetadataCommitBusy 等待，成功后只记录一次身份。既有空间/对象不存在、损坏或不确定提交不会被这一规则吞掉；ShareObjectRangeBatched 原本已有对应处理，继续复用。

## 7. 验收暴露的 S13 交接

正式 C1 在一次约 584 ms 的查询后收到新任期 NOT_LEADER；代码确认 HandleRead 在执行 SQL 时仍持有节点协议锁。584 ms 是请求总耗时，不是经过独立测量的锁占用时长。20,000 行 P2 资格也在准备校验中频繁换主。不能通过健康流程偷偷添加重试、扩大选主超时或降低业务规模来标记通过。

接续 S13 时应先明确 ReadIndex/已发布应用进度与 SQL 读取保护的锁外交接，连同 Apply/同步 Store 调用对协议推进的影响一起分析；不能直接删掉节点锁而破坏一致性。当前轮只保留证据和下一步边界，S12 总验收仍未完成。[逐项审查与实测](s12_node_execution_20261009.md)。

## 8. 冷元数据范围扫描接续

64 页 B 正文预算下，实测元数据换入非常高。代码定位到 ObjectMappingSnapshot::Resolve 先执行没有上界的 Scan(lower, max_query_spans+1)，再由上层过滤对象及读取终点；一次小范围查询也会提前读入后面无关记录的值。

在现有 MetadataSnapshot::Scan 增加显式 [lower, upper) 重载，两种调用共用一个遍历实现；先检查键上界，再读取值。Resolve 保留 GetFloor 的覆盖范围定位，以对象逻辑终点为上界；分页 limit 和空洞语义保持。无新增缓存/索引/线程。同类修复接续 Cut、Retired/Controls/EstimateRewrite、Deferred 枚举及 GC 的所有权/共享/待回收扫描；按其已有终点或 owner/类别边界停止，仍枚举全部相关内容并保留原数量上限，不改成只查一条。上层已由 Scan 保证的重复边界过滤移除，格式和存活性检查仍由原所有者负责。范围 API 有真实生产消费者，独立输入模型覆盖非零起点、跨叶、跨 owner、limit 和空范围，阶段测试仍归 F34 同包。

## 9. 共同快照观察兼容

原 C5 的独立代理只识别原文 InstallSnapshot(type 5)。本轮保持真实 wire type，扩展其已有观察解析到增量(type 9)、压缩(type 12)，使用 REUSE 长度或压缩前长度判断逻辑进度，完成响应仍是 type 6。观察器不重建快照、不解压，也不替代接收端校验。短追赶继续排除全部快照编码；长追赶必须请求/term/ID 对应、非 stale 完成且业务内容一致。原文重放故障工具入口保持原用途，不宣称已升级成新编码重放器。
