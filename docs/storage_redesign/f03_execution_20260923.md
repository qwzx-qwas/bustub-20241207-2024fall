## 1. 测试全景

八项均为 **integration（真实组件链路）**：BootstrapStore → IOExecutor → BlockDevice → Linux Direct 文件。不是三节点 E2E；注入 EIO/暂停/读回损坏的分支明确是测试侧模拟。源码仅在 F03 压缩包中，不注册常驻测试。

| --- | --- |

## 2. 逐项：目标 → 输入 → 执行 → Oracle → 失败含义

### 共同 setup 和 oracle

每例独立临时文件，8 MiB，内容由字节位置的固定公式生成，只有两个槽位按场景置零或置入副本。身份是两组不同的非零 16 字节值，三段区域位置/长度明确，不用空参数凑成功。最多两个 IO worker、一个按需修复协调线程；F02 显式 1 MiB 自有缓冲预算、2 或 8 成员。构建 `-j2`。

测试侧 `Put` 明确写每个固定偏移，`ReferenceCrc` 用独立表驱动 CRC32C（另以 `123456789 → e3069283` 标准向量校验辅助实现），不调用生产 ByteWriter、Decode 或 Crc32c。既用独立镜像测生产解码，也将生产写出字节与独立镜像比较。`ReadRaw` 用独立 POSIX 读取整个文件、检查长度及槽位外邻居；不让 F03 自己读回来给自己作证。真实 Flush 调用及成功次数单独观察，普通读回不能代替持久化证据。

`--wrap=pread/pwrite/fdatasync` 及关闭场景的 `pthread_cond_clockwait` 观察只在测试链接启用。正常分支进入真实系统调用；fixture/oracle 通过 `__real_*` 绕开注入，防止误伤准备和判定。测试本身没有绕开被测的 F03→F02→F01 正常路径，也没有用假内存数据库代替它。

### 2.1 CreationAndIndependentFixturesAgreeOnDurableLayout（包内第 333 行）

- **目标**：格式和持久完成既符合规范，又能重开。
- **输入**：两个全零槽位、非零身份、三个合法区域，槽位外有不同正文。
- **执行**：Create → 两成员写批次/Flush；销毁设备和执行器后重开；再单独装入测试侧编码的镜像 Open；健康状态 StartRepair 无需任务。
- **Oracle**：全文件与独立镜像相等、成功 Flush > 0、返回的每个身份/容量/区域字段等于人工输入、健康无修复写。预期不取自生产编码结果。
- **失败含义**：格式偏移/端序、区域或副本位置错误，漏持久化，Open 解释错误。不能从重开推定物理掉电验证。

### 2.2 OpenRejectsAmbiguityAndUnknownFormatsWithoutWriting（包内第 368 行）

- **目标**：只在来源可确定时接受布局，读失败不是覆盖许可。
- **输入**：好+坏、空+好、双空、双坏；合法 CRC 下的 magic/version/长度/features/reserved/padding 未知内容、两类身份冲突、两个不同有效布局、越界及溢出区域；另一个槽读取 EIO。
- **执行**：每种独立镜像经正式 Open；除模拟 EIO，读取都走真实设备。
- **Oracle**：期望成功/冗余不足，或具体 BootstrapErrorCode；IO 错误保持 EIO。所有分支无写入/Flush、全镜像不变。语义坏样本重新计算 CRC，避免只测到 CRC 拒绝而漏掉身份/布局检查。
- **失败含义**：候选选择/兼容判断/错误传播错误。正反分支同时存在，始终拒绝实现不能通过。CRC 错误与有效未知格式分开验证。

### 2.3 CreateProtectsExistingContentsAndRejectsInvalidRegions（包内第 429 行）

- **目标**：创建不能损坏现有内容，布局不能侵入保留槽或其他区域。
- **输入**：区域覆盖槽位、区域互相重叠、容量不同、越界、零长、按真实设备对齐构造的不对齐区域，以及仅第二槽最后一个字节非零。
- **执行**：正式 Create 准入与空槽检查。
- **Oracle**：明确 InvalidLayout/NotEmpty、没有写 IO、整个文件不变。第二槽尾部非零防止只检查首槽/页头。
- **失败含义**：格式化保护或区域检查缺失。本例不复制 F00 所有整数算术组合，关注 F03 是否在任何写入前拒绝危险布局。

### 2.4 CreationFailureCannotBecomeDurableSuccessOrBlindRecreate（包内第 463 行）

- **目标**：失败不得报告创建成功，已写副本不可被再次创建掩盖。
- **输入**：单 worker 下第二副本写 EIO，确保第一份已写；另例两个写成功但 Flush EIO。
- **执行**：Create 失败 → 再次 Create → Open。只在系统调用边界注入故障，不替换 F03/F02。
- **Oracle**：原 EIO 传出；第一场景只有第一槽有完整镜像、再次创建 NotEmpty、Open 冗余不足；第二场景镜像可能完整可读但 Create 必须失败、成功 Flush 为零、再次创建仍拒绝。
- **失败含义**：吞写入/刷新失败，误认为失败无副作用，或自动覆盖有效内容。模拟 Flush 失败留下可读内容是该注入的观测，不证明真实故障后的任意字节状态。

### 2.5 RepairIsAsyncPreservesSourceAndAllowsIndependentIO（包内第 492 行）

- **目标**：修复不成为 Open/独立 IO 的同步依赖，只写坏目标，健康不能提前发布。
- **输入**：第一槽有效、第二槽空；暂停第二槽真实 pwrite。另一个合法数据范围包含已知不同正文；随后交换有效源位置再修复一次。
- **执行**：Open 已返回 → StartRepair → 目标 IO 确定进入暂停门 → 重复 StartRepair → 同一 F02 的独立读完成 → 放行 → 检查修复；源/目标反向再测。
- **Oracle**：暂停时仍冗余不足，独立读在放行前成功且正文正确；终态成功/错误清空；两种源位置下，所有尝试写范围都只能落在目标槽，成功传输总量恰为一个槽、真实 Flush 成功；完整镜像包含两份准确副本且其余内容不变。合法短写可有多个系统调用，不以调用次数作为成功合同。
- **失败含义**：隐藏串行等待、提前健康、重复任务、写反源/目标或破坏邻居。独立 IO 有预留资源，不能据此推定共享磁盘零争用或后台有公平调度。

### 2.6 RepairRetriesRequireSuccessfulFlushAndReadback（包内第 536 行）

- **目标**：重试有上限，成功同时受持久化、读回及来源限制。
- **输入**：第一次 Flush 失败、持续 Flush 失败、写后目标读回字节被测试侧破坏、写后固定源读回损坏（两种源位置）、Open 后源丢失/目标变成有效异身份。
- **执行**：正式后台 Prepare/Read/Write/Flush/Read/重试；独立真实磁盘 oracle 不受读回注入影响。
- **Oracle**：一次失败后两次尝试成功且确有成功 Flush；持续失败两次后 Failed/保留冗余与异常；读回错误不得 Succeeded。修复前的来源或身份变化一次失败即结束，无写、镜像不变、明确 SourceChanged/IdentityMismatch；写后读回发现源损坏也必须在第一次尝试立即 SourceChanged，不额外重试。
- **失败含义**：重试上限失效、失败后凭缓存字节假 durable、漏读回、无权来源自动覆盖。这些分支新增不同风险，不能只保留普通成功修复测试。

### 2.7 AdmissionFailureIsBoundedAndDoesNotChangeCopies（包内第 614 行）

- **目标**：F03 在无额度条件下正确终止或保留状态，不无界排队。
- **输入**：通过 F02 正式准备接口占满两个成员，Open 明确拒绝；释放后 Open 成功，再占满进行两次各 5 ms 准入等待。
- **执行**：F03 正式启动拒绝及后台 Prepare/Pause/尝试终止，无生产预算 getter。
- **Oracle**：首轮 ResourceUnavailable、无读取；后台两次后 Failed/冗余不足/同类错误，零写且镜像未变。5 秒 watchdog 防永久挂起，不给性能打分。
- **失败含义**：F03 资源失败处理错误，或“启动失败”留下不可再 Open 的半状态。只测消费者如何处理 Full，不复制 F02 的全部预算算法测试。

### 2.8 CloseDrainsAcceptedRepairAndWakesAdmissionWait（包内第 642 行）

- **目标**：关闭不能让已接纳 IO 使用已销毁资源，也不应等满未接纳任务的长退避。
- **输入**：一场景在目标写已进入后暂停，另场景占满 F02 额度并配置 30 秒间隔/60 秒准入时限。
- **执行**：独立线程调用 Close；已接纳场景放行后排空。无额度场景通过测试链接观察生产线程真正进入长定时等待的边界，当时 F03 仍持有其状态互斥锁，Close 的停止决定必须在该等待原子释放锁后才能进行，从而确定地测试唤醒；不靠 attempts 已加一猜测已经睡下。
- **Oracle**：暂停未放行时 Close 尚未返回；Close 返回后检查没有遗留暂停中的 IO，镜像正确。关闭线程若实际先设置停止，应 Stopped/保留冗余不足；若它被抢占、修复先完成，Succeeded/健康也合法。无额度场景确定等待后应在 5 秒 watchdog 内关闭、Stopped、零写、原镜像不变。
- **失败含义**：过早归还生命周期、遗留线程/在途 IO、停机等待整个重试时窗。已接纳 IO 的 20 ms 负面等待窗仅观察关闭尚未返回，不假定线程在窗内先设置 stop；补充 Close 返回时的实际门状态与完成检查。生产定时等待观察依赖本次 Linux/libstdc++ 的 clockwait 路径，未进入该路径会明确失败，不能假通过；这不是测试标准库计时精度或实时调度保证。测试进程总上限 120 秒，永久不返回的真实设备不在有限关闭承诺内。

## 4. 接口污染专项

没有把原 internal 函数变为 public、没有为原接口增加默认值、没有修改业务 API/路径/ABI 来迁就测试、没有 `#ifdef TEST`。新增 F03 API 是本次模块本身的职责；RepairOptions 无隐藏默认值，参数均约束真实任务。private Read/Write 的可省 options 仅复用启动与修复实现，不是对外测试便捷重载。

F03 自有缓冲是引导 IO 的正式用途；本轮不引入无消费者的对象路由框架或第二套设备执行器。F02 新增的 DeviceInfo 访问器不是“只被测试调用”的状态 getter。F34 整节点消费者尚待接入，不能隐瞒目前只有独立模块生产链路这一范围。

## 5. 重复与价值

- 2.1/2.2 共用 fixture，但前者保护写出/正常重开，后者保护多候选拒绝和只读；不是同一个 invariant。
- 2.2/2.3 均校验区域：分别保护不可信落盘格式和创建前防覆盖，调用边界不同。没有给每个字段单独建测试。
- 2.4/2.6 都注入 Flush EIO：前者是创建失败不自动覆盖，后者新增跨尝试的“读到相同字节也不能抹去之前的持久失败”。这是本模块实质风险，不宜去掉后者。
- 2.5/2.8 都用暂停门：前者是运行时独立推进，后者是对象/执行器生命周期，不能相互替代。
- 2.7 不重做 F02 记账测试；它只保护 F03 对资源拒绝的处理和有限重试。
- 原 F01/F02 组件测试没有 F03 格式/选源/修复；现有 C/P/课程套件也未经过这条链路，不宣称已有 E2E 等价覆盖。
- 本轮没有增加性能基准、标准库/第三方行为测试或只验证 enum 数值的测试；八项只按 F03 压缩归档，不常驻。

## 7. 稳定性、运行与实现审查

每例独立文件、固定内容、明确清理；faults 的跨线程暂停和更新受 mutex/CV 保护，设置/读取未加锁字段仅发生在相关工作提交前或批次/线程已排空后。暂停门 RAII 早于 store/future 销毁释放；线程引用的 promise 在对应 future 汇合后才销毁，避免异常退出时死锁或悬空引用。没有随机 seed 漂移、网络/端口或测试顺序依赖。等待完成使用粗状态和 watchdog，不新增生产 WaitForTest。

## 10. 再次方案与测试审查（2026-09-23）

本次从归档恢复测试，核对两个包的哈希及全部十个生产文件，未把上轮八项通过作为免审依据。

### 10.1 发现的问题与修正

1. **P2，生产与约定不一致：写后读回发现固定源损坏仍多重试一次。** 原 Repair 只在写前专门检查固定源；写后 Select 将“一份可读、源 CRC 错误”归为可重试 Corrupt。增强原 2.6 后，在源为第一/第二槽时均实际观察到 attempts=2，而方案要求立即失败、attempts=1，退出 1，其他七项通过。现在私有 CheckRepairSource 在写前与读回后复用；来源丢失立即 SourceChanged，合法目标的普通校验失败仍按原有界策略处理。此次复现没有发现源被覆盖或数据丢失，问题是多余重试/延迟及阶段错误分类。
2. **P2，关闭测试的异常退出寿命及顺序假设。** 原 promise 声明在等待异步任务的 future 之后，早退时可能先销毁仍被线程引用的 promise；已调整为先声明 promise/future，再声明释放门，保证先放门、再汇合、最后销毁被引用对象。这是静态发现的失败路径风险，未声称实际复现内存错误。原用例还把“线程发出即将 Close 的通知”当成“Close 已设置 stop”，现在允许两个真实合法顺序，并分别核对状态/冗余条件。
3. **P2，关闭唤醒测试可能绕过真正等待。** 原仅看到 attempts=1 就 Close，可能在进入 wait 前结束，使漏唤醒实现也有机会通过。现仅在测试侧观察 clockwait 入口，使用生产锁的交接确认实际等待；无公开 getter/hook，新增漏唤醒变异验证断言确实生效。
4. **测试细节简化：保护源不再绑定一次 pwrite。** 正常修复改为核对所有尝试写的范围及成功传输字节，允许合法短写；两种源位置都检查，不能靠重写相同字节逃过全文件 oracle。新增“写目标时也写源”变异验证此风险。
