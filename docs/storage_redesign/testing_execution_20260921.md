## 4. 问题分类与处理

### 生产表现

P2 并发增大后吞吐下降，并出现慢请求、换主与重试；P3 在固定时限内进展有限且后段吞吐降低。原始真实响应和业务核对证明这些现象不能简单归为统计遗漏。本轮保留表现，不优化生产代码。

此前已经诊断到数据库执行与 Raft 推进共享锁；但本次没有新的因果实验，不能断言它解释全部慢请求和 P3 变化。协议推进与数据库执行分离仍属于后续 F35/S13。

### 测试与报告

1. 性能点状态为 `measured`，旧 `all_planned_runs_passed` 仅识别 `passed`，造成与 `all_planned_observations_validated=true` 矛盾。现在性能汇总只用观测字段，正确性汇总保留通过字段。旧汇总保存在 `summary.original.json`，用原结果离线重算，原始历史与点结果不变。
2. P4 前台阶段预算漏算两段已有的 60 秒状态/停止等待，但外层预算已包含。现在共用一个预算函数；本次前台实际 1342.195 秒，未触及旧 2580 秒上限。修正不改变本次成功观测，不为纯预算计算修正重跑长负载。
3. 新增两项自检：合法零吞吐必须纳入中位数；缺失或未验证的重复不得被剔除后仍报告完整中位数。只保护测试器对外承诺，没有给每层实现细节补测试。
