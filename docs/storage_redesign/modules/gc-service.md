## 6. 讨论后的方案与待冻结边界

以下为本轮收录的设计方向和约束；具体字段、数值、接口及当轮验收未确定前，不能把它们补成默认实现。

### 6.1 分层判断与统一执行

F36 判断 A 的记录/页能否清理，F26 处理页/帧生命周期及对象范围释放，F22 安排回收并协调持久引用与在途使用，F12 才允许普通数据 extent 的物理复用。F22 不扫描 SQL 谓词、不解释 slot，也不把课程事务时间戳、Raft index、Journal LSN 取统一最小值。

F36 可先完成页内碎片整理和已有页复用，只有空页安全脱链后才进入 FS 释放。对象里其他活页、共享快照和大分配单元可能继续保留物理 extent；不能承诺每次删除都使物理占用立即降低。S9 集成复用 S7 的正式回收能力，不要求 S12 全部策略先完成。

### 6.2 恢复、引用和预算

解除逻辑引用进入正式持久化事务；等待旧版本、读者/传输/IO 保护后再复用。S11 与 F28/F14 固定业务恢复根协作；共享快照所需内容不因 A 认为新状态中的记录无用而提前删除。任务重试/完成按身份归并，不能二次释放被重新分配的范围。

S12 与 F36、F29 使用 F31 的共同后台预算；可回收判定由所有者提供，调度只负责资源和进度。具体请求格式、重试和预算待冻结。

### 6.3 Journal 复用、调度与物理动作

F07/F10 判断 Journal 恢复保留，S10 加入 F27/F14；F06 持有固定 Journal 槽位及段身份，执行“持久退役依据 → 禁止新访问 → 旧访问退出 → 新身份复用”。F12 只分配普通数据区域，不能用它的 bitmap 直接授权 Journal 槽位覆盖。

基础 Journal 裁剪须在 S5 由 F06/F07/F10 接续形成，S7 本模块再接入同一能力安排预算和任务；不复制一套生命周期，也不要求基础回收等待 S12/F29。明确未提交可先通知失败再异步清理，结果未知需先判定，不能将 IO 错误当释放许可。

待回收和可复用分开；可复用后可以保留旧字节直到新写覆盖，默认不清零整个旧段。若未来加入 discard/清零，其任务也须受分配身份和在途保护，不能在新分配后迟到执行。bitmap 摘要只是候选搜索，不代替存活性、持久退役和读者条件。

记录有效字节、无效但受保留字节、阻塞原因/持续时间及整理搬迁量；前缀整段策略可能出现保留浪费，优先推动所属模块解除依赖。FS Journal 的活内容搬迁另评估引用与恢复协议；F29 已有范围是 Raft 日志。F26 的 RAM hole punching 由其自身负责，不能使用此处磁盘回收状态删除翻译条目。
