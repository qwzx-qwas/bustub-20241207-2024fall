## 2. 已讨论的职责与边界

1. 先实现有界执行与基础对象通路，再接入普通对象寻址适配。
2. 接受已固定的可见映射或事务内预留映射，不把新数据错误写向旧位置。
3. Journal 写入不再次进入普通 Deferred；统一 IO 不等于统一持久化协议。

## 6. 讨论后的方案与待冻结边界

§6.1–6.4 保留设计约束和 F01 交接；S1 当轮具体范围以用户已授权的 §6.5 为准。§6.6 是后续 S9 评审稿，不属于历史授权；未确定的字段、数值和验收不能补成默认实现。

### 6.1 有界执行和页层协作

F02 接收已满足必要依赖的范围 IO，支持多个独立请求在途；同对象重叠范围/同页版本的顺序由相应 F17/F26 等所有者定义，执行器不能擅自重排。拆分/合并仅在身份、版本、操作、屏障和错误归属兼容时进行，不因地址接近扩大原子边界。

[F26](page-storage-adapter.md) 在页缓存中合并同一页身份/版本的加载等待，F02 不另建业务干净页缓存或 SQL 页目录。缓冲在 IO 完成前受保护；拒绝、部分失败、取消和迟到完成均要按 F00 归并结果及资源，不以最大完成序号冒充连续 durable。

请求和完成容量计入 [F31](resource-budget.md)；高层 pending 不能绕过预算。完成结果有可靠保存位置，唤醒可合并；F02 的逐 IO 完成不需要先往返 F35/F33。具体队列、线程/异步后端和额度留待当轮实现冻结。

### 6.2 后端与收益边界

独立页要真正并行，F01 文件模拟/裸设备后端须提供兼容的定位 IO 或明确同步，不能继续让所有请求依赖共享 seek 位置串行化。S1 建能力，S9 由 F26 接入，S13 按测得瓶颈调优。

同步上层接口可以保留；只有调用并发或已约定的有限预读才产生多 IO。顺序扫描/快照可讨论有限异步预读，随机点查不默认扩大范围；物理相邻不保证减少逻辑页数。

### 6.3 第二轮审查补充

采用 [F00 §6.6–6.10](storage-contracts.md) 的身份/范围、缓冲归还、完成和失败约定。统一 IO 不代表统一地址解析：S1 执行已校验范围，S2 接基础/引导区域，S6 再接 B 的普通映射。普通调用者不能伪造基础对象句柄越过映射写入元数据区域。

短 IO/校验失败不得伪装为成功全长读取；只按明确来源拼接有效字节。操作最终结果与输入缓冲不再被访问可分别完成；调用方超时不允许清理仍被 IO 使用的状态。F01 只刷新已提交到该打开实例的写入；F02 必须先确认所需写入实际完成，再调用屏障，并跟踪被合并请求的归属和依赖。上层排队中或尚在执行的写入不能由一次 Flush 自动变成 durable。

### 6.4 F01 当轮契约交接（2026-09-22）

[F01](block-device.md) 已完成本轮 Linux 文件后端验证：默认 Direct，Buffered 显式选择，statx 探测实际内存/偏移/长度约束，无能力信息就失败，不猜测 4 KiB。F02 的正式接口须保留这些保证，提供合规且有预算的工作缓冲，不能通过降级或隐藏 RMW 使非法请求“通过”。同步 F01 方法允许独立线程并行，返回/抛异常后才不再使用该调用缓冲；关闭设备前须由 F02 排空。

F02 测试复用 F01/range-io、reject-invalid、concurrent、durability、failure-boundary 的风险说明；归档中的组件测试不自动等价于队列/取消/业务 E2E。F01 交接本身不授权实施；随后用户明确授权的 S1 实现和验证见 §6.5/§7。

### 6.5 S1 当轮执行范围（用户授权后落定）

本节落实随后关于 IO worker、批次状态及“执行 F02 方案和测试”的讨论，覆盖上文相应待定项。实现 `IOExecutor`，即统一 ObjectIO 的执行部分；尚未引入普通对象目录、基础区域或虚假的 object→offset 映射。输入是可信上层已经解析并固定的设备范围，S2/S6 再接寻址及权限边界。

#### 调用顺序与资源

```text
TryPrepare(成员范围, 是否需要 Flush)
  → 一次预留成员/结果名额、带对齐余量的缓冲字节
  → Prepared：调用者填入写正文
TrySubmit(batch)
  → Queued：设备 IO 接管缓冲访问
  → 多 worker 执行独立范围
  → 全部相关写入成功后才执行所请求的 Flush
  → 保存终态和各成员结果，通知等待者
  → 调用者读取结果/正文；最后一个所有者释放后归还预算
```

- 构造时显式指定 worker 数、最大存活成员数、最大缓冲字节；没有隐含的生产默认数值、文件路径或固定 4 KiB 对齐。按 F01 查询值为每个成员独立分配工作缓冲，字节预算包含实际申请的对齐余量。分配可满足非二次幂约束，不把内存、偏移和长度约束混为一谈。
- `TryPrepare` 不等配额：返回 Accepted/Full/Stopped；非法范围或系统分配失败抛异常。Accepted 在此只代表准备资源成功，不表示已投递设备。分配异常完整退回预留。准备中、排队、执行中和未释放的终态结果占同一预算；成员/结果元数据以成员上限约束，并非声称整个进程的所有内存都等于缓冲字节数。
- `TrySubmit` 不等队列腾位：已经预留全部容量；队列节点分配失败不接受该批次，关闭拒绝仍保留 Prepared。禁止重复提交或交给另一个 executor。队列传递批次引用，不复制正文。
- 缓冲由 move-only 批次句柄拥有，提交后不能经 Buffer 接口访问；保存的裸指针也必须停止使用。完成后再开放访问。WaitFor 超时或销毁观察句柄均不取消已接受 IO，worker 保持所有权直到设备不再访问。没有持久数据缓存或 F01 中转复制。
- 准备缓冲不承诺已初始化，写调用者必须填满所请求的有效范围。失败读取不得把整份缓冲当有效结果；按实际错误和成功字节处理。Buffer 可访问只说明设备不再使用它，不代表读取或写入成功。
- 一个 executor 对应一个既有 BlockDevice；调用者保证设备活得更久，Shutdown 后才关闭。跨 executor 的节点级总预算将由 F31 后续统一接入，本轮是正式消费者需要的最小预算实现，不提前建通用框架。

#### 批次状态、错误与完成

| 状态 | 含义 |
| --- | --- |
| Prepared | 已预留资源，尚未提交，调用者可填缓冲 |
| Queued | 已接受执行责任，等待 worker |
| Executing | 派发或执行成员 IO |
| Flushing | 全部成员 IO 成功，等待/执行本批所需 Flush |
| Draining | 已有成员失败，不再派发本批未开始项，等待正在执行的成员结束 |
| Succeeded | 达到本批约定的完成要求；是否持久化另由 writes_durable 表达 |
| Failed | 成员或 Flush 失败，实际在途 IO 已结束，错误和已知进度可取 |

成员固定在 Prepare 阶段；锁内只派发一次并登记一次完成，保留原成员顺序的结果。所有已派发成员结束且没有错误，才可进入 Flush；不能使用最大完成编号推断没有空洞。未开始成员、成功成员、失败成员分别报告，IO 错误保留 F01 的 exception/成功字节含义。Flush 错误独立记录；`writes_durable=false` 不证明磁盘未改变。

正常读/无需持久化批次跳过 Flush；请求 Flush 必须含写入，仅承诺本批成功成员写入的设备范围。批内含写入的重叠范围拒绝，重叠读可并行；跨批冲突由 F17/F26 等调用者排序。本批非原子事务，不包含 Journal 编码、版本发布、Raft 提交或回滚。失败不会自动重试设备写入，也不把一个批次失败直接提升为整个节点失效。

#### 执行与关闭

使用一条活动批次队列、固定数量 IO worker；每次从一个可运行批次取一个成员，再轮转至队尾。队列节点保留到该批结束，派发、后续 Flush 和完成路径不再申请队列节点或结果槽。没有专门的线程同步等本批其他 worker；最后一个完成者只令 Flush 成为可运行工作。

短暂持调度锁选任务/更新状态，调用 F01 时释放锁。结果保存在批次中，条件变量通知可合并，终态不会因完成队列满而丢失。Shutdown 停止接纳并排空已提交批次，未提交或调用者持有的结果不妨碍线程退出；多个 Shutdown 调用归并，不能强行中止卡在设备里的系统调用。

F35 管 Raft 事件循环及 Prepare/Apply/Snapshot 等业务队列；F02 只管具体 IO 执行，逐 IO 完成直接返回调用模块，不经过 F35/F33 全局审批。保持旧 DiskScheduler、BufferPool 和 Raft Store 正式路径，S8/S9 再迁移；不修改旧单线程调度器来假装已经完成业务接入。

#### 开源机制落点

再次核对 [RocksDB 异步 IO](https://rocksdb.org/blog/2022/10/07/asynchronous-io-in-rocksdb.html)（2026-09-22）：其 MultiGet/迭代器把独立读取的等待重叠起来，用户接口仍可同步。本项目借鉴独立 IO 先派发、之后按依赖汇总结果；当前以 worker 调用 F01 同步定位 IO 实现，不照搬协程、LSM 或预读策略。批次状态、配额、失败收尾是本项目契约的实现，没有声称 RocksDB 采用相同枚举。

F01 的 [Linux O_DIRECT 契约](https://man7.org/linux/man-pages/man2/open.2.html)继续适用：实际对齐、缓冲生命周期与持久化分别处理；本轮不引入新 IO 库，不声称零复制或真实掉电验证。

### 6.6 S9 外部帧缓冲扩展（F02 独立部分已实现，真实帧接入待实施）

目的：让 F26 的 FrameArena 可以作为 F02 的真实 IO 缓冲，减少页帧与执行器工作缓冲之间的复制。F02 仍只执行字节范围，不导入 BusTub PageGuard、页目录或数据库提交规则；F01 已接受调用者缓冲，通常无须修改其接口。只有对齐、范围、稳定内容及所有权均满足时才直接使用帧，不能宣称整个 FS 端到端零拷贝。

许可随所属页后端/对象 IO 路径传递：A 经普通对象映射，B 经 F05 基础区域寻址，均进入 F02。借帧不授权绕过所属后端的寻址、校验、提交或发布约束，也不让 B 查询自己的普通对象映射。上层规划如需合并、转换或稳定副本，仍使用相应缓冲；借帧入口不强制所有对象写入采用同一种内存路径。

外部许可只保护 RAM 的存活和合法访问；普通对象版本及 extent 的使用期仍按 [F14](reference-manager.md) 保留，基础区域由其所属后端保护。内存许可归还不能触发未经上层确认的空间复用；沿用 F00 对字节 IO、durable、发布的区分。

#### 两种来源、一套执行路径

| 来源 | 分配及实际内存归属 | F02 需要保留的内容 |
| --- | --- | --- |
| 批次自有缓冲（现有） | F02 分配；含对齐余量及保留结果记账 | 自有分配及既有 Buffer 访问契约 |
| 外部受保护缓冲（新增） | F26/FrameArena 或其他已获授权的真实消费者 | 字节范围、访问模式、底层存储寿命及使用许可 |

本轮已按 §6.7 落实 move-only 的“缓冲使用许可/租约”：传入的不只是地址，还要使底层内存在 IO 期间存活且不被冲突访问。F26 持有页的逻辑身份/版本和发布权；F02 只持有通用缓冲保留对象。F02 独立入口的命名和签名见 §6.7；F26 的生产许可提供者待其阶段冻结，不为测试增加裸帧 getter、虚拟设备或空壳通用框架。

迁移期间保留显式自有缓冲入口，新入口显式接收外部许可；二者共享 worker、结果槽、Flush、错误收尾和 Shutdown，不另建执行器。迁移结束后，自有入口是否保留按下节的真实调用者清单决定，不预先承诺两种入口永久共存。外部批次不通过旧 Buffer 方法冒充自有存储；调用者通过自己仍有效的受保护帧访问内容，不能从一个已归还租约的结果句柄取裸地址。

<a id="f02-buffer-default-migration"></a>

#### BufferPool 默认路径与旧路径退出（S9.1c 必须完成）

当前代码的 BufferPool 仍经 DiskScheduler/DiskManager 使用页帧，尚未接入 F02；F02 已实现的 S1 入口分配批次自有缓冲。因此，不能把“当前 BufferPool 经过 F02 复制一遍”当作既有事实。若前置阶段曾以自有缓冲做页适配，下面的退出要求同样适用。

1. **显式选择来源。** 调用自有缓冲入口，才由 F02 分配；调用外部入口必须提供有效地址、范围和许可。不设计“许可为空则自动分配”的默认分支。外部许可缺失/无效、额度不足或设备 IO 失败时按对应契约报错/背压，不能通过切换旧入口掩盖问题。
2. **S9.1c 切换正式默认。** 完成帧及页生命周期保护后，已迁移的 BufferPool 常规页加载/写回默认传递 FrameArena 地址及许可，经所属页后端进入 F02；不要求用户额外打开优化选项。对可直传请求，不再经过同尺寸的 F02 自有中转缓冲及往返复制。A/B 保持各自寻址、WAL 和发布约束。
3. **必要工作缓冲单独说明。** 需要稳定写回副本、RMW 拼接或其他已批准变换时，由上层明确规划并记账；这不是许可缺失后的自动回退，也不使 BufferPool 常规路径继续默认使用旧入口。具体例外随当轮方案冻结，不能用“兼容性”保留所有旧分支。
4. **清理旧的页路径。** F26 主责迁移页调用链，F02 主责移除不再被使用的接纳/分配包装。核对正式调用、构建注册和对外契约后，删除失去用途的页中转复制、旧分支、wrapper、默认旧路径的配置及无调用接口；失去正式用途的 DiskScheduler/DiskManager 旧后端实现也纳入检查。不能只新增入口后让正常请求继续调用旧路径，也不能为已归档小测试保留生产空壳。
5. **自有缓冲能力按真实用途保留。** Journal、日志段或引导 IO 不由 BufferPool 管理，可能仍需显式分配工作缓冲；到迁移时逐项记录实际调用文件/函数和保留原因，不能以未来可能使用为永久保留依据。不强迫这些请求经过 BufferPool。若所有生产调用者均已使用外部缓冲，且无必须维持的对外契约，删除自有入口及其无用辅助实现，保留共用执行机制。
6. **完成证据。** S9.1c 交付需列出已迁移的正式读写入口、实际默认调用链、必要缓冲例外、已删除旧路径及仍保留入口的真实用途。沿用 §7.1 的真实路径验证与共同业务测试，不以“外部入口单测通过”代替 BufferPool 默认路径已切换，也不为观察默认分支新增生产测试接口。

#### 准备、接纳及归还的契约

1. F26 先提供符合读写方向的有效许可，F02 校验设备范围、容量、地址算术、实际对齐、批内数据依赖及预算。Full/Stopped、非法输入和准备失败不消费调用者许可，不发 IO；部分预留全部回退。
2. Prepared 成功后批次保留许可，纳入准备阶段额度；Submit 前销毁批次可以归还。Submit 被拒仍为 Prepared，责任不丢失。外部缓冲不能沿用自有 Buffer 的任意填写便利，内容访问受许可模式约束。
3. Accepted 后 worker 保留许可，调用者超时、丢弃观察句柄都不解除它。继续沿用所有成员与所需 Flush 的依赖，不将接受或缓冲归还报告为成功/durable。
4. 当前实现采用在批次终态前保留全部外部许可；失败也先排空正在访问缓冲的成员。真正不再使用缓冲后归还一次；无需强求逐成员提前归还，后续优化需重新证明。归还动作不持调度锁调用上层。
5. 外部结果只保留结果元数据，不因用户长期保留 IOBatchResult 就长期 pin 帧；F26 自己的加载/发布保护持续到消费结果并正确发布或处理错误。自有缓冲的结果保留规则仍按 §6.5。
6. Shutdown 排空已提交 IO；未提交 Prepared 租约由其所有者释放。F34 先停止前台接纳，但保留已接受工作及必要写回的准备/提交能力；生产者结束后才封闭执行器并排空。关闭 FrameArena 前处理未提交许可及 F26 的其余引用，不能仅凭 executor 已停就解除帧映射。

F02 的失败不消费、异常安全及一次归还已由 §6.7 实现；F26 内容保护仍须在接入时落实，不接受“传 shared_ptr 就自然安全”的替代说明。内存还活着不等于内容可并发修改。

#### 读写方向与稳定版本

- 设备 ReadAt 会写 RAM：F26 保持加载帧不可见，许可提供独占填充；失败不得发布部分内容。同页等待者由 F26 在成功或错误后统一处理。
- 设备 WriteAt 会读 RAM：F26 固定正确页版本，并保证期间内容稳定。pin 仅防淘汰/复用；如果上层继续修改，采用已约定的稳定副本或 COW，仍按真实复制及预算报告。
- 同一批中外部缓冲范围相互重叠，且至少一个 IO 会写该 RAM（ReadAt）时应拒绝，避免设备范围独立但内存发生竞争；纯 WriteAt 共享只读字节也须持有效稳定许可。跨批内存冲突由许可所有者/F26 排序，F02 不建全节点指针登记表。
- 禁止把有线程归属要求的锁在任意 worker 上直接解锁；许可的释放和内容保护应明确线程规则。迟到结果与帧/工作库代次由 F26 核验。

#### 预算、兼容与顺序

物理内存按实际分配记账一次；借用不再分配同尺寸中转缓冲，但 Prepared/在途许可的数量、字节及固定帧压力须有显式上限。即使多个只读请求共享内存，它们仍占任务名额/使用压力；这些压力额度不宣称是额外物理内存。上限和去重口径由 F31/F32 冻结，不使用隐含默认值。

沿用 F01 查询所得约束，huge page 不替代 Direct IO 对齐检查。单页长度/偏移不满足设备要求时报告规划缺项或走已授权的上层适配，不由 F01/F02 隐藏补齐、RMW 或降级 Buffered。

完整接入顺序仍是 S9.1a 协议 → S9.1b 稳定帧 → S9.1c 正式页消费者及默认迁移 → 验证与清理。用户随后明确要求先执行 F02 和测试，本轮独立扩展按 §6.7 实施；真实 FrameArena 尚不存在，组件验证使用测试侧拥有的对齐内存和真实 F01 文件，不能宣称 F26 已接入。
