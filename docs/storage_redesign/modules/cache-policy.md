## 6. 讨论后的方案与待冻结边界

以下为本轮收录的设计方向和约束；具体字段、数值、接口及当轮验收未确定前，不能把它们补成默认实现。

### 6.1 缓存职责与预算

业务页由 A BufferPool 缓存，B 元数据页由 B 缓存，FS 解码映射按实际额外内存记账。默认不做重复的 FS 干净业务页缓存；RMW、Deferred、稳定写回及异步 IO 缓冲具有所有权/保留约束，不是可随时丢弃的读缓存。初始 70/30 不冻结，先保证前进资源。

绕过 OS 文件页缓存前，在相同总内存预算下重分 A/B/工作缓冲；当前测试 A 的小 BufferPool 不能代表 OS 后备缓存无用。已有 P1 不能单独量化缓存命中或裸设备收益。Direct IO 对齐和缓冲管理可能仍需拷贝，不承诺零复制。

2026-09-22 F01 交接：新后端默认 Direct，Buffered 仅显式兼容；能力依实际后端查询，不能以 4 KiB 固定分配策略代替。F02 的对齐工作缓冲、F26 的稳定页/写回缓冲都计入预算；F01 本身不缓存或复制数据。业务接入前重新分配缓存预算的要求保持不变，不能用设备层通过推断应用缓存或性能已经改善。

2026-09-22 F02 交接：已实现批次自有工作缓冲，准备时按设备内存对齐分配，预算包含分配余量；执行结束但调用者仍持有的缓冲继续记账。它不保留可复用的业务干净页缓存，也尚未接管 A 的 BufferPool 帧。F26 接入时继续讨论减少填入/读回复制及共享帧所有权，不把当前路径说成零拷贝。阶段风险引用 F02/budget 和 F02/lifetime-close，不新增缓存镜像测试。

### 6.2 局部性和预读

BufferPool 未命中、OS 文件页缓存未命中、代码页缺页分别说明。F35 索引路径减少无关页读取，F36 页内复用改善有效空间，F12 物理连续分配降低部分 IO 成本；几个页组成一个对象不会自动减少页读取。

对顺序扫描/日志/大快照可讨论受预算约束的预读，随机点查不默认扩大预读。F26 同页加载合并和帧保护不是新增 FS 缓存。[LLVM temporal profiling](https://clang.llvm.org/docs/UsersManual.html#profiling-with-instrumentation) 通过函数排列改善启动代码页局部性；只借鉴先观察访问再优化布局的思想，不将其作为本轮 FS 功能，不套用其他 App 的耗时或提升数字。

### 6.3 数组 BufferPool 与外部缓冲（S9，a–e 已接续）

F26 主责实现 [数组子方案](array-buffer-pool.md) 的多级目录、PathCache、原子条目、回收与 FrameArena；本模块决定内存/预取策略并与 F31 合并实际记账，不建立第二套 FS 干净页缓存。

- 翻译数组按 OS 基础页管理，以便 hole punching；帧内存实现 huge page 支持。页大小、Direct 内存对齐与设备偏移/长度限制分别查询/核对，大页不改变数据库页大小。
- 帧区域首地址与槽步长共同保证每个 IO 帧的地址对齐；填充只属于 RAM 布局，不能悄悄扩大数据库页或设备 IO 长度。需要上层适配时按已冻结的规划处理。
- 统计虚拟预留、实际驻留翻译/帧、上层目录、回收组、PathCache、OS 页表、对齐余量、稳定副本和任务占用。不能把“匿名映射读零页”说成没有任何内存开销；稀疏热页可能使数组比哈希占用更多物理内存。
- S9.1c 后 BufferPool 常规页 IO 默认借用帧，可直传请求不再分配同尺寸 F02 中转；缺许可不自动回退。F02 自有入口仅按 [默认迁移规则](object-io.md#f02-buffer-default-migration) 的实际生产用途/对外契约保留，无用途则删除。同一物理帧不重复计费，但 Prepared/在途借用和固定帧压力均须受限；必要稳定副本明确额外分配，不以 pin 代替内容保护。
- PathCache 仅缓存翻译路径；既不重复缓存业务内容，也不改变页版本的可见性。分层候选 bitmap 是易失摘要，不共享 F12 的设备分配事实。
- S9.1e 的预取须有正式消费者，限定已知独立页并保持同页合并；CPU 预取与设备 IO 分开观察，不假设链表下一页为 page_id + 1。
- 大页申请与实际生效分开记录；申请失败的正确回退不能算作大页性能验证。S9 必须有基本安全回收/预算，S12 才做节奏调优。

### S4 实际落点与后续交接（2026-09-25）

S4 B 使用独立版本页缓存，所有当前页驻留 RAM，并统计私有/旧读者页版本额度；它不是 A 的 BufferPool，也不与 A 混用页号。目录指针、容器与返回值不包含在页数额度中。S5 已提供写回/checkpoint，但当前未提供按需页淘汰；S9 的数组改造主责为 A，不把 B 已有版本数组误认为待替换哈希。全节点内存预算仍未完成。代码与验证见 [F08 §6.8](metadata-engine.md#68-s4-实现细化与后续交接) 和 [八项审查](../f08_execution_20260925.md)。本模块其他阶段状态不变。

## 8. 所有实现必须遵守的约束

> 代码要考虑复用性，间接性，安全性，不要破坏别的模块和层次的production级代码。

> 当本次任务接续上一次任务后，需要在完成前检查之前的代码是否因为当前改动有冗余的地方，有的话可以删除，也要检查是否有根本没用到的接口或函数之类的，也需要删除。

> 测试应该保护“这个项目自己承诺的行为和风险边界”，而不是给每一层实现细节、第三方库行为和历史重构痕迹都建立一套测试。

- 保留仍被现有正式路径依赖的行为，不覆盖或清理用户已有的未提交改动。
- 对每项新增、保留、修改或删除的测试，说明它保护的项目承诺或风险及验证它的边界；避免重复覆盖和自证式断言。

## 11. 下一步候选：S12 B 按需读取与安全淘汰（2026-10-08，待确认）

**尚未实施，等待用户确认。** 主责仍为 F32，修改现有 F08 MetadataPager；协作 F05/F09/F10/F30/F31/F33。A/B 保持独立，继续复用 F01/F02，不新建缓存管理器或线程池。

### 11.1 为什么优先处理

当前 `MetadataVersion::pages_` 对每一页持有完整 `PageImage`。写回和 checkpoint 已能持久化，但不会因此释放常驻页正文；`LoadCheckpoint` 也将恢复页装入内存。F31 能限制预算，尚不能让 B 在预算内按需换入换出。F30 新增按单位 CRC 记录后，元数据规模更值得正视；不能把“额度已统一”说成“缓存已可淘汰”。

目标是在正文缓存小于持久元数据工作集时仍能处理请求。目录、私有修改、旧版本及在途 IO 的内存仍受原预算限制；不承诺任意长的旧读者或无限元数据都能在固定 RAM 下前进。

### 11.2 建议实施顺序

1. **先确定版本身份与可重读依据。** 页号、generation、LSN 用来核对具体版本；区分页目录和正文驻留状态，沿用现有 MetadataPager 和树算法。不是把共享 PageImage 简单改为可空指针。
2. **冻结旧版本保护，再接淘汰。** 已持久、没有在途使用且能够重读同一版本的正文才可淘汰。私有未提交页、唯一的脏版本不得淘汰。B 最终页会被后续版本覆盖：旧视图仍需的版本必须在覆盖前保持可用，首轮倾向继续保留这类旧正文；不能查询旧视图却返回设备上的新版本。具体交接及进展额度在编码前共同冻结。
3. **接入有界加载。** 缺页经现有 F05/F02/F01 读取并校验身份与 CRC，同页同版本加载合并；等待 IO 时不持全局缓存锁。目录发布、加载失败、关闭排空沿现有所有者组织。
4. **接续写回、恢复和扫描。** F09 仍只写已提交版本；F10 仍发布完整恢复入口；恢复不要求所有正文长期常驻。F30 直接检查持久内容，避免扫描把冷页全部挤入热缓存。复用同一持久版本核对，不复制页校验器。
5. **按原预算运行并验证。** 正文、版本保留、目录及 IO 工作内存明确归属；资源暂满退让，必要写回/完成有进展额度，实际损坏报错。先保留 A 的 LRU-K，不把 B 驻留协议与更换 A 替换策略混在一轮。

例：B 有 100 MiB 持久元数据，而本轮允许的正文缓存为 16 MiB。热点页可继续驻留，能够安全重读的冷正文释放 RAM，之后访问再从设备取得；100 MiB/16 MiB 仅解释目标，不是冻结配置，也不包括目录及旧版本等附加占用。

### 11.3 测试与待确认条件

- 正式对象/Common/Deferred 操作产生超过正文缓存容量的元数据，循环读取非空内容，结果与独立输入模型一致；不只测试手工页目录。
- 旧视图与新提交/写回并存时，分别得到各自内容；不能将旧版本页误载为最新页。
- checkpoint、关闭与重开后内容和校验依据正确；F30 仍能发现实际冷数据损坏。
- IO/内存暂满时正确退让，解除占用后能够前进；受持有者阻挡时不能用无限等待掩盖资源不足。
- 优先扩展已有场景，沿用真实 IO 门控，不添加 production getter/hook 或重复 B+Tree/CRC 单元测试；阶段源码与结果按模块只保留最终包。

需先确认的协议重点是旧视图所需正文何时必须保留、物理版本覆盖与加载如何交接、缓存/工作内存及进展额度如何分界。首轮不改变持久格式；若论证表明必须改变格式或恢复语义，先报告再决定。本节未将这些待定条件伪装成已完成实现。
