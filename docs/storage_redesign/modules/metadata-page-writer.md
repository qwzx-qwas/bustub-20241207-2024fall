### 6.1 第二轮审查补充

F09 接收已提交、对应 Journal 已 durable 的稳定页版本。页缓冲释放和最终位置 durable 分开，同一页写回顺序与版本比较防止旧完成清除新脏内容；多个不同元数据页可以独立推进。

### 6.2 F05/S2 页写回交接

F05 固定页槽及整页批次准备已交付，IO 仍由原 F02 执行器执行，F05 没有额外 Submit/Wait/Flush 包装。F09 才负责选择已提交、满足 WAL 条件且缓冲稳定的页版本，以及同页写回排序；不能把任意 TryPrepare 成功当成允许越过 WAL 门槛。`writes_durable` 只在所有写入与请求的 Flush 成功后成立；失败不是回滚、等待超时不归还帧许可。外部帧接入沿 F05/F04 传递；沿用 F05 现有页寻址风险，不复制其阶段测试。

### S4 已有基础与 S5 接续（2026-09-25）

S4 已由 F08 独立版本页缓存隔离未提交页，未复用 A 的普通淘汰写回。F09/S5 应写已提交的 canonical 页正文与 64 字节 trailer，经 F05→F04→F02；须处理同页版本覆盖、在途 IO 与代次复用。S4 没有最终页 IO，不能将现有全驻留缓存视为已经具备安全淘汰。 参考 [F08 实际接口](metadata-engine.md#68-s4-实现细化与后续交接) 与 [测试风险交接](../f08_execution_20260925.md#8-最终测试矩阵与交接)。这一段描述 S4 交接时状态；本轮 F09 实现见 §6.3。

### 6.3 本轮执行范围（2026-09-26，已授权）

**先审逻辑，再实现并测试。** 遵守主方案 §1.7：不要过多纠结于边界条件和防御性编程；不添加隐藏重试、降级或测试分支来掩盖错误。保留 WAL 顺序、页身份、IO 生命周期和错误传播这些真实安全边界。代码完成后先推演正常、并发、失败和关闭路径，再编写必要测试。

- 生产入口为 `MetadataEngine::Writeback(max_pages)`，显式正整数限制一次页数；同步返回一次批次的结果，可由后续后台调度调用。F09 作为 B 内部 `MetadataPageWriter` 复用现有页 codec 和 F05，不单独公开可注入任意页字节的写回接口。
- 在短暂的发布锁内取得当前已提交的不可变版本；只有 F07 已确认 durable 的版本能被选择。私有页没有进入这条路径的入口。锁外编码、提交和等待，不持 B 写事务锁等待页 IO。
- B 每次只接纳一个写回批次；并发写回请求明确返回资源不足，不排无界等待队列。批次内不同页交给现有 F02 并行；B Commit/Read 可与之并行。页写回批次按顺序完成，覆盖相同页槽及其换代复用时也保持顺序，不以忽略旧回调代替阻止旧 IO 覆盖。
- 每页保存已经实际持久化的 `(generation, LSN)`，不保留旧页副本。轮询选择未匹配的页面，单次最多 max_pages，避免总从低页号开始造成饥饿。记录元信息在 IO 前准备。成功仅确认此次选中的版本；提交期间出现的新版本仍需下一轮写回，不使用最大 LSN 代替逐页完成情况。
- 使用 F05 `TryPrepare(..., true)` 获得 F02 按设备实际要求对齐的自有缓冲，填入 canonical 正文及已封装 trailer；不能直接 memcpy 整个 native PageImage。编码复制完成后可释放此次取得的版本引用；F02 保持工作缓冲直到 IO 排空。当前编码转换本来就需要工作缓冲，不修改 F02 外部帧路径或 F26 后续默认帧方案。
- 返回 `Clean`（本次观察时无待写页，未执行 Flush）、`Durable`（所选页写入及 Flush 均成功）、`Failed`（接受后写入或 Flush 失败），附选中页数及原始错误。Full/Stopped 在页 IO 前按既有 MetadataError 报告。Failed 不推进该批持久版本，不声称回滚或撤销之前的业务提交；不自动重试。上层可再次显式调用，重写当时最新的已提交版本。
- `Close` 等待已接纳写回排空后返回；调用者仍须先停止发起新操作，之后关闭 executor/device。F09 不增加 worker 池，不把关闭当作唯一保证持久化的路径。
- F09 交付时 F08 Open 完整重放唯一 Journal；重新打开时写回进度重新建立，不能相信旧最终页。F09 不裁剪 Journal、不发布 checkpoint、不安全淘汰旧读者页。F10 必须暂停新提交、排空后反复写回至 Clean，并持久发布恢复入口后才能讨论裁剪；本轮不宣称整个 S5 完成。

## 7. 测试方案与验收（当轮已授权）

沿用主方案 §1.5–1.7，测试保护以下四个实际风险，输入均通过正式 B 提交非空元数据：

| 场景 | 独立判断依据 | 不重复的风险 |
| --- | --- | --- |
| 多页/小值/溢出值写回 | 独立解析实际 Metadata 区的 canonical 页，重建键值与输入模型比较，同时检查身份/LSN/校验 | 编码或最终页位置错误；不能只用全量 Journal Open 自证 |
| Journal Flush 暂停，私有事务在途 | 最终页区保持原提交内容；放行后才可写新版本 | 未提交页越过 WAL 门槛 |
| 指定一张溢出页的旧写暂停期间删除/复用，再写回 | 独立页区读回最终新内容；同一物理页号的代次确实增加且为存活页；旧读取视图保持 | 旧完成误清新版本、同槽写乱序、生命周期错误 |
| 页写/Flush 失败及资源拒绝 | 原始错误、不得返回成功，显式重试确实重写并落到正确页区；Close 等在途任务 | 假 durable、失败进度提前、未排空和无界接纳 |

暂停/失败仅在测试链接侧注入，正常阶段调用真实 IO；不新增 production hook/getter。有限等待仅作测试 watchdog，不作性能阈值。复用 F08 的原组件测试作为受影响路径回归，不重写其树、变长值和日志格式矩阵。原 A 生产行为不改；是否扩大回归由实际改动决定。

验证是 Direct 文件组件集成，不证明真实掉电、最终 checkpoint 恢复、SQL/Raft E2E 或性能。F10/F11 后续接续这些输入模型检验从最终页恢复，不另建同义套件。结果与测试源仅模块压缩保存，归档前核验实际用例/退出码和版本，完成后做八项审查。
