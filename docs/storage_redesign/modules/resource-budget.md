## 6. 讨论后的方案与待冻结边界

以下为本轮收录的设计方向和约束；具体字段、数值、接口及当轮验收未确定前，不能把它们补成默认实现。

### 6.1 全链路预算

为 F35 的 pending、队列、执行和未消费完成结果共同限制数量与字节；队列保存共享任务引用，同一正文不按多个所有权重复分配。F35 判断业务准入，F31 提供通用预留/释放机制，不接管 SQL/共识决策。

接受异步任务时保证其完成结果容量；可采用任务结果槽或等价预留机制，具体结构待冻结。为错误、取消、排空、恢复和关键元数据操作保留前进空间，避免释放资源也需要申请已耗尽资源。协议 event loop 不等待 worker 腾位，预算不足由入口背压/已接受任务有界 pending 处理。

### 6.2 缓存、IO 和后台协作

总内存包含 A/B 页缓存、解码映射、稳定写回缓冲、RMW/Deferred、预读、网络/日志正文和任务元数据；pin/在途内容不能视为任意可淘汰缓存。F26 增加并行 IO 时同时约束帧占用和缓冲，不能仅限制 IO 数量。

F36 的页清理与 F22/F29/快照/恢复共同使用后台预算；所有者判断可清理内容，调度器只安排资源。首轮回收安全性不依赖以后再补后台限速，S12 再完善协调策略。具体额度/调度比例按实际内存与阶段冻结。

F03 引导副本修复按 [其 §6.3](bootstrap.md#63-异步副本修复s2-已实现) 使用有界后台资源：每打开实例合并为一个意图/任务，pending 与结果也计入限制。资源不足不让 Open 或正常请求等待；保留必要前进机会，避免修复永久饥饿。F02 当前只有执行器局部额度和轮转，尚无前后台优先级；实际预算、退避和驱动接入随当轮冻结，不另建无界队列或重复设备执行链。

### 6.3 第二轮审查补充

F10 暂停新修改或空间接近耗尽时，已经接受的提交完成、checkpoint、错误上报和释放仍需可用资源。预算必须包含完成结果和持久化完成记录的前进余量，避免工作完成后为了释放空间反而无处记账。具体数量、字节额度与公平调度留在所属阶段冻结。

### 6.4 S9 数组目录与外部帧许可

新增预算覆盖 F26 的帧实际内存、翻译数组实际物理内存、目录/回收控制区、PathCache、OS 页表、对齐余量和稳定写回副本。虚拟预留与实际物理占用分开统计；保留虚拟地址/描述符不能成为无界增长的理由。

F02 自有分配与 F26 外部帧采用单一实际内存归属；外部 IO 不再为同一帧重复记同尺寸工作缓冲，但许可数量/使用字节、Prepared、在途及不可淘汰帧压力另有限额。同一稳定只读内存供多个 IO 使用时，实际字节仍一次记账，任务与保留压力仍受约束；计量口径实施前冻结。

拒绝/准备失败回退预留，等待超时和观察者退出不释放在途配额。外部结果终态不无故保留帧，仍被 F26 发布/读者持有的内容继续按其归属记账；自有结果缓冲沿用既有保留规则。为错误、回收控制及完成结果预留前进资源，不能为等待帧释放而持有阻止其完成的预算/锁。

基本预算随 S9.1 核心组合实现，S12 再完善后台节奏。F02/external-buffer 及原 budget 风险统一验证，本模块不另建私有计数镜像测试。

### 6.5 Journal 在途窗口与回收前进资源

从 S3 将完整记录字节、跨段空间预留、IO 成员、工作缓冲、批次/完成窗口共同纳入有界准入；逻辑记录可超过一个 segment，但不能无限大，也不能写到中途才等待永远拿不到的剩余容量。F07 的完成事实不是永久结果库，完成交接后释放；未消费终态也计额度，窗口满就背压。

为 checkpoint 发布、必要回收控制、错误完成及 S10 Deferred 完成记录留出专用前进能力。预算按最大必要操作及其依赖推导，不能无依据冻结“留一段/某百分比”。S5 与真实恢复入口/裁剪闭环核对，普通写入不得借走最后的进展资源；需要空间的回收操作不能反过来永久等待被自身保留的前台额度。

IO 缓冲、结果对象与 Journal 持久正文按各自所有者计账。同一正文跨引用不重复计 RAM 分配，但所有实际保留压力要统计；结果不确定及超时不提前释放在途资源。没有可靠回收或依赖长期不解除时，限流/明确失败并报告原因，不通过扩大窗口、覆盖有效段或放松 durable 保证继续运行。
