## 2. 已讨论的职责与边界

1. A 判断 tuple、undo、slot 和表页是否仍被业务读者、事务、索引及恢复状态需要。
2. 整理单页碎片，保持存活 slot 身份，更新正文偏移；寻找可复用槽位及已有页。
3. 维护可重建的页空闲空间搜索摘要，锁住候选页后重新核对真实空间。
4. 空页解除表链、Catalog/首尾入口、索引、读者和在途 IO 等必要引用后，交 F26/F22/F12 释放对象中的相应范围。
5. 不负责 FS 元数据 B 的页管理、业务请求排序或设备 extent 分配；不新建第二套全局 GC。
6. 跨页搬迁/合并、完整 HOT、跨页大记录及每记录长期 page 配额不是第一版隐含任务。

## 6. 讨论后的方案

### 6.1 三个层次分别实现

- **页内整理**：删除确定无用的正文，把零散空洞合并；存活记录仍留在本页，slot 编号保持不变，仅更新偏移。页数不必下降。
- **已有页复用**：按所需记录空间查摘要，再锁页核验；合适则插入，确实无合适页时才新增。目标是避免持续向尾页增长，不给每条记录固定页配额。
- **空页释放/后续跨页合并**：无存活记录的页满足条件可脱链并释放。把多个低利用率页的存活行搬到同一页会改 RID，需索引与恢复协议，属于后续可选能力。

空 slot 只有在旧 RID 及 undo/索引/读者引用不再有效时可复用；同一页号重新使用同样需要代次/失效协议。不能让旧读者读到别的记录。页格式变更须同步 TablePage、TableIterator、表首尾入口及已有课程/业务正式路径，不只修改 memcpy。

### 6.2 更新优化与 HOT 的边界

保持 RID 的原地修改与 HOT 是两条不同路线。前者要证明旧版本已有保护或无人需要，满足当前等长限制，并检查所有相关索引键；键不变的索引项才有保留基础。HOT 则在同页保存新 tuple，经稳定索引入口找到版本链，清理后可保留重定向。当前分布式 Apply 新建 RID 而无 HOT 跳转，直接省去索引更新会留下旧指向。

无论采取何种本地物理布局，复制的逻辑命令、旧值验证和业务结果保持不变；各副本不要求有相同 RID。初版不因模仿 HOT 扩展完整行版本链格式。

### 6.3 释放与恢复顺序

```text
A 确认记录/页可清理
 → F36 保护页面并整理；空页先解除业务引用
 → F26 等待/处理帧及页 IO，提交对应对象范围释放
 → F22 持久化解除逻辑引用并等待仍需的版本/读者/IO
 → F12 允许物理范围再次分配
```

一个对象可能包含多个活页，释放其中一页不能删除整个对象。设备最小分配单位大于页时，逻辑范围可释放与整段物理可复用分别记账。F36 的摘要可重建，不能重复保存 F12/B 的分配权威。

S9 初期仍从已验证快照和已提交 Raft 日志重建业务状态；清理必须不改变重建后的逻辑内容，恢复所需日志和快照仍保留。不能把任意部分写回的活动页当成新 checkpoint。若整页释放的原子性/旧引用失效尚不能证明，只暂缓该子项，不能发布不安全实现。S11 固定恢复根后，快照保护的旧页/extent 通过 COW 和引用协议保留；F36 不能原地破坏旧快照。

### 6.5 数组目录与页号复用

沿用 [F26 数组子方案](array-buffer-pool.md) 的实例/帧身份和访问保护。单页普通淘汰仅更新驻留条目，不必使仍有效的 prefix 路径全部失效；页号真正释放/复用前，则须阻止旧身份新访问，处理读者、已解析帧、加载/写回和 F02 许可，再按协议失效旧映射/任务。

PathCache 缓存的是叶路径，叶数组清零不能单独证明旧页已可复用；同一页号复用和工作库重建仍依赖各自身份/引用边界。F36 的页内摘要、F12 的设备 bitmap、F26 的 RAM 回收摘要分开维护。hole punching 不授权释放对象或复用 RID。

### 6.6 S9.2 执行协议（2026-10-05）

用户已授权本阶段方案、实现与必要测试。先分析生产调用链，再实现，复核逻辑后才编写测试。

**页与地址。** 保持 8 字节页头、24 字节 slot 和 RID=(page,slot)。slot 的正文偏移为 0 表示已物理释放；旧格式的合法记录偏移至少越过页头，因此不与零长度 tuple 或删除标记混淆。目录长度不因中间槽释放而缩短。释放前验证目标均为已删除记录；用一页临时映像整理存活正文，再一次替换页内内容，存活 slot/RID 不变。只在调用方已退出索引、undo、旧读者时允许释放。新代码可读旧页；写出空槽后的页不能交给未支持空槽的旧二进制。当前 A 工作库由快照和 Raft 日志重建，不另造 A WAL 或宣称活动页是业务 checkpoint。

**两套判据。** Raft 复用现有 StateVisibilityLatch：Prepare、读和快照持共享锁；Apply 持独占锁。旧索引退出、删除标记和旧记录回收在该区间执行，复制命令和旧值检查不变。普通 MVCC 使用已有显式 GarbageCollection 入口；有 RUNNING/TAINTED 事务时不复用 RID，保留原水位线 undo 清理。没有未结束事务时，在阻止新 Begin 的边界内分批处理删除记录，每表每次最多 128 条；先从各索引清除该 RID 的所有历史键，再清 undo 入口，最后释放 slot。旧事务的 write set / 索引候选可以跨语句保留，故仅比较删除时间戳不足以授权复用。后续缩小这个保留窗口属于 S12/S13，不能用未经证明的 watermark 判据提前复用。

**历史索引。** 普通二级索引可能保存同一 RID 的多个历史键，undo 被清理后不能再靠当前 tuple 推出它们。为实际 Catalog 支持的索引增加批量退出旧 RID 的维护操作：主键按最后键并核对 RID；非唯一索引过滤历史键桶；向量索引须退出该 RID 的所有历史候选，包括最近邻 SearchVector 路径；只让 ScanKey 不再命中或仅退出 active_entries 不够。逻辑删除供旧事务使用的 stale 候选与物理退休分开表示：HNSW 可保留旧节点作为图遍历中间点，物理退休节点不进入结果队列；IVFFlat 在候选排名前排除退休条目。Raft Apply 同样调用物理退休接口后才释放 slot。IVFFlat 的 active-only 重建必须等全部 stale 条目获得物理退休授权；比例阈值不能替代旧事务判断，不能在第一次查询后丢掉第二次查询仍需要的历史。最近邻执行器会跨轮保留候选编号用于去重，因此 IVFFlat 重建不得从 1 重新编号并把旧编号分配给另一条记录；从实例当前未用编号继续分配，空重建同样保留编号进度。该编号不持久化，也不改变 RID；它只在当前索引实例中维持查询去重的含义。重建还可能改变实际桶数：搜索上限的读取与重建使用同一索引锁；执行器每轮需要扩展搜索时读取当前上限，并保留本查询已见到的最大上限：不能一直沿用首轮较小的桶数，也不能因目录缩小而认定针对旧目录的一轮搜索已经完成。预算值是该次读取的快照，不是整个查询期间不变的目录承诺。VECTOR 的旧版本占位复用 Value 的已有空值表示，不能因为缺少类型分支而使删除后的旧读者失败。只清除本批待回收 RID，不能删除其他记录的同键索引。借鉴 [PostgreSQL VACUUM 实现](https://github.com/postgres/postgres/blob/REL_17_STABLE/src/backend/access/heap/vacuumlazy.c)先清索引、再复用 heap 项的职责顺序；不引入其磁盘格式或完整后台 vacuum。

**迭代与复用。** 迭代器跳过物理空槽，逻辑删除仍交 MVCC 判断。存活迭代器持有表内扫描寿命保护：期间插入沿原尾部追加、不复用前面的空槽/页，避免新行进入已开始的物理扫描；释放记录也不能越过该保护。SQL 的候选 RID 在整个事务结束前受上述 MVCC 边界保护；Raft 的候选受 visibility 锁保护。外部裸 RID 不获得永久身份保证，调用方不得在事务/操作结束后保留它用于访问新数据。

**空闲摘要。** TableHeap 维护按可容纳正文大小排序的内存集合，包含 slot 开销；查询为树查找，不为每次插入遍历表页。持有表修改锁选候选、锁页后核实，摘要失配最多重选两次再尝试尾部/新页。释放与插入同步刷新；Open 沿已有链检查时重建。页面是权威，摘要不写 B；在没有扫描保护时优先利用已有页。有扫描时沿尾追加，扫描结束后重新利用空洞。本阶段沿用表结构修改锁，不承诺表插入无锁或引入另一套全局调度器。

**失败与阶段边界。** 整理只占一页临时内存；不移动存活记录到别页，不缩页链。索引退出失败时不得复用 slot，错误向上传播；Raft 保持已有 fail-stop/重放路径。普通显式 GC 保留现有停止业务访问的调用契约，不承诺后台并发 vacuum；分页/128 条限制控制本轮回收量，原 undo 扫描及索引历史项过滤仍是全表/索引维护。HNSW 图节点的内存整理不在本轮，保留路由节点不表示允许继续访问旧 RID。页写回失败沿用 F26 脏页保留及对象 Common 恢复，整页释放仍属 S9.3。

### 6.7 S9.3 空页退役与延迟物理复用（2026-10-05，已授权）

**保留前轮约定。** “清理”指解除引用和归还分配权，不默认清零旧设备内容。逻辑空洞读零由映射提供；旧物理字节可以一直保留到新的合法写入覆盖。S9.2 空槽仍优先服务本表；本轮只对已经没有任何占用 slot 的非首页面退役，不搬迁活记录。表页链是 TablePage 的 next_page_id 单向链，用于无索引扫描和恢复首尾入口，不是 FS extent 映射。页仍在链上就不能将其物理空间交给别的内容。

**回收依据与安排。** 普通事务沿用显式 GC 的无 RUNNING/TAINTED 事务边界，退出历史索引与 undo 后才成为候选；Raft 在独占 Apply 的整个命令批完成后处理被修改表，先给同批 update 的新记录复用空槽。存活迭代器阻止整页退役。TableHeap 在内存维护前驱和空页候选，Open 随现有链遍历重建；每次最多尝试 4 页，游标轮转，忙页保留给下一次维护。未触发后续维护的忙页可以暂留到下一次显式 GC/相关 Apply；S12 再完善周期调度。首个页稳定保留；空表不更换入口。页格式与 RID 编码不变。

**两次提交和恢复。**

1. 持有待退役页读许可、前驱页写许可。F26 核实 victim 只有本次 pin、无 IO，暂时封住该页新访问；有其他 pin/写回则本次暂缓。读取候选若加入既有加载，会先等该页 IO 完成再核验，等待不占 BufferPool 全局锁；本轮不将整个 A 维护异步化。不持 BufferPool 全局锁、翻译条目锁或帧 mutex 等待设备。
2. 准备前驱页的新完整映像。Common 批次 A 原子持久化“前驱绕过 victim”及“victim 待退役”控制记录。正文走既有 COW，控制走同一 B 提交。成功后才更新缓存中的前驱并退出 victim 驻留；失败直接报错并停止该缓存的新调用，重开后判断结果，不把不确定提交伪装成回滚。
3. TableHeap 更新首尾/前驱/空闲摘要后，页后端通过批次 B 原子执行 Unmap(page range) 与控制记录 pending→retired。Unmap 不改变对象长度，左右活页映射保持不变，退役范围进入 F13/F14 既有目录。B 失败不丢掉 A 的 pending；明确未提交时可由下次维护接续，结果不确定或 Common 已停止时必须 Open 恢复，不能盲目重试。
4. F14/F22/F12 在旧版本/读者/IO 退出后归还完整分配单位，后台完成物理可复用；不要求本次前台等待全部回收，更不擦除旧块。单位大于数据库页时不能承诺每退役一页马上归还一个单位。

控制记录位于工作空间 {space,0}：item 0 仍为已有 descriptor；item=page_id+1 表示退役页，值为两个字节（格式 1，状态 1=pending/2=retired）。状态 2 保留到整个工作区退役，防止旧 page_id 在数组打洞/重新加载后复活；不建立命中路径上的第二张全局页表。页后端实际读、预取及写前检查持久退役记录，Open 分批扫描并完成 pending 后才开放。新增字段与已有 descriptor v1 兼容；含退役页的新工作区不能交给不认识退役协议的旧程序。新 page_id 继续单调递增，物理单位可复用与 page_id 复用明确分开。对象描述和退役标记仍随已发放页号增长，不声称元数据达到长期空间稳态；记录压缩及 page_id 循环复用不属于本轮。

**接口及层次。** 既有 DeletePage 是缓存/索引删除接口，不具有持久父引用退出证明，继续不授权释放对象范围。新增显式 RetirePage 由 TableHeap 的正式维护调用；F26 只接收替换页映像，不理解 TablePage 布局。PageStorage 声明是否支持持久退役，现有文件兼容后端保留 S9.2 页内复用、明确不支持该原子协议；对象后端支持。ReclaimRetiredPages 复用 Common 有界事务，单次最多 4 项，不产生逐请求线程。空闲帧容器在启动时预留容量，避免已提交后归还帧时再分配节点失败。

**业务恢复边界。** 这保证页链退出与空间释放的先后，不把 A 的随时写回页或旧索引变成完整业务 checkpoint。节点继续快照＋Raft 后缀重建 Catalog/索引/会话；独立 TableHeap::Open 只打开调用者提供的工作链。S11/S13 的共享快照/新并发仍需后续接续。

**已有开源机制的复用。** 继续参考 [PostgreSQL VACUUM](https://www.postgresql.org/docs/17/routine-vacuuming.html) 将不可见旧内容变成可复用空间，而非默认重写整表；参考 [buffer README](https://github.com/postgres/postgres/blob/REL_17_STABLE/src/backend/storage/buffer/README) 将 pin、内容保护和 IO 分开。本项目在对象 FS 中能解除中间页的映射，不声称 PostgreSQL 普通 VACUUM 也以这种方式归还任意中间页。两批次、工作区退役编码是复用本项目 Common 原子控制和 F13/F14 持久交接的具体设计，不新造 WAL/GC 引擎。

**本轮验证。** 先审生产逻辑和锁/提交依赖，再运行真实 SQL/TableHeap→BufferPool→对象 Common→Direct 文件路径：首/中/尾页、存活行及索引、迭代/pin/预取保护、A/B 之间中断的 Open 接续、旧页号拒绝和真实物理再分配。独立业务输入是正文 oracle；只在必要的空间再分配场景通过现有 FS 映射接口观察 extent，不复制 bitmap 用例。保留并适配已有 S9.2 场景：释放后页号仍增长，不能继续以“新尾页号等于旧尾页号”作为空间复用判据。阶段用例和结果仅留 F36 当前压缩归档；八项审查包括 mutation、生产接口用途和测试重叠。不是裸设备/真实掉电或共同 C/P 性能验收。
