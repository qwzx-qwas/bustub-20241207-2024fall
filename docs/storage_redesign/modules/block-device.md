## 6. 讨论后的方案与待冻结边界

以下为本轮收录的设计方向和约束；具体字段、数值、接口及当轮验收未确定前，不能把它们补成默认实现。

### 6.1 F26 并发接入所需能力

S1 明确设备能力、对齐、错误与写入/持久化屏障，支持 F02 对独立范围的有界在途执行。文件模拟后端必须说明是否使用定位 IO 或怎样保护共享文件位置；仅增加上层线程而仍用全局 seek/read/write 串行路径不构成完整并发方案。

IO 完成只按 F00 的后端契约确认，不自动代表掉电持久化；对齐也不代表原子写。缓冲在实际 IO 结束前有效，取消请求不意味着设备已停止访问该缓冲。具体异步/线程后端、错误值和屏障接口待 S0/S1 冻结，不因文档选择实际裸设备或格式化。

### 6.2 复用与层次

F01 不解释 SQL、Raft entry、slot 或对象共享引用。F02 负责统一 IO，F26 固定页/帧，F12/F14/F22 保证范围可写/可释放。当前 DurableStorage 文件持久化能力继续按迁移方案保留，不能为了接新接口改弱原保证。

### 6.3 第二轮审查补充

IO 完成与设备持久化分别报告。屏障须说明所属设备/打开实例和实际覆盖的写入范围或边界；不能将尚未送达设备的前序请求包含在“全部 durable”中，也不能用 O_DIRECT/对齐代替掉电保证。文件模拟与裸设备分别声明所支持的故障模型。

参考 [Linux 设备写缓存控制](https://www.kernel.org/doc/html/latest/block/writeback_cache_control.html)：设备写缓存可能提前完成 IO，flush/FUA 解决持久化顺序；本项目借鉴保证的区分，用户态系统调用和设备能力在 S1 冻结，不直接照搬内核 bio 标志。核对：2026-09-21。

已分配有效范围短读须作为错误交给调用者，不能隐式补零掩盖损坏；新页/逻辑空洞的零填充由 F15/F26 明确语义。缓冲可释放的通知与 durable 分开，取消等待不允许后端继续访问已释放内存。
