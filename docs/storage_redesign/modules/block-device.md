## 2. 职责与边界

```text
页、Raft log、HardState、Snapshot、元数据、Journal
  → 各自上层适配及对象映射
  → F02 统一 ObjectIO / 有界执行
  → F01：设备字节范围 / 调用者缓冲 / 刷新
  → Linux 设备接口
```

F01 不解释 page、entry、object ID，不分配 extent，不做隐藏 RMW、补零、缓存、复制或事务回滚。F02 负责在途数、依赖和完成通知；F17/F18 管范围冲突和写入规划。F01 的同步方法可由多个线程并发调用，不能持一把全局锁等待所有 IO。Close / 析构前调用者须排空操作；重叠范围的并发写入由上层排序。

## 6. 当轮实现契约

### 6.1 打开、能力与默认路径

- 生产 Options 的访问模式默认 Direct；构造时显式传路径和 Options，没有默认路径或为测试增加的默认参数。
- Direct 使用 O_DIRECT；Buffered 必须显式选择，能力信息始终标出模式。不自动降级，不混用两种模式。
- 只打开已有普通文件或块设备，固定打开时的容量，不创建、截断、扩容或格式化。普通文件由开发环境独立准备；它的命名持久化不属于设备 Flush。
- Linux 文件容量从 fstat 获取；块设备从 BLKGETSIZE64 获取。块设备使用 O_EXCL 打开，复核打开前后目标身份；不把它宣称为针对所有外部写入者的全局锁。
- **文件及块设备 Direct 对齐均通过 statx(fd, "", AT_EMPTY_PATH, STATX_DIOALIGN, ...) 获取。必须检查返回 mask 及非零的内存/偏移对齐字段。不能统一假定为 4 KiB，也不能拿文件系统推荐 IO 大小冒充 Direct 约束。**
- 缺少编译期查询支持、运行时字段缺失/为零时，Direct 明确失败；不试写探测、不猜测、不切 Buffered。较新的更宽松读对齐不在首轮优化范围，读写共用已查询的严格对齐。
- 文件 Direct 仍经文件系统映射；WSL 文件验证不代表物理裸设备或宿主机掉电保证。

### 6.2 接口与缓冲有效期

使用一个实际 Linux BlockDevice 类型及精简 Options / Info，不建立只服务模拟测试的虚基类。操作为构造打开、Info、ReadAt、WriteAt、Flush、Close。读写参数为 StorageByteRange、缓冲地址与缓冲容量；调用者对实际内存有效性负责，容量须覆盖范围大小。

同步返回（成功或异常）表示该调用已停止访问缓冲；并发调用可交错，但析构/关闭不得与 IO 并发。F02 取消等待不等于可以释放仍在执行的缓冲。设备自身不分配数据缓存或对齐中转缓冲。

### 6.3 范围与失败

- 先验证范围在容量内、可表示为 off_t、缓冲容量足够；Direct 非空 IO 还验证地址、偏移、长度。合法空范围是无 IO 的空操作，不用它替代测试有效负载。
- 非法请求在提交 IO 前失败。已关闭实例拒绝 IO。
- 精确读取/写入循环处理正数短 IO，EINTR 重试；EOF、零进展写入、系统错误均不能当成功或补零。
- Direct 短 IO 后仅当余下地址/偏移/长度仍满足约束才继续，否则报告部分失败，不偷偷复制或 RMW。
- IO 错误携带系统错误码、原范围、此前成功报告的字节数。该字节数不是“除此之外设备绝未改变”的证明；失败的 Direct 写本身可能已部分改变目标。上层不得据此实施无保护重试或假定回滚。
- 关闭不隐含 Flush；显式 Close 报告错误，析构只负责释放。Linux close 出错后不重试，避免误关复用的描述符。

### 6.4 完成、持久化和原子性

```text
WriteAt(A) 成功 ─┐
                ├→ 调用者确认依赖完成 → Flush 成功 → 按后端契约 durable
WriteAt(B) 成功 ─┘
```

Flush 调用同一打开实例的 fdatasync 并检查错误。调用者（后续 F02/提交路径）先建立目标写入已完成的关系；F01 不知道上层队列中尚未送出的请求，也不根据最大序号猜测覆盖范围。同期其他写入不纳入承诺。Flush 失败不等于什么都没写；Close 不替代错误可观察的 Flush。

O_DIRECT 不等于 O_SYNC、零拷贝、掉电原子覆盖；文件重开成功不证明掉电安全。COW/Journal/Deferred 承担更上层恢复保证。

### 6.5 S9 FrameArena 接入边界（文档交接，接口不变）

现有 ReadAt/WriteAt 使用调用者提供的地址和容量；F02 传自有缓冲或合法外部帧都须满足同一运行时能力。FrameArena 的 huge page 是内存机制，不是 F01 的设备单位或原子性。F01 不自动复制、填充、RMW、降级 Buffered，也不把任意 4 KiB 数据页当作合法对齐请求。

F26 保证页版本和内容稳定，F02 使外部许可保持到设备不再访问；F01 只保证同步调用返回/抛异常后不再使用该次缓冲。超时和异步批次归还不下放 F01。仍由 F02 建立所需写完成后再 Flush 的顺序，F34 在排空及所有调用结束后关闭。

F01 历史 S1 结果和完成状态不覆盖外部帧接入；新增风险由 F02/F26 验证并引用 F01/range-io、failure-boundary，不为相同设备契约重写镜像测试。
