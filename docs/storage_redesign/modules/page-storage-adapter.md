## 6. 讨论后的方案与待冻结边界

本节保留设计依据；本轮首轮协议及验证设计以 [S9.1a](../s9_buffer_pool_protocol.md) 为准。未实施的生产签名/磁盘编码/部署额度仍在其阶段细化，不擅自猜测兼容语义。

### 6.1 改造前限制与当前职责

改造前 CheckedReadPage/CheckedWritePage 缺页和脏页淘汰路径持 `bpm_latch_` 等待 DoDiskIO 的 future；FlushPage 也在全局锁内等待。c 已迁移到局部页状态和锁外 PageStorage IO；BufferPool 不再使用单线程 DiskScheduler。文件后端仍有共享 seek/read/write 锁，对象后端沿 F02 并行，不能将二者吞吐能力等同。

改造前 DoDiskIO 未使用 future 的布尔结果。c 删除了这个中转；DiskManager 实际失败抛出异常，PageStorage 返回给页调用者，独立 DiskScheduler 也将异常交付 promise。不能仅增加异步状态而沿用无法表达后端错误的完成链。

F26 演进既有 BufferPool/PageGuard/页适配生命周期，F02 执行独立范围 IO，F32/F31 管缓存与工作内存；[F36](table-space-management.md) 判断记录/页能否释放。页内整理不放入 F26。

### 6.2 加载与等待

最终正常驻留查找采用数组条目及局部同步，不依赖全局映射锁；过渡步骤可用短锁登记身份、固定帧和加载/淘汰状态。IO 与页内容锁等待不占用全局映射锁。条目、条件 pin、淘汰及 PageGuard 释放必须采用同一套安全协议；不宣称整个 BufferPool 无锁，LRUK 自身竞争另行观察。详见子方案 §3.4。

```text
A 请求 page 7：预留帧及加载身份，登记 Loading，解锁后提交
B 请求 page 7：等待同一加载结果，不重复读取
C 请求 page 8：独立预留并提交，可与 page 7 并行
完成：核对页/帧代次 → 成功发布可用状态或错误 → 唤醒等待者
```

Loading 等表达概念状态；首轮状态所有权及同步按 S9.1a §4/§12，C++ 类型随 c 实现。映射存在不等于数据已有效；同一身份/版本才可合并等待。锁内保存稳定帧引用并 pin，不能解锁后继续使用可能失效的映射表迭代器。帧在 IO/读者引用期间不可复用；每次重用的代次用于拒绝旧回调，不能只核对 frame_id。

等待加载成功后仍须重新进入正常查找/固定协议，通知不授予正文访问权；完成后被淘汰就重查，不能按任务遗留帧号构造 Guard。首次发布目录/叶也必须保证同一 prefix 只有一个赢家，不能只保护最后一级条目。

### 6.3 脏页写回和淘汰

- 写回必须捕获受页内容保护的稳定版本。首轮保持逻辑内容使用权至后端提交收尾，禁止同页并发修改，其他页可继续；不是跨线程解锁 std::shared_mutex。受预算约束的稳定副本属于后续扩展，不默认建立 FS 干净页缓存。
- 比较送出版本与当前修改版本：v5 写回完成后若内存已是 v6，不能清除 v6 的脏状态；同页写回仍要有顺序/完成边界，不能让旧写覆盖新写。版本捕获、脏标记及 PageGuard 生命周期须一起适配。
- 淘汰先保护旧帧并登记状态，必要写回达到约定完成边界后再解除旧映射、装入新页；其他页可以推进。同页访问应等待/重试正确状态，不另读出旧设备副本。
- FrameHeader 维护当前所属页身份，选出帧后直接取得旧页号，取消遍历驻留页表的反向查找；两方向信息按加载/淘汰协议一致变更，失败保留必要旧身份。
- 失败保留仍必要的脏内容，通知全部相关等待者并解除正确的预留；不得返回半页或把 false/异常当成功。完成和取消也须归并资源，不能释放后接受迟到回调。
- 页可从缓存释放、写入完成和 durable 的区别归 F00。只有后端可靠接管对应版本及其所有权后才能释放；业务 checkpoint 另等待所需 durable/发布边界。
- 多页首轮按每事务每对象一页组批，同对象剩余页有序递交；不合并覆盖中间未修改页，也不承诺 FlushAllPages 多页原子性。数据 IO 完成而 B 尚未发布的窗口必须保留该写回责任，详见 [S9.1a §6/§11.2](../s9_buffer_pool_protocol.md#112-关键判据如何落地)。
- 组批同时受实际成员/许可容量及 Common 配置限制；多页可在 Common 接纳前缩组，单页计划永久超限则明确返回，不能一直重试 Full。消费内部批次结果后退出下层票据，不持有全部历史票据等到 FlushAllPages 最后；数据来源也不能仅因结果仍被观察而长期占帧。

### 6.4 上下游与兼容

F02 要有多个有界在途 IO；文件模拟后端若仍共享可变文件位置，须由 F01/F02 定位 IO/后端同步方案解决。保持已有同步 PageGuard 正式接口的同时允许独立调用并发；单调用持续读一页再等一页不会自动生成并发，有限预取已在 S9.1e 通过真实索引窗口接入，额度由对象部署显式提供，0 表示关闭。没有可用帧时沿用明确的资源不足契约，不把任意生产失败隐藏为无限等待。

A/B 是独立运行实例，目前共享 B+Tree 的页访问算法；内存/IO 代码的进一步复用须保留各自版本模型。变更共享实现时回归 F08 私有页、WAL 先行、错误传播和 B 恢复，不把 A 的 Raft index、表页格式或 F36 回收规则强加给 B；也不能简单让通用脏页刷写绕过 B 的提交约束。

当前实际代码已由 F08 分离：A 使用 BufferPoolManager/PageGuard，B 使用独立的不可变版本页及事务私有页访问；两者通过页访问类型复用 B+Tree 算法，并没有共用一个运行时 BufferPool。S9.1a 已据此确定数组/帧组件的交接，不能把早期共享缓存示意图当作现成调用链，也不能将 B 的私有版本直接塞进 A 的公共驻留条目。

即使后续复用部分内存/IO 组件，也不合并页后端：A 经本模块适配普通对象，B 经 [F05](metadata-backend.md) 使用基础元数据对象和区域描述，两者共用 F02 执行 IO。B 的读写不能反过来依赖自己的普通对象映射；直接寻址也不能绕过 B 的 WAL/发布规则。

2026-09-22 F01 交接要求持续有效：新后端默认 O_DIRECT，实际内存与偏移/长度约束分别探测，不能将 page 大小 4 KiB 当作内存地址已经对齐。c 已由 FrameArena 替换原 FrameHeader 的 vector<char>，按实际能力安排首地址和槽步长；F01 不替 F26 分配中转缓冲或偷偷切 Buffered。A/B 保持独立，B 私有页不接入 A 的目录。

### 6.5 S9 顺序和释放

S9.1 按 [数组子方案 §4](array-buffer-pool.md#4-实现顺序和模块交接) 的 a–e 完成：协议冻结 → 帧内存/数组条目（含按组首次初始化、访问保护及计账）→ 页生命周期及 F02 外部缓冲 → PathCache/安全归还及重新使用 → 真实预取消费者及组合验证。首次访问的安全构造由 b 提供，d 复用它来重新启用已归还组；直接将既有安全要求纳入新 BufferPool，不先大改一轮哈希版再重复改造。

b/c 是内部开发顺序；正式用数组替换驻留目录前须具备 c 的生命周期和失败保护并通过约定验证，不允许先切换生产路径再补安全条件。对话逐项覆盖及当前代码兼容核对见 [子方案审查表](array-buffer-pool.md#coverage-audit)。

S9.2 的 F36 使用其保护做页内整理与复用；S9.3 在引用、页链、读者/IO、旧页号失效和恢复条件成立后，执行 F36 → F26 → F22 → F12 释放。释放对象内一个页范围不等于删除包含其他活页的整个对象。条件缺失时暂缓整页释放，不延后基本正确性。

### 6.6 第二轮审查补充

对象分组中的数据库身份须包含工作库重建的独立身份。当前 BusTubRaftStateMachine::InitializeEmpty 会清理工作目录，InstallSnapshotFile 构建候选工作库后切换；新 FS 对象不会因删目录自动消失。S9 须定义创建新身份、切换和旧工作集回收，不允许只用重新开始的 page_id 寻址旧对象。

零初始化新页是页层明确的动作，设备短读或映射损坏不得伪装为新页。S4/S5 的 B 私有页、WAL、写回及恢复已完成，S8 对象三 Store 与正式 C++ 节点接入也已完成，证据见主方案阶段表；F26 已完成 b 基础组件、c 真实页接入及 d 路径缓存/归还。本模块并发改动须保留已有契约。F26 的工作页可写出不代表已有 F28 一致恢复根。

### 6.7 数组目录、内存与跨模块交接

[数组子方案](array-buffer-pool.md) 是上述机制的详细设计入口。保持现有 int32_t 非负页号/RID 格式；数据空间身份与打开实例身份由目录上下文承载，运行目录无需 WAL。首轮条目按低位到高位为 frame 32 / version 24 / latch 8，frame 编码零表示无帧；其他位不能忽略，整个条目全零不作为唯一未驻留形式。

PathCache 缓存路径而非页正文；hole punching 保留叶虚拟地址，整个目录释放另等旧访问退出。分层候选 bitmap 可参考 F12，但设备分配、A 页内空间与翻译 RAM 状态独立。FrameArena 负责实际对齐与大页使用，F32/F31 计账；[F02 §6.6](object-io.md#f02-external-buffers) 扩展外部缓冲保留，不把裸指针或 pin 当成内容稳定证明。F01 维持调用者缓冲接口。

### 6.8 S9.1c 默认切换与旧页路径清理

F26 完成帧生命周期和后端适配后，BufferPool 常规页 IO 默认传帧地址及许可。可直传请求不再经 F02 自有中转缓冲；不得以可选开关、空许可回退或旧包装使正常请求继续使用旧页路径。必要稳定副本或规划缓冲显式说明，A/B 各自的寻址和提交条件保持。

按 [F02 默认迁移规则](object-io.md#f02-buffer-default-migration) 核对正式消费者，清理失去用途的页复制、旧调度适配、分支、配置、wrapper 和接口。非页对象仍有实际用途的自有缓冲由其调用者显式选择，不强制经过 BufferPool；无生产用途且无必须保留契约的入口删除。S9.1c 的完成证据必须包含默认调用链、清理及保留原因，不仅是新增接口的测试结果。
