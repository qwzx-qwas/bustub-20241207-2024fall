## 6. 讨论后的方案与待冻结边界

S6 具体协议以 §11 为准；下列 S10/S11 的共享方向不表示提前启用。

### 6.1 内容归属与共享

延续 ObjectRef/PayloadRef 的一份正文、多方引用；持久引用随相关事务原子变更，运行中读者/IO 也要保护。F25 的清单发布不复制正文；S11 由 F28 固定一致业务边界后才共享页版本/extent，不把引用存在当作已捕获一致快照。

### 6.2 F36 清理和范围释放

A 的记录逻辑死亡不说明所有旧快照中的物理内容死亡。F36 通过 F26 清理或释放时，本模块保留仍需的旧版本，修改受保护数据要使用相应 COW/版本协议；等待完成再交 F22。对象内还有其他活页、范围共享或最小分配约束时，不释放整个 extent。

临时引用结束与持久引用解除分开，迟到回调须按对象/代次归并；同一个引用不得重复释放新分配内容。S6 范围所有权/临时保护已按 §11 实现；S11 持久计数/根追踪选择和共享单位仍待冻结，不新建第二套引用数据库。

### 6.3 Journal 跨段引用与两种保留

跨段记录/批次有一份正文和必要的位置/身份信息；只要消费者仍需以原格式读取或恢复，就共同保留必要片段及提交验证范围，不能仅 pin LAST 所在段。单元/段身份与逻辑范围一起防止旧引用指向新复用内容；具体句柄布局、引用计数或根追踪协议仍待冻结，不建独立引用数据库。

持久引用解除进入正式事务；读者/IO 的临时保护在运行中同步取得与释放。禁止新引用、零引用判断和段退役须与 F06/F07 配合，防止检查后新访问进入。批次完成状态释放不代表 PayloadRef 已释放，反之保留磁盘正文不要求长期持有 IOBatch 或第二份 RAM 正文。

S5 的基础恢复保留由 F07/F10 完成，独立于 S6 的普通对象范围回收；S10 将同一协议接入 Deferred。若后续搬迁仍有效 Journal 正文，要先持久化新位置和原子切换引用，再等待旧读者；不能直接挪动半条记录，暂时双份不等于永久重复存储。

## 11. 2026-10-02 当轮执行协议（用户已授权）

### 11.1 范围与顺序

本轮实现 S6 的普通对象引用/范围保护和回收组件。当前对象只通过新分配建立映射，旧分配退出的字节不能重新挂回当前映射；因此 F13 的持久退出记录是普通对象旧内容死亡的依据。S11 增加共享版本时必须在同一判定中加入其持久引用，不能直接沿用仅有当前映射的释放条件。Journal PayloadRef 留在 S10；节点 owner/统一 ObjectIO、完整 F15 写服务另按 S6/S7 接入。

代码分析先验证：退出记录与映射同批；分配身份不可复用；局部所有权不能凭旧原始范围扩大；取得读取保护与建立回收栅栏互斥；释放事实与位图原子提交；结果不明沿 B/F12 停止接纳。

### 11.2 粒度、碎片和尾部

按实际 allocation_bytes（u）释放完整单位，不要求原 extent 整体无用。相邻可释放单位合并；不相邻范围可在一次有界 Release 中提交。单位内还有有效字节或受保护读者时保留；多条退出记录应联合判断，不能因每条不足 u 而永远不回收。

不足 u 的尾部仍归原分配所有，不报告给 F12 全局空闲表，不每产生余量就提交一条新通知，不扫描其他对象拼接零碎空间。逻辑长度/有效映射与分配容量分别管理；未映射字节不能作为有效正文读出。整单位全部死亡后，连同其对齐尾部一起释放。可复用旧字节默认不擦零、不异步清零；实际写出的缓冲仍须初始化。短 IO/失败不得假装成合法短输入。

S7 的追加只检查本对象当前尾部候选；可安全容纳就复用，不足或不适合时整次追加申请新空间，暂不拼接旧尾和新分配。上层只给对象及逻辑操作。F17/F18 处理并发和写策略；F13 发布映射/长度；F14 保护范围；F12 只处理新增完整单位。尾部复用若会重写旧有效单元，须走已明确保护或 COW，不能仅按容量判断。不提前实现子单位共享分配器、预分配 API 或自动碎片搬迁。

### 11.3 同一份 B 中的所有权与兼容

新建 F13 格式为 v2；新程序继续打开和读写 v1，沿用其三字段分配值，不自动迁移。F14 对 v1 明确拒绝启用，旧二进制因格式号不支持而拒绝打开 v2。固定组合键保持原型。

v2 分配记录 value 为：原始物理起点、原始分配长度、创建版本、最初初始化的正文长度（四个 u64）。后者用于把从未发布的对齐尾部与已退出正文共同判断，不代表此后追加能力已实现。F13 Replace 必须按需申请，仅最后一个单位可含余量。

新增类型 6 的剩余所有权记录：category 高 8 位为 6、低 56 位为空间号，owner 为对象号，item 为物理起点；value 为长度、分配号。新分配初始一条，局部释放后只保留左右剩余段。所有权是按 u 对齐的范围；缺失不能当作仍拥有原完整分配。最终全部释放时删除原分配记录。同一物理位置后来被新身份占用，旧分配只能认自己的剩余记录。F13/F14 共用内部编码，不让二者各维护一套 schema。

部分释放时，同一 B 事务更新所有权、裁剪/删除退出记录及其数量，并由 F12.Release 清 bitmap；只对实际处理的范围生效。被分割的退出条目保留原移除版本。若拆分或事务预算超限，提交前整体拒绝。不会同时再保存一套释放位图或每字节计数。

### 11.4 读取许可与寿命

一个 ObjectReferenceManager 绑定一个已打开的 ObjectMappingStore；每个 store 生命周期只创建一个引用管理上下文。显式预算限制活跃调用、读取许可数、每次许可的范围数、回收扫描、释放范围数/字节数；没有为测试提供默认参数。

ProtectRead(snapshot, object, offset, length) 从指定不可变视图解析整个请求，受范围预算限制；返回可复制的 RAII 许可和实际 Data/Hole 计划，复制只延长同一次保护寿命。先登记所需分配单位的保护，再按当前 B 所有权验证；与回收栅栏登记互斥。不接受仅凭旧元数据地址读取已释放内容。保护覆盖请求所需物理单位，调用方 IO 不能扩大到许可外。把许可随 IO 上下文/现有 F02 缓冲许可保留到实际完成；销毁观察者或超时不结束已提交 IO 的保护。

已持许可的旧视图仍可读；未取得保护的旧元数据快照仅能解析历史映射，许可获取可能因 Busy/Stale 明确拒绝。不能静默改为读新版本。上下文停止后拒绝新调用，排空已进入调用；许可析构只操作所属内存状态。owner 在关闭/重开 B/F12/F13 前仍须结束旧 Data IO。

### 11.5 有界回收流程

Reclaim(base, object, allocation_id) 处理一个明确分配身份；单次可释放其中多个不相邻范围，不扫描设备或全部对象。按显式上限扫描该对象的退出记录、相应物理区间内的剩余所有权，将目标分配的退出覆盖与原始对齐尾部取并集，再取其中可释放的完整单位，并与剩余所有权相交。S6 的“旧字节不可重新挂回”约束使这个判据无需再维护一份当前映射反向索引。

以短锁建立候选范围栅栏，阻止新的重叠读取许可；快照已有读者范围后，跳过仍被 pin 的完整单位，其他单位继续释放。无须持线程等待读者退出，也不持锁等待 B/设备 IO；被保护部分留在持久退出记录，后续调用重新评估。回收结果区分没有提交、实际提交结果、durable 释放字节及被读者阻挡字节，不能伪造一次 Flush。

已回收的旧 allocation_id 重试不影响新分配；原 base 冲突不自动刷新/重试。显式 pre-IO 拒绝可解除本次栅栏；已接纳失败后 B/F12 不再服务，栅栏解除也不构成可继续读写的许可。S7/F22 将这些动作纳入有界后台调度，本轮不建立独立 worker 或全局事件队列。

### 11.6 必要验证与后续接管

先完成生产逻辑审查再写测试。重点通过真实正文/容量验证：非零逻辑起点的中间单位回收且两侧保持；读者只阻挡重叠单位并随真实 IO 保留；旧快照无法取得已复用地址；多个不足 u 的退出合起来释放一个单位；对齐尾部最后随单位回收；重复回收/重启不伤新身份；预算/原 base 冲突不部分释放；Flush 暂停/失败下所有权、退出及 bitmap 整体恢复。兼容测试使用旧生产代码生成 v1 数据，再由新代码打开，不能手造格式当作兼容证据。

F13 原六项、F12 原六项及必要 B/生命周期/旧格式回归直接复用，测试内容不复制。风险归属 F14/range-lifetime、partial-reclaim、ownership-reuse、atomic-recovery、legacy-format；S7 的完整读写、F21/F26、S11 共享版本接管后再评估退役组件测试。组件通过不代表裸设备、真实掉电、SQL/Raft E2E 或性能提升。

### 11.7 参考与本项目落点

本轮重新核对 [Linux iomap 设计](https://docs.kernel.org/6.13/filesystems/iomap/design.html)：区分物理空间占用与有效内容，未初始化范围不能泄露旧字节。本项目内化为完整分配、有效映射及对齐尾部的分工，不照搬 IOMAP_UNWRITTEN 编码、不新增内核文件接口。范围保护、事务和 bitmap 接续本项目既有 F12/F13/B，不另引入外部库。RocksDB 的正文引用共享仍按 §4 留待 S11，不把它说成当前普通对象已支持多方持久共享。

S7 接入尾部复用时，新增映射与该分配的初始化边界必须同一事务推进，使 F14 不再把已发布的新增字节当作从未使用的尾部。S6 的“退出字节不可重新挂回”仍有效；若要复用曾退出的旧内容范围，先扩展这条持久协议，不能只改内存余量或继续沿用旧退出记录。
