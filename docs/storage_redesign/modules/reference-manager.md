## 4. 开源参考与本项目落点

- [RocksDB checkpoint](https://rocksdb.org/blog/2015/11/10/use-checkpoints-for-efficient-snapshots.html)：共享不可变文件而非再复制正文。内化为 F25/F28 的已固定对象版本通过本模块保留；页式可变数据仍须 COW 与正确恢复根，不直接采用硬链接。核对：2026-09-21。

- [RocksDB Integrated BlobDB](https://rocksdb.org/blog/2021/05/26/integrated-blob-db.html)：为减少大值随索引整理反复搬运，将大值与索引分离并保存引用。 借鉴大内容与索引分离；不声称所有写入只发生一次。 来源核对日期：2026-09-20。

## 6. 讨论后的方案与待冻结边界

以下为本轮收录的设计方向和约束；具体字段、数值、接口及当轮验收未确定前，不能把它们补成默认实现。

### 6.1 内容归属与共享

延续 ObjectRef/PayloadRef 的一份正文、多方引用；持久引用随相关事务原子变更，运行中读者/IO 也要保护。F25 的清单发布不复制正文；S11 由 F28 固定一致业务边界后才共享页版本/extent，不把引用存在当作已捕获一致快照。

### 6.2 F36 清理和范围释放

A 的记录逻辑死亡不说明所有旧快照中的物理内容死亡。F36 通过 F26 清理或释放时，本模块保留仍需的旧版本，修改受保护数据要使用相应 COW/版本协议；等待完成再交 F22。对象内还有其他活页、范围共享或最小分配约束时，不释放整个 extent。

临时引用结束与持久引用解除分开，迟到回调须按对象/代次归并；同一个引用不得重复释放新分配内容。具体引用编码、持久计数/根追踪选择和共享单位仍待冻结，不新建第二套引用数据库。
