### 6.1 第二轮审查补充

一个 TxContext 组织可并行的规划、分配和独立数据 IO，维护每步依赖并通过完成事件推进；它不执行每次 IO、不替代 B 或 F35。元数据提交角色可串行，等待 IO 的线程不持全局锁。

Common 进入本模块是为了原子提交映射/分配/引用，不要求把正文再写 redo。Deferred 的元数据和可恢复正文同批提交；混合批次还要等 Common 的 durable 依赖。批次身份与 Journal 位置可共享表示但含义不混淆，组刷盘不扩大原子边界。

提交 durable 与发布成功分开记录。durable 后发生发布故障不能假装未提交并释放数据；已承诺内容由恢复协议保留。按 F00 归并结果未知、迟到完成、取消和关闭，不新增第二套日志或全局状态机。

### 6.4 复合原子性与系统调用边界（2026-09-23）

F19 的提交单位覆盖对象正文的持久依赖、对象元数据、分配与引用。用户函数封装多个 pwrite/setxattr、单个 IO batch 或一次 Flush 都不产生事务；本项目元数据在 B/共享 Journal 中，不走宿主 xattr。Common 先正文 durable，Deferred 元数据与恢复正文同批，发布交给 F20，恢复交给 F11。详见[总方案 §6.1](../README.md#61-原子提交不是合并系统调用2026-09-23)。此为方案约束，非本轮 F04 已实现能力。

### S4 实际落点与后续交接（2026-09-25）

S4 的 Prepare/Publish 直接组织 B 私有页、根/分配与 FULL/PATCH，同批交给唯一 F07，再完整发布；不新建没有业务价值的包装类。当时 S7/S10 尚未完成；本轮已补 S7 数据依赖，S10 Deferred 原子批次仍未完成。 代码与验证见 [F08 §6.8](metadata-engine.md#68-s4-实现细化与后续交接) 和 [八项审查](../f08_execution_20260925.md)。本模块其他阶段状态不变。

## S9.3 接续：复用 Common 的空页退役提交

复用现有每对象一操作、有界请求、COW 正文先持久化再 B 原子发布的协议。批次 A 包含前驱页 Write 与待退役控制；批次 B 包含 victim 范围 Unmap 与控制状态转换，同一对象中的两页也分成有恢复衔接的两批，不绕过“一对象一操作”。Unmap 不写正文，仅变更映射与退役记录；不制造擦零任务。两批之间失败由 pending 接续，细节见 [F36 §6.7](table-space-management.md#67-s93-空页退役与延迟物理复用2026-10-05已授权)。
