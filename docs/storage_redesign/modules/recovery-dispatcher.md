## 6. 方案：本轮已执行协议及后续约束

以下区分当前已执行协议与未来裁剪、Deferred 等职责；本轮已冻结协议见 F10 §6.4。

### 6.1 第二轮审查补充

只分发完整有效批次，不分别恢复新元数据与缺失的 Deferred 正文。pageLSN/版本必须建立在校验有效的页或重建基础上；缺少恢复链的坏页不能靠一个可能已损坏的 LSN 跳过。

无效未提交尾部与已确认提交范围的损坏分别处理。前者只在保留所有确认内容的条件下裁剪；后者停止相关服务并上报，不能默默回退旧状态。FS 的 redo/Deferred 重放归本模块及 F27，Raft 业务命令重放仍归 Raft/A。

### 6.2 跨段记录、失败结果与重新开放

F06/F07 从直接入口识别有效段身份/日志链，重组并验证完整批次后，本模块才分发到 B/F27；不另写一套片段解析器。新代次短记录后的旧尾部不得拼入本轮，缺片/坏校验不能应用半批；已确认恢复链损坏须明确失败，不能当普通未提交尾部裁去。

运行中出现结果不确定时，F07/F34 隔离受影响提交并排空旧 IO，本模块协作重建有效状态后才满足重新开放条件。不重建或持久化历史逐 IO 完成列表，恢复依据是日志、checkpoint 和持久引用。业务 Raft 已提交命令的重试/Apply 仍归 Raft/A，不能以本地失败通知视作业务取消。

恢复入口选择还必须检查裁剪许可与段身份：checksum 合法但依赖已复用段的旧 checkpoint 不能被接受。测试在真实 F07/B 接续时覆盖，不能用 F06/S2 的字节往返替代。

### S4 已有基础与 S5 接续（2026-09-25）

S4 的 B 记录解析、基版本验证和完整视图恢复在 MetadataEngine::Impl::Replay；F07 已负责外层完整批次，不重写第二套解析器。S5 应抽取有真实多消费者的部分而非复制一套 B 恢复器，S10 继续共享同一 Journal 所有权与批次。S4 只从完整日志恢复，没有最终页/checkpoint 选择。 参考 [F08 实际接口](metadata-engine.md#68-s4-实现细化与后续交接) 与 [测试风险交接](../f08_execution_20260925.md#8-最终测试矩阵与交接)。本轮后续实现以 F10 §6.4 和执行记录为准。

### 本轮 F10/F11 依赖分析（2026-09-26）

本轮用户已授权 B 的 checkpoint 恢复闭环，不含 Deferred、日志裁剪或段复用。已确认 F03 直接保存 B checkpoint 引用，见 [F10 §6.3](metadata-checkpoint.md#63-f09-后的本轮范围与代码前推演2026-09-26)；本轮按 F10 §6.4 实施，不另建重复的日志解析器。

读取 checkpoint 页时必须区分后续已修改页和未修改页：后者校验最终页，前者使用首改 FULL 及后续 PATCH 重建。恢复全程保持未开放状态，结束后复用 B 的引用/树/空闲链校验。继续使用 F07 的完整批次校验与唯一 Journal；不另写片段读取器或为模块编号增加没有实际消费者的转发层。遵守主方案 §1.7：先分析生产逻辑，确认后实现并审查，再写测试。
