## 6. 已认可的本轮方案（2026-09-23）

### 6.1 职责与接口

F03 成功 Open → RegionManager → 区域入口和相对范围 → 既有 F02 → F01。对象元数据/Journal/普通数据使用同一执行链；引导槽继续由 F03 从已知位置访问，区域入口不能覆盖它们。

- RegionManager 只能从成功打开且未 Close 的 BootstrapStore 构造；不接受外部拼接的 layout/executor。F03 私有 BindRegions 一次返回其已验证区域和原执行器，friend 仅授予 RegionManager，不新增公共布局/设备 getter。
- RegionKind 为 Metadata/Journal/Data；RegionHandle 私有构造，持有所属 manager 的不可变上下文。Region(kind) 拒绝未知值。不同 manager 的 handle 一律拒绝，即使同一设备或同样容量；旧 handle 保留上下文身份，避免销毁后地址复用造成误认。
- RegionIORequest 指明 handle、读写操作、区域内 offset 和 size。offset/size 使用字节；F05 以后转换页号，F06 转换段偏移，F04 不理解记录/页/日志格式。
- TryPrepare / TryPrepareExternal 先解析并验证整批，再调用 F02 对应入口。复用 StorageByteRange::Subrange 检查包含和加法溢出；拒绝空 IO 和越界。空批次、IO 操作、设备对齐及冲突规则继续由 F02 验证，不补零、不扩大范围、不隐藏 RMW。
- 返回既有 IOPreparation/IOBatch，由同一个现有 IOExecutor::TrySubmit 提交；错 executor 提交仍由 F02 拒绝。不增加纯转发的 Submit/Wait/Flush wrapper。
- 外部缓冲在任何 F04 拒绝时仍归调用者；真正接纳后的移交、归还和资源限制沿用 F02。不会因为区域寻址改回自有复制缓冲。
- F03 未打开/已关闭为 logic_error，错误 region 或范围为 invalid_argument；F02 的 Full/Stopped、批内设备异常和 Flush 结果原样保留。失败不是回滚，批次不是事务。

### 6.2 数据、并发和寿命

布局保存在 F03，引导打开后复制三个已校验范围建立 F04 内存上下文；不增加磁盘格式、Journal、bitmap、checkpoint 或分配元数据副本。不建立新线程/队列。准备只读上下文，可并发调用，不持全局锁等待 IO。解析产生每请求一项的临时描述，无数据正文复制；请求来源仍是可信内部模块，F02 额度约束实际接纳。

构造须由生命周期所有者与 F03 Create/Open/Close 串行组织。复制后不依赖 BootstrapStore 的寿命，但 executor/device 必须覆盖所有 F04 使用及已接受 IO。区域视图不是设备 pin，也不是跨格式化的永久授权：改设备/重新格式化前，上层停止调用、废弃旧 manager/handle，并排空 IO。F04 不新增撤销服务或另一套关闭协议。误用防护不等于同进程恶意代码隔离。

首版不在线改区域；完整 F34 生命周期接入和 F05/F06 后端未完成。F03 冗余不足但成功打开时仍可建立 F04，修复继续由 F03 驱动；F04 不把修复完成作为准入条件。

### 6.3 与事务原子性的边界

一次用户态调用、一次 F02 batch、一次 pwrite 或 Flush 均不自动让数据及元数据成为原子事务。F04 只保证区域身份/寻址/接入；F19 组织依赖，F07/F08 负责提交恢复，F20/F21 负责一致发布和读取，F11 负责恢复。无业务元数据 setxattr 路径，元数据由 B 管理。详见总方案 §6.1。

### 6.4 复用、改动与清理

F03 编解码/双槽修复不变，只新增真正被 F04 使用的私有绑定；F02/F01 不改变准入/调度/缓冲/持久化语义。现有业务 DiskScheduler/DurableStorage 仍有消费者，不因本轮加入区域入口而删除。F04 不提前替代普通对象映射或复制一套地址算术。

本轮固定区域绑定依本项目合同设计，没有另引外部算法或依赖。已有 Ceph 原子事务及 SeaStore 分层参考用于明确上/下游职责，不声称固定三段布局等于其 SegmentManager，也不照搬其设备格式。

## 7. 本轮测试方案与验收

仅建立三个真实组件集成场景，路径为 F03 正式 Create/Open → F04 → F02 → F01 → Linux Direct 文件，不假称已运行数据库或 Raft E2E。测试在专用 /tmp 构建，使用两份各 16 MiB 的有区别内容/布局/身份文件，2 worker、8 个成员和 1 MiB 缓冲预算；构建 -j2。对齐来自真实设备查询，文件整体独立 POSIX 读取为 oracle，IO 故障注入仅在测试链接侧。

| 场景 | 独立预期 / 风险 |
| --- | --- |
| 三个区域及另一个布局读写 | 不同正文落在 fixture 明确计算的位置，区域首尾及跨区域批次正确；全镜像比较保护其他区域、间隙和引导槽；读路径核对独立正文，不能用同一错误映射的写后读自证 |
| 绑定与非法范围 | 未打开/关闭 F03 不可绑定；不同设备、同设备不同 manager 及残留 handle 不可混用；后一个非法成员使整批拒绝，镜像不变；不把空参数作为成功业务场景 |
| F02 接入语义 | Full/Stopped 保留语义、外部许可拒绝不消费；真实读写及 EIO/Flush 失败保留结果和物理范围，不伪造 durable 或回滚 |

不重复 F03 编码/CRC/修复或 F02 全部并发/预算/许可矩阵，不新增性能基准。使用 ASan/UBSan/LSan 和与新风险对应的少量隔离变异；检查完整 XML 名称和无 skip，编译失败、挂起及检测器错误不算变异命中。F03 私有接续需跑原八项作为受影响回归，不复制旧测试代码到 F04 包。

完成后执行总方案八项测试设计审查；源码、runner、结果按 F04 压缩归档，删除展开测试/构建/镜像/变异产物；替换 F04 旧包不保留问题版。F03 有效历史包继续保留。共同 C/P 内容及旧性能结果不变，裸设备/掉电/完整节点能力明确未验证。
