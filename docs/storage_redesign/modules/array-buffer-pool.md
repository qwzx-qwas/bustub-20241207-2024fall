## 1. 归属、目标与状态

本方案属于 F26，不新增顶层模块，也不建立第二套 BufferPool。正式目标是以数组翻译体系替换现有驻留哈希表，组合实现 prefix/suffix、多级翻译、path cache、紧凑 TranslationEntry、按需翻译内存及 hole punching、支持 huge page 的 FrameArena，并接通正常页访问、淘汰和有界 IO。

- 方案方向：已按用户要求纳入；具体编码、并发协议、接口和阶段验收待审查冻结。
- 实现状态：未完成。文档写入不代表上述机制已经实现。
- 实现 prompt：F26 未启用；用户已另行授权并完成 F02 独立外部缓冲能力，详见 [F02 §6.7](object-io.md#67-本轮外部缓冲独立扩展用户已授权)。
- 主阶段：S9.1a–e；S9.2/S9.3 衔接 F36，S12 调整预算与回收策略，S13 结合上层并发评估后续实验。

## 3. 结构与职责

    A 的表 / B+Tree / 执行器       B 的元数据页访问
             ↓                         ↓
      各自独立的 BufferPool / PageGuard（共享实现）
        ├─ PageKeyLayout：实例上下文及 prefix/suffix
        ├─ PathCache → MultiLevelDirectory → TranslationEntry
        ├─ 页生命周期：固定、加载、写回、淘汰、错误
        ├─ TranslationMemory：回收组、候选摘要、hole punching
        └─ FrameArena：稳定数据地址、对齐、huge page
             ↓ 缺页 / 满足各自条件的写回
        A：F26 页适配 → FS 普通对象 / B 的 extent 映射
        B：F05 MetadataBackend → 基础元数据对象 / 区域描述
             ↓ 两类寻址共同汇入
        F02 ObjectIO / IO 执行器 → F01

翻译目录回答“页是否驻留、在哪个帧”，FS 的 F13 回答“对象字节位于哪个 extent”。前者是运行时派生状态，可在重启后重建，不新增 WAL、Journal 或 B 的持久表。数据、日志等仍沿既定对象 IO 路径；PathCache 不缓存页正文。

共享数组实现不合并 A/B 的后端：B 的页依据引导信息和区域描述定位，不能为了读取 B 再查询 B 自己保存的普通对象映射；其写回仍受 F07/F09 的 WAL 和提交条件约束。这里统一的是对象范围 IO、缓冲及执行机制，普通对象和基础对象的寻址分别保留。

### 3.1 页身份与多级目录

- 当前 page_id_t 为 int32_t，INVALID_PAGE_ID 为 -1；保持非负页号约定时有 31 个可用编码位，不是论文限制。页号溢出和非法值必须在寻址前拒绝。
- 概念身份为“持久数据空间身份 + 原 page_id”；目录所属的打开实例还具有运行身份。A/B 相同页号不混用，安装快照建立的新工作空间与旧空间隔离。普通重启打开同一数据空间不强制创建新的持久身份；旧缓存/回调用运行身份隔离。身份可由所属目录承载，不在每个条目重复存储。
- 候选拆分为高 8 位 / 中 7 位 / 低 16 位，前两部分构成 prefix，低位是 suffix：Root[高位] → Directory[中位] → Leaf[suffix]。这是待评估的候选，不是已批准的常量。叶数组及下层目录按需建立；8 字节条目时一个候选叶覆盖 65,536 个页号、占 512 KiB 虚拟范围，物理占用另算。
- 当前页号按 BufferPool 分配，prefix 表示页号区间，不能假定等于 table/index ID。保持 RID/磁盘页号格式；扩大为 unsigned/64 位或改为关系内编号属于另行讨论的格式变更。
- 翻译分段大小与 FS 对象打包 K 分别决定。数组直接定位不意味着磁盘物理连续。

### 3.2 PathCache 与目录寿命

线程本地缓存“当前 owner 身份、目录代次、prefix、叶数组指针”。命中时直接按 suffix 访问叶数组；未命中才走多级目录并更新缓存。初始缓存容量及替换规则在实施前冻结，不能无限增长。

缓存的是路径，不是某页当前的帧号；正常帧替换不使整条路径失效。访问缓存指针前先通过有效 owner 上下文核对身份，不能先解引用已释放描述符来检查其代次；地址相同也不等于同一个实例。

普通 hole punching 保留叶虚拟地址和描述符，仅归还物理页。整个目录/叶的解除映射、关闭和结构替换另走停止接纳、缓存失效、旧访问退出及延迟释放。运行中保留描述符也必须计入预算；目录增长和地址空间不足要有明确错误，不允许无界占用。

### 3.3 TranslationEntry、FrameHeader 与权威状态

候选采用一个 64 位原子字；按作者公开实现的位号表示：

    低位 → 高位
    [0..31 帧编码 32 bit] [32..55 version 24 bit] [56..63 latch state 8 bit]

latch state 表示访问保护，不能直接混装 F02 的 Queued/Executing/Flushing 等请求阶段。具体状态转换、共享计数上限、原子内存序及回绕处理须冻结；用掩码/移位定义，不能依赖 C++ 位域布局或把图的方向误认为大小端。

全零表示未驻留，不表示页正文为零。当前 frame 0 有效，候选帧编码采用 frame_id + 1，零保留为无帧；检查容量，不全局改 INVALID_FRAME_ID。24 位版本不是持久 LSN、Raft index 或不重复的帧身份；回绕、清零和旧观察者的安全不能只靠它。

TranslationEntry 管翻译和发布；FrameHeader 管所属页身份、pin、内容保护、脏版本及帧复用代次；加载任务管 IO、等待者和错误；回收组管预留及回收代次。每项权威只有一个所有者，避免重复状态各自提交。

FrameHeader 保存当前所属页，淘汰得到 frame 后直接取得旧页身份，取消遍历整个驻留目录。两方向映射在加载/淘汰协议中一致更新，失败保留必要身份及脏内容。

### 3.4 正常访问、加载和淘汰

目标：正常驻留查找不依赖全局映射锁。过渡步骤可用短锁，最终使用条目原子操作、局部同步及正确的帧固定协议；不宣称整个 BufferPool 无锁。

    找到条目 → 读取映射 → 条件固定匹配的帧 → 复核身份/映射 → 取得内容保护
    缺页 → 取得加载权及回收组预留 → 分配帧 → 锁外 IO → 核验 → 发布 / 报错

同页同版本合并等待，独立页并行。不能拿旧帧号无条件 pin；淘汰者与访问者必须共享同步协议。PageGuard 释放也应采用对应局部协议，不把原全局映射锁转移到 unpin 热路径。LRUK 自身同步仍可能是热点，保留其明确契约并单独归因，不因数组改造悄悄更换策略。

沿用父方案的稳定写回、旧写不清新脏、失败保留脏内容、迟到完成拒绝和写出/durable 分离。B 的未提交私有页不能通过通用淘汰写出或被公共目录提前发布。

### 3.5 按需翻译内存、bitmap 与 hole punching

翻译数组采用私有匿名映射，不能靠全表初始化把按需分配变成全量物理分配。匿名存储中的 C++ 原子对象寿命、初始化、访问及回收协议必须有明确实现依据，不把裸地址强转当作完整证明。

按实际 OS 基础页大小划回收组；4 KiB / 8 字节 = 512 条仅为算例。组的驻留计数、加载/发布预留、回收标记和代次放在不会随该组一起清零的控制区。正在访问翻译条目的线程也须受访问退出协议保护。

    L1/L2 候选摘要 → 候选 bitmap 定位组 → 精确检查
       → 标记回收、禁止新冲突访问/预留 → 等旧访问退出
       → 再核验无驻留及在途需要 → MADV_DONTNEED → 更新代次/摘要

不持全局锁等待 IO 或旧访问。计数为零/候选位为 1 都不是单独的安全证明；加载在 IO 期间保留预留，完成回调核对身份。归还失败保持可用映射和正确计数，不谎报内存已回收。摘要更新允许重新检查，但须保证遗漏候选能由后续更新或有界扫描重新发现。

与 F12 可复用分层查找、位操作的机制；F12 记录设备分配事实，本组件记录易失 RAM 状态，不能共享同一 bitmap、持久化权威或设备释放动作。F36 页内剩余空间又是第三类视图。是否抽取公共位图实现按实际消费者决定，不预建万能 allocator。

hole punching 最小归还单位是 OS 内存页，不能归还单个 8 字节槽。假设 512 个有效条目集中在一页，需要约 4 KiB；若分散到 512 页且每页一个有效条目，就需要约 2 MiB（未含目录/控制信息/OS 页表）。多级目录和候选 bitmap 不能消除这种部分占用；不承诺数组总比哈希省内存，也不把论文讨论中的混合哈希回退当作已实现目标。

### 3.6 FrameArena 与 huge page

帧数据由地址稳定的区域统一管理，FrameHeader 可分离；替换现有每帧 vector<char> 数据分配。翻译数组使用基础内存页以便细粒度归还，帧区域实现 huge page 申请与使用报告。huge page 是 RAM 映射粒度，不改变数据库页大小、设备分配单位或持久化原子性。

大页请求与实际生效分别报告；环境不支持时普通内存路径仍正确，不能把该运行算作大页验证成功。查询 OS 能力，并分别满足 F01 实际内存/偏移/长度约束，不统一写死 4 KiB/2 MiB。预留地址、实际物理内存、对齐余量和页表开销分别计入观察/预算。

区域首地址对齐不代表每个帧都对齐：须同时核对帧槽步长，使每个参与 IO 的帧地址满足实际要求。RAM 槽位可含对齐填充，但不能据此改变数据库页内容长度或磁盘页格式。若单页长度/对象偏移不满足设备要求，交给已约定的上层规划，不能由 Arena 或 F02 偷偷扩大 IO；具体布局及适配在 S9.1a 冻结。

帧正常淘汰只复用槽位，不解除每个数据库页对应的 RAM 映射。FrameArena 关闭须晚于 PageGuard、加载任务和 F02 外部租约结束。

F02 已提供自有与显式外部缓冲入口（§6.7）；真实 FrameArena 尚未接入。直接用帧需由 F26 提供其 §6.6 所要求的许可：pin 防复用，另有稳定内容保护；上层继续修改时仍可能需要有界稳定副本/COW。减少一次拷贝不等于整个 FS 端到端零拷贝。

S9.1c 接入完成后，常规页 IO 的正式默认是“帧地址 + 有效许可”，不作为需另开选项的旁路。可直传请求移除 F02 自有中转及复制；缺许可不自动退回旧入口。必要的稳定副本/变换缓冲由上层明确规划。[F02 默认切换与退出规则](object-io.md#f02-buffer-default-migration) 规定旧页路径清理及其他对象调用者的保留条件。

许可沿所属页后端和对象 IO 路径向下传递：A 经过普通对象映射，B 经过 F05 的基础对象区域寻址。调用者不能用裸设备偏移绕过所属后端的校验、提交和发布约束，也不能强迫 B 走普通映射形成循环。只有规划后的物理请求满足直传条件才借用帧；需要合并、转换或稳定副本时保留相应工作缓冲并如实记账。

F02 的许可保护 RAM 字节；FS 对象版本/extent 的使用期保护仍由 [F14](reference-manager.md) 等所属层维持。设备不再访问帧不等于空间可立即重分配，IO 成功也不等于上层版本已提交或发布。

### 3.7 批量预取与乐观读取

批量预取纳入 S9.1e：真实调用者提供已知独立页号，先预取翻译/驻留数据，再合并并提交未驻留页的有界 IO。CPU 预取与设备读分别统计；同页请求仍合并。下一页不能假定为 page_id + 1，B+Tree 依赖下降不能凭空并行。实施前明确调用路径；没有消费者时报告缺项，不交付空接口冒充完成。

乐观读取作为 S13 的独立实验，不阻塞上述核心组合。普通 PageGuard 保留正确的 pin/内容保护语义；若引入可重试短读，需定义合法的并发数据访问、生命周期、版本回绕及副作用边界。对普通非原子页数据无锁读写后再校验版本，不构成 C++ 数据竞争的补救。

F26 统一实现缓存访问机制；F32 管策略、F31 管预算、F02 管范围 IO 和缓冲保留、F01 保持字节设备接口、F08 核对 B、F34 管工作库切换/关闭、F36 判定页可释放。无需先完成一轮大规模哈希版重构再重做数组版；将既有生命周期安全要求直接纳入新设计。

S4/S5 的 B 恢复基础仍先于 S9；新数组优化不能成为其倒置前提，也不能绕过其私有页/WAL。F36 的释放必须处理已解析帧、路径缓存所属目录和在途 IO；单页淘汰不要求清除仍有效的 prefix 路径。

## 5. 测试边界、复用与待冻结项

沿用主方案 §1.5 八项测试设计审查、§1.6 阶段退出和共同 C/P；业务输入、独立预期和 durable 含义保持。模块小测试必要时临时编写，审查后按 F26 压缩归档；未被真实 E2E 接管的风险继续登记，不复制 F01/F02 的镜像套件。

- F26/translation-lifetime：同页合并、独立页推进、实例切换、淘汰/页号复用、旧缓存及旧回调不能读错内容；失败不发布半页。F34/F36/F08 引用同一风险。
- F26/translation-memory：加载/访问与 hole punching 交错后内容仍正确；预算受控、回收失败不损坏状态；A/B 私有版本不混用。bitmap 内部形状不单独变成测试契约。
- F02 外部缓冲的独有风险及既有 admission/budget/failure-drain/lifetime-close 复用见其 §6.6/§7.1；不新增测试专用生产 getter、默认路径或后端。
- 验收记录同时给出真实 BufferPool 默认调用链、旧页路径删除清单及自有入口的实际保留用途；不能只通过新入口组件测试就报告正式路径已迁移。
