### 6.1 第二轮审查补充

采用主方案的三个维度，详细字段/优先级规则待本模块讨论：

| phase | 表示的事实 |
| --- | --- |
| Starting | 正在打开依赖，业务入口尚未就绪 |
| Recovering | 正在恢复一致状态；仅允许已明确安全的恢复/复制工作 |
| Serving | 本地必要依赖就绪；业务读写仍检查角色、读屏障和条件 |
| Draining | 停止接纳相应新请求，处理已接受任务；未等于停止完成 |
| Stopped | 约定工作已安全结束，资源可以按关闭协议释放 |
| Failed | 无法维持相应正确性保证，需恢复或人工处理，不能伪装只读就绪 |

IOFault、ReadOnly、SpacePressure、ReplicaLag 等 conditions 可叠加；对外主原因的排序仅用于展示，不能用一个高优先级条件抹掉其他限制。capabilities 按操作综合全部适用条件，某条件解除只解除它自己的限制。Follower 的 Serving 不自动授权 Leader 写入，ReplicaLag 也不直接宣告整个节点所有操作失败。

控制器只汇总服务级事实；每个 IO、事务、待落位范围继续归执行模块。调用者检查发布视图和本地安全条件，普通操作无需等待控制器逐次发令。借鉴第 4 节 Kubernetes Conditions 的并存表示；不是移植 Ceph PG 的状态/peering 协议。
