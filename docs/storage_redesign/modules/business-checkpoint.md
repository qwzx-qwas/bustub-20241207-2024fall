## 6. 历史设计方向（本轮已由 S11 共同协议细化）

以下为本轮收录的设计方向和约束；具体字段、数值、接口及当轮验收未确定前，不能把它们补成默认实现。

### 6.1 固定一致业务恢复边界

与 F25/F14 同步固定表、索引、Catalog、会话、分配状态、applied index 及对象版本/映射根；这些状态必须可共同恢复，单独保存一个进度数值无效。S9 的页/slot 与 F36 回收规则应在本阶段物理格式冻结前明确。

当前 canonical 快照与活动物理页格式不同；是否物理保存索引、如何支持跨节点安装或回退重建，仍待冻结。接入初期保持已验证快照+Raft 重建，可靠本地 checkpoint 验证后才依赖新恢复根，不新增另一套独立 A WAL 作为隐含工作。

### 6.2 共享与清理

固定引用的页/extent 在后续修改或 F36 整理时通过 COW/引用协议保护；空闲页摘要可重建，但真实表链/分配及引用变化不能作为可丢失提示。引用计数不能代替一致性边界的捕获。

RocksDB checkpoint 依赖不可变 SST 共享的条件在本项目需通过一致版本/根和 COW 建立，不能直接硬链接活动数据文件。压缩不解决捕获期间并发变化或全表重建成本。F35 在 S13 改会话/Prepare 并发时同步本模块的视图和兼容协议。

### 6.3 A 的入口与 B 引导隔离（2026-09-26 补充）

A 也有恢复入口，但它保存业务状态，不能与 B 的物理引导混用。B 的 checkpoint 引用位于已知设备槽，先恢复“逻辑对象在哪里”；之后 F28 用稳定的逻辑对象身份找到 A 的恢复描述，再恢复 Catalog、表/索引、会话及 applied index 对应的业务边界。A 描述的具体编码/对象标识仍在 S11 冻结，不在本轮增加未使用的字段或接口。

因此双槽 0/1 是同一设备引导的冗余，不分别属于 Engine A/B；A/B 有独立根、页空间、缓存与恢复上下文。A 的逻辑根随普通映射使用 B 恢复出来的寻址能力；B 的底层入口不能反过来依赖 A 或普通对象查询，避免启动循环。S8/S9 继续当前快照＋Raft 重建路径，S11 接入这条业务恢复根后才改变恢复权威。

2026-09-26 当时只更新设计交接；F28 此后由 S11 本轮实现。B 的实际进度见 [F10/F11 执行](../f10_execution_20260926.md)。
