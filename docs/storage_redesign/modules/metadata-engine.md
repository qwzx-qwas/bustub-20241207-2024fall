## 4. 开源参考与本项目落点

- [PostgreSQL full_page_writes](https://www.postgresql.org/docs/current/runtime-config-wal.html#GUC-FULL-PAGE-WRITES)：为处理页面撕裂，checkpoint 周期首改保留完整页恢复基础。 用于 B 的完整页恢复基础与后续增量；不照搬 PostgreSQL 整套事务实现。 来源核对日期：2026-09-20。

- [BlueStore 论文 §4](https://pdl.cmu.edu/PDL-FTP/Storage/ceph-exp-sosp19.pdf)：正文直接设备 IO，专门的 RocksDB 管元数据，BlueFS 提供可引导的底层支撑。内化为 B 的专用元数据职责、F05 直接页后端和先 B 后普通对象的恢复依赖；本项目复用 BusTub 算法，仍须自行补齐恢复，不能借 RocksDB 的成熟度为当前 B 背书。
- [RocksDB 多实例资源共享](https://github.com/facebook/rocksdb/wiki/RocksDB-Overview#support-for-multiple-embedded-databases-in-the-same-process)：独立 DB 实例可以共享线程池、缓存和限速设施，解决实例隔离与资源复用同时存在的问题。本项目内化为保留 A/B 状态隔离、复用 F01/F02 和统一资源预算；本轮不新增共享 BufferPool 或 FrameArena。
- [SeaStore](https://docs.ceph.com/en/latest/dev/crimson/seastore/)：缓存和事务设施位于地址映射树之下，使映射树和其他结构可参与同一底层事务，根和映射节点仍有物理寻址入口。用于评估统一内核路线的代价，并支持 F19 的本地原子提交分工；不据此合并 A 的业务事务与 B 的存储事务。

后三项来源核对日期：2026-09-25。F26 的 Calico 数组翻译继续按独立数据空间复用实现，参见 §6.2；它不要求 A/B 合成一个运行实例。

- [ext4 extent 格式](https://www.kernel.org/doc/html/latest/filesystems/ext4/ifork.html)：单条叶子映射为 12 字节，条目增多时树增长。内化为单条映射与整个对象映射集合的长度分别设计；不复制 ext4 字段宽度或限制。
- [BlueStore 元数据类型](https://github.com/ceph/ceph/blob/main/src/os/bluestore/bluestore_types.h)：`bluestore_onode_t` 的属性/分片目录及 `bluestore_blob_t` 的 extent/校验数据会增长，部分整数还用变长编码。内化为按类型和访问粒度设计 B 记录；C++ 字段定宽不等于磁盘编码定长，不引入本项目未要求的全部 Ceph 属性功能。
- [Btrfs 设计](https://btrfs.readthedocs.io/en/latest/dev/dev-btrfs-design.html)：固定 item 目录记录变长内容的位置和长度，并以对象/type/offset 组合组织条目。内化为固定索引描述与变长内容可以结合的设计依据；组合键已在 §6.6 确认，不把 Btrfs 页内布局或磁盘 ABI 当成本项目已定实现。

以上三项核对日期：2026-09-25。它们支持混合表示的选择，不证明当前 BusTub 已经实现同样能力。

### 6.1 第二轮审查补充

复用当前 B+Tree 的查找、比较、分裂/合并算法，B 使用独立运行实例和事务页访问。实施前树构造函数会重置 root_page_id；Page::SetLSN 写入偏移 4，与现有 B+Tree 页头 size 冲突。因此 Create/Open、页格式和容量计算必须显式适配，不能直接给当前树开启一个 WAL 开关。

建议的事务顺序：从已发布页取得受保护版本 → 私有页上修改 → 收集 FULL/PATCH 与分配/根入口变化 → F07 同批 durable → F20 发布 → F09 写回最终元数据页。初期单元数据写入角色避免未经设计的脏依赖；读者仍固定已发布版本。未提交页不允许沿原 BufferPool 淘汰路径写到最终位置。这一私有页/写回接入在 S4/S5 就需要完成，不能等待 S9/F26 的并发优化。

沿用已讨论的 checkpoint 周期首改 FULL、后续 PATCH，新页/复杂结构变化允许 FULL；不是每次都写整页。相应恢复链、页代次、校验、增量基版本及裁剪边界必须齐备。页面校验失败时不可仅信任其 pageLSN 来跳过 redo；有效 FULL/恢复基础不足时报告损坏。分裂涉及的新旧页、父节点、根和分配状态按同一事务恢复，元数据 WAL 只经 F07 一份，不另启独立 B 日志。

参考仍为第 4 节 PostgreSQL FULL 页保护；本项目私有页、字节后像增量和简化 checkpoint 需自行实现，不等于复制其成熟恢复系统。

### 6.2 S9 数组 BufferPool 的共享边界

[F26 数组子方案](array-buffer-pool.md) 将 Calico 的驻留翻译机制用于本项目；其来源/差异在该文档 §2 统一说明。本模块可复用实现，但保持独立目录、数据空间、打开身份和帧预算，不能把 A/B 同页号当作同一页。

S4/S5 的私有页、WAL 先行和恢复基础仍先行，不依赖 S9 优化才能正确。S9 若替换共用 BufferPool/PageGuard，未提交私有版本不能直接发布到公共页号条目或走通用淘汰写到最终位置。私有版本的存放/索引方式由本模块定义，数组条目不接管元数据事务。

F02 外部许可只保留合法的稳定字节版本；B 页写出仍受 F07/F09 的提交和 WAL 条件约束。翻译目录是运行时派生状态，不另作为 B 的持久表、不新增一份日志。

B 页后端保持 F05 的基础元数据对象/区域寻址，不套用 A 的普通对象分组与 extent 查询；复用 FrameArena 实现或借帧 IO 不改变该引导边界。否则恢复映射需要先读取 B、读取 B 又需要该映射，会形成循环依赖。

共享代码回归引用 F26/translation-lifetime、translation-memory 及本模块既有恢复风险，不建立一套数组内部细节测试。

### 6.3 F05/S2 已交付的基础页后端

F05 将当前 4096 字节 `BUSTUB_PAGE_SIZE` 的非负页号映射到 Metadata 区整页槽位，支持 F02 自有/外部缓冲与显式 Flush 结果；不分配页、不解析页内容、不提供 WAL。`PageCapacity` 仅代表可寻址容量。S4 必须在持久化 B 格式中记录/核对页大小与版本，定义保留页/根页、空闲状态、页代次及事务恢复，不能因后端构造成功就宣称打开了有效 B 数据库。分配事实与 B+Tree 新旧页/父页/根变更走同一 F07 恢复批次，不能单独新增一份 WAL。沿用 [F05 风险记录](metadata-backend.md#7-本轮测试方案与验收)，后续集成补真实 B 行为，不重写页地址小测试。

### 6.4 A/B 独立上下文的执行边界（2026-09-25）

- A 的 `WorkingState` 与 FS 内 B 的上下文独立，B 不通过 SQL/Catalog 管理存储元数据，不另建完整 SQL 实例或进程。业务 SQL 调用者持有 A 的接口，FS 元数据管理持有 B 的接口；当前不增加每次调用选择 A/B 的通用句柄注册系统。

### 6.5 本轮已确认的混合表示与复用边界（2026-09-25）

**本轮决定。** A/B 采用两个独立运行上下文；复用代码及 F01/F02、统一资源预算不要求共用同一个缓存或事务。B 元数据采用混合表示，不再沿用“只推荐索引全部指向独立记录页”和“所有值必须定长”的过度简化。具体选择需同时兼顾 A 的既有路径和 B 的事务页访问。

| 内容 | 已确认的表示方向 | 不能推导出的承诺 |
| --- | --- | --- |
| 对象编号、长度、版本等小描述项 | 可以定长 | 不表示所有类别用同一结构或统一填充长度 |
| 单条逻辑范围到物理 extent 的映射 | 可以定长 | 不固定一个对象最多只能有几条映射 |
| 一个对象的映射集合 | 多条记录按需增长 | 不每次重写整个对象的全部映射 |
| 校验、引用等可增长集合 | 按访问/更新粒度分项或分块 | 不为每个字节新建一个键，也不预先复制其他项目全部字段 |
| 较大的元数据内容 | 通过记录集合或引用管理 | 不把内存 string/vector 的指针原样持久化 |
| Deferred 与快照正文 | Journal/对象保管正文，B 管描述与必要引用 | 不因树值编码而在 B 再存一份完整正文 |

固定树索引描述和变长内容可以结合，但不自动决定内容必须跨页。若让变长内容直接驻留叶子，需适配字节容量、整理、分裂、合并；若使用独立记录页，需管理记录长度、引用、页内复用及回收。任何路径都必须让树/值/分配/根变化由同一 F07 批次恢复，不借原子发布掩盖未持久化内容。

### 6.6 固定组合键＋变长值（2026-09-25 已确认）

用户已确认“类别编号＋所属对象编号＋条目编号/逻辑偏移”的固定组合键，值允许变长。三个字段分别使用无符号 64 位数，按上述字段顺序比较；键编码采用大端字段，树中 32 字节键槽的余下 8 字节保留为零。使用现有 `GenericKey<32>` 的字节容器和专用比较器，不构造 SQL Schema、Tuple 或 Catalog。

小值放在 B 自己的 slot 记录页中，树内保存固定记录引用；大值使用有长度的页链，记录页保存引用。映射集合用多个组合键增长。这里选择复用现有固定键/值树和稳定记录引用，不强迫 A 更换 RID/表页布局，也不把 B 的变长值填成统一宽度。后续是否让某类小值直接内联叶子属于性能演进，不是本轮必须再实现第二条路径。

### 6.7 F08 落实顺序与交付判据

1. **确定入口和页表示。** 按已选键契约定义小描述/可增长记录的表示、长度范围、页身份、根和分配信息、Create/Open。按类型明确数据所有者；不扩张 A 的 SQL API。
2. **复用树与事务页访问。** 复用查找、比较、分裂/合并中适用部分；隔离未提交修改，补记录空间复用和页分配归属。不能只把现有树挂上 F05 就称为可恢复引擎，也不能只用一个内存 map 冒充已落实 B+Tree。

### 6.8 S4 实现细化与后续交接

**正式入口。** `MetadataEngine` 由同一个已打开的 BootstrapStore 装配 F04/F05/F07，独占本轮 B/Journal 区域。`Create` 创建新 Journal 及 B 格式；`Open` 从完整批次重建 B；`Read` 返回不可变视图；`Commit(base, mutations)` 以该视图为前提执行原子修改；`Close` 停止新调用并排空日志。过期或其他实例的 base 在 IO 前拒绝；不存在每个调用再选择 A/B 的全局 handle 系统。视图提供 Get 和有数量上限的有序 Scan；删除与“存在但值为空”分别表示。

**共享树。** 现有 BPlusTree/IndexIterator 通过页访问类型参数复用同一份查找、分裂、合并和迭代代码；默认仍是 A 的 BufferPoolManager。B 使用自己的版本页访问和页缓存，修改时复制被修改的页，读者保留已发布页。原构造入口继续 Create；显式 Open 不初始化根。页 Init 模板定义移到头文件供 B 比较器使用，不复制第二套树算法或引入 SQL 系统。

**S4 缓存限制。** 当前 B 页面保留在 RAM 中，页数、同时存活的页面版本数、值长度、批次字节均由显式配置限制；当前页目录在提交时复制指针，不复制全部页正文。旧读者继续占用页面版本预算，超额明确拒绝，不悄悄淘汰未提交页。该预算不是逐字节的全进程内存 accounting：页目录、容器和调用方返回值也占内存。S5 接入可靠最终页/恢复基础后再加入淘汰与按需读取，S9/F26 的数组目录不被当作 S4 前置。当前不能把 B 所能寻址的整个设备容量等同于可以全量驻留的缓存容量。

**记录与分配。** slot 保存位置、长度及必要的大值引用；删除后同页 slot/字节可整理复用，尾部空槽缩回而不改变存活 RID，避免旧 slot 目录挤占近整页值。较大的值由多个 overflow 页组成，最后一页按实际长度读取，短值替换不暴露旧尾部。释放树页和 overflow 页进入 B 私有空闲链，重新分配增加页代次；旧读者保留旧页版本，不能读到新一轮内容。空记录页继续供后续 slot 复用，不在 S4 强制压缩整个 Metadata 区。页号 0 保存根、高水位、空闲页链和记录页链入口，所有变化和对应页内容同批提交。

**格式。** v1 页大小为当前 4096 字节，尾部预留 64 字节给身份、代次、64 位 pageLSN 和校验；B 树容量相应下降，A 页格式不变。树运行时沿用现有页访问，Journal 页正文由显式大端编码转换，不持久化 C++ 指针/容器布局。页 trailer 的校验覆盖 canonical 正文和身份前缀。F05 可寻址容量约束 page_limit；page_limit、最大值长度、页大小及格式版本写入 B 的首批记录，重开必须匹配。运行时 live-page/batch 预算可调整。

**唯一 WAL 与发布。** 每批首记录保存 B 格式、前一提交位置、页高水位和页恢复记录数量；后续 FULL/PATCH 记录页身份/代次、基版本、重建后的正文校验及完整正文或字节后像。F07 的批次位置从提交结果或 replay 回调获取，持久化后原位填写私有页 pageLSN；不提前猜位置，不在现有 32 位 Page::SetLSN 中截断。发布所需页、目录和缓冲提前准备，确认 durable 后只填写固定大小 trailer 并切换完整视图。

**FULL/PATCH 阶段。** S4 尚无 checkpoint，只有从创建开始的恢复周期：新页、页代次/种类变化使用 FULL，普通修改采用 PATCH；增量不比 FULL 更小时回退 FULL。重启恢复所有批次并校验 PATCH 的基页版本。S5 新 checkpoint 周期的首改 FULL、裁剪边界和最终元数据页写回仍需 F09/F10/F11 接续，不能把 S4 的内存重放称为已完成 checkpoint/稳态回收。

**失败与并发。** 初期单写入角色串行提交，读者读取独立的不可变视图；等 Journal IO 不持发布锁。输入/页/版本/Journal 资源不足在本批 IO 前拒绝，私有修改丢弃。F07 接受后的失败保留其 NotCommitted/Indeterminate 分类并停止该 B 的新操作；已取得的旧视图继续表示旧提交。需要销毁旧上下文并 Open 重建后才重新服务；不把未知结果视为确定取消。生命周期由调用方串行，Read/Commit 在 Open 完成后可并发，Close 排空写入。组件同步接口由后续 worker 调用，不在本阶段改造 Raft 提案线程。

**完成范围。** F08 和 F16/F17/F19/F20 的 S4 最小角色共同落在上述事务路径中，不为了模块编号增加空壳转发类。S5 的页写回/checkpoint/日志回收、S6 普通对象目录、S8/S9 业务接入和 S10 Deferred 均不在本轮完成范围。
