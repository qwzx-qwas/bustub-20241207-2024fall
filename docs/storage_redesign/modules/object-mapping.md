### 6.1 对象范围和 extent

一个物理 extent 是连续设备范围；普通对象可由多段非相邻 extent 构成，映射保证逻辑寻址。F12 尽量连续分配是性能策略，不是正确性前提；页按 K 分组进对象不保证物理相邻，也不减少查询需要的逻辑页数。

### 6.2 F36 释放和 S11 共享

F36 经 F26 释放的是对象内相应页范围，不能删除包含其他活页的对象。映射切换、分配事实与持久引用按本地事务更新；是否能立即归还物理空间取决于最小分配单位及 F14 的共享引用/读者/IO。A 的页内空闲字节摘要不重复充当本模块的设备映射。

S11 与 F28/F25 固定对象版本或映射根以支持一致快照，再由 COW 保护旧引用。对 canonical 正文不自动获得物理页共享。共享粒度与一致快照发布仍需 S11 冻结；S6 普通范围拆分、编码及 B 原子发布已按 §11 实现。

### 6.3 第二轮审查补充

A 业务页到普通对象的确定性公式必须包含相应数据空间和业务工作库身份，当前重建可能重用页号。B 的自身页面继续由 F05 基础区域直接定位，不进入本模块的普通对象映射，避免恢复循环依赖。普通逻辑范围的分配代次、内容版本和对象生命周期分别保护寻址；并非把一个 Raft term 或 page_id 当成全部版本。可计算的 page→object 关系不重复持久化，但持久映射、分配和引用变化仍原子提交。

### 6.4 B 混合表示的消费边界（2026-09-25）

按 [F08 §6.5](metadata-engine.md#65-本轮已确认的混合表示与复用边界2026-09-25)，单条映射可定长，一个对象的映射数量按需增长；不能因 B 的树采用固定描述项就限制整个映射集合大小。元数据存储布局归 F08，本模块定义映射语义、拆分/合并及事务变更；不把可计算关系重复持久化，不把对象正文塞入 B。

参考 [ext4 extent 格式](https://www.kernel.org/doc/html/latest/filesystems/ext4/ifork.html) 的定长单项与树增长，以及 [BlueStore 元数据类型](https://github.com/ceph/ceph/blob/main/src/os/bluestore/bluestore_types.h) 的可增长 extent/分片目录。本项目借鉴这种分工，不复制字段或全套 Ceph 属性。F08 已确认固定组合键“类别编号＋所属对象编号＋条目编号/逻辑偏移”、变长值；本模块沿用该入口，不另定义相冲突的第二套通用键格式。F13/S6 与 S11 实现状态均不因此改变。

### 11.1 身份与元数据编码

- 对象身份为持久数据空间号和空间内对象号；普通重启沿用空间号，工作库重建创建新空间。空间号由 B 中持久计数分配，与创建空间同批；删除对象保留墓碑，空间内对象号不复用。F26 的页分组 K 仍由后续确定，不新增重复的 page→object 表。
- B 固定组合键不变。全局格式/空间计数使用类别 13；高 8 bit 记录类型、低 56 bit 空间号形成对象类别，owner=对象号，item=逻辑起点或相应记录号。类型 1=空间控制（owner/item=0），2=对象描述（item=0），3=映射，4=物理分配记录，5=待处理旧范围。空间号从 1 起，耗尽拒绝，不循环；不占 F12 类别 12。
- v1 格式统一使用 ByteWriter/Reader 大端显式字段，不落 C++ struct，不在 B 已保护的值上重复加 WAL/CRC。全局格式魔数/版本/最新空间号；空间记录确认此空间存在。
- 描述保存模式（固定/变长）、存活状态、逻辑长度、内容版本、下一分配号、下一待处理号、待处理记录数。长度不等于物理容量或业务有效记录数。固定容器创建时确定长度，覆盖不改变；变长对象可以扩展/截断。版本每次成功变更递增，墓碑禁止重建同号对象。
- 每条映射的键保存逻辑起点，值保存长度、Data 相对物理起点、分配号。一对象可有多条映射；读位置 50 不创建键 50，而是寻找覆盖 50 的已有范围。不同分配身份不持久合并，仅在相同身份和连续范围下才有合并语义；本轮不做额外后台归并。
- 每次新预留的各物理 extent 各获对象内单调分配号，完整物理范围存于分配记录。裁剪后的映射仍保留原分配号；未映射的对齐尾部不能丢掉所有权。分配身份由空间/对象/分配号组成，不能只拿物理地址认旧释放请求。

v1 字段顺序全部为 u64 大端（仅 B 通用键仍为原三字段编码），用于固定恢复契约：

| 记录 | value 的字段顺序 |
| --- | --- |
| 全局 `{13,0,0}` | magic `0x4253544f424a4d50`、format=1、最新空间号 |
| 空间 | 空间号 |
| 描述 | 存活标志、模式（0 变长 / 1 固定）、逻辑长度、内容版本、下一分配号、下一待处理号、待处理记录数 |
| 映射 | 长度、Data 相对物理起点、分配号 |
| 分配 | v2：完整物理起点、完整分配长度、创建版本、初次有效长度；v1 兼容读取/写入前三项 |
| 剩余所有权（v2 类型 6） | item 为剩余物理起点，值为长度、分配号；随 F14 局部释放更新 |
| 待处理范围 | 移除版本、逻辑起点、长度、物理起点、分配号 |

### 11.2 正式路径与读取

- ObjectMappingStore 绑定已有 DataAllocator，通过私有生产绑定取得同一 B，不允许拼错两个设备；Create/Open 显式分开，Open 缺格式拒绝，不静默格式化。依赖寿命由 owner 保障，生命周期操作不与普通操作并发。
- 提供不可变 ObjectMappingSnapshot，内部保留同一 B snapshot、来源身份及预算；对象描述和映射查询不混读新旧视图。snapshot 仅保护元数据 RAM，不代替 F14 的设备内容 pin；F14 已提供独立的范围读取许可和实际回收入口，旧 snapshot 单独不足以保护 Data。
- 共享 B+Tree 增加 inclusive floor 查询；记录并利用下降路径上的左侧子树，处理删除后分隔键与真实首键不同的情况。不从对象开头扫描，不公开内部页。B.MetadataSnapshot 以 GetFloor 返回键和值。
- Resolve 返回有界逻辑片段（Data 或 Hole）及 next_offset，读取跨多段时用同一个 snapshot 继续。对象不存在报错；offset>=长度返回空；跨 EOF 裁到长度；对象内空洞补零。调用方负责真实 IO 对齐、组合及 F26 整页要求。

### 11.3 写入、截断与回收交接

- CreateObject 建立空洞对象，可显式选择固定长度。Replace 将一个非空逻辑范围与 F12 的新预留逐段对应，v2 最后一段只允许不足一个分配单位的对齐尾部；v1 保留原限制；调用方必须先完成初始化及所需 durable，再发布映射，取消时通过 F12 lease 保护真实 IO。本模块不接受裸物理范围冒充已分配空间。
- 局部替换只修改相交映射，保留两侧逻辑/物理对应关系。映射、完整新分配记录、对象描述与 F12 C 位图一次 Commit(base,reservation,related)；原 base 冲突不自动刷新/重试。
- Resize 缩小时裁掉 EOF 后的映射并保存退出的子范围；扩大时新范围为空洞。固定长度对象拒绝改变长度。Delete 移除当前映射并留下墓碑。所有操作先完整准备并检查预算，超限整体拒绝，不先发布长度再逐批删映射。
- 退出范围记录包含旧逻辑起点/长度、物理起点、分配号及移除它的对象版本，与映射切换同一 B 事务。F14 据此检查完整分配单位及读者/IO，将剩余所有权、退出切片和位图同批更新；F13 的 Replace/Resize/Remove 本身不调用 Release。原分配记录仍在，崩溃不会遗忘对齐尾部或部分仍用范围。
- 公共 snapshot 提供有界待处理记录读取，作为 F14 正式交接；没有“测试计数 getter”。不确定提交沿 B/F12 的原结果返回并停止其正式接纳，不把它转换成可安全重试的失败。

### 11.4 资源与测试

显式预算：每批读取片段数、每次修改涉及/产生的记录数、修改编码字节数、每对象待处理记录数、同时活跃操作数。超过预算明确 ResourceUnavailable；B 的页/批次/Journal 限制继续最终准入。快照持有的 B 页仍由现有 B live-page 预算限制，调用方返回的结果内存由调用方持有；不隐式增建队列/缓存。

每次写完测试执行主方案八项设计审查；仅最终模块源码/结果压缩归档，删除旧同模块包、展开测试/build/镜像/变异。C/P 的测试内容不改，不宣称裸设备/真实掉电/节点 E2E/性能已验。

### 11.5 开源参考的具体内化

- [ext4 NFS inode generation](https://github.com/torvalds/linux/blob/master/fs/ext4/super.c)：防旧句柄误认复用编号；本项目使用新空间号与对象号不复用，内容版本另计。
- [BlueStore onode](https://github.com/ceph/ceph/blob/main/src/os/bluestore/bluestore_types.h)：对象身份/长度与物理映射分开；内化为描述及多条映射，不复制属性全集。
- [ext4 extent](https://www.kernel.org/doc/html/latest/filesystems/ext4/ifork.html) 与 [Btrfs 文件范围](https://btrfs.readthedocs.io/en/latest/dev/dev-btrfs-design.html)：一条记录表示连续范围，局部覆盖保留两侧；本项目复用 B 树与 F12，不引入它们的树格式。
- [iomap](https://www.kernel.org/doc/html/latest/filesystems/iomap/design.html)：逻辑 offset/length/address 分离、空洞/未初始化不暴露旧内容；本轮只发布已初始化 Data，空洞由无映射表达，不增加持久预分配状态。
- [ext4 orphan](https://www.kernel.org/doc/html/latest/filesystems/ext4/orphan.html)：清理依据不能只在内存；内化为同批待处理记录。大删除跨事务续作仍未启用。
- [SeaStore transaction_manager](https://github.com/ceph/ceph/blob/main/src/crimson/os/seastore/transaction_manager.cc)：提交前核算资源；本项目显式有界准入，不引入其调度器或新服务。

上述来源已在本轮前讨论查阅，机制借鉴不新增第三方依赖或复制外部代码。

### 2026-10-04 S8 尾部回收规划

`ObjectMappingSnapshot::PlanTailTrim(object, maximum_bytes)` 是只读生产查询，给 Store 回收器返回下一步裁剪后的逻辑长度。复用 B 的 `GetFloor` 找最后一条映射；尾部为空洞时先裁空洞，否则停止在该映射起点或字节上限，空对象返回 0。每步最多涉及一条映射，不因小接收块形成大量映射而使单次删除超限。

调用方负责串行修改；本查询不持有物理引用、不释放空间、不改变磁盘格式。S8 先确认正文退役且没有整次使用许可，再提交现有 S7 Resize；最后 Remove 和清除归属同批提交。原正向 Resolve 会裁剪输出范围，不能直接提供尾部原始映射边界，故不通过从对象开头扫描来拼出这个答案。

该接口由真实 RaftObjectStorage::Collect 调用，删除阶段测试后仍需要；不是测试 getter。测试复用 S8 T8，检查小块接收、大 IO 上限、小元数据预算、部分回收重开，不另外建立逐字段查询测试。证据见 [S8 复审](../s8_execution_20261003.md#9-2026-10-04-复审按字节分步仍不能限制映射数量)。
