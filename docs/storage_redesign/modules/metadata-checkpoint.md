### 6.1 第二轮审查补充

暂停 B 新修改的准入后排空已接纳批次并确定边界；完成通知、错误处理、页写回和 checkpoint 自身保留进展资源，不能同时关闭其依赖通路。新周期的首改 FULL 判定须与 checkpoint 入口的有效发布同步；发布中断时仍能从旧入口及保留日志恢复已确认内容。

S10 建立元数据 checkpoint 不必无条件等待全部 Deferred 落位；需要保存可恢复的待落位描述/引用并保留相应正文。若实现选择等待部分任务，须证明其完成事务仍能进入提交路径，避免“暂停 B → 等写回完成 → 写回等 B 提交”的循环。

日志裁剪依赖整个有效恢复链及所有 PayloadRef，不因某一页写回过就丢掉 FULL。旧入口失效、日志可裁剪和新入口确认必须组成可证明的顺序。

### 6.2 S5 Journal 裁剪与复用

本模块给出“从哪个恢复入口开始，哪些 Journal 内容仍必需”的持久依据；F07 计算完整记录/批次及引用保留，F06 执行段复用。先发布新入口/裁剪依据，再关闭旧身份的新访问并排空，不能仅更新内存边界或 bitmap 就覆盖。

新的回收许可不能只写在即将删除的段中。发布失败时保留旧恢复链；旧段已复用后不得退回依赖该段的旧 checkpoint。对跨段批次及 FULL/PATCH 依赖，保留完整恢复所需范围，而非仅看某页已写回或最后片段位置。

基础 Journal 回收在 S5 闭环，不依赖 S7/F22 或 S12/F29 才能推进。S3 的空间准入需提前为本阶段建立预留，S5 与 F31 核对真实 checkpoint、控制发布和错误完成所需额度。S10 checkpoint 可保存待落位引用而不强等全部 Deferred，不能停掉这些任务完成记录的提交路径。
