## 6. 方案：本轮已执行协议及后续约束

以下区分当前已执行协议与未来裁剪、Deferred 等职责；本轮已冻结协议见 F10 §6.4。

### 6.1 第二轮审查补充

暂停 B 新修改的准入后排空已接纳批次并确定边界；完成通知、错误处理、页写回和 checkpoint 自身保留进展资源，不能同时关闭其依赖通路。新周期的首改 FULL 判定须与 checkpoint 入口的有效发布同步；发布中断时仍能从旧入口及保留日志恢复已确认内容。

S10 建立元数据 checkpoint 不必无条件等待全部 Deferred 落位；需要保存可恢复的待落位描述/引用并保留相应正文。若实现选择等待部分任务，须证明其完成事务仍能进入提交路径，避免“暂停 B → 等写回完成 → 写回等 B 提交”的循环。

日志裁剪依赖整个有效恢复链及所有 PayloadRef，不因某一页写回过就丢掉 FULL。旧入口失效、日志可裁剪和新入口确认必须组成可证明的顺序。

### 6.2 S5 Journal 裁剪与复用

本模块给出“从哪个恢复入口开始，哪些 Journal 内容仍必需”的持久依据；F07 计算完整记录/批次及引用保留，F06 执行段复用。先发布新入口/裁剪依据，再关闭旧身份的新访问并排空，不能仅更新内存边界或 bitmap 就覆盖。

新的回收许可不能只写在即将删除的段中。发布失败时保留旧恢复链；旧段已复用后不得退回依赖该段的旧 checkpoint。对跨段批次及 FULL/PATCH 依赖，保留完整恢复所需范围，而非仅看某页已写回或最后片段位置。

基础 Journal 回收在 S5 闭环，不依赖 S7/F22 或 S12/F29 才能推进。S3 的空间准入需提前为本阶段建立预留，S5 与 F31 核对真实 checkpoint、控制发布和错误完成所需额度。S10 checkpoint 可保存待落位引用而不强等全部 Deferred，不能停掉这些任务完成记录的提交路径。

### S4 已有基础与 S5 接续（2026-09-25）

S4 交付时从唯一 Journal 的创建批次 FULL 开始重放全部历史，当时尚无 checkpoint。S5 接续同一 B 页格式/分配根与 FULL/PATCH codec，建立持久恢复入口、周期首改 FULL 和可证明的裁剪边界；不能增加第二份 B WAL。旧读者页没有等价可恢复位置时不能淘汰。 参考 [F08 实际接口](metadata-engine.md#68-s4-实现细化与后续交接) 与 [测试风险交接](../f08_execution_20260925.md#8-最终测试矩阵与交接)。本轮后续实现以 §6.4 和执行记录为准。

### 6.3 F09 后的本轮范围与代码前推演（2026-09-26）

用户已授权上一轮提出的 F10/F11 checkpoint 恢复闭环及测试；本轮保留全部 Journal，不裁剪、不复用段，不扩大到 Deferred 或业务 A。先按主方案 §1.7 分析生产逻辑，确认协议后实现，再编写必要测试，不用回归测试代替原因分析，也不以隐藏重试或降级掩盖问题。

**本轮已确认采用直接入口（2026-09-26）：** F03 固定引导信息保存 B 的 checkpoint 引用，Journal 只保存一份 checkpoint 正文；撤回“本轮扫描定位、以后再加入口”的候选。本轮同时演进 F03/F07/F10/F11，保留全部旧日志，不裁剪或复用。A 的入口仍是未来普通对象层的稳定逻辑对象，A/B 的页空间、缓存、根与恢复状态独立；两份引导槽编号为 0/1，不称 Engine A/B。

与入口位置无关、已经完成的依赖分析：

1. checkpoint 排除新 B 修改、排空已接纳修改和写回，固定本轮提交边界；已取得的不可变读视图继续有效。页 IO、Journal 和完成通路保持工作，不关停依赖后再等待它们。
2. F09 对固定视图反复有界写回，只有实际写入及 Flush 成功才能发布入口；写回失败原样报告，不能宣称撤销此前已提交业务。
3. 新周期某页首次有效修改记录 FULL；可用该页已提交 LSN 与 checkpoint 覆盖的 B 提交边界判断，不为同义判断再持久化一套逐页计数器。后续 PATCH 仍严格验证基页代次和 LSN。入口发布成功后才切换周期；结果不明确则停止该 B 的新修改，重开恢复。
4. 最终页会继续被后续提交覆盖，不是永远不变的 checkpoint 副本。恢复时，未在 checkpoint 后修改的页从最终页区读取并校验；修改过的页从本周期首个 FULL 重建，再按顺序应用 PATCH。不能用可能损坏的 pageLSN 判断跳过，也不能只改变日志起点而沿用原来要求完整旧基页的 Replay。
5. 恢复结束前不暴露部分视图；根、页范围、空闲链、树/记录/溢出引用沿现有 Validate 校验。旧全历史恢复仍服务无 checkpoint 的已有设备，不能因新路径增加而误删有效兼容能力。
6. 当轮编码、发布、恢复和失败规则见 §6.4；未涉及的裁剪、Deferred、业务 A 接入保持后续范围。

### 6.4 当轮实现协议（已授权）

- F03 Create 仍生成原 v1；第一次发布 B checkpoint 时写 v2，保留原身份/区域布局。v2 有效头 144 字节：原 112 字节布局之后为发布代次 u64、Journal 相对 checkpoint 批次位置 u64、Journal 身份 16 字节；显式大端，余量为零，沿用槽尾一次 CRC32C 覆盖整条引导记录。不是逐字段重复算 CRC，也不在普通页 IO 时反复扫描设备头。v1 为无 checkpoint、代次 0；新程序支持 v1/v2 并存过渡，未知格式拒绝。
- F03 由 B 专用入口访问/发布引用，普通 A 调用者不能修改设备恢复入口。两份身份/区域须一致，同代次不同内容拒绝，不同代次选择新候选；候选目标仍由 F07/B 验证，损坏不静默回退。先向非当前源槽写新代次并 Flush，一份成功即发布；另一份落后由显式后台修复补齐。发布与修复实际 IO 串行，修复每次使用当前源；已发 IO 排空，不能只丢回调。成功发布后的修复可以再次发起，不新增 worker 池。
- B checkpoint 使用既有 B 48 字节批次头、kind=2、count=0，包含原格式/页大小/键宽/页与值限制、覆盖的 B 提交 LSN、页高水位；外层身份、位置、批次完整性由唯一 F07 保护。根仍是 B 的页 0；checkpoint 正文不再保存页面内容。引用位置指向这条完整批次，不另存一份完整数据库。
- B 的正式 Checkpoint(max_pages) 暂停新修改，排空已接纳提交与写回，释放短准入/发布锁后通过 F09 有界写回至 Clean；不可变读视图继续有效。页写失败返回未发布且保留原错误；Journal 接纳失败不发布；接纳后的 Journal 故障隔离 B；引导发布提交阶段失败返回结果不确定并隔离 B，重开确认。新周期边界只在入口发布成功后生效，无隐式重试。
- F07 保持原 Open 全历史兼容；新增从可信批次位置打开的生产入口，第一遍验证必要后缀并仅收集恢复计划，第二遍恢复。跳过旧前缀，仍验证控制身份、起点批次、后续链和尾部。首次起点的前驱可在保留前缀中，后续链必须连续；不增加第二套片段解析器。
- 第一遍计划记录 checkpoint 后哪些页被修改；第二遍未修改页经 F05 读取/校验，已修改页不依赖磁盘旧内容，从首个 FULL 恢复，再使用原 PATCH 基版本检查。新周期首改判断由 pageLSN 与持久 checkpoint 覆盖边界比较。恢复全程不发布局部视图，最终复用 Validate。无 checkpoint 的 v1 设备仍从完整历史恢复；日志里未被引导入口选中的 checkpoint 只是记录，不擅自升级恢复权威。
- 本轮不会因旧日志保留就隐式回退掩盖已选 checkpoint/必要页损坏；CRC 不能证明任意篡改或设备掉电原子性。直接入口也不等于整个 Journal 不再扫描，后缀空白和完整性检查仍有成本。

先完成实现及正常/并发/失败/关闭逻辑审查，再编写第 7 节测试。复用现有 codec/树/页后端/IO/Journal，新增接口只服务正式恢复和维护，不为测试暴露内部状态。

## 7. 测试方案与验收（本轮已授权）

沿用用户已经确认的四类风险；先完成生产逻辑推演和实现审查，再编写测试：

| 场景 | 输入与生产路径 | 独立 Oracle / 新风险 |
| --- | --- | --- |
| 非空 checkpoint 后继续修改并重开 | 固定生成的组合键、小值/溢出值，经 B Commit→Checkpoint→继续 Commit→重建生产栈 Open | 输入维护的独立键值模型；确认实际读取最终页，不能仅以旧全日志恢复成功证明新路径 |
| 写回、入口发布失败及并发准入 | 在真实 IO 链路上暂停或注入失败；保留已有读取视图，尝试新修改及关闭 | 已确认数据不丢失、不伪报 checkpoint 成功；按 §6.4 的拒绝/未发布/结果不明确边界核对；不把有响应视作 durable |
| 首改 FULL 与页面损坏恢复 | checkpoint 后修改同一页多次；人为破坏可由保留 FULL 重建的页，以及没有本周期 FULL 的必要页 | 重建后的完整业务集合等于输入；不足以恢复时明确失败；独立核对首改 FULL、后续增量的输入条件，不复测 F07 全套格式 |
| 多轮 checkpoint 和页槽复用 | 非空增删改、长短值转换，跨多轮发布再重开 | 最终集合、旧读取视图与真实复用身份对应；不能把任意一页换代当作目标槽已复用 |
