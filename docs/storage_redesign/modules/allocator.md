## 6. 讨论后的方案与待冻结边界

本节保留职责划分；当轮具体接口/格式/预算由 §11 确定，验收见 §10。后续扩展不能自动成为本轮实现要求。

### 6.1 三种空间视图

F12 管普通对象的设备分配事实；B/提交协议持久化相关权威，分层 bitmap 高层摘要尽量重建。[F36](table-space-management.md) 维护的是 A 页内可用字节摘要，不能拿该摘要直接释放设备范围；MetadataBackend 管独立元数据区域。

单个物理 extent 描述连续设备范围；同一逻辑对象可映射到多段不相邻 extent。优先连续分配和预分配可以改善顺序访问，找不到时仍允许多段映射。对象打包数不保证物理连续，也不保证减少要访问的逻辑页。

### 6.2 释放前提

仅接受满足 F22/F14 引用与 IO 安全条件的释放。对象内某页无用不代表整个对象/extent 无用；最小分配单位更大或还有共享引用时，逻辑释放和物理可复用分别记账。具体子范围拆分、最小单位、代次和坏块隔离在当轮格式/接口中冻结。

### 6.3 与翻译内存 hole punching 的协作

可参考 L0 事实、L1/L2 搜索摘要的组织：F26 的候选 bitmap 找到可能冷的翻译组，再检查驻留、加载/发布预留、访问者及回收代次，最终由 F26 归还 OS 物理内存页。候选位不是可直接释放的证明；仍有一个有效条目的页也不能按 8 字节局部归还。

F12 设备 bitmap、F36 页内剩余空间摘要、F26 RAM 回收状态各自维护，不能共享一张权威表、坏块语义、Journal 或释放接口。RAM hole punching 不删除对象、不释放 extent，也不让页号自动可复用。

若存在两个真实消费者，可抽取不带资源权威的分层查找/位操作；具体同步、精确判据和持久化留在所有者。不能为追求复用提前建无消费者的通用 allocator。F12 仍在 S6 实施，F26 在 S9 使用此机制；不倒置依赖。

### 6.4 与 Journal 延迟覆盖的边界

F12 管普通数据 extent；固定 Journal 槽位及其复用身份归 F06，元数据页归 F05，RAM 翻译组归 F26。可以复用 bitmap 搜索工具，不能共用一张资源权威表。只有待回收条件全部满足才标成可分配；已逻辑删除但仍被引用的范围不能提前置空闲位。

普通数据空间可按最小分配单位切分并保留剩余空闲范围；Journal 剩余空间供该段后续追加，其整段复用不要求 F12 提供任意段内打洞。可复用旧字节通常无需预先清零，但新分配对象的有效长度/未写范围必须遵守 F13/F15 的读取契约，不能暴露上一任内容。

候选摘要可重建，分配/释放权威仍需随正式事务持久化。若后来增加异步 discard/清零，要把它们纳入在途范围保护，避免清理已被再次分配的新数据。

### 11.1 范围与逻辑先审

实现 DataAllocator：Data 区空间查找、预留、随 B 单批提交的分配/释放、明确隔离、恢复及关闭；不另建 WAL。F13 映射与 F14 S6 范围保护/回收已在后续接续；F22 自动调度和 NodeStorage 普通对象接入仍待实施。本轮释放接口要求调用者已阻止新引用并排空读者/IO，不能以 F12 已实现宣称自动 GC。

先检查：预留不能重叠；同块位图的修改不能互相覆盖；durable 前不能发布内存分配/释放；结果不确定后不能继续分配；放弃预留但 IO 仍持有许可时不能复用；提交后更新内存不能再分配可能失败的内存；关闭不持 bitmap 锁等待 IO。逻辑审查完成后才编写测试。

构造时仅接受一个 MetadataEngine B，通过新增的私有、仅供分配器使用的 Data 区描述取得真实长度和对齐，不提供给测试的 public getter，也不允许任意设备/元数据引擎拼装。一个 B 的分配命名空间由一个 live allocator 独占，像 B/Journal 本身一样由 owner 串行 Create/Open/Close。B 和 IO 依赖必须活得更久；F34 后续接入同一 owner，不额外复制引擎。

### 11.2 数据结构、格式和预算

- 显式 options：allocation_bytes、bitmap_record_bytes、max_bitmap_bytes、max_request_bytes、max_extents、max_reservations、max_search_nodes。没有统一 4 KiB 默认。allocation_bytes 为实际偏移对齐的倍数；Data 尾部不足一个单位的部分不参与分配。
- L0 以 64 位字组织；C 为已提交占用，R 为运行期预留，Q 为明确隔离。搜索使用 C|R|Q。三个 RAM 位图和摘要大小在分配前核算；票据数量、每请求 extent 数及查找工作量各有界。
- 每层 64 路，2 bit 摘要 00=无可用、01=部分可用、10=全可用，11 不使用。逐层打包，L1 及以上不持久化；摘要表示有效单位，最后不足 64 个的组不会越界。只更新变化路径。
- 优先找连续范围；搜索在连续地址次序遍历摘要，全空节点可以直接贡献一段；跨组连续范围可合并。未找到完整连续范围时按先遇到的空闲段有界拆分。受 extent/查找预算限制而未满足不能谎报设备物理空间耗尽。申请整体成功或撤销本次准备。
- 本轮 B 键类别保留为 12：owner=0,item=0 为格式描述；owner=1 为 C 位图分片；owner=2 为 Q 分片，item 为分片号。其他模块不得绕开 allocator 写此类别。同行附带元数据不得使用该类别。
- 描述 v1 保存版本、实际 Data 长度、分配单位和位图记录字节数；整数使用现有 ByteWriter/Reader 的大端编码。位图字按单位从低 bit 到高 bit，64 位字以大端编码。record_bytes 必须是 8 的倍数。B 已保护页/日志完整性，不重复为每个值增加 CRC。
- 描述存在时，缺失的位图片段明确表示全零；Create 只在该类别为空时提交描述，Open 缺描述拒绝。非零分片固定 record_bytes 长度；范围外尾部位必须为零。Open 扫描同一 B 快照重建 C/Q/摘要，不自动格式化、迁移或更改粒度。

### 11.3 正式接口与提交

DataReservation 为 move-only 预留，返回 Data 区相对范围列表；Lease 保持预留寿命，可随真实 IO 交给调用方保存。丢弃主预留时，最后一个 lease 退出前仍不清 R。它只保护本次未提交预留，不代替 F14 的已发布对象引用；实际 IO 仍走 F04/F02/F01。

Commit(base, reservation, related_mutations) 将位图变化和调用方提供的相关元数据一次交给 B.Commit。Release(base, ranges, related_mutations) 在调用方满足引用/IO 安全条件后以同样方式提交清位。SetQuarantine(base,ranges,isolated) 保存独立 Q；隔离操作不与临时预留重叠，不因一次 IO 错误自动永久标坏，不负责修复数据。所有范围必须是分配单位的完整倍数。

同一 allocator 的提交角色串行，bitmap 短锁外调用 B。Reserve/lease 析构不等 Journal；准备位图值基于调用方同一 B base，更新范围外的位原样保留。B 拒绝旧 base 时不重试、不吞 Conflict，预留保持可由调用者重新验证或放弃。related_mutations 不能通过第二次提交实现“看似原子”。

B 返回 Durable 后一次更新 C/Q、R 与摘要；所需 buffers/range 列表在提交前准备好。明确的 pre-IO 拒绝保持原状态。任何已接纳提交失败隔离 allocator，与现有 B 一致；不确定的 reservation 不再转回可用，重新打开由 B 恢复决定。运行期 R 不持久化，旧实例的临时预留不会导入新实例；owner 重新打开前必须先排空旧 Data IO。旧 lease 最终退出仅修改旧 RAM 上下文，不能凭它允许旧 IO 跨重新打开继续运行。

Close 先拒绝新调用，再等本 allocator 已进入的元数据提交结束；不负责关闭外部 B/F02/F01，也不把“lease 已销毁”当 IO 已完成。owner 仍须在设备关闭前结束实际 IO。释放带旧 B 快照必须被拒绝；所有权/分配代次的最终验证由 F13/F14 与同一快照原子变更提供，本轮不伪造完整引用层。
