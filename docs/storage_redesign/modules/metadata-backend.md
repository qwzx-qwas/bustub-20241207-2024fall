## 4. 开源参考与本项目落点

- [PostgreSQL 页布局](https://www.postgresql.org/docs/current/storage-page-layout.html)：用固定大小页面组织存储，便于按页号定位。本项目借鉴固定页槽寻址，落到 `MetadataBackend::Resolve`；使用 BusTub 的 `BUSTUB_PAGE_SIZE`（当前 4096），不照搬 PostgreSQL 默认 8 KiB、页头或页格式。
- [PostgreSQL WAL](https://www.postgresql.org/docs/current/wal-intro.html)：先持久化恢复日志，再允许受保护的数据页落盘，解决崩溃后恢复顺序问题。本项目将此顺序交给未来 F07/F08/F09；F05 仅执行获准的 IO，不自行实现日志、提交或恢复。S2 不宣称已经具备此项保障。

项目代码的直接复制、依赖引入、版本或许可处理若在后续需要，应在讨论后的方案中明确；这里记录的是机制参考。

## 6. 方案约束与待冻结内容

### 6.1 与 S9 数组 BufferPool 的兼容交接

[F26 数组子方案](array-buffer-pool.md) 允许 A/B 复用缓存代码，但不统一它们的页寻址后端。B 元数据页继续依据引导信息和区域描述转换为基础对象范围，经 F02 执行；不能依赖 B 内的普通对象映射查找自身页面。元数据页写回继续服从 F07/F09 的 WAL 与提交条件。

S9 的外部帧许可只改变缓冲的传递方式，不改变本模块的区域归属、定位与恢复权威，也不新增一套设备执行器。本模块 S2/S4 基础能力仍先行；S9 只核对既有契约兼容，S2 页槽和 IO 接口按 §6.2 冻结，页分配协议仍未冻结。该项是本项目既有引导约束对共享缓存改造的延续，不是新借用的外部算法。

### 6.2 已批准的 S2 页寻址方案

**定位与容量。** `P = BUSTUB_PAGE_SIZE`。仅接受非负 `page_id_t`，页号小于 `min(Metadata区长度 / P, page_id_t最大值 + 1)`；检查后才计算区内 `page_id × P`。不足整页的尾部不可寻址，页 0 在本层没有特殊含义。物理起点由 F04 添加，F05 不接收任意设备地址、布局或第二个执行器。

**实际对齐。** F04 新增只读 `Describe(handle)`，返回该区域长度及绑定设备实时查询的内存/偏移长度对齐，验证 handle 归属且不暴露区域物理起点。F05 构造时检查区域至少容纳一页、P 能满足设备偏移/长度对齐。例如设备要求 8 KiB，4 KiB 页面明确拒绝，不偷偷补齐、RMW 或改走 Buffered。内存对齐和外部许可仍由 F02 验证。查询是 F05 的正式依赖，F06 可复用，不是测试 getter。

**接口。** `MetadataPageRequest{page_id, operation}`；`MetadataBackend(RegionManager&)`；`PageCapacity()`；`TryPrepare(requests, flush_after_writes)` 和 `TryPrepareExternal(requests, leases, flush_after_writes)`。完整解析所有页号后才交给 F04/F02，返回原有 IOPreparation/IOBatch，调用者经原执行器提交、等待、检查结果。没有新队列、缓存、线程或 Submit/Wait/Flush 转发层。

**并发与寿命。** 无可变寻址状态，可并发准备独立页面；跨批重叠修改由调用者/F09 排序。RegionManager 和原执行器/设备须活过本后端调用，已接受 IO 按 F02 原规则排空。保留 Accepted/Full/Stopped、异常、不消耗被拒绝的外部许可等语义。只有所有写入和请求的 Flush 成功才能报告 writes_durable；失败不是回滚，超时不是取消。

**恢复边界。** 仅处理原始整页字节，不解析或伪造页头、LSN、校验值，不把打开此后端称为打开完整 MetadataEngine B。F08/S4 必须在持久化格式中记录/核对页大小及格式版本，不得用变化后的编译常量重新解释旧库。未来 F08 私有修改 → F07 恢复记录 durable → F09 选择可写回版本 → F05 IO。不得在 S2 提前增加只有内存状态的 AllocatePage/FreePage。

**S4/S5 交接。** Metadata 区内分配事实归 F05/F08 的恢复协议，不能复用依赖普通对象映射的 F12 分配入口。分配、新页、父页、根变化须由同一事务恢复；预留/释放/代次复用/空闲记录在 S4 讨论，checkpoint 和恢复入口由 F09/F10 等在 S5 完善。本次保留既有业务 DiskManager/BufferPool 路径。

修改范围：新增 `metadata_backend.h/.cpp`、Linux storage CMake 注册；F04 增加 Describe 并复用归属检查；文档、阶段归档与结果记录。F01/F02/F03 无功能修改。

## 7. 本轮测试方案与验收

只新增两个组件集成场景，不新增常驻 CMake 测试目标：

1. **PageSlotsPreserveOtherRegionsAndReopen**：真实 F03→F04→F05→F02→F01 Direct 文件，首/非连续/末页写入不同非零内容，自有与外部缓冲，显式持久化后关闭重开。独立 pread 检查整个文件，预期位置由测试布局确定，不能调用被测寻址算法生成 oracle；验证其他区域、间隙、未使用页及不满页尾部不变。
2. **InvalidPagesAndGeometryRejectBeforeIO**：负数、首个非法页号、极大页号、整个批次拒绝、外部许可不被消耗；合法后续批次仍可准备。F04 Describe 拒绝其他 manager 的 handle。容量不足和不兼容设备几何明确拒绝。后者仅在测试链接侧加强 statx 返回的对齐要求，明确不是真实 8 KiB 设备验证。

复用 F04 原压缩包中的 3 项测试作受影响回归，不复制其测试矩阵。对页偏移/容量、对齐、绑定、持久化传递做少量隔离变异；不以编译失败或检测器崩溃算作抓住 bug。使用 ASan/UBSan、严格 XML 用例核对、运行超时，执行主方案八项审查。

风险归属 `F05/page-address、page-capacity、page-io-adaptation`，维护者 F05，F08/F09/F26 引用；真正 B 页面事务、业务 C/P 接入、裸设备与掉电仍待后续。阶段测试/runner 仅按 F05 压缩归档，结果另包；清除展开源码、镜像、编译产物与错误旧包。保留共同 C/P 测试内容及原基线，不把此轮结果当作 E2E 或性能结论。
