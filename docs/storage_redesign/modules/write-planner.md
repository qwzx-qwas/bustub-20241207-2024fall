### 6.1 第二轮审查补充

读取保留字节并组装与 COW 选位置可在 Common 内组合；原地 RMW 另需完整保护协议。一个逻辑原子请求可混合 Common/Deferred，但共同提交必须等所有 Common durable 依赖和 Deferred 恢复内容就绪。

选择 Deferred 的安全门槛先于尺寸/性能阈值：原地写若可能撕裂整个物理单元，日志/其他保留内容须能重建其全部有效字节；只记录修改片段不够。无法证明时选 COW 或拒绝不支持的方式，不能因为“有 redo”默认安全。实际保护单元、设备能力、可恢复正文范围、阈值和预算仍待冻结；这是本项目恢复约束，不声称 Ceph 的所有模式均如此实现。

## 2026-10-02 范围回收与对象尾部接续

本轮追加采用 COW，由 FS 为新正文申请空间；不足 u 的余量仍归其原分配，不上报全局空闲。后续启用原分配复用时，只检查本对象当前尾部候选；足够且安全时内部使用原分配，余量不足或不适合时为本次追加申请新空间，不默认拼接旧尾+新 extent、不扫描其他对象/历史碎片。已有分配的余量不再次进入 F12.Reserve；新分配按 u 取整。复用必须检查实际处理范围、旧内容/共享引用、对齐及完整恢复保障。F01 当前只有 IO 对齐信息，未满足这一安全前提；F13 的原分配映射扩展及 F17/F14 写入范围保护因此留待接续，不能绕过当前 Replace 的新预留约束。

未来接入原分配尾部复用时，新增映射与该分配的初始化边界必须同一事务推进，使 F14 不再把已发布的新增字节当作从未使用的尾部。S6 的“退出字节不可重新挂回”仍有效；若要复用曾退出的旧内容范围，先扩展这条持久协议，不能只改内存余量或继续沿用旧退出记录。

## 2026-10-04 S9.1a 稳定页来源交接

F26 的常规页写回沿本模块现有 Common 规划，设计见 [S9.1a §6/§12](../s9_buffer_pool_protocol.md#6-真正把帧接到对象-io)。当前 ObjectMutation 仍为自有 vector，外部帧尚未接入；c 需要将稳定只读来源贯穿准入、排序、空间规划和数据 IO。可直传片段使用帧，需对齐/合并/读旧字节时显式安排有界工作缓冲，不在 F02 隐式回退，也不绕过 COW/提交保护。

每事务每对象一次 mutation 的原约束保持。首轮每个对象选择一页与其他对象的页组成有界批次，同对象余页按现有排序继续递交；不能机械追加同对象多次 mutation，或跨过未修改页拼成大范围后覆盖其中内容。相邻页的多来源合并未在本轮实现，不承诺同对象多页一次 Common 提交。沿用原范围规划保护对齐边缘，不能从“合批”推导出扩大逻辑修改范围或多页业务原子性。

本轮无生产改动；将来有实际消费者时才增加输入表示，不预建只用于测试的借帧 API。
