# F10/F11 checkpoint 恢复执行与测试审查（2026-09-26）

基准 `c948797`，执行范围为 [F10 §6.4](modules/metadata-checkpoint.md#64-当轮实现协议已授权)。本轮同时接续 F03/F07/F08/F09，普通 Journal 仍单份；不裁剪、不复用段、不实现 Deferred 或业务 A 接入。状态：本轮 B checkpoint 发布/恢复已完成，测试与静态审查完成；整个 S5 仍未完成。

## 1. 编写测试之前的生产逻辑审查

- 固定引导位置保存 B 的引用；A 的逻辑恢复对象与 B 的物理引导分离。F03 Create 保持 v1，首次发布写 v2；静态身份/区域冲突仍拒绝，代次差异正常，同代次矛盾拒绝。只写非当前源槽，Flush 成功后以 move 接管已预先编码的缓冲，不在 durable 后复制分配。
- F03 publication/repair 同一个 update mutex 串行实际槽 IO；不会只忽略旧回调。修复尝试之间释放锁，重试使用当前源；不能以外部出现的新权威覆盖成旧缓存。发布结果不明确后不允许继续修复/发布或以同一 Bootstrap 实例重开 B，必须重新读盘确定入口。Close 先停止/排空修复，再等待发布。
- B checkpoint 使用 writer→writeback→短 view 顺序排空既有工作；设置修改准入门后释放 writer。后续 Commit 在正式入口拒绝，Read 只短持 view，现有快照可读。Checkpoint 不等待需要 writer 才能完成的工作；Close 等待 writeback 排空，形成一致锁序。
- 先 F09 页持久化，再唯一 Journal 的 checkpoint 批次持久化，最后 F03 引用持久化；引导目标未验证时不开放 B。失败不解除以前提交的 durable 承诺，不隐式重试或截尾。
- 新周期首改由旧 pageLSN<=checkpoint 覆盖边界决定；不另建同义逐页持久计数器。未变化的页面不产生伪修改；后续 PATCH 仍检查准确基版本。
- 恢复第一遍只建立有界的修改页位图，仍由 F07 校验完整后缀。第二遍未修改页从 F05 读出校验，修改页以首个 FULL 重建，不信任被覆盖页的 LSN；整个恢复视图在完成并 Validate 之前不可访问。未发布的其他 checkpoint 记录不能越权成为入口。
- 原无 checkpoint 设备仍走全历史恢复；新路径复用同一个 B header/页 codec/PATCH/Validate 和同一个 F07 Scan。必要前缀只在入口明确时跳过，尾部仍检查；不是常数时间恢复，也不是已经有空间回收。

上述逻辑审查先于新测试编写。生产库随后编译通过，再为本轮新增风险编写临时集成测试。以下记录 Oracle、变异、接口污染与局限。

## 3. 逐项：目标 → 输入 → 执行 → Oracle → 失败含义

### 3.1 DirectRootAndRepeatedCheckpoints

- **目标/输入：** 350 条确定性组合键与长短混合值，保留旧读视图；checkpoint 后删除、重新填充 390 条，再 checkpoint、修改长值及删除，涉及树、记录与溢出页。
- **路径：** 真实 B Create/Commit/Checkpoint → F09/F05 和 F07 → F04/F02/F01 Direct 文件 IO；关闭整套对象后重新 Open，再次提交和 checkpoint。
- **Oracle：** expected 由输入独立维护的 `std::map` 得出；独立读取、解析最终 Metadata 区；引导头按公开格式手工读字段并独立计算 CRC。破坏不再需要的旧 checkpoint，验证最新直接入口确实生效，不只验证生产自身 Encode→Decode。
- **失败含义：** 集合、旧视图或代次不符分别指向恢复/发布/版本隔离；旧前缀破坏后失败说明仍依赖错误起点。第二次复审（§11）补充跟踪首轮实际溢出页的页号：第二轮同一槽代次必须增加且仍为存活页，再验证旧视图和重开集合。该断言确认跨 checkpoint 用例确实具备页槽复用前提；在途旧写回覆盖新页的风险仍由原 F09 保护。

### 3.2 FullThenPatchRepairsChangedPages

- **目标/输入：** 250 条混合值；checkpoint 后两次修改同一值中的一个字节，保持长度，足以进入小增量路径。
- **路径：** 正式 Commit/Writeback；关闭 B 后通过正式 F07 只读解释恢复记录，再破坏修改过的一个物理页，重新 Open。随后破坏一个没有后续修改、必须从 checkpoint 读取的页。
- **Oracle：** 记录类型从 F07 交付的原始字节独立检查：第一次 FULL，后续出现 PATCH；不调用 B 编解码器判断自己。恢复内容仍与输入模型比较；可恢复页损坏应恢复，必要页损坏须 `MetadataError`。第二个拒绝与第一个成功构成成对证据。
- **失败含义：** 能区分首改策略错误、FULL/PATCH 基础错误、必要页完整性被忽略。F07 外层解析本身仍由其原八项回归负责，本测试不是新的完整 Journal 格式套件。

### 3.3 FailuresDoNotPublishOrHideCommit

- **目标/输入：** 四个独立非空设备场景，基线 checkpoint 后已提交长值更新；分别注入页写 EIO、checkpoint Journal Flush EIO、引导写 EIO、引导 Flush EIO。
- **路径：** 只在测试链接侧暂停/失败一次真实系统调用；其他 IO 真实执行。检查结果和现有快照，随后销毁全部生产对象、重新打开并再次 checkpoint。
- **Oracle：** 页写或 Journal 失败为 NotPublished；引导发布错误为 Indeterminate。页写失败允许显式重试，已接纳 Journal 或入口失败使 B 停止接纳。原错误必须为 EIO，旧已提交集合保持。入口 Flush 报错时即使读到新代次，也不能据此当成功；只在新的引导/B 上下文恢复后继续。
- **失败含义：** 区分失败被吞掉、错误完成边界和错误后继续服务；恢复集合不符说明破坏已有 durable 承诺。注入失败不模拟设备断电，不能推导真实介质掉电行为。

### 3.4 CheckpointGateAndCloseDrain

- **目标/输入：** 80 条记录；在实际入口 Flush 处设置测试握手，既有视图有效，尝试新提交和 Close。
- **Oracle：** Flush 未完成时 Checkpoint future 未完成，新 Commit 明确 `ResourceUnavailable`，读集合不变，Close 未结束；放行后 Checkpoint Durable，Close 返回，重开集合相同。与普通事务的 F08 发布等待、F09 写回关闭不同，这里保护的是 checkpoint 准入及引导发布阶段。
- **失败含义/限制：** 指向错误门禁、过早完成或不排空关闭。Close 的 100ms 观察在极端调度下不能数学证明线程已走到内部等待点；只保证开始调用、真实 IO 握手以及对应最小变异实测，不能宣称穷尽所有线程交错。

### 3.5 RepairCannotOverwriteNewRoot

- **目标/输入：** 非空 checkpoint 后暂停旧修复的实际引导写；前台再 Commit，新 checkpoint 已达到 Journal 写入握手，再放行修复。随后显式发起第二次修复。
- **Oracle：** 前台提交能推进，第二代入口发布成功；修复最终报告完成且两槽独立读取完全一致；重开全部内容等于输入模型。等待的是已发生的 IO/状态事实，不靠任意 sleep 猜测工作已开始。
- **失败含义：** 陈旧修复源、完成状态复用或后续修复调度错误。该例验证一个有意义的交错，并结合 update mutex 代码审查；不是所有可能交错的并发证明。

### 3.6 DamagedRootAndDamagedTargetDiffer

- **目标/输入：** 两轮含非空修改的 checkpoint；分别破坏最新引导 CRC 覆盖的引用字段、破坏最新有效引用所指 Journal 批次。
- **Oracle：** 第一种忽略无效副本，旧有效入口加完整后缀必须恢复全部已提交数据；第二种引导有效但必要目标损坏，必须 `JournalError`，不能试更老入口假装成功。
- **失败含义：** 选源和恢复权威边界混淆。不同于 3.1 的“不读取无关前缀”，本例检查“必要内容不得忽略”。旧入口恢复成立依赖本轮保留全部日志；未来裁剪/复用必须交接这一前提，不能直接沿用结论。

## 6. 发现错误的能力

变异只写到临时目录、独立编译对象后链接，生产文件未改坏。要求编译/链接成功、测试退出 1，并且 XML 中出现指定 oracle。超时、链接失败或 Sanitizer 崩溃不算检出。

| 最小错误 | 指定场景 / 判断依据 |
| --- | --- |
| 去掉 Publish 与 Repair 的更新互斥（§10 新增） | 3.5 旧修复写仍暂停时新发布不得完成 |
| 去掉 checkpoint 周期首改 FULL 条件 | 3.2 首改记录必须 FULL |
| OpenFrom 改成从创建位置扫描 | 3.1 起点不是引用的 checkpoint，恢复失败 |
| 允许 checkpoint 中继续 Commit | 3.4 新修改应被门禁拒绝 |
| Close 不等待写回/checkpoint 互斥 | 3.4 Close 提前返回 |
| 忽略页写失败继续发布 | 3.3 结果/入口代次错误 |
| 引导发布异常后仍保持 B ready | 3.3 Read 未按故障状态拒绝 |
| 只在首次发布更新修复源 | 3.5 后续修复使用陈旧源失败 |
| 跳过必要 checkpoint 页 CRC | 3.2 损坏必要页未被拒绝 |

变异脚本审查中两项诊断已修正：错误扫描起点首先触发 B 的“缺少引用 checkpoint”检查，不能误要求它一定先遇到 CRC；修复源变异仅破坏后续发布，否则会在首次修复设置握手前失败。最终证据不把这两次非预定失败计为成功。F07 回归首次链接因测试 runner 共享列表误附 F03 参数而失败，已改为独立列表，生产未因此修改。

## 7. 稳定性、资源与证据边界

- 输入为固定生成规则，无随机 seed 漂移；各场景独立 mkstemp 设备文件，析构删除。无 GPU/网络依赖，基线和变异顺序执行，不争抢性能测量资源。
- 48 MiB 普通文件，F01 默认 Direct；设备对齐由真实 Info 获取，测试的页/日志格式尺寸不是宣称所有设备对齐固定。环境不支持该 IO/预算时明确失败，不自动换 buffered 路径。
- 全局故障门受 mutex/condition_variable 或 atomic 保护，每次 Arm 重置；只供单进程顺序测试使用，不支持把同一测试二进制内部用例并发化。Futures 先于 ReleaseOnExit 创建，失败退出先放行已接纳 IO，再销毁 future/生产对象。
- 10s 握手/修复看门狗用于限制挂起，不作为性能指标。修复状态用正式 Status 观察并 yield；Close 的有限调度观察限制见 3.4。未做 TSAN 或穷尽式并发模型检查。
- F09 输入/磁盘 oracle 来自被 SHA-256 固定的有效归档。独立解析有重复理解格式的共同失误风险，所以同时保留输入集合与定向变异；不能以同一生产 codec 自证正确。
- 没有进程在任意指令处突然断电、真实块设备或多机电源故障证据。新路径仍保留全部 Journal、扫描必要后缀及空尾，B 当前仍驻留全部页；不据此声称空间已回收、恢复时间达到性能目标或缓存淘汰已完成。
