# S11/F25 压缩与异步正文任务：实施与测试设计审查

基线 `c20bd98`，2026-10-07。协议与 prompt：[共同方案](s11_snapshot_compression.md)。本轮只接续 F25 与 F35 的快照正文任务；不改 Journal、对象落盘格式或 Raft 提交权威。最终验证及归档见文末。

## 1. 实际改动及先行逻辑审查

| 位置 | 改动及原因 |
| --- | --- |
| `raft_types.h`、`rpc_codec.cpp` | 新扩展 Offer/Response、压缩 DATA 类型；旧消息编码保持原样。可无基础协商压缩；raw_size 表示原始长度；先限制 Blob 再分配其正文，不在编解码器重复压缩。 |
| `snapshot_tasks.{h,cpp}` | 内部两 worker、四个排队/执行任务上限。接纳时创建完成 future；不另建会丢事件的完成队列。锁外运行读取/压缩/解压，异常随任务返回。析构排空。 |
| `raft_node.cpp` | Offer 能力确认；未知新类型超时退回 legacy Offer/Raw。发送固定输入、任期/请求身份的任务；Tick/Receive 消费完成，缓存编码块以重传。接收解压完成后再次检查身份，继续原有 Stage/Prepare/Publish/Install。 |
| 同上 | 慢正文任务不阻断心跳；匹配的心跳/重复 Offer 延续现有 delta 会话。高任期退出旧会话；已取消任务自行保留输入至实际 IO 结束。 |
| `third_party/lz4`、CMake | 官方 v1.10.0 原样源码/许可证及链接，避免依赖本机偶然安装的运行时库或手写 ABI。 |

审查先检查四条依赖：①能力确认后才能发新编码；②字节数/ACK 以解压长度计算；③任务只访问不可变输入，不碰可变 Store/Raft 状态；④输出只能回到仍有效的传输，完成旧任务不提前释放输入。之后才写补充测试。

发现并解决：异步待生成块会使原 SendSnapshot 暂无消息，需继续心跳；重复扩展 Offer 在无共同基础时也必须幂等；心跳续期要同时维护已接纳的 delta 会话；接收编码长度上限要在复制 Blob 前检查。

仍有同步部分：OfferDelta 头部探测/差异目录规划、接收 Stage 的数据持久化、Prepare/安装数据库。socket connect/read/write 原已在节点锁外，本轮不声称新实现了这点，也不声称全部快照操作无阻塞。

## 2. 测试全景与目标 → 输入 → 路径 → Oracle → 失败含义

下面五项新增，一项增强；其余共同依赖只复用，不复制测试源码到常驻目录。

### C1 FullRestoreRejectsDamagedBlocksThenRetriesWithoutChangingPublishedState（integration/regression）

目标：压缩全量与现有发布/安装具有相同业务结果，坏块不替换已发布快照。
输入：真实 SQL 的稳定行及更新/删除/插入，接收端先有旧快照；无 delta 基础协商、重复 Offer、截断编码、假原长度、旧协商身份、正常块重试和超限声明。
路径：真实 BusTub/对象快照 → 正式压缩 → RPC 编解码 → Raft.Receive → worker 解压 → 原 Stage/Prepare/Publish/Install。
Oracle：明确的行集、Session 重试分类和应保留的旧/新快照身份；并非只比较 encode/decode 的同源输出。错误块后查询旧业务；成功后查询完整新业务。异常可定位协议/解码/发布边界，但数据库恢复失败还需日志定位。

### C2 WorkerAdmissionKeepsInputsAliveAndReturnsFailuresWithoutBlockingProtocolOwner（integration，阶段组件证据）

目标：已接纳工作持有输入；满额不接纳；执行失败有结果。
输入：真实固定快照读取，两个任务在条件变量处暂停，另两个排队；第五个被拒绝；丢弃一个消费者；一个任务抛出明确读取错误。
路径：内部生产 executor → 实际 SnapshotInput/对象读取；暂停只在测试任务中，没有伪造数据库实现。
Oracle：有界拒绝、仅被丢弃消费者所对应任务持有的寿命 token、预先读取的明确字节及错误传播。字节对比不是本测试唯一判据；它不证明 Raft 调用线程未被阻塞，该职责由 C4 接管。固定四任务属于本阶段已承诺资源上限，不作为永久内部布局契约。

### C3 AdaptiveEncodingKeepsIncompressibleAndSmallDataRaw（unit，阶段策略证据）

目标：小块和无净收益的块保留 Raw，避免无谓网络/CPU 扩大。
输入：173 字节及 64 KiB 固定种子的高熵非空内容。
路径：正式压缩选择函数；没有数据库，所以不称 E2E。
Oracle：Raw 标记与输入字节保持，不规定 LZ4 输出字节或压缩率。只保护本项目启用策略。价值低于完整恢复场景，单独保留为压缩阶段证据，未来性能/E2E 接管后可删。

### C4 SlowBodyReadDoesNotHoldProtocolAndOldTermCompletionCannotSend（integration/regression）

目标：慢快照读取不占住协议调用；更高任期到达后不发送旧任务结果。
输入：真实 SQL 快照，通过既有 PosixDurableStorage 子类暂停 ReadFileRange；多次正常选举及高任期取消留下四个未完成任务，第五次快照等待准入；选举/快照协商使用正式 Raft 接口。
路径：Raft.Receive → Submit → worker → 真实文件读取；主调用返回后处理更高任期；放行读取再 Tick。
Oracle：读取被确认暂停时，原调用已返回；能持久化/回答高任期；执行中及队满待接纳时仍有发往该 Follower 的正确任期心跳；取消后检查消息中无旧 InstallSnapshot。最后这项消息采样不单独证明任意完成时序，仍须结合高任期清除传输状态、完成结果身份检查及真实 TCP 组合证据；不加测试 getter 来窥视 future。有限等待仅用于调度/死锁判定，不是吞吐/延迟合格线。这里手工协议消息用于指定故障边界，与自动 TCP 场景职责不同。

### C5 LegacyPeerFallsBackWithoutLosingIncrementalCatchup（integration/regression）

复用自动三节点场景，传输过滤器只拒绝未知扩展 Offer，模拟旧解码器不识别新类型。目标是退回既有增量 Raw；不声称运行了旧版本二进制。Oracle 是无压缩 DATA、仍有 REUSE、真实业务/Session/重启后缀正确。与 C6 共用执行函数，差异为能力回退边界。

### C6 AutomaticLeaderCatchupUsesRetiredBaseAndKeepsTargetAcrossPublication（既有 integration，增强）

正式三 RaftNode + loopback TCP、真实 SQL/Direct 对象存储，保留离线/日志裁剪/中途新快照发布/真实业务后缀/重启。新增断言压缩 DATA 与 REUSE 混用；丢弃一次 ACK，观察同一请求的线上编码重传一致。测试驱动补齐生产已有的周期 Tick，异步任务完成不依赖恰好收到下一条网络消息。
独立 Oracle 为固定业务行、会话重试、后缀执行结果和固定目标身份；没有从实现生成同一份 expected 数据。字节相同可以证明重传一致，但单凭它不能证明绝对只压缩一次；后者还须检查仅无缓存/无任务时才提交的代码路径。

## 3. Production/API 污染检查

新增析构函数用于排空工作；新增编码/协商字段用于真实线上兼容；SnapshotTasks 为 `src/raft` 私有实现头，正式由 RaftNode 调用。删除测试后仍需要它们。没有测试 getter、test-only hook、配置默认值、宏分支，没有为了测试改变路径/ABI。Posix 子类及门闩仅在归档测试中。旧 Raw/RPC 类型仍有兼容用途，保留；旧同步块生成逻辑已替换，不另留平行开关。F02 继续只负责设备 IO，未塞入压缩 CPU 任务。

## 4. 重复与稳定性审查

- C1 验证全量接收坏块/发布，C6 验证真实 Leader 自动选择及网络链路，互不替代。
- C2 保护有界容量/所有权；C4 保护 Raft 实际调用不等待，移除了用组件证明整条链路的错误推论。
- C5/C6 共用函数，分别 Raw 兼容与压缩协商；不另复制数据库 fixture。
- C3 为低成本策略证据，只归档，不加入永久套件。没有 LZ4/Zstd 自己的库正确性测试。
- 输入 seed 固定，临时设备/路径独立，RAII 放行暂停任务并排空线程。真实 TCP 使用动态端口；CI socket/LSan 需允许执行环境。条件变量有时限；繁忙机器可能超时，不能把超时计为 mutation 检出。未跑 TSan。
- 原自动场景首轮出现进度超时；补上周期 Tick 后定向通过。保留失败诊断，不将首次失败结果算通过。原共同 C/P 内容未改。

## 6. 同正文编码测量

固定 seed 8912，真实 SQL 240 行，正文包含重复结构、带不同字段的记录及高熵字符串；生成 122,880 字节原生快照，按 64 KiB 分两块。每算法 100 轮，相同 4 KiB/12.5% 策略；LZ4 1.10.0 与 Zstd 1.5.5，codec O3/无 sanitizer，夹具生产库保留 sanitizer。单线程热数据局部测量，包含块 API 成本；没有带宽限速/网络往返，也没有跨机结论。

| 算法 | 正文+新增描述字节 | 编码 CPU ms/快照 | 解码 CPU ms/快照 | 编码块 p95 µs | 解码块 p95 µs |
| --- | ---: | ---: | ---: | ---: | ---: |
| Raw | 122880 | 0.0142 | 0.0078 | 6.55 | 4.30 |
| LZ4 | 59175 | 0.1133 | 0.0287 | 78.54 | 14.86 |
| Zstd level 1 | 48132 | 0.9993 | 0.4577 | 591.57 | 303.86 |
| Zstd fast 1 | 57122 | 0.9184 | 0.2680 | 489.53 | 183.51 |

LZ4 在这份样本节省约 52%，编码成本低于 Zstd；Zstd level 1 再省约 11 KiB。此结果支持首轮 LZ4，不能证明它在所有网络最优。没有宣称 RSS 为 codec 独占内存：环境文件的 max RSS 包含编译/夹具进程。线上工作内存由块上限、四个任务和每 peer 一个缓存块限制。

## 8. 追加复查：具体修正与重复模块（2026-10-07）

先沿生产逻辑核对协议/所有权，再修改测试。此前实施不等于本次复查未发现问题。本次改动：

1. `RaftNode::Tick`：原来仅 `work_` 存在才补心跳；队满时尚未获得 future，容易漏发。现在已结束协商且尚无缓存块的传输都补正常心跳，覆盖 pending 和执行中两种状态。
2. `TcpRaftTransport::Send/SendLoop/SendOne`：删除入队与发送各编码一次的重复工作；私有队列直接持有第一次编码后的帧。原校验时机、队满行为及 socket 锁外执行不变，公共 API 不扩大。
3. `RaftRpcCodec`：删除 DecodeMessage 内部的额外 EncodeMessage，保留 Decode 最终一次完整规范重编码比较。没有删除 CRC、范围/长度或合法字段校验。
4. `IncomingDecode`：原身份记录又复制一整份压缩请求；现在只持有完成后确实要核对的字段，正文由任务独有。
5. C2 原共享 token 可能被其余任务掩护；改为只由被丢弃消费者对应任务持有，排空后验证释放。C4 在原场景中加入四个迟到任务占满容量、第五个 pending 仍需心跳的风险，不另建重复套件。

模块对照见共同协议 §3.1。没有发现同职责的新增模块；SnapshotTasks、F02、F19、TCP 分别处理正文 CPU 工作、设备 IO、事务和网络。共同 Channel 无界，不能直接替代所需准入；设备线程可能是正文任务的下游，强行共池反而引入相互等待。将来 S13 抽取通用执行器时需整合此私有实现。

测试仍无新增 public API、getter、默认参数或 test-only 分支；新增 PendingFrame 是 TCP 私有队列值，删除测试后仍有避免重复编码的生产用途。删除重复编码不另写“调用次数必须一次”的实现细节测试，复用正式 RPC/TCP 正反场景与快照组合验证。

本次最终复验：Clang 14、ASan/UBSan/LSan，59 个不同正常场景全部通过：Deferred 12、快照组合 35、原 Catalog 5、原 RPC 3、原 TCP 4。原套件源码未改；RPC 的固定 golden 字节与非法帧测试验证合并校验后兼容性和错误拒绝，TCP 的真实收发/停止测试验证复用帧后的行为。不用相同 suite 重跑累加计数。

3 个定向变异全部按指定断言检出：放宽 executor 四任务上限；恢复 pending 漏心跳（第五次传输的 heartbeat 明确失败）；在协议调用内等待正文 future。前次 §7 的 12 个变异未全部重跑，不冒充本次结果。此次寿命测试改为指针变量后，首轮变异 runner 的旧断言文字匹配失效；只修正匹配词，再完成上述三项检查，保留诊断。编译命令首次把既有目标名字多写了 raft_ 前缀，改为原 rpc_codec_test/tcp_transport_test 后构建通过，不涉及生产构建修补。

唯一源码/结果包原位替换，当前源码哈希与 7 个不变依赖已核对；只保留当前测试源码，历史日志标明日期和范围。旧包无备份，临时构建/展开/设备均清理。原 C/P E2E 内容不变，局部 codec benchmark 未重跑；未新增 TSan、真实掉电、裸设备或跨机性能证据。当前没有发现阻止本轮范围验收的剩余问题；不据此宣称全部异步调度或所有时序已验证。未 commit/push。
