# S12 / F30 校验与后台扫描共同协议

2026-10-08；用户已授权按上一轮讨论实施。本文件是本轮协议；实现及测试证据见 [执行与八项审查](s12_integrity_execution_20261008.md)。

## 1. 范围与顺序

1. F30.1：普通 Data 写入生成 CRC32C、原子发布校验依据、正常读取验证。
2. F30.2：现有 F22 角色有界推进扫描，F14 保护原内容，F02 执行真实 IO；不新增线程池或对象目录。
3. F30.3：接续 Journal/已有格式的检查、F33 错误状态、压力和关闭验证。

沿用现有新目标 Common/Deferred；不启用原地覆盖、自动修复、跨节点修复或自动迁移。

## 2. 唯一依据、格式与兼容

新建 F13 使用 v5。v1–v4 保留原能力，不能把无校验数据标为已验证；不因 Open 自动升级。新格式每个 F12 分配单位 U 保存一个 CRC32C；U 来自实际存储配置，不假定 4 KiB。Key 使用原所有者和 Data 单位位置，value 包含分配身份及 CRC32C，防旧位置重新分配后串用依据。记录由原 F13/B 管理，F30 不建第二份权威表。

CRC 覆盖实际提交的完整 U，包含已初始化的对齐尾部。旧字节不暴露，空洞仍由逻辑语义返回零；不为回收另发清零 IO。一个物理单位被多个快照引用，校验信息仍只保存一次；部分回收在同一事务删除对应校验记录，其他单位保留。持久共享和读者依赖继续由 F14 判断。

校验记录的数量/字节、新增 CRC 向量和读取校验描述符纳入已有元数据与内存预算；S7 在发送正文 IO 前执行容量预检：Deferred 任务描述与正式提交共用 Changes 的条数/字节检查，B 的 PayloadRef 额外计入 B 批次预算；不能只核算 B 总字节而漏掉对象层变更上限。S6 显式分阶段 Write/Publish 在 Write 时尚不知道目标对象，映射变更的最终容量检查仍发生在 Publish；其写票据必须保留原 CRC，不能现场从设备重新生成依据。预检不是并发提交额度承诺，最终仍可能因冲突/压力失败，不能将未发布正文视为成功。

读取校验列表按实际读取的完整单位数预留容量，与已有额度对应；不要一边按元素数量计账，一边让列表逐步扩容产生额外容量。缓冲及描述符释放后才归还其额度，不把这些工作内存额度称为进程 RSS。

## 3. 写入与读取

Common：完成组装/填零 → 计算 CRC → 数据 durable → B 同批发布映射、分配、CRC。外部帧在原内容许可内计算，不为 CRC 复制整份正文。

Deferred：最终单位的 CRC 随映射/任务发布；未落位读取 Journal，复用 Journal 校验；最终 Data durable 且完成元数据提交后读取 Data 并验证对应 CRC。不能检查尚未完成的 Data 并将旧内容判为损坏。

正常读取与扫描共享校验实现，必要时扩展读取至完整 U（保护也须覆盖该 U），验证后才向调用者报告成功。完整对齐的帧读取继续走外部缓冲，不能为了校验全退回自有缓冲。页预取的完成也必须携带校验错误。

## 4. 扫描、保护与调度

沿 B 的现有原所有权枚举，避免按快照别名重复扫描同一正文。每批取新视图并取得物理保护，禁止只拿元数据快照就发设备读取。IO 完成前，批次上下文持有保护/缓冲；下游未接纳则资源责任仍在扫描器，释放暂时资源后再试。游标只在 RAM，重启重扫，不为每批进度写 Journal。

一轮限制查询量、字节与在途资源；首轮最多一个扫描批次，Data 一单位、B 一页、Journal 一个由原格式预算限制的完整批次。Deferred 同一 allocation 的完整批次已经验证后，直接越过其目标范围，避免按每个 U 重复读同一正文。接入既有 GarbageLoop，正在执行 IO 时返回调度器，不能在 GC 线程阻塞等待。普通后台额度不足就让出；读取保护名额耗尽使用既有 ObjectReference Busy 分类，等待其他持有者释放后重试；不得消耗已提交任务的进展保留。关闭停止新扫描，并让既有 IO 完成后再释放依赖。

F30 不是全库瞬时一致性证明。每批记录本次检查的版本；并发插入到游标之前的内容可在下一轮检查。B/Journal 的持久校验由各自所有者提供安全入口，不能用 Data 的 pin 代替其写回/日志保留协议。没有被实际设备读取覆盖的来源必须明确列出，不能用内存视图冒充设备扫描。

## 5. 结果与故障

资源忙/候选已退出：可让出或跳过；原格式无依据：未覆盖；校验不符：含原所有者、分配身份、物理范围、预期/实际值的损坏错误；真实 IO 错误保持原错误。F33 沿现有 fail-stop，不引入不完整的按对象隔离。错误不得改成零数据、现场重算覆盖预期或无限重试。

## 8. 实现配置与覆盖边界

`ObjectTransactionOptions::integrity_scan_` 显式开启可选后台扫描，默认关闭；沿已有 `gc_interval_` 轮询，不增加定时线程。新格式正常读校验不受该开关影响。NodeStorageView 提供 Data/待落位 Journal/未覆盖字节、Data 遍历次数及让出次数；不是进程 RSS、全库一致性或完整 B/Journal 扫描进度。

B 扫描和写回共享原串行角色，已在途的一页检查会在写回修改该页前完成；扫描调用自身只轮询，不等待 IO。Journal 只选择不超过 B 已提交位置的现存批次，采用原 retention 防止复用。关闭排空实际 IO，未完成的遍历下次重新开始。B 未写回的页不作为有效磁盘页检查，其恢复正文仍由 Journal 保护。

写回或 checkpoint 接手已接纳扫描的完成时，校验/IO 失败同样遵守正式结果契约：写回返回 Failed，checkpoint 返回 NotPublished，且不再开始页写入或发布新恢复入口。NodeStorage 在交付结果前记录失败；损坏仍归 Corruption，真实设备错误仍归 IOFault，不能依赖下一轮可选扫描才停服。
