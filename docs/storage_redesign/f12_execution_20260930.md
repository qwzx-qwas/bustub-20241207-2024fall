## 1. 先审逻辑，再编写测试

- `AllocationContext`：持久占用 C、暂时占用 R、明确隔离 Q 分开；搜索使用三者并集；上层 64 路、2 bit 摘要重建，不另记 WAL。坏块诊断不是分配器的自动策略。
- `Reserve`：地址顺序有界查找，优先连续，再有界拆分；完整满足后才设置 R，失败不能泄漏部分预留。设备空间不足和预算不足分开报告。
- `AllocationReservationState`：未提交申请的所有者与 IO lease 共用寿命；最后一份退出才清 R。提交后的对象读者保护由 F14 实现，不能滥用这份 lease。
- `Change`：提交角色串行，但位图锁不跨 B/IO。分片更新基于调用者同一个 B snapshot，保留其他位；一次 B.Commit 同时保存附带元数据。B 拒绝旧 snapshot 时不刷新、不重试。
- durable 后只做已准备好的内存更新；已接纳提交失败后停止本 allocator，沿用 B 的恢复结果；不因报错提前认为空间可用。
- `Open`：格式描述存在才读取 C/Q；粒度/区域长度/记录格式不匹配拒绝，不能自动初始化。运行预算可改变，持久格式不能偷偷解释成另一种。
- `Close`：先关接纳，再等本分配器的提交退出，不持位图锁等 IO；不代替 owner 排空外部 Data IO。

**写测试之前发现并修正：** 隔离变更提交 B 时，范围原本可能是空闲的；只在 durable 后修改 Q 会允许另一个 Reserve 抢走它。`ReservationFence` 在提交前设置临时占用，成功后由 Q 接管，提交前异常时撤销；结果不明确时先停止分配再收尾。这个修正来自锁与状态顺序推演，之后由真实 Flush 暂停场景验证。

没有自动修复错误、吞异常、无限重试、整段清零或另建 allocator Journal。没有为未来 RAM allocator 提前增加通用抽象。显式预算约束 RAM 位图、预留数量、每次字节/extent 数及搜索工作量；B 自身仍可因页/值/批次预算拒绝提交，Reserve 不承诺 B 一定能够提交。

## 3. 逐项：目标 → 输入 → 执行 → Oracle → 失败含义

共同路径：正式 DataAllocator → MetadataEngine B → Journal/MetadataBackend → F04/F02/F01 → Direct 文件。Data IO 单独调用正式 RegionManager/IOExecutor；没有模拟数据库。8 MiB 文件、2 MiB Data 区和现有 B 预算来自原 S5 fixture。系统调用暂停/EIO 仅在测试链接侧，正常调用仍进入真实设备后端。

### 3.1 预留与 IO 寿命

- **目标：** 同一物理单位不能同时许给两个有效申请；取消不能越过实际 IO 完成。
- **输入：** 一次申请全部可用 Data 空间；持有 lease，向其中一单位写入确定的非零模式；在真实 pwrite 暂停后丢弃主申请。随后 32 个并发调用各申请一单位并保留结果。
- **执行：** Reserve/Lease → RegionManager 准备真实写入 → F02/F01；主申请退出、申请被拒绝、IO 完成、lease 退出；并发 Reserve 和 Close。
- **Oracle：** 暂停期间申请报 NoSpace；完成后原始文件字节等于输入模式；并发返回单位的独立集合没有重复；取消全部申请后可一次取回全部容量；关闭后 NotReady。单位集合来自返回范围及显式粒度，不读取内存位图。
- **失败含义：** 预留寿命、并发互斥、取消或准入有误。并发唯一性只证明本次观测，不声称穷尽所有调度。lease 由调用方保留到 batch.Wait，本阶段未伪造 F14 已提交内容 pin。

### 3.2 连续/碎片查找与整体失败

- **目标：** 在边界两侧连续的可用单位可组成一个 extent；有容量但超过本次预算必须准确拒绝且不泄漏。
- **输入：** 明确隔离其他 Data 单位，只留 3、8 和 62～65；最后一组跨 64 单位边界。分别以 1 extent、1 搜索节点的预算重开；常规预算为 8 extent。
- **执行：** 正式 SetQuarantine 提交 B，再 Reserve/Open；不直接改内部摘要或持久位图。
- **Oracle：** 四单位申请返回一个从 62 开始的 extent；持有它后两单位申请因 extent 限制报 ResourceUnavailable；随后两次单单位申请必须都成功、合并恰为 `{3,8}`。正常预算可返回这两片，全部占住后为 NoSpace。
- **失败含义：** 连续合并、拆分、预算分类或失败回滚错误。不是对固定树层数/内存 bit 布局的单测。

### 3.3 原子提交、checkpoint 与释放

- **目标：** C、Q 与附带记录反映同一提交历史；释放前不会重用，释放后不能影响别人的分配。
- **输入：** 分配单位是实际对齐单位的三倍，使 Data 尾部不能完整分配；两个申请落到同一位图分片；49/63 字节不同伴随值和一单位非零正文；另隔离单位 5。
- **执行：** 正文正式 IO → Commit(x) → 用旧 snapshot 提交 y 被拒绝 → 调用方取新 snapshot 后提交 y → Checkpoint/Close/Open → Release(x) 与删除伴随记录同批 → 再 checkpoint/重开。
- **Oracle：** x/y 的值等于独立输入；原始正文逐字节不变；第一次重开能申请的单位恰为全集减 `{0,1,5}`；尾部不能再申请。释放后只新增单位 0，y 与隔离位保持；第二次重开仍成立。
- **失败含义：** 丢位、自动刷新旧前置条件、恢复遗失、未提交释放或误释放邻居。伴随记录是验证原子接口的普通业务负载，不冒称它已是 F13 的对象映射格式。

### 3.4 隔离提交窗口

- **目标：** 尚在提交中的隔离不能被并发申请穿透，且等待 B 不锁住所有 Reserve。
- **输入：** 隔离第一个单位；在真正 Journal Flush 处暂停。
- **执行：** 异步 SetQuarantine，暂停确认后同步申请其余全部空间，结束 Flush，随后正式解除隔离。
- **Oracle：** 暂停期间申请仍能完成，其范围不含单位 0、大小恰为其余容量；durable 后再申请无空间；解除后唯一新增空间是单位 0。
- **失败含义：** 临时占用或 durable 后转换错误；死锁由运行看门狗报运行失败，不能当作指定变异被断言检出。

### 3.5 提交失败与恢复原子性

- **目标：** 结果不明确不允许继续分配；重开不会得到“记录说已占用，空间却空闲”等半笔结果。
- **输入：** 独立镜像中分别执行全 Data 分配、已有全 Data 分配的释放；伴随 87 字节非零值；在实际 Journal Flush 暂停后返回一次 EIO。
- **执行：** 正式 Commit/Release、B.Read、并发 Reserve、结果返回、Close/Open。
- **Oracle：** 暂停时元数据仍为旧视图且没有可用空间；EIO 不能报 durable、保留错误，之后 Reserve 必须 NotReady。重开若有伴随值，值必须等于输入且全区被占；若无该值，必须能申请全区。
- **独立性与限制：** oracle 验证原子关系，不用 allocator 内部 C 判断 B 应恢复什么。不确定提交允许有或无，不声称知道失败 Flush 时介质上的确切结果。这个输入不能替代真实掉电验证。
- **失败含义：** 提前发布/释放、故障隔离失效、或跨元数据与位图的不一致。

### 3.6 打开不格式化与粒度匹配

- **目标：** 打开/新建必须尊重已有持久事实。
- **输入：** 先保存 59 字节非空伴随值；无 allocator 描述时 Open；Create 描述后、还没有位图记录时用双倍粒度 Open；再正式分配全区，尝试重复 Create。
- **执行：** 正式 B.Commit 与 allocator Create/Open/Reserve/Commit；没有测试侧篡改私有格式。
- **Oracle：** 依次 NotInitialized、Corrupt、AlreadyInitialized；正确粒度重开仍全区占用、其他值未变。
- **失败含义：** 静默创建/覆盖或格式验证被跳过。错粒度场景在空位图阶段执行，避免范围尾部检查掩盖目标错误。

## 5. 重复、兼容和退出

- F12 新保护空间归属/事务组合/预留寿命，不重写 Journal 校验、段回收、B 树分裂或 F02 缓冲生命周期的测试矩阵。
- 原 F34 五项、S5 八项直接从有效压缩包恢复，对当前生产库运行；S5 保留原旧生产镜像生成器。旧包的来源哈希不改，也不删除仍有效的依赖包。
- 正常提交恢复与故障恢复共享原子目标，但后者新增不确定结果和停止接纳的风险，不能由成功场景替代；隔离窗口是单独的并发风险。
- 六项只以 F12 压缩包保存，不进入长期自动发现。后续 F13/F14 沿这些风险接入真实对象映射、引用和释放条件，优先复用同一输入与独立 oracle；不要另建同义位图套件。
- 共同 C1～C5/P1～P4 保留完整内容；它们尚未经过新后端，不能宣称本轮已将阶段风险交给 E2E。

## 6. 杀伤力与修正过的弱判据

变异只改临时源码中的一个生产编译单元。必须编译成功、退出为测试失败并命中指定断言；编译失败、sanitizer 崩溃、超时不算检出。

| 最小变异 | 指定测试/Oracle |
| --- | --- |
| 搜索忽略 R | lease 仍在实际 IO 中时申请意外成功 |
| 失败查找仍设置部分 R | 两块剩余空间不能全部取回 |
| 重开不恢复 C | 成功恢复的可分配单位集合错误 |
| 丢掉 companion mutations | x 的业务值不存在 |
| B.Commit 前自动刷新 snapshot | 旧 snapshot 意外成功 |
| 更新一个分片时把其他位从零构造 | 重开后已提交邻居变成空闲 |
| 移除隔离提交 fence | 暂停期间返回的范围含单位 0 |
| 不在不确定结果后关接纳 | 后续错误不是 NotReady |
| 跳过 descriptor 匹配 | 错粒度 Open 意外成功 |

初轮审查发现两处弱测试，已修正后重新验证：失败申请后只取一块不能排除部分泄漏；已写满的位图会由其他尾部检查拦住错粒度打开，掩盖 descriptor 检查遗漏。只归档修正版，不保存旧弱测试版本；也不把初轮未检出的变异计为通过。

## 7. 稳定性和环境

- 每个场景使用独立 mkstemp 文件、明确 cleanup；数据模式确定，不依赖随机种子或测试顺序。
- 正式 Direct 对齐运行时查询，fixture 以最小公倍数适配；超出夹具预算明确失败，不静默切 buffered。三倍粒度场景验证非整分配单位尾部。
- IO 通过条件变量握手确认已暂停，未用 sleep 猜线程进度。10 秒握手、120 秒运行限制只是卡死诊断，不是性能门槛。
- 先构造异步任务、后构造 ReleaseOnExit，断言早退时先打开故障门再等待 future/设备析构。并发调用保留所有返回申请直到比较结束。
- wrapper 使用同进程全局 gate，因此测试二进制按 GTest 默认串行运行；不能在同一进程并行跑这些场景。环境/调度仍可能使看门狗报失败，需按日志区分。
- ASan/UBSan 检查内存及未定义行为；并发互斥仍主要来自锁顺序分析和场景验证，不宣称 TSan 已运行。

### 9.2 找到的测试问题与处理

1. **不必要的夹具限制。** 碎片场景只使用单位 0～65，却要求总数大于 130；2 MiB Data、16 KiB 分配单位只有 128 个，属于夹具可以支持的合法输入。改为至少 66 个；实际设备对齐允许时，该场景使用 16 KiB 分配粒度，以覆盖此种形状。修改的是测试分配策略，没有伪造设备对齐，也没有要求生产默认用 16 KiB。
2. **缺少拒绝后的回滚判据。** 隔离场景原来只证明提交窗口与成功解除，不能检出 B 因旧 snapshot 拒绝后遗留临时占用。现于同一场景保留旧 snapshot，解除隔离后用它再次请求隔离；必须准确抛 Conflict，随后能重新取到唯一空闲单位。只报错不验证容量恢复是不够的。
