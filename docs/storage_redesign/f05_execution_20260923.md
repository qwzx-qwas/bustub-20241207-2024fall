## 二、逐项：目标 → 输入 → 执行 → Oracle → 失败含义

### 1. PageSlotsPreserveOtherRegionsAndReopen

- **目标**：地址转换、许可和持久化请求经完整生产 IO 链仍正确，错误位置不能被对称错误的读写掩盖。
- **输入**：16 MiB 真实文件，两个 64 KiB 引导槽外初始内容为固定公式生成的非零混合字节；Metadata 起点分别 2/3 MiB，四整页容量，第二布局另留一个实际 IO 单位的尾部。页 0/2/3 各用不同 payload，页 1 故意不写。末页覆盖容量边界；不同起点防止错误固定基址。PAGE=4096 是测试的格式 oracle，另显式检查它与当前 BusTub 格式一致，不能跟随错误实现一起变化。
- **执行**：正式 BootstrapStore Create/Open → RegionManager → MetadataBackend TryPrepare/TryPrepareExternal → IOExecutor → Direct BlockDevice。自有缓冲批次写 0/3，外部缓冲写 2、清零后读 2；再销毁整套后端/执行器/设备，重新 Open 并读 0/2/3。没有真实 B+Tree 或 BufferPool，这不是数据库 E2E。
- **Oracle**：以引导完成后的整文件为基底，由测试给定起点/页大小在副本中替换三个预期范围，再经独立 pread 读全文件比对；不调用 F05/F04 查物理地址。重开后逐页与原 payload 比较。Flush 成功次数只断言大于零，不规定系统调用精确次数；同时要求 writes_durable=true。缓冲先清零，避免未执行读取仍通过。回调归还次数观察许可契约，不暴露生产计数器。
- **失败含义**：全文件不等直接说明位置/内容/范围保护出错；回读失败也可能来自底层设备错误，须结合阶段及 F02 原错误诊断；没有把所有失败一律归于寻址。页面换位变异中，同样错误的回读仍可通过，但独立物理 oracle 确实失败。

### 2. InvalidPagesAndGeometryRejectBeforeIO

- **目标**：非法页的整个批次不能进入 IO 准备和消费许可；构造时明确拒绝无法承载整页的设备几何。
- **输入**：合法页 1 加非法页 -1/-2/4/INT32_MAX；四页区域，合法/非法范围不以重叠制造另一种拒绝。两个只读于 IO 的写许可允许共用稳定 RAM，验证拒绝后原 vector 仍有两项且没有归还回调；随后合法准备成功再销毁。另一 manager 绑定同一引导，Describe 必须拒绝其 handle。
- **执行**：经过真实 F03/F04/F05/F02 构造/准备。小于一页的非空 Metadata 区由真实 512 字节对齐支持并被 F05 拒绝。另由测试链接包装 statx 将实际可兼容的偏移对齐加强至 8192，再经真实 F01/F02/F03/F04 构造 F05。此分支明确是能力注入；F03 使用兼容的 64 KiB/8 KiB 整数倍范围，不能被无关前置失败冒充。
- **Oracle**：明确 invalid_argument、许可仍归原调用者、可再次合法准备、整个文件保持原样。不提交故意无效 batch，也不通过 F05 读回验证“没写”。几何 case 要求已得到 8192 的生产查询结果，再断言构造拒绝；不会因真实设备不支持注入前提而静默跳过。
- **失败含义**：缺少拒绝说明入口契约弱化；许可被消费说明批次准备破坏所有权；文件变化说明非法操作提前执行。负数/越界也受 F04/F02 防御检查保护，删除某个重复检查未必让此黑盒测试失败；不为区分内部在哪一层拒绝而引入测试 hook。

### 3. 原 F04 回归

输入仍是原两种布局、真实文件、明确错误范围及链接侧 EIO/Flush 注入；路径是修改后的 F04→原 F02/F01。独立全文件、原错误类型/物理范围、许可计数与结果字段不变。这里验证旧契约是否回归，不宣称重新检验完整 F02 并发或 F03 恢复矩阵。

## 四、接口污染与冗余检查

- 原 F01/F02/F03、SQL/Raft、DiskManager/BufferPool API 和默认 Direct 路径未改；没有把 private 变 public。
- Describe 的内存对齐供缓冲提供者参考，真正 IO 的合法性仍由 F02/F01 检查，不能把描述值当成绕过检查的许可。
- 替换了 F04 原重复归属检查；新接口中无提交/等待/缓存冗余。旧 DiskManager 仍有真实业务消费者，不能因为 F05 出现而删除。
- F02 自有缓冲支持当前基础后端，外部缓冲预留给受控帧，当前都有必要；S9 默认帧接入时仍需依照原方案清理旧业务页路径，不能据此长期保留两个业务默认入口。

## 五、重复与低价值检查

- 两项新测试分别保护正确定位/读写及非法操作隔离，不按每个私有函数增加 unit test。
- 两布局同时提供不同物理起点和部分尾页，分别触发固定基址与向上取整错误；不是仅换 seed 复制同一 failure mode。
- owned/external 都检查 Flush，是两条真实准备入口的参数传递风险；各自移除 Flush 均被独立发现。F02 的完整刷盘算法/失败排空不在 F05 重测。
- F04 与 F05 都使用全文件 oracle，但一个保护区域范围，一个保护页号适配；原三项只作回归，未新增/复制。没有把标准库或 PostgreSQL 的行为当作本项目测试目标。
- 小于页/8 KiB 几何合在同一非法场景；没有专设仅检查 Describe 返回字段或 enum 值的小测试。
- 共同 C/P 尚未经过 F05，不能据其存在删除本阶段所有风险证据；按用户要求只压缩归档。待真实 B/业务接入时优先引用同一风险并接入共同场景，再决定旧用例退出，不复制第二套内容。

## 六、最小变异与实测杀伤力

六份变异仅存在临时编译副本，仓库 production 没有切换到错误版本。全部成功编译、退出码 1、指定测试断言失败，无 ASan/UBSan/LSan 错误；逐条人工核对实际 failure，不把“某处失败”自动算命中。

| 变异 | 指定测试与实际判据 |
| --- | --- |
| `page_id ^ 1` 换位到另一合法页槽 | 第一个场景，全文件与 expected 不同（250/287 行）；同错读写无法掩盖 |
| 容量多报一页 | 第一个场景，四个整页被误报为第 5 页（212 行）；不依赖设备能否表达不足一页的尾部 |
| 自有准备丢 Flush | 第一个场景，writes_durable=false 且无新成功 Flush（227/228 行） |
| 外部准备丢 Flush | 第一个场景，对应外部批次同样失败（244/245 行） |
| 取消页大小与设备对齐检查 | 第二个场景，8192 几何下构造未抛异常（379 行） |
| 取消 F04 handle 归属检查 | 第二个场景，Describe 接受另一 manager（305 行） |

这六项不代表任意错误都能抓到。例如单独移除 F05 某个边界判断可能仍被下层拒绝；大于 `page_id_t` 可表达范围的巨型区域容量上限没有创建多 TB 镜像验证，当前由类型和算术审查覆盖。没有为测实现细节刻意要求异常必须来自某一层。

## 七、稳定性与资源

- 固定内容公式、独立 mkstemp 路径，文件 RAII 关闭删除；无网络、GPU、随机 seed 或 sleep。每个场景有独立设备/执行器，外部回调按值保留 buffer 与共享计数器，提前失败不会引用已销毁的栈。
- 原子计数只用于测试观察；强化几何由作用域对象复位，在无 IO worker 留存后销毁。本轮按 GTest 默认顺序执行，不依赖先跑某个测试生成持久文件。
- 每次 F05 使用一个 16 MiB 文件，F04 回归最多两个；F02 预算两 worker、八个成员、自有 1 MiB/外部 1 MiB，整镜像 oracle 占用额外测试内存。构建 `-j2`，未做压力或吞吐结论。
- 等待 watchdog 5 秒，进程超时 120 秒。高度拥挤或设备长期停顿可能触发超时；不是性能 SLO。终止等待不声称取消真实 IO，析构沿原排空语义。
- 需要 Linux、可用 O_DIRECT/statx DIOALIGN 与实际兼容 4 KiB 页的文件系统；条件不满足明确失败，不静默改 Buffered。本机测得内存对齐 4、偏移长度 512，小于页场景实际执行。更大几何只做标明的注入。
- runner 清理外部 GTEST_*，严格核验 XML 中名称、数量、run/completed、零失败/错误/禁用/跳过。实际在 `GTEST_FILTER=NoSuchTest`、分片变量干扰下仍执行完整两项和三项回归。

## 九、2026-09-23 再次复审：变异脚本的对齐环境依赖

**发现并修正一处测试工具问题：** 原 `round_up_capacity` 将容量计算改成向上取整。若真实 IO 偏移对齐恰好等于整页 4096，合法区域本来就是整页倍数，向上/向下取整结果一样；原 runner 却要求此变异必然失败，会把等价变异误报为测试缺陷。这不否定上轮本机 512 对齐且存在尾部时的六次有效检测，但影响脚本跨环境复用。
