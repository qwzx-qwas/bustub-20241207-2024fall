## 1. 当前实现与证据边界

F26 已在正式取页路径采用数组翻译：`BufferPoolState::Fetch` → `TranslationDirectory::Lookup` → PathCache 命中或多级目录 → `Leaf[suffix]` 原子读取 → frame → 帧访问保护及正文。31 位非负 PID 按 8/7/16 分级；PathCache 最多 8 项。它优化 PID 到驻留帧的查询，SQL 找记录仍由表/索引执行。

数组接入不等于没有同步成本：[零页接续](s12_translation_zero_page.md)已将查询的组共享锁/条目独占替换为访问登记与代次核对；映射修改仍走 Access 的独占协议，帧锁/pin、替换器更新、调用保护仍在。现有索引 RID 窗口调用 `PrefetchPages`，CPU 翻译/正文提示与设备预取分别处理；唯一主键的一条 RID 不保证有多个独立候选。功能、寿命及零页私有内存观察不能证明命中加速。

代码核对入口：[目录访问](../../src/buffer/translation_directory.cpp)、[BufferPool 取页/预取](../../src/buffer/buffer_pool_manager.cpp)、[索引 RID 消费者](../../src/execution/index_scan_executor.cpp)。这里只记录正式路径，不把内部字段或函数名变成测试 Oracle。

| 模式 | 原 T0 实际内容 | 仍缺的性能证据 |
| --- | --- | --- |
| SS 顺序扫描 | 加载/收尾核对及部分业务路径会扫描 | 没有独立测量连续取页的局部性及翻译成本 |
| RS 范围扫描 | `ReadRange` 用于分批业务核对 | 没有独立的索引定位起点后扫描负载；SQL 范围谓词不证明物理执行方式 |
| PL 点查 | P1 强一致整行主键点查，均匀/热点两种分布 | 已有业务性能基线，但未隔离翻译成本，也未冻结跨 prefix 等访问模式 |
| GT 图遍历 | 原 P1–P4 无该负载 | 无页翻译图遍历基线 |

证据来自 [P1 内容生成](../../test/storage_acceptance/content.py)、[P1 实际执行](../../test/storage_acceptance/performance.py)、[范围核对](../../test/storage_acceptance/workload.py)。P2/P3 中的扫描和原有课程 benchmark 不能事后改称本矩阵已覆盖。

## 2. 开源参考及本项目落点

[Calico v1 §2–3](https://arxiv.org/html/2604.00423v1) 用 SS/RS/PL/GT 区分局部性、依赖链和内存级并行（MLP）；第三节采用单线程、数据驻留的实验以分析翻译开销。顺序扫描使用连续 PID；其随机扫描模拟不连续 PID 的 B-tree 叶扫描；图遍历在一次扩展中暴露多个候选。§5.1 的 group prefetch 提前访问已知候选。

本项目内化为下表的访问模式、驻留诊断与独立候选条件，不复制论文数据规模、硬件要求或性能倍数。MLP 指 CPU 同时等待多个独立内存访问；它与 F02 同时处理多个设备 IO 分开观察。页驻留 BufferPool 不代表正文/目录已命中 CPU 缓存。

## 3. 场景方向、真实路径与独立结果

以下是待细化场景卡的方向，不是已冻结的 SQL、数据规模或测试数量。正式业务输入仍沿用“内容层 → 测试适配层 → production”；CPU 诊断通过既有正式取页能力，明确标明非分布式 E2E。

| 模式与独立问题 | 建议输入和被测路径 | Oracle 与防止误测 |
| --- | --- | --- |
| SS：连续访问能否利用局部性 | 非空表，经真实执行器做全表扫描/聚合；驻留诊断可经正式页接口访问已装载的连续 PID 正文 | 预期计数/聚合由输入生成，内容覆盖整个范围；观察实际执行路径与页局部性，不从 SQL 排序推定 PID 连续 |
| RS：起点定位后扫描的成本 | 改变非零起点与短/长范围，经真实索引到叶页/记录路径 | 按输入键区间推导结果和顺序；先确认能定位下界，若当前只能全扫再过滤，如实标为业务范围查询，不冒充定位式 RS |
| PL：单条依赖链的延迟 | 复用已有点查数据生成/结果判据；补充明确的驻留诊断，单执行流与整体并发分开 | 比较完整目标记录，错误页不能以成功状态通过；唯一键点查与一键多 RID 的预取窗口分别标注，不重复建设 P1 |
| GT：不规则多候选访问能否重叠 | 正式业务 GT 需要邻居访问经过 PID→BufferPool；先核对生产能力 | 图及可达集合由固定输入定义；遍历不得漏邻居或返回旧帧正文。纯内存图或串行随机点查不能充当页翻译 GT |

### 当前 RS / GT 的接入限制

- 当前 `IndexScanExecutor::Init` 的全扫描分支先取得 `GetAllEntriesSnapshot()`；不能据范围 SQL 的名称推定已有索引下界定位。需要改善正式范围执行能力时，先明确其生产职责及方案，不为 benchmark 加隐藏捷径或指定内部执行器的测试开关。
- 当前 [HNSW](../../src/include/storage/index/hnsw_index.h) 的节点和邻接表在 `nodes_`/`neighbors_` 内，邻居搜索直接访问这些容器；后续 RID 回表不等于图边访问经过页翻译。因此当前 GT 记为能力缺口，不把现有向量查询计为这一项通过。
- 若另行认可图访问诊断，可将生成的非空图页经正式页接口保存/读取，并保留一次多个候选的访问特征；报告为 F26 诊断，不称为现有 HNSW 或完整业务 GT。不得仅为填表实现一套假的生产图服务。真正的页式图索引属于生产功能扩展，需另行讨论，不默认塞进 F26/F25。
- 逻辑键顺序、PID 相邻、帧内存位置及设备 extent 相邻分别记录，不能互相推定。顺序/稀疏布局不可通过测试接口强改生产分配器来制造。

5. 所有模式共用准备、驱动、结果核对和报告设施，不为四个名称建立四套框架。阶段诊断只保留 F26 命名的当前压缩证据；真实 E2E 接管后按总方案 §1.6 合并/退出，缺失风险继续登记。

## 5. 计量与资源约束

- 同一次测量收集成功吞吐、延迟及有效操作数；诊断可收集 cycles、instructions、LLC/DTLB miss，按操作或有可靠来源的访问页数归一化。无法可靠取得页访问数时不猜分母。
- CPU 指标优先外部工具；硬件计数器不支持/无权限时记录观测缺口，不能记成零开销或已验证。工具开销、采样进程和测量阶段明确记录。
- 固定总内存口径，包括 A/B 缓存、翻译目录、帧、工作缓冲及相关 OS 缓存。驻留诊断和超过缓存的设备场景分开，不把 OS 命中等同 BufferPool 命中。
- 数据规模可以按现有 16 GiB 机器缩放，先确认服务器/生成器/OS 合计预算及避免换页；不预设照搬论文规模。工作集是否超过 CPU 缓存、是否驻留、huge page 是否实际生效分别报告，申请大页不等于获得大页。
- 候选参数只围绕不同问题：集中/分散 prefix、连续/非连续 PID、范围长度、可同时得知的候选数。避免无依据的全组合及大量仅换数值的重复场景；每个参数解释新增的性能问题。
- 先按已批准规则资格运行，再冻结时长、规模、重复次数和资源上限；不得根据新版成绩挑配置。当前未冻结数值，也未授权本轮运行资格测试。
