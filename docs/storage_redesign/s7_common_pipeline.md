# S7 Common 对象事务与异步交接

日期：2026-10-02（Asia/Shanghai）。用户已授权按最近讨论补方案、实现、先逻辑审查再测试。本文件是 F15–F22/F31 本轮共同执行协议；各子模块引用这里，避免复制不同版本。

## 1. 已确定的交接与复用

- F02 已有有界 IO worker、批次成员结果和 Flush；F07 已有 Journal 队列与提交结果。继续复用，不建立第二个设备线程池或 WAL。F35 的协议 event loop 仍属于 S13，复用设计约束，不声称已有可调用的运行时。
- 接收确认、worker 开始、阶段完成、持久化成功分别表示不同事实。下层可靠入队并持有执行资源后才返回 Accepted；不再等待 worker 取走任务。未接收的工作仍由上层保有，不能标作已发送。上层可以继续处理独立工作；同一请求的后续阶段仍等待真正依赖。
- 请求、正文、结果槽和执行上下文在准入时建立并计入上限。队满不丢已接纳任务或完成结果；pending 也占额度。完成通知可以合并，结果本身保存在有主人的任务中。
- F02 原资源回调在终态前运行，不能在那里等待/提交 B。增加同一完成机制的终态后通知：归还保护和外部缓冲→发布终态→通知协调器。通知只唤醒；B 提交由元数据执行角色处理。允许 IO 在 Submit 返回前完成，提交后的状态赋值不得覆盖完成事实。
- 调用者超时/丢票据只退出观察；关闭停止新准入并收束尚未发出的工作，排空已经发出的数据/元数据 IO，再关闭 F14/F12/B/F02。

## 2. 本轮接口与组织

有界 ObjectTransaction 保存对象操作及可选 ControlKV 变更，返回接收结果和票据。一个事务是一份原子提交；不同事务共享执行设施不扩大原子边界。每批每对象至多一个创建、写、追加、调整长度或删除操作，调用方先合成同对象的重复修改；控制项去重。限制均为显式配置，不引入设备路径/对齐默认值。

协调角色只组织 RAM 规划和阶段推进；一个元数据执行角色调用既有同步 B 提交，等待不占 F02 worker，也不持协调锁。独立对象的数据 IO 可重叠；本轮同对象按接收顺序推进，包含追加、截断和删除。后续若细分同对象不相交范围，必须保留对象长度/版本和实际物理处理范围依赖。

输入缓冲由事务取得所有权，执行器工作缓冲继续受 F02 额度约束。提交所需位置和完成结果预先保有。暂时没有执行容量的已接纳任务保留 pending；通过完成通知和显式配置的有界重试间隔推进，不能忙循环。关闭时未发出的任务可明确结束为未提交；已发出的 IO 必须先收束。下层错误不做隐藏重试。仅明确的临时 IO 名额占用、F12 预留票据占满（Busy）、F14 短暂范围占用允许等待重试；请求自身超过字节、成员、碎片或查找预算则结束为 NotCommitted，并保留原错误，不能无限等待。ObjectIO 在投递前按节点传入的同一份 F02 容量检查实际批次及对齐内存开销，避免将永远放不进去的 batch 当作临时 Full。

## 3. 数据与原子提交

Common 先将本事务的必要正文组成一个数据批次：多个 extent 并行写，全部成功后共享一次数据 Flush；随后 B 原子提交所有对象描述、映射、分配、退出范围和控制项，发布完整视图后才返回 Committed。普通正文不重复进入 B 值或 Journal。

写策略以安全条件为先：完整新范围 COW；小范围读取所在旧单元、组装后写到新位置（读旧内容组装后 COW）；大范围只读取需要保留的两端，不读取被完整覆盖的中间正文。不启用没有掉电保护的原地覆盖。尾部追加本轮使用 COW：当前 F01 只提供 IO 对齐，不能据此证明同一分配单位内的写入有掉电隔离保证。按既有“无法证明安全就选 COW”规则，不启用原分配小尾部复用，不拼旧尾+新分配、不搜索历史碎片。未来取得实际设备故障/写入保障后，才能只检查当前尾部并复用；届时必须同批扩展映射与初始化边界。当前不保留没有安全调用者的尾部原地写接口。

数据阶段取对象版本；提交角色读取当前 B 视图并核验所依赖对象版本，再构造同批变更。不能刷新 base 后忽略对象已被修改；外部并发 B 提交产生的冲突原样报告，不隐藏重试。IO 失败前后的未提交新分配不影响旧映射；B 返回不确定时保留恢复责任，不能按明确未提交处理。

F20 复用 B 不可变视图原子发布；F21 复用 S6 受保护 Data/Hole 读取。Deferred/Journal 来源仍在 S10，业务共享快照在 S11。

## 4. 回收、预算和生命周期

F22 使用 F13 已持久化退出记录，分页发现候选、调用 F14 范围判定及 F12 原子释放；不再复制释放算法。前台结果不等待 GC。被读者阻挡的候选以后重查，重启从持久记录重新发现，不依赖 RAM 队列存活。后台操作与提交角色公平轮转，每次受现有扫描/范围/字节限制；错误可见，不静默吞掉持久化错误。

F31 本轮落实对象请求数量、输入字节、操作数及结果保留额度；F02/F07/B 保留原额度。元数据等待不得持有所有可用 IO 名额：已完成的数据批次在元数据提交前归还 IO 缓冲/成员额度，分配责任单独保留。全节点业务预算仍属后续阶段。

NodeStorage 显式配置对象事务服务，先恢复 B→F12/F13/F14→ObjectIO→事务流水线；关闭逆序。元数据专用和 S6 分步对象部署仍是真实支持路径。事务服务开启时普通修改以事务入口为主；旧分步入口的冲突与关闭保证保持，不靠测试专用开关绕过生产约束。
