# F09 MetadataPageWriter 执行与测试设计审查（2026-09-26）

基准 `b043695`；本轮授权范围见 [F09](modules/metadata-page-writer.md#63-本轮执行范围2026-09-26已授权)。**当轮 F09 验收完成：4 项 F09、6 项原 F08 回归通过，8 个指定变异检出。** 未完成 F10/F11/checkpoint/日志回收或全节点业务接入。

## 1. 编写测试前的生产逻辑审查

- F08 仅在 Journal Durable 后发布版本；F09 从同一发布入口取得不可变页，不接收外部任意页字节，也不接触私有 pager。
- 独立 writeback 锁只排斥第二个写回批次；Commit 使用 writer 锁，Read 使用短 view 锁；F09 仅在复制版本引用时持 view 锁。IO 等待不持 writer/view，F02 在批次中并行不同页。
- 每个批次开始前捕获 `(generation, LSN)`，同一页槽跨批次包括复用均串行；完成记录只写所捕获值。新事务继续修改并发布后，不会被旧完成标为已写回。
- native 页正文先通过已有 EncodeBody 转为 canonical，再附上 Seal 已生成 trailer；F02 自有缓冲满足实际设备对齐，不能直接写内存页或假定 4 KiB 对齐。
- 对齐缓冲、请求数组和进度数组在 Submit 前准备；复制后释放临时快照引用，IO 等待不强留全部旧页。只记录版本标记，不复制一份旧页缓存。
- 写入或 Flush 错误返回原始 exception_ptr，不更新本批持久进度；再次写回必须由调用者显式发起。先前 Commit 的 durable 承诺仍由完整 Journal 支撑。
- Close 按 writer → writeback → 短 view 顺序排空；Writeback 不获取 writer，避免循环等待。生命周期调用者先停新入口，再关闭 B、executor、device。
- F09 Open 后从零建立写回进度，仍从完整 Journal 恢复 B。尚无最终页恢复、checkpoint 或日志裁剪，F09 成功不授权删除日志。

本轮生产新增正式 Writeback 入口及结果类型，供后台调度/checkpoint 使用；Bootstrap 的 private friend 只让 B 取得同一设备绑定的 executor，不增加 public getter、任意 executor 参数或测试钩子。内部写回角色与页 codec 放在同一 cpp，避免仅为模块编号增加无用途的公共抽象。

代码完成并分析上述路径、Clang 模板编译通过后，才开始编写第 2 节测试。主方案 §1.7 的先逻辑后测试、避免掩盖错误的要求已在子方案 §6.3 与 prompt 重申。

## 2. 测试全景

四项均为真实 Direct 文件链路的 integration/regression；没有三节点或物理掉电 E2E。本模块源码只在仓库外编写，最终压缩归档，不注册常驻测试目标。

| 测试 | 保护的 invariant / 具体 bug |
| --- | --- |
| `CanonicalPagesAndReopenWriteback` | 最终页区独立解析等于已提交输入；防止把 native 页直接写盘、漏 trailer、错位置、更新未写和超出批次预算 |
| `UncommittedChangesStayOutOfPageRegion` | Journal Flush 在途时最终页区保持旧版本；防止私有修改越过 WAL/提交边界 |

| `FailuresRetainWorkAndCloseDrains` | 真实 Full、pwrite/Flush 错误不能推进成功进度；显式重试补齐，Close 等待已接纳写回 |

另从原 F08 压缩包读取同一测试源码、核验 SHA-256 后原样运行六项，验证 F09 接入未破坏已有 B 提交/读者/恢复。没有重写 F08 场景或重复其变异套件；A 算法及接口本轮未改，不再重跑上轮十二项 A 回归来堆数量。

## 3. 逐项目标、输入、路径、Oracle 与失败含义

### 3.1 CanonicalPagesAndReopenWriteback

- 目标：有限批次反复写回可收敛到当前已提交视图，最终页的持久格式真实可读。
- 输入：350 条三字段键，重复与不同内容混合；43–151 字节小值、9,013 字节溢出值及 UINT64_MAX 三字段键上的 19,017 字节值。随后短值改为 17,111 字节并删除一条，批次上限分别为 7、3、11。
- 路径：正式 B Create/Commit → Writeback → EncodeBody → F05/F04/F02/F01 Direct；重新装配生产栈 Open 后再次写回。没有测试页直接注入 F09。
- Oracle：测试从实际 Metadata 区 pread，独立大端解析 root/tree/RID/slot/overflow，独立逐位 CRC32C，逐键完整值与输入 std::map 比较。不开 B 的内部 getter，不调用其 codec/比较器/replay 得到 expected；最高页号和 trailer 身份也交叉核对。写回后再调用应为 Clean，重新打开则重新建立持久进度。
- 失败含义：格式/CRC/引用错误给出具体解析错误；最终集合不符说明写回数据不对应提交输入。仅 B Open 成功不算写回正确证据。

### 3.2 UncommittedChangesStayOutOfPageRegion

- 目标：新事务尚未完成 Journal durable 时，不能把它的私有页写进最终页区。
- 输入：70 条非空初始记录，先写回；将一条更新为 14,017 字节，在测试链接侧暂停 Journal fdatasync。
- 路径：真实 Commit 已写 Journal、等待 Flush；另一调用执行正式 Writeback；放行后重新写回。
- Oracle：暂停期间 Writeback 为 Clean，整个 Metadata 区逐字节等于独立保存的旧内容；放行后最终磁盘模型等于新输入。这里要求 Clean 是因为初始视图已全部写回，不把“任何时候暂停都应 Clean”作为错误契约。
- 失败含义：私有页被提前发布/选择、没有等待提交边界，或者正确提交后页面未写入。

### 3.3 ReusedSlotsKeepNewerWorkPending

- 目标：写回只确认捕获版本，不占据业务提交锁；同一物理页槽的写入与复用不会乱序。
- 输入：160 条记录写回后，再改一条为 21,019 字节；明确暂停一张溢出页的 pwrite，记录该物理页号和旧代次，并从暂停握手处重新计数以确认另一张页之后完成。此时一个真实事务删去全部旧记录再插入 320 条不同值，确保旧空闲槽被消耗，并保留原读取快照。
- 路径：F02 多 worker 的真实页写与 B Commit 交错；第二个 Writeback 调用须按正式契约拒绝。放行旧写，再有限批次写完新版本。
- Oracle：握手确认旧写正在进行、另一页确实写完；Commit 在独立 watchdog 内完成；旧完成之后仍有可写页；磁盘模型等于新输入、原快照仍等于原输入，独立读取暂停的同一物理页号，其 trailer 代次必须大于捕获代次，且不能只是 Free 标记。不得用仅比较最大 LSN 代替这些实际数据判据。
- 失败含义：IO 持业务锁、没有实际页并行、重叠写回被接纳、旧完成清除新待写状态或错误版本覆盖。

### 3.4 FailuresRetainWorkAndCloseDrains

- 目标：拒绝不动盘，接受后失败不伪造持久进度，关闭等待实际 IO 结束。
- 输入：80 条初始记录；通过既有 F02 正式 TryPrepare 占满 4,096 个操作槽；随后分别只让一个 Metadata pwrite、一次写回 Flush 返回 EIO。每次失败后显式再次写回，期间继续提交不同长值。最后暂停写回 Flush，并并发 Close。
- 路径：真实 F09/F05/F02 准入、写入、Flush、Close；只在测试可执行文件链接 pwrite/fdatasync 包装。正常路径调用真实系统调用。
- Oracle：Full 时 Metadata 区不变；接受后返回 Failed 与原 EIO，不用“没有改变磁盘”来误判部分失败；显式重试必须仍有页要写，磁盘模型正确。Flush 暂停时 Writeback 未结束，Close 在任务排空前不能结束，释放后均完成。
- 失败含义：忽略准入、吞掉错误、失败却更新完成标记、假 Flush 完成或 Close 漏等待。它不证明真实断电会保留已写字节。

## 5. 重复、价值与后续兼容

- 第一项判断最终页区，F08 Mixed 判断事务/WAL 恢复；两者不是同一 Oracle，不能用重开 B 替代前者。
- WAL 等待与 F08 发布测试有交集，但本项保护新最终页写路径在提交期间不会漏出私有数据，不重复日志格式或完整提交矩阵。
- 旧读取快照在并发场景仅作为交接判据，不另写完整读者/预算套件。
- Full/EIO 用既有 F02 真实接口构造，关注 F09 是否错误推进进度；不重复 F02 字节范围、对齐和队列算法测试。
- 不新增标准库、CRC 库或内部类构造测试。独立 CRC 实现只是磁盘格式 Oracle，不调用后端编码自证。
- F10/F11 接续最终页/恢复风险，复用数据与模型，把目前的直接磁盘判据扩展为真实 checkpoint 恢复；S8/S9 接通后使用共同 C/P 验证完整系统，不把本轮局部结果直接升级为 E2E。

## 6. 最小错误示例与测试杀伤力

八个隔离变异只作用于临时生产副本，不改工作树；必须编译/链接成功、指定场景退出 1 并出现预定业务断言，崩溃/超时/编译错误不计检出：

| 变异 | 对应判据 |
| --- | --- |
| 将 native 正文直接写盘 | 独立磁盘解析拒绝错误的大端 high-water |
| 不写 trailer | 独立页身份检查拒绝缺失 trailer |
| 只比较代次，忽略 LSN 变化 | 同代次更新后最终磁盘内容不等于输入 |
| 失败也记录为持久化完成 | 显式重试无工作/遗漏未落盘内容 |
| 取消页批次 Flush | 不能满足真实 durable 返回 |
| 忙时返回 Clean 假装接受 | 并发写回必须明确拒绝 |
| Close 不等待页写回 | 暂停 Flush 时 Close 提前结束 |
| 页 IO 期间持 B 事务锁 | 暂停页 IO 时 Commit 无法推进 |

八个变异已全部编译/链接成功，指定场景以预定断言失败；实际 XML、退出码和变异构造见第 10 节当前归档。正常实现没有因变异检验而修改生产逻辑。

## 7. 稳定性与资源

数据确定生成，没有无固定 seed 的随机数；每项 mkstemp 独立文件，退出按依赖清理。Gate 是测试进程内全局状态，各场景显式 Arm 且不并行运行；只暂停首个匹配 IO，其他页/Journal 可以继续。future 在解除暂停守卫之前声明，失败退出先释放 Gate，再等待异步任务，避免测试清理自己挂死。

10 秒 condition-variable/future 等待及 runner 超时为 watchdog，不是性能目标；Close 的 100ms 未完成观察是有限的调度证据，不是形式化时序证明。对应故意删除排空的变异用于检查它确能发现提前返回。没有 sleep 或按运行时长判吞吐的测试。

F09 每项临时文件逻辑容量 48 MiB，Metadata 4 MiB、Journal 32 MiB、Data 8 MiB；B 页上限 1024、存活页预算 4096、值上限 64 KiB，F02 自有缓冲 32 MiB、3 workers；对齐由生产查询。F08 回归沿原 192 MiB fixture。全部是 Direct 文件，未接触用户裸盘。完整构建和临时变异放 /tmp，最终仅压缩源码/日志/XML/版本证据。

### 10.2 发现的测试缺口与修正

原 ReusedSlots 场景暂停第一个任意 Metadata 页，可能是始终保留的根页；最后仅检查任意一页 generation > 1，不能证明被暂停的同一物理槽发生了复用。这是测试场景的确定性不足，不是已证实的生产错误。

增强原场景，不新增测试：只暂停已提交溢出页写，捕获实际设备偏移对应的页号和代次；确认该写已暂停后，另一张页确实完成；随后删除原 160 条并插入 320 条不同值，消耗旧空闲槽。最终除了新旧模型检查，还独立验证被暂停页号的代次增加并且保存存活内容。没有增加 production getter/hook 或额外 API。页号从实际在途 IO 动态捕获，没有写死某个分配顺序；同槽换代断言首先用于证明场景确实到达了预期风险。

同时显式使用仓库 .clang-format 格式化位于 /tmp 的测试，避免工具默认样式与仓库不同。F09 子方案的阅读入口从旧模板 BufferPool 改为实际 MetadataEngine/F05，并清除已解决的模板提问；F10/F11 未完成状态保持。
