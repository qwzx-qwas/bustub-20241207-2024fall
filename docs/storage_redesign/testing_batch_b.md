## 场景与判断

| 场景 | 实施步骤 | 独立结论与证据 |
| --- | --- | --- |
| C2 | D0，一个共享键；4 客户端各 16 次交替 Bump/ReadPoint；尾部强一致读；种子 20260920/21/22，各用新目录 | 32 次逻辑写及 33 次逻辑读；实际调用区间重叠；整个历史可解释，不能只看最终计数 |
| C3 kill | 同 C2，确认第 16 次 Bump 后停止继续派发，SIGKILL 当前 Leader、取得 wait 状态，再放行剩余操作 | 真实进程退出；恢复多数派服务；原身份解决未知写；故障后至少 8 次成功业务调用；完整历史通过 |
| C3 isolate | 同一触发点；三个接收入口全部经过代理，隔离旧 Leader 双向通信；规则 ACK 和实际阻断后另发新身份写；多数派继续，之后解除隔离并解决该写 | 新身份写在隔离期间不能 COMMITTED；代理规则、双向阻断和多数派服务分别成立；不能用隔离前已确认写假装错误 |
| C3 drop | 专用键从 0 经过 10 次确认增量到 10；外部代理收到已提交响应后丢弃；客户端确实未知，按原请求号和原 SQL 重试 | 原业务响应相同；最终版本 11，不能 12；至少 8 次恢复后业务读；代理保存的成功不作为客户端已收到成功 |
| C4 | 阈值 64；最多 256 次准备修改等待非零恢复基点，再追加 16 次确认修改；停止新写，保留身份；SIGKILL 全部进程并使用原目录重启 | 三次 wait 证据；全表独立结果正确；最后已确认身份重试不重复执行且业务响应一致；继续 8 次新写并再核对 |
| C5 short | 等目标 Follower 初始 published>=L，停止它；阈值 10000，追加 16 次确认修改；固定 K，启动目标 | 有内容的 AppendEntries 与匹配成功响应，未走 InstallSnapshot；目标 published>=K，直接向目标显式 STALE 核对全部数据 |
| C5 long | 阈值 64；停止目标后先改 256 次，必要时继续但总计不超过 1024，直到正式恢复基点>L；固定 K，重启目标 | InstallSnapshot 的请求/响应关联节点、任期、请求号；完成、成功、非 stale、匹配位置及总长度；目标全部业务数据正确 |

C5 核对目标期间停止新写，随后恢复正常业务并完成 8 次新写与全表核对。目标 STALE 读取只证明已追到固定边界的数据，不作为线性一致读证据。没有使用 CURRENT、私有页位置或内部恢复调用。

C3 在第 16 次确认后阻止新业务派发，已经在途的少量操作仍保留；故障完成边界由同一 C++ 驱动时钟记录。是否有足够故障后工作，由真实调用时刻核对，不假定第 16 条触发就必然覆盖了故障。

## 身份、重试与未知结果

- `WriteIntent` 在首次发送前保留操作、client_id、request_id 和完整 SQL。健康 C1/P2 仍只有一次尝试；未解决写阻止分配下一个请求号。
- B 可以重发同一 intent，每条逻辑写累计最多 8 次网络尝试，解决窗口 60 秒，100/200/400/800/1000 ms 退避后封顶。重启后重放最后已确认 intent，不从零建立新会话。
- 只有已识别的传输丢失、NOT_LEADER/TIMEOUT/UNAVAILABLE 允许按规则重试。协议格式或请求号错误保存为故障，不能作为普通网络抖动被重试掩盖。
- 每次尝试保留自己的调用和响应；未知写不按“没有生效”处理。输入和原始历史不改写，不把几个重试合并成一条新身份。
- 总历史最多 128 次业务网络尝试，达到上限停止并保留结果；状态轮询另存，不属于被建模的业务读写。

## 历史模型与资源

模型状态为完整共享行、已生效请求身份及其正文/已知业务结果。Bump 由模型独立递增 version、更新 last_op；ReadPoint 必须对应一条完整合法状态；同身份只能增加一次，已知的重试结果必须一致。

写入的 NOT_LEADER 也按未知处理：当前 HandleWrite 可能追加后等待，再因角色变化返回该状态；不能认定本次尝试没有效果。

未知写在检查时保留“无效果”或“生效一次”两种可能。网络超时不代表服务器取消，允许生效的上界延至这份历史的观察末尾，原超时信息仍保存在原始记录中。每次尝试使用独立展示 ID，真实生产身份仍在模型输入；不用 Raft index 给模型规定执行顺序。

Porcupine 固定 v1.3.0；搜索 30 秒，连同读取/可视化的外部进程上限 45 秒。节点清理后独立执行检查，观测 RSS 上限 1 GiB，GOMEMLIMIT=768MiB 是软目标。节点阶段仍按 600 秒、三节点 3 GiB、观察程序总计 512 MiB、产物 10 GiB 的已有预算；代理算入观察程序预算，重启后的 PID 另算生命周期。采样不是硬配额，也不覆盖样本间所有尖峰。

只有检查结果 Ok 且有效工作量、实际重叠、故障生效、恢复服务和退出检查均满足，场景才能通过。Illegal 是正确性失败；Unknown、未观察到目标路径、输入/历史不完整、资源超限分别报告，不能作为通过。
