## 二、逐项：目标 → 输入 → 执行 → Oracle → 失败含义

### 1. SegmentRangesPreserveOtherBytesAndReopen

- **目标**：定位不能被对称的错误读写掩盖；多段批次和显式持久化保持原含义。
- **输入**：一个 16 MiB 真实文件，固定公式生成非零混合内容，只有两处 F03 引导槽预先清零。两布局的 Journal 起点分别是 4/5 MiB；从真实偏移对齐 U 推导段大小 3U/5U，四个完整槽，第二布局额外有 U 字节尾部。改变起点、段步长及尾部引入不同错误模式，不只是换 seed。
- **关键边界**：自有缓冲按槽 3、0 的顺序各写整段，批次合计 2S；外部缓冲写槽 2 从 U 到段末，槽 1 保持不动。检查首槽、末槽、非零段内偏移、原有间隙及区域余尾。正文长度不同、内容不同。
- **真实路径**：BootstrapStore Create/Open → RegionManager → JournalBackend → 原 IOExecutor → 默认 Direct BlockDevice。关闭整套设备与执行器后重新 Open；读取前主动清空缓冲。没有手写 Journal reader、真实 B 或 Raft/SQL 路径。
- **Oracle**：引导完成后读取完整文件作为基底，仅在测试显式布局的 start+3S、start、start+2S+U 三处填入独立 payload；通过独立 pread 读取整个设备文件比对，不调用生产 Resolve 或从后端取物理起点。即使错误地址同时影响写入和回读，完整物理镜像仍会失败。重开和外部读取另与原 payload 比较。
- **持久化依据**：要求 writes_durable 为真并观察真实成功 fdatasync；只要求存在成功刷新，不固定精确次数。此证据验证请求传递和 OS 持久化调用，不证明真实断电下设备保证。外部 release 回调的次数观察原许可归还契约。
- **失败含义**：镜像不符指向位置、内容或边界保护错误；独立内容正确但重开读取失败需结合底层 IO 错误定位；Flush 断言失败说明适配或完成语义问题。失败不一概归咎于 F06。

### 2. InvalidGeometryOrMemberRejectsWholePreparation

- **目标**：任何非法成员不得使准备“部分成功”，外部许可仍可供下一次合法请求使用。
- **输入**：四个 3U 槽加 U 字节尾部。构造检查零、超过区域、UINT64_MAX 段大小，以及实际 U>1 时的非对齐段大小。每个非法批次至少两个成员：槽 0 合法写加一个错误成员。
- **错误成员**：槽 4（字节能落在区域余尾但不是完整槽）、UINT64_MAX 槽；槽 1 中跨越段尾但仍在 Journal 区内的范围；偏移等于段大小、极大偏移、极大长度、零长度，以及实际可表示的非对齐偏移/长度。这些不是以空请求或重叠范围触发无关拒绝。
- **执行**：真实 F03/F04/F06 构造；两种 TryPrepare 经正常校验路径。测试侧缓冲按真实内存对齐，正文初始化；两个不可修改写许可可以共享同一稳定 RAM，设备范围不重叠。拒绝后用同一组许可准备合法批次，再销毁未提交批次。
- **Oracle**：明确 invalid_argument；测试侧链接观察 pread/pwrite/成功 fdatasync，准备前后没有 IO；原许可数量未变且 release 未触发；后续合法准备可接纳并在销毁时一次性归还；独立整文件保持不变。没有生产 fd/getter/hook。测试链接观察不定义底层精确调用次数，只检验正式的“准备失败不 IO”承诺。
- **独立性**：输入直接给定非法数和布局，预期拒绝由范围契约决定，不调用 Resolve 计算 expected。已有下层也拒绝的错误不强求指定层抛出；删掉某项冗余检查未必导致黑盒失败，不能据此新增内部计数 API。
- **失败含义**：漏抛异常表明几何/边界契约弱化；许可变化说明准备破坏所有权；真实文件或 IO 计数变化说明提前访问设备。包含“仍在区域内但越段”的情况，能够区分 F06 新边界与 F04 旧边界。

## 七、稳定性与资源

- 固定数据公式，无随机 seed、sleep、网络、GPU 或测试顺序依赖。临时文件独立 mkstemp，RAII 关闭/删除；单场景一个 16 MiB 文件。原 F04 回归最多两个文件。
- 测试侧观察量为原子计数，取样在相关 IO 完成后；外部回调按值保留 Buffer 和计数所有者，失败提前退出不会引用已析构栈变量。设备/执行器沿原析构排空，未用超时取消 IO。
- 两 worker，最多八成员，自有缓冲预算 2 MiB、外部 1 MiB；全文件 oracle 是额外测试内存，未谎称纳入生产额度。测试限定真实偏移对齐非零、可支持 F03 的 64 KiB 槽且不超该 fixture 预算，环境不满足明确失败。
- 本机查询 memory=4、offset=512；由查询推得本轮 S=1536/2560，均非 production 常量。没有 statx 能力模拟；U=1 时不存在非对齐整数，此边界条件会明确报告，其他场景仍执行，不虚构非法参数。
- IO watchdog 5 秒、测试进程 120 秒、构建 -j2；这是防挂起上限，不是性能 SLO。拥挤机器或长期停顿可能触发时限，不能报告为实现错误或性能结论。
- runner 删除外部 GTEST_* 配置，核对 XML 名称、数量、run/completed 及无失败/错误/禁用/跳过。本次故意设置 NoSuchTest 与分片环境，仍实际运行 2+3 项。
- mutation 检查要求指定测试名、指定 oracle 文本、退出码 1 且无检测器报告，并逐条人工复核日志。编译失败、零用例或崩溃不能算命中。
- 依赖 Linux/Clang14、真实 O_DIRECT/statx 支持；不是不同硬件对齐能力的全面验证。未测真实断电、裸设备、TSan 或性能。
