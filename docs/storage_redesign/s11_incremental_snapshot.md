# S11 / F25：节点间增量快照

2026-10-07：用户已授权方案、实现与测试。本节接续 [共享快照](s11_shared_snapshot.md)，本轮尚未完成；执行证据另记。主责仍为 F25，配合 F28/F13/F14 及现有 Raft 传输，不新建同职责服务。

## 1. 已确认的取舍

- 传输发生在 Raft Leader 与 Follower 之间。发送端比较自己的两份固定快照；接收端复用自己的基础快照，物理地址不跨节点传递。
- 沿用 index/term/CRC32C 身份与现有格式/长度核对，不增加 SHA 或全局内容寻址。接受原校验的风险边界，不称 CRC 为无碰撞证明。
- 差异只按固定映射的原 owner、allocation 和范围判断。同一不可变内容可复用；无法证明相同就发送新正文。不做新旧正文比较，也不新增 changed bitmap。现有生成/接收完整校验仍保留。
- 传输描述可以增量，最终持久目录仍完整，恢复不追溯增量链。完整目标页面目录表达页面删除；Catalog/Session/恢复边界随完整头部传输。
- 格式限当前原页流 BSPAGE01；canonical/文件 Store 保留全量。压缩、跨重启续传及 F35 全面异步仍未在本轮启用。

## 2. 协议与资源

**先行审查发现的待确认项：传输基础保留。** 当前 `previous` 同时承担恢复入口职责，Leader 留有从它开始的 bridge log。拥有同一基础的 Follower 通常可直接补日志；等 Leader 又发布一代、裁剪到更新恢复边界时，该基础可能已退出两代清单。因此，仅以 `previous` 为增量基础不能据此宣称真实追赶已获得收益。已向用户提出选择：推荐最多额外保留一个独立传输基础；另一种是在日志仍可补齐时改变追赶策略、优先尝试增量。选择未返回前，不修改持久保留和正常日志追赶决策，不标记整轮完成。

1. 已实现的差异机制暂以发送端 `previous` 为基础、目标为 latest；最终自动选择须接续上述保留决策。接收端在 latest/previous 中确认身份、长度、格式、边界，先取得整次使用 lease 再确认。没有匹配基础返回 unsupported。
2. 保留现有全量 RPC 字节编码，增加 Offer/OfferResponse 和增量分块类型。未获 Offer 确认，在一个 heartbeat 周期后走原全量；旧二进制不识别新 Offer 时也不依赖它处理增量。确认后错误不转换为 unsupported。
3. 每块明确目标逻辑偏移，包含 DATA 或 REUSE(基础偏移、长度)，最多 64 KiB，按数据库页边界组织；连续同类范围可合批。响应进度为已构造的目标逻辑前缀，不是网络正文累计量。
4. Offer 的 request id 标识会话，结合 term/leader/target 隔离迟到请求；重复块必须与已接受记录/正文一致，不能重复加引用。接收停滞、换 term、转选举和改走全量退出会话。每节点仅一个接收候选，每 peer 一个发送状态。接收端沿用发送端已有的递增请求号，保留当前 term 的快照请求边界；旧 Offer/旧全量块不能取消较新的会话。当前 Offer 重发并再次被接受时续期。会话结束后仍保留该边界，进入新 term 时清除，不持久化接收进度或新增网络字段。
5. 复用已有 max_snapshot_bytes、IO/提交额度；描述条数至多目标大小/页大小，正文工作缓冲至多一个有界块。基础与目标目录有相同上界；不收集整份正文到 RAM。
6. 增量协商确认前，沿用 S8 的最终清单预检：计入目标发布、私有正文退役及可能退出的旧入口。Raft 验证完成后才决定是否保留旧恢复入口，因此预检覆盖两种发布结果所需的最大额度。额度不足时，在创建新候选前明确失败，不先收正文再发现清单无法提交。此检查只针对已知配置上限，不承诺随后设备写入或动态空间申请必然成功。它保护新申请的容量及已发布状态；Raft 开始更新的协商时可以取消尚未发布的旧接收，不承诺新协商失败后继续旧接收进度。

## 3. 接收布局与发布

头部首先作为 DATA 接收。所有网络 DATA 按序写入私有正文对象；仅记录有界的目标范围→正文来源说明。写完后，新快照对象扩大逻辑长度，逐范围共享私有正文或本地基础正文。这个目标对象不再执行覆盖写，避免不同分配粒度下的扩展写与共享映射相撞。

私有正文不是第二份复制：最终快照直接共享新正文的分配，不再复制一遍正文；底层 Common 追加仍可能存在对齐/COW 写放大。私有对象随 Manifest 发布在同一提交中退役，F14 保护被引用的单位。目标目录和共享引用持久化、完整校验通过后，沿用原 Validate/Install/后缀接续。中断候选不成为恢复入口；重启沿原所有权登记清理候选，从零接收。阶段收尾关闭 lease 后才允许物理回收。

## 4. 开源参考与内化

- [Ceph RBD snapshot mirroring](https://docs.ceph.com/en/latest/rbd/rbd-mirroring/)：fast-diff 借助变化跟踪避免扫描全镜像正文。本项目先使用已有不可变映射身份筛选，不照搬新的 object-map/bitmap。
- [RocksDB BackupEngine](https://github.com/facebook/rocksdb/wiki/How-to-backup-RocksDB)：识别已有不可变 SST，备份各自保存完整文件清单。本项目保留完整目标页目录与独立引用，沿用现有身份而非新增哈希机制。
- [Btrfs send](https://btrfs.readthedocs.io/en/latest/dev/dev-send-stream.html)：发送 extent 复用说明而非正文，发送格式独立于两端物理布局。本项目 REUSE 指基础快照逻辑范围，接收端查询本地映射。

## 5. 实现顺序、审查及测试

先行逻辑审查：固定目录解析复用、内容身份比较、lease 交接、不同分配粒度、消息重复/换代、失败不发布、恢复和 GC。之后按顺序实现目录解析→F25 差异/候选→RPC/节点接入→生产路径验证。复用原 F25/S8/F28 测试，新增增量与全量同目标恢复、错误基础、删除/修改/新增、取消/GC/重启、重复块及网络传输量判据。原 C/P 内容不变；发送字节减少不等于已完成性能比较。

代码要考虑复用性，间接性，安全性，不要破坏别的模块和层次的production级代码；接续完成前检查冗余旧代码、未用接口并删除。不要过多纠结于边界条件和防御性编程，防止可能出现的问题被掩盖。先从代码逻辑分析，确认后再写必要测试；不要一开始通过编写回归测试检验。

测试应该保护“这个项目自己承诺的行为和风险边界”，而不是给每一层实现细节、第三方库行为和历史重构痕迹都建立一套测试。写完走总方案八项设计审查，禁止 production test hook/getter/默认路径污染；模块测试只压缩归档，替换本模块旧包，独立依赖包保留。
