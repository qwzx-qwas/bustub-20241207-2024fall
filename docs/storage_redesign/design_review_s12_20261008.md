## 3. Calico 的优势落到哪里、尚差哪里

依据 [Calico v1 §4.1–4.4](https://arxiv.org/html/2604.00423v1#S4) 核对：论文将逻辑页翻译与帧内存支撑分离，结合零无效编码、按需内存和冷翻译组归还。本项目的具体边界如下；细节唯一入口为 [F26 §3.5](modules/array-buffer-pool.md#35-按需翻译内存bitmap-与-hole-punching)。

1. `buffer_memory::Region` 使用匿名私有 mmap，不预触整个翻译叶；多级目录按需创建。末级按 suffix 索引，PathCache 避免重复走前缀目录。
2. `TranslationEntry::word_{0}` 的全零状态有效地表示未驻留。实际帧号存为 `frame_id + 1`，帧编码 0 表示无帧；并非拿帧号 0 冒充无效。
3. **首次 Access 先显式构造该 OS 页内的一组原子条目，再获取条目保护。** 因而当前是按首次组访问物化，不是论文所描述的“只读空条目仍只依赖共享零页、首次有效写入才物化”的完整路径。这样定义 C++ 原子对象寿命，但会提早触发该组内存使用。
4. 淘汰时清空帧编码并递增翻译版本，不要求整个 64 位字始终归零。回收依据是 `live_entries_ == 0` 加组独占保护，不扫描全字判断；组析构后 MADV_DONTNEED 归还 RAM，下次按原路径重新构造全零条目。不能直接删版本或同步来追求全字归零。
5. 叶虚拟地址、组控制及上层目录仍保留到目录销毁。归还的是空闲末级翻译组的物理内存，不是全部元数据、帧正文或设备空间。FrameArena 的大页建议与翻译区的基础内存页策略分离。

因此，已经具备“快速数组定位＋无需常驻全量翻译 RAM＋空闲组可归还”的核心能力，尚未完整实现纯只读零页路径、无锁正文读取，也没有本项目 SS/RS/PL/GT 的性能成绩。后续只读命中和组寿命改造继续归 F26，不新增目录模块。
