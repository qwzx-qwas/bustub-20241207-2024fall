## 1. 公共 CRC 与 B 页读取

保留 CRC32C 的多项式、初始/最终取反和 Extend/Combine 接口。x86 支持 SSE4.2 时一次选定硬件实现，否则使用可移植查表实现；不全局开启机器专属编译选项。批次内仍保留各持久单元的校验边界，固定正文后计算；已有分块校验可通过 Combine 合成，不能把独立单元改成一项延后校验。读盘校验必须先于使用。

B 冷页与 checkpoint 读取经 CheckDiskPage 后，解码正文、复用已验证页尾和 LSN，不再调用生成新页的 Seal 重算。内存正文和盘上正文不同，禁止整页拷回覆盖解码结果。新页/修改页继续 Seal。

## 2. F14/F22 有界哈希分组

同一对象最多 16 个 allocation 共用一次 PendingRange 扫描。游标携带固定发现视图及按 allocation 分组的候选记录；每轮扫描和每 allocation 保存记录都不超过既有 `max_scan_entries`。发现缓冲先取得 F31 额度，跨对象不混用身份。扫描完成即释放 B 视图，释放事务仍按当前版本核对记录、剩余所有权、共享引用和 IO/pin；直接引用分组结果，不再复制整组。发现结果不是新的权威索引，不持久化；冲突后复核，关闭丢弃。仍是一批共用一次扫描，并非哈希函数能直接从盘上找到全部旧记录。

## 3. F28/F25/F35 捕获与后台构造分离

在完整 Apply 边界固定 index/term、Catalog、Session、脏页副本和已持久范围保护。实际完成捕获且既有执行器接纳后台工作后，协议线程才解除业务收束。后台只使用捕获内容，不再读取活动数据库的最新版本。克隆、正文写入和 checksum 不占用 Apply 执行角色。

后台构造的是未发布候选；完成事件交回序列化协议所有者，复核目标是否仍适用，再沿原 Manifest 发布、日志保留和回收顺序推进。新任期不能使旧完成事件回滚状态；已安装更高快照时丢弃旧候选。关闭排空已接纳任务并处理候选，资源紧张时不把“排队未接纳”当成已交接。旧文件/KV 状态机不支持固定共享捕获时沿原路径。

允许捕获本身等待必要保护/IO，不承诺零暂停；目标是移出捕获后的耗时构造。F28 小恢复根的提交仍持生命周期锁、可能等待持久化；Clone/正文写入/checksum 不持该锁。独立 F28 请求保留现有有界预刷，Raft 共享捕获直接保存尚脏正文，不等待整轮刷出。正常快照触发不再同时安排独立 F28 候选。普通页版本、已捕获范围、候选与已发布恢复入口分别沿既有所有权管理，不取消必要保护。

## 4. F23 恢复探测复用

对象日志探测返回拥有已验证索引的未挂接 LogStore 候选，恢复边界查询复用该候选。验证状态机/快照和 term/commit 边界后再完成 Open/Attach；不再重复构造 ObjectLogStore。候选失败直接销毁，只在原本允许的完整快照覆盖场景重建日志。本地 checkpoint 不得超出 effective commit 的检查提前到探测前，避免探测失败时访问不存在的候选；term 核对仍在获得已验证索引后完成。文件后端保持原恢复协议。未改变磁盘格式或段顺序；不以缓存旧正文替代实际恢复校验。
