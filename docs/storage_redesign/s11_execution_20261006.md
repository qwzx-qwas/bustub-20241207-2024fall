# S11 / F28 本地业务 checkpoint：实施与八项测试设计审查

2026-10-06，基线 `e4d8703`，实现与本文随同一 S11 提交保存。协议：[S11 共同方案](s11_business_checkpoint.md)。本轮本地恢复点与最小共享保留：**已完成**。跨节点增量、压缩、统一后台调度/压力预算未因此完成。

## 1. 具体改动及逻辑审查

先审生产依赖、锁与恢复顺序，再写测试；没有通过先堆回归用例决定设计。

| 位置 | 本轮改变 | 所保护的行为 |
| --- | --- | --- |
| `object_mapping_internal.h` / `object_mapping.cpp` | 新建格式 v4；共享映射保留原 owner/allocation；切片同时增减 SharedUnit；旧 v1–v3 保留原能力 | checkpoint 引用固定字节，活动对象后续覆盖不能偷换版本 |
| `object_reference.cpp` | 保护读取时使用原内容身份；回收扣除持久共享单位 | 当前 owner 退役或重启之后，旧 checkpoint 仍可读；只保留仍需要的单位 |
| `node_storage.cpp` | 正式 ProtectObject / ShareObjectRange 接入；下层 Share 收为 private | 先持有源范围，再发布共享引用；不允许调用方裸传物理地址绕过保护 |
| `page_storage.cpp` | 捕获页空间、克隆共享表页、密封 v2 描述，保留真实 next_page；registry item 0 是恢复根 | 候选完整不等于发布；重启清理不能删除正式恢复点；索引重建不能重用旧页号 |
| `buffer_pool_manager.cpp` | 有界预刷、边界内复制尚脏表页；预先 reserve 控制副本容量 | 固定的是当时字节，不是后台执行时已经变化的缓冲；IO 等待在捕获外 |
| `table_heap.cpp` | 根据当前表成员捕获页号，派生索引页不共享 | 页内整理/空页退役之后仍能准确保留有效表链 |
| `raft_state_machine.cpp` | 一个后台候选；Catalog/Session/表页同一 Apply 边界；后台共享/保存后原子发布小根；恢复页空间并重建索引 | 业务内容、去重结果及 Raft index/term 一致；失败不推进成功边界 |
| `persistent_state.cpp` / `raft_node.cpp` | 接受已验证 local checkpoint＋提交后缀；较新的 portable snapshot 仍可接管 | 不把未核对的本地页当成 Raft 权威，不回滚已提交后缀 |
| `distributed/node.cpp` | 累计 applied 条数触发，Poll 报错，Stop 排空 checkpoint | 接收任务与 durable 发布分开；工作未结束不能销毁其依赖 |

重点逻辑核查：

1. 源临时 lease → B 中持久共享引用的交接期间没有无保护窗口；物理 GC 与引用增加使用同一个 B 事务版本检查。
2. 共享的是原 allocation 的内容，S10 的完成记录改变保存位置，不能改变字节。恢复后仍查询这个 allocation 的任务状态，复用 Journal/Data 读取，不复制第二份 Deferred 任务。
3. 密封候选完整后才发布 control 根；旧根退出后再删除旧候选及共享引用。失败/未发布候选留在原登记链，重启通过原清理机制处理。
4. 先恢复页号高水位，再调用既有 Catalog 恢复/索引重建。Catalog 内已有的高水位设置只取 max，不会把它降低。
5. Worker 不持业务锁等待刷盘；捕获阶段仍有 CPU/复制及映射保护成本。所有后台候选只有一个；不会每条日志生成一个 checkpoint。
6. Worker 所引用的 WorkingState 在并发安装快照时保持存活；销毁 FSM 先等 worker 结束，再销毁其成员。捕获内容的本地变量使用 optional，清除无实际共享用途的 shared_ptr。
7. F14 单位粒度持久共享计数与原分配剩余所有权配合，不新增 allocator 或第二份 bitmap；未来原地写策略必须同时服从共享不可变约束，本轮仍为 COW/新目标 Deferred。

## 3. 逐项：目标 → 输入 → 路径 → Oracle → 失败含义

### T1

- 目标：恢复同一业务边界，去重结果与表内容一致，之后的 committed entry 只在需要时接续。
- 输入：非空 SQL；两条不同主键/金额/字符串记录、二级索引；checkpoint 后更新；恢复后另建表，插入 40 条约 180 字节正文、删除多数记录，第二次 checkpoint/恢复后再插入。
- 路径：真实 PrepareSql → Raft LogStore/StableStore → Apply → F28 worker → F26/F13/F14 → Direct 文件；重开 NodeStorage → 本地恢复 → Catalog 重建索引 → Raft 后缀。
- Oracle：手写行值、保存的已返回 Session 结果、确定的 checkpoint index 和后缀。通过 SQL 查询索引/数据可达性，不用实现计算 expected。删除真实高水位恢复时实测报“database page identity is retired”。
- 失败：可定位到恢复状态/会话/页身份链，但一条用例覆盖组合路径，需结合失败查询和异常定位具体层。

### T2

- 输入：真实两条业务操作后，在链接层阻挡 Data `pwrite`；没有 production hook。
- 路径：正式 RequestCheckpoint → worker → 真实 F02/F01，另一个调用等待正式 DrainCheckpoint（Node::Stop 使用同一接口）。
- Oracle：先用测试侧 promise 确认排空线程已开始执行；IO 尚被闸门阻挡时 Request 已返回、重复请求未接纳、published 为零、Drain 尚未返回；放行后完成，重启查询得到原正文。
- 失败：任务交接、发布进度或生命周期不正确。30 ms 用于“确定阻挡时仍未完成”的负断言，不是延迟/吞吐指标；全程 watchdog 防止挂死。

### T3

- 输入：先发布有效 checkpoint，再提交新 SQL 更新；一次真实 Data 写返回 EIO。
- 路径：原 worker 异常 → Drain/Poll → 关闭故障实例 → 重开设备/恢复根 → 应用已提交后缀。
- Oracle：Drain/Poll 必须报错；重启先读旧值 40，再应用唯一后缀得到 99。预期值来自 SQL 输入。
- 失败：错误被吞掉、提前切根或旧根不再可恢复。本例注入在保存过程中，不枚举每个 root 提交系统调用的失败点。

### T4（第二次复审替换原组件拼装）

- 目标：生产 F28 worker 必须把一致边界捕获的脏页正文保存进正式 checkpoint；后续已提交 Apply 不能改变捕获内容或 Session。
- 输入：80 条不同主键和不同 300 字符正文的 SQL 记录；按实际内存对齐计算借用缓冲预算，将现有 PageIO 能力限制为每批一页。工作集可驻留在真实 BufferPool，预刷无法一次清完。
- 路径：真实 Prepare/LogStore/StableStore/Apply → RequestCheckpoint → F28 预刷/捕获/共享/脏页保存/根发布 → 重开设备/Catalog/Session → 查询与已提交后缀重放。测试不再调用 Capture/Clone 或手写候选保存循环。
- 执行：后缀日志及 HardState 先持久化，暂不 Apply；用输入中的唯一正文标记在 Data 写处暂停 checkpoint worker，再 Apply 后缀，查询活动状态已变；放行后等待发布，再重启。
- Oracle：恢复边界和 Session 必须仍是捕获时的 index/已返回结果；80 行逐行等于输入构造的旧值；重放唯一后缀后只修改指定行。旧值与新值都由 SQL 输入决定，不根据内部映射重算 expected。
- 失败：实际 worker 漏存脏正文、捕获与后续 Apply 混合或后缀恢复错误。正文闸门只组织执行顺序，最终判据是可恢复的表、查询结果和 Session；不把闸门命中单独当作内容正确。
- 限制：闸门依赖当前明文页在实际 Data IO 中可匹配输入字节，未解析 slot/page_id/extent。未来若引入压缩/加密，需要调整这一测试适配，不改业务 oracle；该场景不是三节点或物理掉电测试。

### T5

- 输入：Data 区仅三个分配单位，正文占满；共享至另一对象，原 owner 删除；后台 Data 写先阻挡、后 EIO；B checkpoint 后重启仍保留任务，再放行落位；解除中间单位，最后退出两侧。
- 路径：实际对象事务/共享事务 → B/Journal → 后台 Data → 重启来源解析 → F14/F12 回收 → 新对象重新分配并写入。
- Oracle：正文来自独立确定性字节数组；未落位和重启后必须读到同样内容；中间回收后读空洞为零，两侧保持原值。小设备上新对象写入成功，证明空间实际可复用，不能只靠 `released_bytes_` 自证。最后分配两侧时中间新对象内容不能受损。
- 失败：共享来源身份、恢复保留、局部引用或分配归属错误。部分 source-state 断言用于确认真正走了 Journal 路径，不替代最终字节/容量 oracle。

### T6

- 输入：本地 checkpoint 中 value=10，后续 portable snapshot 中为 20，再有 committed 后缀改为 30。
- 路径：两种正式 Store/恢复入口、Catalog/Session 装载及日志接续。
- Oracle：重启边界为 portable snapshot，查询 20，接续后缀为 30。
- 失败：恢复选择或后缀边界错误，与 T1 的“优先本地恢复”不同。

### T7

- 输入：父进程先停止所有存储 worker 再 fork；子进程打开真实设备，更新非空业务数据、发布 checkpoint 后 `_exit`。
- 路径：正式数据库/存储链；子进程跳过析构、工作空间退役和 NodeStorage::Close，父进程重新打开。
- Oracle：查询得到 `published-in-child`，index=3，同一请求被识别为 RETRY_LAST。
- 失败：发布成功依赖关闭补写或重启清理错误。进程退出不等同主机断电/设备断电，子进程 `_exit` 也不会进行 LSan 正常退出扫描。

### T8（复审新增）

- 目标：本地恢复边界与已提交日志不匹配时，拒绝必须先于 Raft 恢复材料清理。
- 输入：真实 SQL 生成 index 2/3 两个 portable snapshot，日志基点已推进至 3、旧快照尚未清理；再提交 index 4。通过正式 checkpoint 请求故意提供与日志不同的 term 9（真实日志 term 3），形成完整但不能接受的本地恢复描述。
- 路径：SQL/LogStore/StableStore/F28 → 关闭并重开真实对象设备 → `RecoverRaftPersistentState` → 正式只读 Probe；不是伪造 BufferPool 或替换数据库。
- Oracle：恢复必须抛错；重新打开 SnapshotStore 后最旧/最新快照仍为 2/3，HardState commit 和日志末尾仍为 4，日志基点仍为 3、term 仍为 3。预期来自显式操作历史，不依据生产分支计算。
- 失败：抛错缺失，或者拒绝之前已产生不允许的恢复历史清理。它不枚举所有磁盘损坏；错误 term 是有意的非法输入，保护的是项目恢复拒绝边界。

## 4. Production pollution / 接口审查

| 新增/修改接口 | 实际生产调用方 | 删除测试后是否仍需要 |
| --- | --- | --- |
| BPM `FlushDirtyPages` / `CapturePages` | F28 BuildLocalCheckpoint | 需要：减少捕获时脏内容、固定 RAM 字节；不是测试 getter |
| TableHeap `CheckpointPages` | F28 捕获表成员 | 需要：不遍历 tuple、不把派生索引正文重复保留 |
| PageStorage `Capture/Clone/Seal/SealedPageCount`、带保留集合的 `RetireAbandoned` | F28 候选/恢复/清理 | 需要：定义不可变页版本和排除正式入口；原无这些生命周期语义 |
| NodeStorage `ProtectObject/ShareObjectRange/SupportsObjectSharing` | PageStorage / FSM 启动 | 需要：统一源许可、共享事务及格式能力；没有暴露 F12 内部状态 |
| Mapping `SupportsSharing`；private `Share` | NodeStorage | 需要。Share 未扩大成无保护的 public 物理写接口 |
| RaftStateMachine `LocalRecoveryPoint` | PersistentState / RaftNode | 需要：声明并核对已恢复业务边界；KV 默认无本地恢复点保持兼容 |
| FSM `RequestCheckpoint/PollCheckpoint/DrainCheckpoint` | DistributedNode 请求/观察/关闭 | 需要：生产 worker 生命周期和错误传播 |

没有新增 test-only getter/hook、`#ifdef TEST`、为了测试放宽生产默认路径或格式检查。格式 v4、descriptor v2、旧格式能力分支都是生产持久化兼容要求。私有 Descriptor 的可选 sealed 参数和新增结构字段默认 nullopt 用于保留旧调用/编码，不是测试便利默认值。测试故障闸门、S8 fixture 参数和包装器仅存在压缩源码/临时链接命令中。

## 5. 重复性、兼容与退出

- T1 与 T7 都读恢复结果，但 T1 覆盖优雅退出原 owner 后的持久共享/多代恢复，T7 刻意跳过关闭；风险不同。
- T1 与原 S8 SQL recovery 有重叠，但后者验证 portable snapshot，前者验证页版本根和重建高水位，保留各自恢复分支。
- T5 与 F27 都看 Journal/Data 切换；F27 无持久共享 owner，不能替代 T5。没有复制整个 F27 场景。
- T4 已替换为完整本地业务路径，不再保留旧的手工候选保存循环。它与 T1 共用业务恢复结果，但 T1 的小工作集可能预刷即清空，不能覆盖 F28 脏页保存步骤；T4 使用小预刷预算和捕获后的 Apply 验证这个不同风险。
- 既有归档只作为依赖解压到 /tmp，原源码与 oracle 不变。S8 延用已有 page-backend 适配；新增 fixture 开关只为 T5 在 Create 时配置匹配 Deferred 正文的 Journal 上限，原八例默认值不变。
- 常驻共同 C/P 内容、旧性能结果均未改。8 项新源码本轮结束仅压缩保留；不新增常驻 CTest 目标。

## 6. 首轮定向变异：实测可发现的最小错误

隔离编译生产源副本，不修改工作树/正常静态库；五个变异均由测试断言/异常检出，编译失败或超时不算检出。

| 变异 | 对应测试 | 实际失败依据 |
| --- | --- | --- |
| GC 忽略 SharedUnit 保留 | T5 | 应保留的范围被释放，释放字节与后续受保护读取失败 |
| 查询 Deferred 时用克隆对象身份代替原 owner | T5 | 尚未落位的共享读取正文与输入不符 |
| CapturePages 不保存脏页字节 | T4 | 多个候选页 memcmp 不相等 |
| 不提交小恢复根却报告 published | T1 | 重启缺少 LocalRecoveryPoint |
| 不恢复真实页号高水位 | T1 | 后续索引重建碰到已退役页身份 |

## 7. 稳定性、失败分析和局限

- 各测试独立临时镜像/目录；字节数据确定性；TCP 端口沿用既有运行时预留方案，不固定机器端口。测试不依赖用例顺序。
- 链接层闸门有退出清理；超时 runner 杀进程组（含 fork 子进程），不遗留阻挡线程。允许的调度等待不是性能结果。
- 初次运行 12 个 Deferred 断言通过但 LSan 因沙箱进程检查限制退出失败：没有计为完整通过；转为允许本地检查的执行环境后，ASan/UBSan/LSan 保持开启并完成最终验证。
- 初版 T5 复用了 S8 的 8 KiB 记录上限，却提交更大的 payload，随后尝试在 Open 改该上限又被格式校验拒绝。两次都属于测试部署错误；修正为 Create 时配置实际预算，生产校验保持。失败日志保留在压缩证据中。
- 隔离编译 F28 变异一度缺少项目已有 libpg_query 头文件路径，补齐后才实测；该次编译失败不算杀伤力证据。
- 只验证 Direct 普通文件、真实数据库和本机三节点。未运行裸设备/真实掉电、TSan 或前后性能比较；没有扩大声称为这些场景已验收。
- 还未穷举新清单每个字段损坏/每个系统调用中断；未量化大 Catalog/数百万页捕获暂停、共享元数据量、写放大、预刷收益。资源上限可能导致显式失败，不能据小负载通过宣称规模能力。
- 本轮不新增持续 eviction 清理器：预刷是一次有界批次；原 canonical snapshot 仍会生成。S12 再讨论全局预算/公平调度，F25 继续讨论跨节点共享、增量、压缩。

## 8. 最终测试矩阵与结论
