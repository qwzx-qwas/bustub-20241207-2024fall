# S11 / F25：固定业务页的共享快照

> **2026-10-07 增量接续已授权、实施中**：[当前增量协议与 prompt](s11_incremental_snapshot.md)。沿用 CRC 身份；只比较固定映射，不比较新旧正文。共享/全量部分已有完成标记仅指原轮范围，压缩仍待后续。

## 1. 本轮范围与依据

用户已授权本轮方案、实现和测试。接续已完成的 F28；复用 F25 Manifest、传输 lease、候选/发布/退役状态，F13/F14 持久共享和 S10 来源解析。增量、压缩及 F35 协议线程解耦留在后续。SS/RS/PL/GT 的补充设计见 [翻译访问评测](testing_translation_access.md)，本轮不更改原 C/P 基线或执行尚未冻结的性能负载。

[RocksDB checkpoint](https://rocksdb.org/blog/2015/11/10/use-checkpoints-for-efficient-snapshots.html) 共享不可变 SST，清单负责确定完整数据库状态。本项目内化为：已固定的表页范围直接共享到 F25 已有候选对象；对象拥有独立持久引用，不依赖 F28 当前根一直保留。不是 POSIX hardlink，也不对活动 BufferPool 帧直接共享。

[Raft §7](https://raft.github.io/raft.pdf) 用 lastIncludedIndex/Term 确定快照与日志后缀的连接点。本轮坚持请求的准确边界：先等待已有 F28 任务，必要时请求该边界的 checkpoint；读取根后核对 index/term，不能把较旧内容标成较新位置。复制出的清单已经冻结；之后业务 Apply 可以继续，checkpoint 发布/退役与取得共享引用串行协调。当前 Capture 同步入口可能等待 checkpoint；不宣称整个过程无阻塞。

## 2. 表示及生命周期

发送端只有一个 F25 普通对象：有界头部（末尾含正文校验值）+ 紧凑表页流。头部记录格式/页大小、index、原页号高水位、按升序排列的表页号、一次 Catalog 和 Session 编码；页流按目录顺序保存原表页。索引按定义重建，不保存物理索引页；页空间按较大分配单位写入时产生的零填充映射可随页目录一起描述。头部对齐数据库页大小便于共享，设备 IO 对齐仍由 F01 实测/F02 处理。

新格式 `BSPAGE01` 明确区别于旧 canonical `BSBUND01`；版本 1 采用当前 TablePage 物理表示，只支持相同页格式的节点。页格式改变必须升级版本，不能把该表示宣称为跨架构的通用数据库交换格式。总长沿用 F25/codec 原有上限；页目录及 Catalog/Session 有界，先检查再扩展候选。CRC32C 校验整个流，发现损坏不能回退成另一种格式。旧格式保持可读，非对象部署或不支持共享的旧设备继续 canonical 路径。

源表页共享到候选对象中的新逻辑偏移：F13/F14 保留原 allocation/owner，目标有独立引用。候选完整、正文校验完成才走原 F25 Manifest 原子发布。失败候选按原 ownership 清理；启动不能从“存在的对象”猜测发布状态。后续 F28 根退出、业务 COW、页回收不得破坏快照。传输持有整次会话 lease，两块之间不能回收；旧快照退役后等待 lease 再走既有 Collect/F14。

Deferred 页面仍按固定分配身份解析 Journal/Data，不把地址写入传输格式，不复制一份待写回任务。Header 只保存页逻辑身份；接收端不能使用发送端物理地址。

## 3. 接收与兼容

复用 F25 Stage 的顺序块、完整校验、重复块正文比较、失败不发布和重启从零规则。状态机识别格式后，在新的工作空间按原页号装入表页、恢复高水位，复用 Catalog/Session 校验及索引重建。校验与安装沿生产入口完成，错误不替换原状态。原清单发布、Raft 安装、后缀恢复次序不改变。

发送端减少表记录扫描重建和页正文写入；Catalog/Session 仍编码到每份快照自己的小头部，不宣称消除了所有控制信息复制。仍有目录遍历、共享元数据提交及校验读取成本。接收端首轮仍需写入本地页和重建索引；没有声明增量传输、压缩或零成本快照。

## 5. 回收隔离接续

组合验证发现 F14 会先隔离整片退役候选，再排除其中仍被共享使用的范围，导致有效快照读取短暂报 Busy。修正为：先查询持久共享引用，在引用锁内合并在途读取、选择真正要释放的单位，仅对选中范围建立隔离；然后释放锁执行元数据提交。没有空间可释放时不建立隔离。B 基于原视图提交仍负责拒绝并发元数据变化，不能跳过该校验。

这不是通过重试吞掉错误，也不新增 GC 服务。新增确定性验证暂停真实回收提交，要求仍被引用的中间单位可以正常读取；原有上下两侧回收和物理复用验证继续复用。

## 6. 不把数据库页大小当作分配粒度

头部校验通过读取固定版本计算，先写完头部；此时对象逻辑长度只到头部，Common 扩大处理范围不会提前把后面的页流映射成 Data。随后 Resize 留出页流空洞，逐页共享；共享完成后没有尾部写入。这样不需要新建暴露 allocator 内部状态的 getter，也不假定分配单位等于 4 KiB。接收端从有界头部计算页流位置，校验时排除头部内的校验字段本身，继续覆盖目录、Catalog/Session、填充及全部页正文。
