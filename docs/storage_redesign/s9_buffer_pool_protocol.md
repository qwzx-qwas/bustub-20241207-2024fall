## 3. 分层、身份与对象组织

```text
A 的表/索引/执行器
  → F26 数组 BufferPool：页号 → 当前内存帧
  → A 页后端：页号 → 普通对象及逻辑范围
  → F13/F14 + Common：物理映射、引用、提交
  → F02 → F01

B 的树/版本页访问
  → F05 + F07/F09：基础寻址、WAL、写回
  → F02 → F01
```

1. 保持 `page_id_t=int32_t`、合法非负页号和现有 RID 格式。31 位用于本地页号；不为数组改持久页号宽度。
2. 持久身份为“数据空间身份 + 页号”；打开实例另外具有运行身份。A/B 同号页、新旧工作库同号页不能混用。普通重开不强行改持久身份；重建 A 工作库使用新空间。
3. 数据空间及运行身份由目录上下文携带；不在每个 8 字节条目里重复记录。异步任务保留所属上下文和帧复用身份，不能仅保存 page_id/frame_id。
4. A 的页到对象采用既定确定性分组：令 K 为该工作空间的 pages_per_object，则 `object=1+page_id/K`、`offset=(page_id%K)*page_bytes`。K 与页大小属于空间描述，不能在打开时任意换值；K 的部署值及描述编码在 c 的页后端实现前确定。这里不是 prefix 的语义，也不保证物理连续。
5. 翻译目录是易失状态，重启重建，无需 WAL。对象映射、空间归属仍由已有 B/FS 持久化，不重复保存另一份 extent 表。
6. S9 延续已验证快照+Raft 日志重建 A 的恢复权威。已写出一批活动页不等于形成了 S11 业务 checkpoint。工作库创建/切换/退出必须接入 F34，不能仅删旧工作目录就认为旧对象已删除。

## 4. 数组条目、目录与状态所有权

prefix 按页号区间定位叶数组，suffix 作数组下标；首轮采用既有候选高 8 / 中 7 / 低 16 位，三级容量分别为 256/128/65536，下层按需建立。它是 RAM 布局，不是持久页号格式；叶虚拟范围为 512 KiB，实际 RAM 按 OS 页物化。PathCache 首轮每访问上下文最多 8 项，具体同步和总额度见 §12；这些选择可通过同口径测量修订，不改变外部页号。

TranslationEntry 采用 64 位表示，低至高为 frame 编码 32 / version 24 / latch state 8。编码用掩码与移位，不依赖位域 ABI。frame 0 合法，编码为 frame_id+1，零表示无帧。version 是易失翻译版本，不是 LSN、Raft index 或永久唯一身份。完整身份保护不能仅依靠 24 位版本不回绕。

| 状态所有者 | 保存及决定的内容 | 不承担 |
| --- | --- | --- |
| TranslationEntry | 页到帧指向及该指向的同步/发布 | 页正文读写锁、设备任务队列 |
| FrameHeader | 所属页、复用身份、pin、内容保护、脏版本 | FS extent 分配权威 |
| 页加载/写回任务 | 接纳阶段、IO/提交结果、等待者、资源保留 | 另建永久页目录 |
| 翻译回收组 | 活跃访问、加载/发布保留、可回收候选 | 数据库记录可见性 |
| F33 | 节点可服务能力与故障条件 | 每次页访问的审批 |

概念页状态为：Absent → Loading → Resident；Resident 可进入 Writeback 或 Evicting。这些由上述所有者组合表达，不要求在每层复制一个枚举。加载失败不发布半页，等待者收到本次错误；脏页写回失败保留旧身份与脏内容。错误属于任务结果/所属后端故障状态，不以“清零后继续”掩盖。

FrameHeader 保存反向页身份；淘汰不遍历数组找页号。PageGuard 的取得和释放都采用相同局部同步，不能只把全局锁从查找移到 unpin。

## 5. 正常访问、加载及淘汰协议

### 5.1 命中与缺页

命中：在有效实例及翻译组访问保护下读取条目，条件固定匹配的帧，复核身份，再取得内容保护。不得解锁后继续使用可能失效的哈希迭代器或未保护的旧帧号。

缺页：首次查到 Loading 时直接等待已有任务，不先申请另一张帧；查到 Absent 才保留帧及任务额度，在本页条目保护下复核仍未加载，再登记 Loading 并在锁外提交。若这期间其他请求已先登记，则归还自己多取的资源并等待同一加载。相同身份/版本共享已登记任务；其他页可独立推进。取得空闲帧/淘汰候选时不持目标页条目锁，避免两个缺页任务交叉等待。局部同步见 §12，不能声称整个 BufferPool 无锁。

等待者保留的是本次加载任务及其结果，不是可直接访问的帧地址。加载成功后，等待者重新进入正常查找，在条目/帧短保护内核对身份并 pin，再取得正文使用权；加载完成通知本身不能授权访问。若通知后该页已正常淘汰，则重走查找/加载；不得拿任务里旧 frame_id 直接构造 Guard。加载失败将该次失败交给已有等待者，不能被下一次同页加载的成功覆盖。单个等待者超时或退出不取消其他人及 IO 仍需要的加载任务。

没有可用帧或任务额度时保留现有 Checked 接口的明确资源不足语义；IO 损坏/失败不得伪装成资源不足或返回半页。已接纳加载的等待者等待该任务真实结果，不靠无限重试把失败隐藏起来。

初版保留同步 ReadPage/WritePage 返回 PageGuard 的生产语义；调用者只等待自己需要的页。内部允许多请求并行，不要求 SQL/Raft 全面异步化，也不改 LRUK 替换策略来混算数组收益。

### 5.2 交接是两步，Accepted 不是 durable

| 时点 | 谁持有责任 | 能否释放/换用帧 |
| --- | --- | --- |
| F26 本地规划/等待准入 | F26 的有界任务上下文 | 否 |
| `TryPrepareExternal` 返回 Full/Stopped/抛异常 | 原许可仍归调用方；没有设备 IO | 只能按本次任务收尾释放，不能当成功 |
| Prepare Accepted | IOBatch 已接管许可，但尚未执行 | 否；批次仍由提交方负责提交或放弃 |
| `TrySubmit` Accepted | 执行器/worker 持有执行责任；票据可被调用者丢弃 | 否，须等真实 IO 收尾 |
| Submit Stopped/异常且仍 Prepared | 尚未转给 worker，提交方负责 Prepared 批次 | 可明确放弃；不会假称取消已执行 IO |
| 全部设备 IO 完成 | F02 归还设备使用许可并给结果 | 页层仍须核对内容、身份及提交要求 |
| Common Durable 并完成映射发布 | 本次写回达到页后端约定完成边界 | 可清对应脏版本、解除写回保护 |

任务不能在下层未认领时从上层责任集合消失。每层只保留尚未交接或确实需要的执行状态，不复制整份任务到多个无界队列。不为每次 IO 创建等待线程。完成结果存在原任务/票据中，通知只唤醒推进者，通知拥塞不能丢结果。F02 的准备槽位、原 worker 和完成机制继续复用；F35 队列不参与本次页 IO 审批。

**Full 的处理不能只看枚举。** 现有 F02 的 Full 同时可能表示临时占用和本批永久超过配置。F26/ObjectIO 先按正式配置检查实际成员数、每份许可 capacity 的合计、所需工作缓冲及 Common 额度；不是只按页数乘正文长度估计。只有放得进空执行器而当前被占用，才进入有界 pending 等待。这个检查沿用 ObjectIO::CheckBatchBudget 的既有职责，在 c 扩展外部来源，不增加公开预算 getter，也不改变 F02 的 Full 契约。

**终态与票据寿命分开。** F02 终态前归还外部许可，但成员/结果名额直到 IOBatch 最后一个拥有者退出才释放；Common 的请求名额也受 ObjectTransactionTicket 寿命影响。F26 消费内部完成结果后，复制所需结果摘要并及时释放下层票据，再推进后续页；不能将每批完整票据都存到 FlushAllPages 最后才统一销毁。IOBatch::Result 返回的引用不能在销毁票据后继续用。若直接调用者按现有接口明确保留结果，其预算背压仍然有效，不能为了此改造悄悄改变原接口合同。

责任沿已有封装：ObjectIO 消费并释放它拥有的 IOBatch，F26 消费它持有的对象/事务票据，不要求 F26 穿透私有状态。现有 ObjectIO::FinishCommon 已在确认数据 durable 后 reset batch_，给后续 B/Journal 让出 IO 名额；S9 保留这一步，不重复实现，也不能等到 B 发布后才归还这些名额。分配责任和必要的稳定正文来源另由父任务保留。

### 5.3 写回与淘汰

首轮直接借帧写回时，相关页内容在后端仍需读取它期间保持稳定；其他页照常推进。允许同页修改与稳定副本并行属于显式预算下的扩展，不能默认复制每一页再声称默认直传。

pin 只防帧复用，不能替代内容保护。不能在提交线程锁住 `std::shared_mutex`，再让 F02 完成线程解锁。首轮采用 §12 的逻辑内容使用权：短临界区登记读者、写者及 IO 占用，保护期间不持线程所属互斥锁；归还只更新计数并通知。PageGuard/Flush 正式调用点须一同迁移，不修改线程所有权规则来迁就测试。

写回捕获脏版本；成功只清该版本的脏标记，旧写不能清掉或覆盖较新的修改。同页写回有顺序。Common 结果不确定时沿已有规则隔离，不能重试成“确定失败”。

淘汰先在条目/帧短保护中核实无业务 pin 并占住候选及旧身份，标为 Evicting 后禁止新增业务 pin；同页请求等待此任务退出后重新查找，不能再次读出旧设备内容。必要写回达到后端完成边界后，才能撤销旧驻留关系、复用帧并加载新页。失败恢复旧驻留及替换器的对应可选状态，保留仍必要的脏数据，不为腾出帧而丢弃。选择新页、旧页的多项状态时采用明确锁序/重试，不持一页锁等待另一个潜在反向依赖。

c 已将原先遍历 page_table 的 `FlushAllPages` 改为捕获待写页身份/帧代次、分有界批次推进；不在可并发变化的容器上无保护遍历，也不承诺它就是业务 checkpoint。`FlushPage` 对象后端成功须满足自身持久化/发布约定，文件兼容后端的实际保证单独标明。

## 6. 真正把帧接到对象 IO

本阶段后续实现仍沿一条生产流水线，不能额外建立“BufferPool 专属 FS”。

**读取：** 页适配将目的帧及许可交给普通对象读；F13/F14 解析并保护范围，Data 经 F04/F02/F01 填充，Hole 在受保护帧中生成零。EOF/不存在页与 NewPage 的初始化分开：只有正式分配的新页可初始化，已存在页的意外短读不能伪装为全零新页。所有片段完成且身份匹配后才发布 Resident。

**写入：** 帧稳定内容作为 Common 的合法输入来源，与自有字节输入共享 F16–F20 的准入、排序、规划、持久化和原子发布。不能保留最前面一次无条件 vector 复制，仅在最后一次 pwrite 借帧就宣称迁移完成。

**多页批量写回：** 沿用 S7 每事务每对象一次 mutation 的限制。首轮从待写页中每个对象选一页组成有界事务批次，不同对象可进入同批；同对象剩余页按现有对象排序继续递交。整个 Common 事务 Durable 且发布后，才清除批内对应页版本的脏状态；FlushAllPages 涉及多个事务时分别记录完成，不能把一个事务成功当作全部成功。不把两个不相邻脏页拼成一个大范围，再用零或未保护的缓存内容填中间页。以对象 K 包含 p、p+1、p+2 三页为例，只写 p 和 p+2 时，p+1 的原内容必须保持。相邻页将来若合并，须先有能表达全部稳定来源的正式输入与明确范围语义；本轮不新增这种表示。该选择落实原“沿对象排序”分支，代价是同对象多页暂不合并为一次 Common 提交，批次/Flush 合并仍沿现有下层能力，不保证固定 syscall 次数。FlushAllPages 也不因此成为多页原子业务 checkpoint。

组批必须在接纳前符合实际容量。多页候选过大时，F26 在构造 Common 事务之前减少本批页数，剩余页保留为有界待写任务；不能拆开已接纳事务来规避原子性。若最小一页所需的合法计划也放不进配置，则明确返回容量错误，不一直重试 Full。预先通过正文大小检查不代表后续映射分片/对齐规划一定符合成员上限；实际计划不满足时也不能当作临时占用。

**对齐/拼接：** F01 实际查询 memory_alignment 和 offset_alignment；后者也约束长度。可直接满足物理请求的帧使用外部入口；需要读旧字节、合并、跨范围或更大对齐时，由现有 FS 规划安排有界工作缓冲并记账。FrameArena 不能扩大磁盘页大小，F02 不能偷偷降为 Buffered/自有路径。借帧也不授权对已发布数据原地不受保护地 RMW。

**节点装配：** c 已在 NodeStorage 接通显式外部固定容量，正式页部署使用三参数 IOExecutor 构造；元数据专用和其他合法自有缓冲部署保持其行为。不为测试新增默认值。页输入/目标接口已经与正式 F26 调用链一起接通。

**寿命：** F02 许可保 RAM，F14 保设备范围，F26 保页身份和可见性，不能互相替代。F02 归还许可早于整个 FS 写入发布时，F26 的任务仍须保留所需帧/版本。关闭先停新请求，收束 Prepared/pending，排空 Accepted 的真实 IO/提交，再使旧目录失效并释放内存；不让一个旧回调发布进新工作库。

借帧的另一端也须明确：正文稳定来源只保留到整个提交/失败收尾不再使用正文，不随“结果还没被观察”无限保留。实施前 Common 的自有 input_ 随结果任务存活；c 已增加终态前归还借用源，不能把帧许可无限塞在结果中。成功或确定未提交时，在最终结果对外可见前归还已无用途的正文使用权；Indeterminate 先按现有隔离规则接管仍需保留的状态。保留的结果元信息与排序身份不必保留正文许可。F26 自己的页发布责任和业务 Guard 的 pin 另按各自边界退出，不能反过来提前释放。

迁移完成后，A 的常规页 IO 默认使用上述路径，删除无人使用的旧复制/调度包装/分支。仍服务合法文件部署或非页对象的接口按真实调用者保留，不能因课程测试还在就保留无人使用的生产抽象，也不能误删仍有正式消费者的 DiskManager 后端。

## 7. FrameArena、路径缓存与翻译内存

### 7.0 本轮对话补充：寻址、权限与大页时机

TranslationEntry 解码得到 frame_id 后，分别定位 FrameHeader 管理信息与 FrameArena 正文槽位；不是正文依次经过三个中间件。Header 核对所属页/帧复用身份、pin 和正文使用权，Arena 用稳定基址及槽步长提供正文地址。pin 防止帧换用，不能替代正文读写保护。b 当时仅实现基础组件；c 已接通完整查找/固定并替换 A 的 BufferPool。

大页建议在 FrameArena 创建匿名映射后、交付使用前发出（MADV_HUGEPAGE）。建议成功不证明物理大页已分配；首次实际访问或内核后台合并才可能生效。分别报告建议状态和可观测的实际 RAM/大页占用，无法观测时明确未知。普通帧淘汰只换槽内身份和正文，不重新申请或拆除大页。不默认触碰全部帧预热、不修改系统 THP 策略；THP 是否在首次访问同步整理内存由环境决定，不能承诺零停顿。翻译内存单独采用基础页和 MADV_NOHUGEPAGE，以便 d 细粒度归还。参考 Linux THP/madvise，内化到 b 的内存组件；非数据库文件 mmap、非设备 extent 回收。

普通内存策略也必须能在不支持 THP 的内核运行。若 `MADV_NOHUGEPAGE` 返回 EINVAL，按 [Linux madvise 的能力探测约定](https://man7.org/linux/man-pages/man2/madvise.2.html) 用零长度调用确认：该 advice 确实不支持时，继续使用普通匿名内存；advice 支持却在实际区域失败，或者其他错误，仍传播原错误。帧区和翻译区复用私有 Region 的同一实现，不把任意失败当成功，也不把能力探测当实际大页观测。此处只修正 b 的已承诺回退，不提前实现 d 的 RAM 回收。

授权和完成状态随阶段推进：b、c、d 已分别获授权并实施；e 和 F36 尚未实施。先逻辑审查再编写测试，按 §11/主方案八项审查并按 F26 压缩归档。

### 7.1 两类内存分开

- FrameArena 保存页正文，地址在帧正常复用期间稳定；区域首地址和槽步长都满足实际内存对齐。
- TranslationMemory 保存页到帧的条目；按实际 OS 基础页划回收组，避免整个数组预初始化触碰全部 RAM。
- huge page 支持用于帧区；请求成功与实际生效分别报告，不改数据库页/持久化单位。内核不支持时仍按已说明的普通内存路径运行，不能算大页实测成功。

### 7.2 PathCache

缓存实例/目录身份、prefix 和叶描述符/路径，不缓存可脱离验证使用的旧 frame_id。命中前先取得有效 owner；不能解引用悬空对象后再读代次。缓存容量及全部缓存实例总占用受 F31/F32 约束。普通页淘汰不必清除仍有效的 prefix 路径；目录关闭/整体解除映射必须让旧访问退出。未完成此协议前不能靠永久泄漏目录来维持指针安全。

### 7.3 hole punching

步骤确定为：候选 bitmap → 精确检查 → 阻止冲突的新访问/预留 → 旧访问退出 → 再核对无驻留及在途需要 → 归还 RAM → 更新状态。控制计数、访问门及构造状态存于不会随被回收数组清零的位置。d 使用弱 owner 身份与组访问门排除旧路径/条目，没有另设无人消费的组代次；帧完整身份仍独立保留。忙组跳过，不占全局目录锁等待。

回收只归还整 OS 内存页；保留虚拟地址，不释放磁盘页/extent。C++ 原子条目的构造、结束寿命及重新初始化必须与访问退出一起实现；不能把 mmap 返回的零字节直接强转为现成原子对象，或在有访问时清零。失败如实报告，不能已失败却减少实际占用计数。

F12 的设备 bitmap、F36 的页内剩余空间和本节 RAM 候选摘要分别拥有权威；仅按真实需要复用位操作/分层搜索代码。稀疏热页仍可能保留许多部分占用的内存组，预算与实测不能承诺数组总比哈希省内存。

## 8. A/B 与 F36 的冻结边界

**B：** A/B 保持独立运行实例和页编号空间，可以处于同一进程，不要求进程地址空间隔离。B 当前的 `MetadataVersion::pages_` 已是页数组，私有版本不能进入 A 的公共驻留条目。F26 的主要替换对象是 A；B 仅在有真实收益且保持版本/WAL/恢复顺序时接入可复用内存或 IO 组件，不以“代码复用”为由强制套用 A 的页生命周期。影响共享 B+Tree/PageAccess 时回归 A/B 两侧。

**F36：** 本轮冻结的是安全交接，不提前冻结 TablePage 新磁盘格式或实现记录回收。S9.1 不引入新的页号/slot 复用；现有分配高水位和业务恢复语义保持。F36 在 S9.2 前确定 MVCC/undo/索引/RID 的清理判据和 slot 格式；在 S9.3 前确定整页失效与释放协议。旧“进入 S9 前确定 F36 全部 slot 格式”调整为先固定这些不得破坏的条件，具体格式仍在其阶段确定。

存活 tuple 的页内移动保持 slot/RID；已失效 slot 能否复用必须先排除旧引用。空页须先解除数据库引用，再让 F26 排空读者/IO和驻留身份，最后通过 FS 释放页对应范围。一个对象包含多个页时，不能删除整个对象。页不驻留、hole punching 成功、F12 有空闲位均不能证明记录或 RID 已可回收。

## 9. 资源和真实预取消费者

预算类别：帧正文及对齐余量、翻译目录/控制区、PathCache、加载/写回任务、固定外部容量、必要工作副本。A/B 不共用一个可被业务耗尽的无保留池；B/Journal/回收需要的进展资源继续沿既有约束保留。相同帧只计一次实际 RAM，F02 外部额度计的是在途占用压力，不再算一份物理分配。

配置需包含最大帧数、翻译/缓存字节限额、最大页任务/在途字节和预取窗口。实际值由正式部署配置与设备/OS 能力确定，不把本机 4 KiB、16 GiB 或测试输入写成通用默认值。S12 调优额度比例和后台节奏，基本有界性必须在 S9 交付。

预取在自己的有界份额内准入，不能占尽前台加载和脏页退出所需的帧/任务/IO 额度；不足时停止投递预取，不能一边占住全部资源一边等待下一项资源。正常请求与预取的具体额度随正式部署落定；“归还后合法请求可继续”是验收条件，而非只检查内存计数归零。

e 的第一正式消费者选现有 `IndexScanExecutor` 已取得的 RID 集合：按有限窗口抽取不同 page_id，去重后预取，随后原顺序执行 `GetTupleAndUndoLink`、可见性重建、过滤及输出。预取只提前装页，不代替 SQL/MVCC 判定，不触发未来尚未消费的业务异常；真正读取时仍核验当前身份并传播实际失败。不为预取先全表搜集页号。

TableIterator/B+Tree 链式下降只对已经从有效页读取出来的后继页号预取；不按 page_id+1 猜测。CPU 预取和设备 IO 分别观察。若正式 RID 集合在某负载只有一个页，如实说明并行度，不为性能数字改变查询路径。乐观正文无锁读继续归 S13，版本复核不能补救 C++ 数据竞争。

### 11.2 关键判据如何落地

1. **并发证据是事件先后。** 明确接收“页 A 已进入并暂停在实际 IO”“页 B 已完成”两个事件，随后才放行 A。预算和执行容量须足够容纳这些独立请求，不能用故意配置单 worker 的排队误判全局锁。测试挂起超时只负责失败退出；无论断言成功与否都解除测试侧暂停并 join 工作线程，避免清理死锁。同页去重 fixture 使用已初始化、单个对齐映射范围；不得将一般碎片页的多次合法物理读误判为重复逻辑加载。
2. **页写回成功必须晚于发布。** 测试侧在 Data 区写入/Flush 完成后、B/Journal 提交发布前保留暂停。该窗口内页 Flush 不能报告成功，也不能允许该写回版本被丢弃；放行后必须得到实际 Durable 结果。正常完成后经生产页后端重新读取准确正文。需要验证进程恢复时仍走已有快照+Raft 权威，不能凭活动页写完就假设有了 S11 恢复根。数据 IO 失败、B 提交不确定分别使用原契约判断，不能统称失败后任意接受新/旧值。
3. **合批不能影响未修改页。** 使用三页不同且非零的正文，只更改同对象首尾两页，经真实 Flush/再加载核对三页。Oracle 由测试输入保存，不能从当前映射或缓存复制 expected。跨范围填零/覆盖会破坏中间页，简单两个连续页无法发现这个问题。
4. **资源判据是能否继续做合法业务。** 分成两个不同失败边界：能放入空执行器的请求遇到占用，释放占用后应继续；连空执行器都放不下的单页计划应明确失败，不得等成超时。另用 Common 请求额度只够一批、待写页超过一批的真实 FlushAllPages 验证消费结果后能提交后续页；B/Journal 等基础配置须仍然足够，不能用无法启动的配置制造挂起。测试不替 F26 释放内部票据、不读取私有计数；完成后通过真实换页和正文核对发现帧来源未释放。明确由外部调用者持有的原 F02/Common 票据继续占用原契约预算，不把这个合法背压判为泄漏。
5. **回收效果与安全分开。** 归还后再读对只证明内容路径安全；物理 RAM 是否归还由已识别翻译区域的外部观测佐证，不能让实现自己上报的计数同时充当 Oracle。THP 实际生效属于单独环境观测。不会为了测内存而新增只有测试调用的 getter，也不能在缺少可靠区域观测时报告回收效果通过。
6. **关闭判据不能只有“短时间还没返回”。** 在测试侧记录受阻设备操作实际退出与 Close 返回的事件，检查 Close 不早于该操作退出，并核对后继打开/读取的内容。暂停期间的 future 超时可以辅助发现明显提前返回，但“等了 20 ms 没返回”不能独立证明正确排空，也不能借此宣称帧寿命已验证。需要检查生产路径确实到达关闭阶段、确保失败清理解除暂停；具体事件设施复用已有测试侧边界，不加 production hook。原 S7 的相似辅助断言不直接充当 S9 新路径的验收结论。

这些是同一风险矩阵中的判据和必要子场景，不要求按条目机械增加测试套件或重复统计。最小改坏示例只有在实际运行并命中对应断言后，才能记录为“变异已发现”；b/c/d 的实际证据见 [d 执行审查](s9d_execution_20261004.md)，不覆盖尚未实施的 e。

### 11.3 对比、去重与实施限制

功能测试使用小的显式帧/设备/任务预算并测试资源满的真实行为，不用空参或假数据库。真实停顿/错误注入只留在测试侧；依赖实际 Direct/THP 的部分分开报告，不能静默跳过并算通过。超时是挂起上限，不是证明并行的唯一 Oracle。

共同 C1–C5/P1–P4 的内容、请求完成含义和统计口径保持；新的翻译诊断不冒充旧性能基线。相同总内存包含 OS 缓存影响、A/B/翻译/工作缓冲。F26、F36、F35 分别保留版本边界，避免把后续 SQL/流水线收益全归于数组。

资源场景按已有测试复用：F02 的 BudgetIncludesPreparedRunningAndRetainedResults、ExternalRoundTripReturnsPermissionsBeforePublishingCompletion，S7 的 RetainedResultsBoundAdmissionAndDroppedTicketStillDrains、UnsatisfiableRequestsFinishAndLeaveOldStateIntact 已覆盖底层相应合同。S9 新验证只增加真实 F26 提供者、外部来源预检和内部消费结果后的页级进展，优先复用输入/故障设施，不能复制旧矩阵再计一份覆盖。当前归档对照见 [审查 §10.3](s9_design_review_20261004.md#103-测试设计审查结论)。

## 12. 首轮实现协议及尚未编码的边界

### 12.1 条目访问与回收互斥

- 每个 OS 基础页大小的翻译组有一个稳定控制块，含访问门、物化状态、有效条目/在途保留数。控制块不在可归还的叶页中。
- 目录/叶首次创建也需要发布协议：先预留目录及控制区预算，构造完整描述符，再在对应父槽的短保护下检查并发布唯一指针；竞争失败者销毁自己的未发布候选并归还额度。描述符在本实例运行期保持稳定，正常 hole punching 不卸载它；达到预算上限明确返回资源不足。不能只给条目加锁，却让两个线程同时发布同一 prefix 的叶。
- 普通查找持组的共享访问门，只覆盖条目访问及固定帧的短步骤，不跨越内容等待、设备 IO 或调用者使用 PageGuard 的时间。首次物化在组独占门下逐个 placement-new 构造该组原子条目，不触碰其他组。
- 条目高 8 位首轮只用 0 表示未锁、255 表示短暂独占；其他值不作为页生命周期。通过 acquire CAS 取得，release 写回后放开；保护期内读取帧号、校验并固定身份或更新指向。首轮不进行无保护正文乐观读取。
- 固定顺序为：有效 owner → 组访问门 → 条目 → 帧短状态锁。取得内容使用权/等待前释放条目及组门。替换器选候选后先释放自身内部锁再按上述顺序核验；不持帧状态锁等待条目或另一个页。两页之间的迁移分成旧页退出与新页登记两个受控步骤。
- 回收器只 try-lock 组独占门，忙则稍后处理，不占全局锁等待。独占后再次检查有效条目和在途保留为零，结束组内原子对象寿命后归还 RAM，标记未物化。归还失败则在独占门下重新构造空条目并保留实际占用，报告错误；不能允许访问已结束寿命的原子对象。
- 加载/写回期间保留条目或组在途计数，因此“暂时没人查数组”不会误回收 Loading。PathCache 存叶路径/控制块，不保存可跨出组门使用的条目引用。

这是有局部锁的首轮方案。共享门及条目短锁可能带来开销，按同口径性能观察；不为模仿无锁术语引入难以验证的访问退出算法。以后若优化同步，仍保持这些不变量。

### 12.2 版本及内容使用权

条目 version 在指向变化时递增并允许按 24 位回绕，但它不独自授权访问：查找始终在上述短保护内完成，异步任务另外持有 owner、帧和完整复用身份；帧有在途 pin 时不能复用。回收重建条目可归零，因为旧条目引用已退出。运行身份/帧复用计数采用 64 位且不循环发放旧身份；耗尽时显式停止该实例接纳，不靠概率忽略。

FrameHeader 的短状态锁管理 reader_count、writer、IO 内容占用及条件通知。ReadPageGuard 持逻辑读权，WritePageGuard 持逻辑写权；互斥锁不跨整个 guard 生命周期持有。写回取得稳定内容使用权后阻止新写者，读者可读同一稳定版本；加载帧在成功发布前不允许业务访问。首轮写回保持该页版本到后端提交结束，不同时允许同页修改；稳定副本扩展仍受预算和版本检查约束。

取得内容权时如需等待，释放短锁并等待状态变化。IO 归还动作仅执行短状态更新/通知，不等待 IO、不关闭 executor。F02 子许可释放不等于父级页写回任务结束，父任务在 Common Durable/失败收尾后解除剩余内容与身份保护。

WritePageGuard 首次可变访问标脏；写回捕获版本后仅清除匹配版本。FlushPage 的正式调用方不得在仍持同页写权时同步等待自己释放写权；当前活跃生产 FlushAllPages 调用在 canonical_snapshot/single_node_runtime 的阶段边界，c 实施时需复核而非新增测试专用递归锁。若新真实调用方需要 guard 内 Flush，应先报告并设计正式语义，不能静默死锁。

### 12.3 内存、接口和资源

FrameArena 首轮采用 Linux 匿名映射，按查询的 OS/设备能力设置区域对齐和槽步长；THP 采用显式建议并记录实际生效，普通帧复用不解除映射。翻译区按基础页回收，使用禁止合并为大页的区域策略，避免细粒度回收目标与帧大页混淆。A 页请求的偏移/长度对齐需要更大范围时由 FS 规划有界合并缓冲；不能据此宣称整套节点支持任意设备粒度：当前 F05 的 B 页后端仍要求元数据页满足设备偏移/长度对齐，不满足就明确拒绝打开。S9 不暗改该磁盘格式或兼容限制。

PathCache 每个注册访问上下文最多 8 项，按最近使用替换；缓存管理本身受实例配置的总额度限制，退出归还额度。缓存额度不足时明确走同一多级数组查找，不回退旧哈希或扩大 IO；它只是寻址优化，不影响业务正确性。弱 owner/有效调用上下文保证旧缓存不延长已关闭整棵目录的寿命。

新对象读需要“目的范围 + 可写使用权”，写需要“只读范围 + 稳定使用权”。写输入作为现有 Common 请求的一种来源，与 Owned 字节来源互斥表示，同一事务/排序/提交代码处理；不建第二套写事务。移交失败输入仍归调用方；移交成功由请求上下文持有，结果观察者退出不取消。IO batch 的直接帧片段和明确的规划缓冲分别记录实际占用，任务和许可总额由正式配置限制。

max_frames、翻译内存/PathCache 总预算、max_page_tasks、外部固定字节、预取窗口和 K 必须由部署提供有效值。外部固定额度至少容纳一张合法帧，全部资源不足如实背压；不是把未给参数偷偷设为某台机器的观测值。K 是页空间描述参数而非算法未知项，c 编码时必须固化并在 Open 校验。

“至少一张帧”只是配置下限，不证明任意分片计划都能执行；§5.2/§6 的实际计划预检仍需进行。实际 RAM 按物理拥有者计一次，F02 外部保留额度沿现有实现按各许可 capacity 求和；两个口径不能混用。结果摘要本身计入页任务预算，但不依赖长期持有已经完成的下层票据来保存。

## 15. S9.1c 实施选择（2026-10-04，用户已授权）

本轮接通真实生产页路径，不开展 d/e/F36。owner 短锁只保护关闭、空闲帧列表及任务预算；驻留查找使用组/条目→帧局部锁，Guard 退出也用帧局部锁。等待页内容、加载、Common 提交及设备 IO 不占目录保护或 owner 锁。LRUK 保留自身短锁，不把本轮称为无锁实现。

- 保留现有文件部署的生产入口，使用同一个数组 BufferPool；对象部署显式提供页工作区参数及预算。页正文均由 FrameArena 持有。
- 对象工作区以 B 控制记录保存版本、页大小、pages_per_object；Create 与 Open 分开。每次 Raft 状态重建创建新空间，同号页不复用旧实例身份。业务恢复权威仍是快照加 Raft 日志。
- 读目标和写源显式带正文地址、有效长度、保留容量及寿命/内容许可；接续现有 ObjectIO、Common 和 F02，不新增设备线程池。可直传页默认借用帧；对齐/保留边缘确实需要的工作缓冲由规划器显式管理。
- Common 完成结果消费后及时释放 ticket。父页写回保护持续到映射发布完成，不能按子 IO 结束提前开放修改。永久超预算报错，只有暂时占用才等待。
- FlushAll 捕获当时的页身份，分有限批推进，同一对象每批最多一项；不靠拼接零填满不同页之间的间隔。它不是业务 checkpoint。
- Close 停止新页请求并排空已接纳调用；已有 Guard 保留旧 Arena 的寿命，只能访问其原有页，不能使新实例接受旧帧。调用者须在持有写 Guard 时避免同步 Flush 同一页。
- 新测试先于编写做生产逻辑审查，随后以真实 BufferPool/对象/Direct 文件链验证；小阶段测试更新 F26 唯一压缩包，不增添测试专用生产接口。

### S9.1c 并发提交补充

工作区身份创建与 Common/GC 可同时更新 B。B 在 WAL IO 前发现基准视图过期时抛出 `MetadataViewConflict`（仍归既有 Conflict 类别）。创建者重新读取并计算空间身份；Common 重新生成映射/分配变更并再次核验对象内容版本，不重复数据 IO。对象版本改变、容量失败及持久化结果不确定不走这条重试。该区分修复实际三节点快照验证中出现的冲突，不能把普通并发冲突升级为节点损坏。

## 16. S9.1d 执行协议（2026-10-04，用户已授权）

本轮按已讨论的 PathCache → 候选 bitmap → 安全归还/重新使用 → 真实页组合验证接续，不实施 e/F36。继续先分析生产逻辑再编写测试，不添加掩盖错误的兜底；测试执行总方案八项审查，仅保留唯一 F26 压缩归档。

### 16.1 路径缓存、预算和寿命

每线程至多保留最近一个目录的 8 项 LRU 路径，内容为 prefix 和叶描述符。切换目录先检查 weak owner 的控制块身份，再解引用旧路径；不依赖重用的裸地址，不保活关闭后的目录。叶描述符和虚拟地址在 owner 存活期间稳定，归还组 RAM 不解除映射，缓存不持条目地址。使用缓存仍走组门、条目锁和既有帧核验。

PathCache 的拥有内存计入既有 `directory_bytes_`，不新增测试默认值或全局无界 owner 表。线程本地壳仅为指针/计数；缓存额度不足走同一数组路径，组申请不足时先退出该线程的可选缓存再做一次有界回收重试。最后一个 owner 退出时控制块与大目录分开释放，闲置线程的 weak 引用不会保留根数组。此层不需要新增一个无人消费的持久代次；owner 控制块身份防实例混用，组独占门排除旧条目访问，帧原有完整复用身份继续保护异步页任务。

### 16.2 候选与实际归还

候选分为根→中层叶→OS 页组三级 bitmap；从空条目的访问退出或最后驻留关系退出发现候选。加载、写回、淘汰中的页仍保留 frame 编码并计入组存活数，不能误回收。只有一个维护访问者消费候选，各层轮转避免忙组长期遮住其他候选；生产者始终先标下层再标上层，消费后重新挂起剩余或忙的候选，摘要允许陈旧但不得永久漏候选。

维护只 try-lock 组独占门，忙则跳过，不等持有者、不持全局目录锁等待。独占后再核对已物化且存活条目为零，结束原子对象寿命，调用 MADV_DONTNEED；成功才扣除物化内存计账。失败在独占门内重新构造空条目、保留计账和候选，向调用方报告 OS 错误。重新访问复用 b 的构造过程，重新取得共享门后再次检查是否仍已构造，避免初始化与回收之间的竞态。

没有缓存或异步任务携带越过组门的原始条目引用，故回收后条目版本允许归零（沿 §12.2），不增加一套无消费者的回收版本号。bitmap 不共享 F12 的设备所有权；归还翻译 RAM 不代表归还数据库页或磁盘 extent。

### 16.3 生产触发与错误收尾

首轮维护节奏是本项目有界实现选择：每线程每 64 次 BufferPool 请求在入口尝试至多 16 个候选；翻译预算不足时至多再检查 64 个候选并重试一次。后续 S12 根据测量调节；不是论文常数，也不承诺已达到最优。维护入口由真实 BufferPool 调用，独立目录消费者可调用同一入口，不提供测试 getter 或额外线程池。无新请求时不额外唤醒后台线程，闲置空组可延迟到后继访问/预算压力时归还。

周期维护在接纳调用后、任何帧/条目权利建立前运行，OS 错误不会插进淘汰发布的一半；错误仍释放本次调用计数。预算压力可能发生在新页登记时，此时失败必须归还私有暂占的空帧。已登记 Loading 的条目不得因维护而清空。批量 Flush 的错误收尾必须覆盖准备和写出两段：准备后续页时失败，也要解除已保留帧的 pin/IO 使用权及任务额度，保持脏版本，不执行尚未提交的数据 IO。可选路径缓存申请失败只退出优化，真实目录/物化资源失败正常上报，不把所有失败吞掉。压力回收不等待另一回收者；其额度尚未归还时，本次申请仍可能按原接口抛出 bad_alloc。调用者重试也必须有时限，不能把未接纳算完成。

### 16.4 参考与验收

继续借鉴 [Calico §4–5](https://arxiv.org/html/2604.00423v1) 的路径缓存和冷翻译内存归还，内化到 F26 的实际页身份、局部同步和预算；不引入作者实现作为依赖。依据 [Linux madvise](https://man7.org/linux/man-pages/man2/madvise.2.html) 的匿名私有映射 DONTNEED 语义，保留地址、按实际 OS 页操作；本项目的错误收尾和候选组织属于自己的实现。

验证沿当前正式 BufferPool/对象页路径，复用已有输入与正文 oracle；新增的独有风险是活跃访问不能被归还、真实 RAM 归还、失败保持可重新使用、预算下循环进展。用测试链接侧观察及 mincore 区分“确实归还 RAM”与“内部计数说已归还”，不能为观测新增生产 getter。路径命中后的安全仍由跨 prefix、跨 owner 的不同非空正文验证；组件访问门的定向验证不冒充数据库 E2E。保留 e/F36、裸设备、真实掉电及共同性能比较的未完成边界。
