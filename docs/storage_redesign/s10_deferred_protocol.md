# S10：Deferred 正文提交、读取来源和后台落位

2026-10-05。用户已授权补齐设计并实施、审查及测试。本协议优先于各子模块历史“未讨论/未启用”的描述；本轮新目标范围已完成，证据与未覆盖项见 [执行审查](s10_execution_20261005.md)。

## 1. 本轮范围与共同协议

首轮使用新分配目标，完整接通 Deferred；不启用没有完整掉电恢复和旧版本保护依据的原地覆盖。Common 与 Deferred 平级，COW 是目标位置选择；“读保留字节并组装”不代表已经实现原地 RMW。两种路径复用现有 F18/F19 排序、准入和 worker，不为每请求创建线程。

Common：必要 Data 正文 durable → B 原子提交 → 发布。
Deferred：新正文与 B 页恢复记录在同一个 Journal batch durable → 发布 Journal 来源 → 后台 Data durable → B 持久化删除待落位引用并发布 Data 来源。成功后的后台错误不撤销之前成功；保留日志、报告错误，不静默回退旧 Data。

F18 依据实际对象写入及组装范围选择；业务页接口当前交付整张 4096 字节页，不根据 SQL 改动字节猜测。首轮大小上限由部署显式设置，不宣称测得最优阈值；默认兼容 Common。Raft 日志及快照正文保持 Common。未启用时仍能读取/接续设备已有 Deferred，不能把选路开关用作数据丢弃许可。

## 2. 正文引用与恢复

PayloadRef 标识本 Journal 中完整已提交批次的逻辑 LSN、记录序号及长度；LSN 递增，物理段槽位循环。由 Journal 唯一追加所有者 B 在串行提交中确定下一批位置，追加位置必须与引用匹配，不由普通调用者猜测。正文作为独立 Journal record，与 FULL/PATCH 同批，B 的普通页面只保存短引用和任务信息。

F07 为完整批次建立可重建的位置索引，提供有界异步读取；跨段沿已验证的批次范围读取并校验，不假定对象编号相邻。B 的已发布版本保留其 PayloadRef；读者固定该版本，实际 IO 独立保留引用，丢弃结果不能提前释放。第一版旧 B 视图可能共同保留多个正文，限制由既有视图页预算及 Deferred 预算约束，后续按测量决定更细的索引保留优化，不影响 F14 的物理范围保护。

checkpoint 先保存 B 状态，其含义可以是“任务仍未落位”。元数据恢复起点不等于 Journal 最早保留位置。正常 checkpoint 与 Open 后回收都取有效 checkpoint 与正文引用的共同安全边界。恢复必须先完成 checkpoint 和之后全部元数据重放，再建立最终仍有效的正文引用；不能要求已经由后续完成记录取消的旧正文仍存在。所需正文缺失/损坏报错，不能返回旧 Data 或补零。

## 3. 对象映射与后台执行

映射仍保有最终 Data 分配身份；每个待落位分配另有持久任务，关联 PayloadRef。F21 查询固定版本：待落位任务存在则 Journal，不存在则 Data，没有映射则 Hole；按范围拼接。来源切换提交前，即使 Data 已写完仍读 Journal。

F27 沿现有有界执行机制处理任务，先保护目标所有权，再经 F02 批量写入和 Flush，然后 B 同批删除任务与正文引用。当前目标独占且不覆盖旧分配；后来的写入得到不同分配，旧任务不得恢复旧映射。待落位任务和真实 IO 都阻止 F14 提前回收目标。完成后旧视图仍可读其 Journal 来源，引用退出后才允许前缀整段复用。

持久目录负责重启接续，内存队列不保存第二份长期正文。关闭停止新请求、排空已接纳 IO；未执行任务可以留在日志中供重启。预算必须为完成记录和 checkpoint 保留进展空间；普通请求不得用光这些空间。

## 7. 本轮格式与预算落点

新建对象格式为 v3，旧 v2 保持 Common 读写，不自动迁移；只有 v3 可以启用 Deferred，新版本可恢复已有 v3 待落位任务，即使本次部署把新请求阈值设为零。这样旧二进制会拒绝 v3，而不会把尚未写好的目标当有效 Data。

B 独占 category 高八位为 254 的正文引用目录；普通 Commit 不得修改该目录。引用只记录 batch LSN / record ordinal / length。待写回目标在对象私有命名空间独立记录。F07 的内存批次索引只保存单元位置（包括重启预留造成的逻辑间隔），不缓存正文。初版读取一个正文会校验其完整提交批次，有一定读放大；不宣称已经优化成只读正文片段。

Journal 按 B 元数据批次上限保守推导每个完成事务的空间，普通提交额外保留所有当前待完成正文所需预算及 checkpoint 单元；完成事务可使用这部分额度。这有容量代价，后续测量后才能缩小，不能以过小保留掩盖进展问题。队列和临时缓冲仍沿用 F02/B 已有上限。

## 8. 读来源、LSN 和路径选择的直观解释

例如对象 O 的旧内容已经位于 Data。把逻辑 `[4096,8192)` 改为 X：先把 X 作为 Journal 的独立正文记录，与 B 的“该范围当前从这条正文读取”及目标分配信息同批提交。不是往 Data 的目标位置写字符串 `journal`。上层随后 `Read(O,3072,6144)`，读取计划按映射取 Data 的前段、Journal 中的 X、Data 的后段，拼到调用者的结果缓冲中。空洞才补零，缺失正文报错。

后台完成 `Data Write + Flush` 还不立即改变来源；必须再提交完成记录。提交前的新读者继续读 Journal，提交后新读者读 Data，已经固定旧视图的读者仍可读受保护的 Journal。这与是否命中 B 的内存页/元数据缓存无关，不要求每次查询来源都额外读一次盘。

LSN 100/200 是举例的递增逻辑顺序，不是元数据编号，也不承诺物理偏移相邻。checkpoint C 覆盖此前 B 的状态，可能包含“任务 T 引用正文 P”。重启先从 C 恢复目录、再重放 C 之后的修改；若最终 T 仍存在，则读取并保留 P，即使 P 的 LSN 小于 C。无需因此把 C 以前的所有元数据再应用一遍；也不能仅凭 C 较新就删除 P。

实际选择在 `ObjectTransactionPipeline::Impl::Plan()`：

| 输入/条件 | 当前选择 | 原因 |
| --- | --- | --- |
| 完整大范围、`common_only_` 或阈值零 | Common/COW | 正文先到 Data，避免大正文再写一份 Journal |
| 非零阈值内的小范围且积压额度允许 | Deferred 到新分配目标 | 完整组装正文与元数据先 durable，后台落位 |
| 部分覆盖 | 先读必须保留的边缘；随后按上两行选路 | 保持未修改字节；这一步不是原地 RMW |
| 同一事务有大小不同的对象修改 | 可以混合 | 所有 Common 部分 durable 后，再同批提交 B 与 Deferred 正文 |
| 需要原地 RMW/复用旧物理尾部 | 本轮未启用 | 尚无完整的撕裂恢复与旧版本保护证明 |

每项 `ObjectMutation` 当前整体选择一条路线，不宣称已把一个 mutation 的大块和小边缘分别提交到两条路线。事务可包含多个 mutation。Raft Store 显式要求 Common；数据库页写回按 FS 实收到的整页判断，SQL 改了几个字段并非 FS 的输入。

`deferred_max_bytes_` 是**组装后每项修改**的最大正文，不是 SQL 字段大小；`deferred_pending_bytes_`/`deferred_pending_tasks_` 分别限制当前持久待落位字节与目标数。前台先按固定视图规划，提交前再核实实际 extent 数及最新积压。超额的尚未提交请求不部分发布；已提交任务不因阈值改变而丢弃。新请求可在规划时选择 Common，但 Common 同样需要元数据 Journal，Journal 真满时必须背压/拒绝，不能无限绕过。

## 9. 执行资源及错误边界

- F27 是现有 `ObjectTransactionPipeline` 内的一个后台执行角色/线程，复用 F02 的 worker 和 IO 队列，不新增独立执行器或每请求线程。当前每次处理一个持久目标；多目标合批调优留待实测，不能把“复用 batch API”说成“已经合并多个后台任务的一次 Flush”。
- 首轮持久目录按对象/分配键取任务；持续写入时优先最老 Journal 前缀的调度优化留待 S12，并未声称实现公平或最老优先。
- 成功交接给 F02 后等待真实完成；一次执行中完成事务被临时占用，只重试完成元数据，不重新写已完成的 Data。checkpoint 互斥和 IO 暂占可重试；持久容量不足、批次过大和真实 IO 错误明确上报。重启可以重新写同一独占目标。
- 日志定位目录按磁盘可容纳的写入单元数有界；没有保存长期正文缓存。B 版本保留短引用，读票据/在途 IO 共同持有引用。对象读可能暂时同时持有多份有界 IO 缓冲，未引入逐字节全节点总预算，整体记账仍属 S12。
- 前台 Journal 读与 Data 读使用相同的真实 IO 完成错误通道；票据丢弃不取消错误汇报，完成回调与完成后唤醒分开，不能提前唤醒后漏掉推进。单个/混合来源读取要把完整 Journal 批次、Data 及对齐开销合计到 F02 总容量中；永久超限明确拒绝，不伪装暂时 Full 反复重试。已经接纳的部分读取仍保留保护直到实际 IO 完成；拒绝不会回退旧 Data。
- `NodeStorage` 沿既有顺序先恢复 B（包括最终正文引用），再打开对象映射/引用与事务后台角色。后台故障沿既有 `error_`、`Failed`/`IOFault` 汇报并限制服务；`object_error_` 是初始化诊断，不将它改作新的运行期错误通道。
- 关闭先停止前台接纳、完成已接纳提交，F27 排空已经接纳的真实 IO；可以把尚未开始的持久任务留给下次 Open。关闭不偷偷 checkpoint，不因释放 RAM 引用而直接删除磁盘正文。
