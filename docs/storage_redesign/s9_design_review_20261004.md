## 5. 先做逻辑推演

| 交错情形 | 必须成立的逻辑 | 本轮结论 |
| --- | --- | --- |
| 查到帧的同时另一线程淘汰 | 同一条目/帧短保护决定 pin 或 Evicting；进入 Evicting 不再允许新增业务 pin | 协议已明确；实现竞态验证在 c |
| 两线程同时缺同一页 | 已有 Loading 直接合并；资源预留后重查，竞争失败归还多取资源 | 不重复发布，不为同页再建第二次读 |
| Prepare 成功后 Submit 拒绝 | 批次尚未交 worker，原提交方负责保留或放弃；不能把它当在途成功 | 对应现有 F02 契约 |
| 脏页写回失败 | 原页身份/脏内容仍可定位；不能先复用帧再报告错误 | Common 不确定结果继续使用原隔离规则 |
| F02 许可已归还，B 尚未发布 | 父页任务继续保持所需内容和身份，只有完整提交结束才决定清脏 | 设备完成不替代页后端完成 |
| 翻译组空闲候选遇到 Loading | 候选只提示搜索；组独占门检查有效条目及在途保留；访问者退出后才结束原子对象寿命 | 不靠计数零或 bitmap 单独授权归还 |
| PathCache 指向已关闭实例 | 先取得有效 owner 再使用路径；整体释放等待活动访问退出 | 不能先解引用悬空路径再核对版本 |
| 帧数不足或 IO 失败 | 资源不足、设备失败、提交不确定分别沿真实接口传播 | 不通过清零、无限等待或任意重试隐藏 |

逻辑审查不能替代后续并发验证；局部门和计数的实现错误仍要由真实组合测试检验。共享访问门与条目锁也有成本，不能从协议设计推定吞吐已提升。
