## 1. 实际改动

- BufferPoolManager、内部 FrameHeader：增加每线程可复用短读登记、帧内双正文描述与按需备用 FrameArena；读者保护已发布正文，写者必要时复制并发布新正文。普通 WritePage 修改已启用的索引页也遵守此协议。
- PageGuard：写保护退出时发布正文。淘汰、删除、退役和关闭先停止发布，再等待真实短读退出。最后一次逻辑复核修正了退役失败路径：持久退役成功前不能释放备用正文或改变调用者仍持有的 guard 地址；成功后才完全归还。
- B+Tree 公共模板：仅 `PageAccess=BufferPoolManager` 的 A 点查启用新路径；B MetadataPager 仍走原固定视图和页保护。新增树级修改序号，写者仍由原树锁排序；序号范围包含全部页 guard 发布。
- A GetValue：进入时读取序号，沿索引查找并暂存独立结果，退出时核对序号。最多两次尝试，缺页、版本变化或可选资源不足时回到原共享锁路径。没有逐层新增版本验证；未命中也必须验证。删除原保护路径重复读取根入口的工作。
- 数组翻译仍负责页号到帧；B+Tree 负责业务键到子页/RID。没有第二套页表、树算法、缓存、分配器、线程池或恢复日志；CLOCK-Pro 与原 IO 继续复用。设备和页格式未变。

## 2. 先审逻辑，再写测试

先检查发布、保护、写入、换页和关闭链，再编写场景；后续逻辑复审修正身份重复写入、关闭入口时序、总帧预算和退役失败地址保存，最后重新构建并运行下列证据。

读者先原子读取正文描述地址，登记保护，再核对发布地址、翻译帧和页身份；核对通过前不解引用正文。写者撤销发布后，旧正文若仍被使用就采用另一个槽，两个槽都被使用时等待短读退出。描述身份不在重新发布时反复写入。回收先撤销可见入口，再等待既有保护退出，随后才能复用地址。

登记最多128项；额度不足可拒绝可选短读。备用正文最多每帧一份，同时受 F31 和原 `arena_bytes_` 剩余额度限制。已有正文的热读取不重复申请其 RAM。写者无法获得可选复制额度时等待 CPU 短读；IO、系统错误不伪装成缓存未命中。长时间 PageGuard 与 IO 仍走原协调路径。

树序号保证路径整体一致，正文保护保证 C++ 并发访问合法，二者不是重复职责。短读回调只能计算并复制结果，不等待 IO、不修改页、不泄露指针。仍有目录访问登记、CLOCK-Pro 标记和原回退同步；不能宣称读侧完全没有共享写入。

## 5. 本机点查性能证据

实际同一 B+Tree 模板，4096键、128帧；测试派生 pager 使用既有保护分支作为对照，没有复制树算法或增加生产策略开关。每读线程10万次查询，1/4读线程，各3次交替运行取中位数。混合组另有一个写者对其他半区执行2000次删插；计时等待读写双方完成。

## 7. 再次复审：失败封闭不能被短读入口绕过

先检查源码，发现 RetirePage 抛错后的 `closed_` 只封闭普通 Call；短读检查 `short_closed_`，仍可能读取其他已发布索引页。帧代次耗尽也有相同入口遗漏。修正两处：设置普通关闭标志的同时，禁止新短读登记。保持原错误上报，不新增重试、错误缓存或同步模块。

新增 `FailedRetirementPreservesGuardAndFencesBothReadPaths`：通过既有 PageStorage 接口注入退役失败，其余读取写入复用 FilePageStorage。先由真实旧读者促使写者切换备用正文，再保留 victim guard；失败后检查 guard 地址与新正文不变，普通读取抛错，短读不能访问另一张已发布的 witness 页。测试没有生产钩子，也未将实现内部标志当作判据。

同时新增去掉失败路径短读封闭的定向变异，要求上述行为断言检出。其余6项短读场景继续复用，不以固定内部槽位排列判断。首次77项和性能样本保留其原版本归属，不标成这次全部重跑；本次最终验证结果与源码指纹记录在当前结果包 review 目录。

本轮继续核对 A/B 模板隔离、序号覆盖 guard 发布、旧正文保护及资源上限，未新增重复模块。此修正不改变正常点查算法或磁盘格式。完整系统压力、全节点TSan及共同性能验收仍未完成。
