# F14 S6 执行与审查（2026-10-02）

## 1. 先于测试的生产逻辑审查

本节写于新测试之前，不以跑回归代替逻辑审查。

- F13 新格式在一次分配事务中写完整分配、初始化长度、剩余所有权与映射；旧 v1 新写仍用三字段记录，CreateSpace 保留实际格式号。F14 不自动开启旧格式回收。
- 普通 S6 映射只接受新预留，退出的旧字节不能重新挂回。回收将退出范围与从未发布的对齐尾部合并，按 u 向内取整，并与当前剩余所有权相交；不同 allocation_id 的新占用不能被旧范围带走。
- 读取先从固定 snapshot 解析整个有界请求，再在范围互斥下登记保护，随后验证当前 B 所有权。先登记避免“检查之后、pin 之前”被回收；当前 B 检查拒绝已被释放/复用的旧视图。验证失败销毁本次许可，不留下 pin。
- 回收先登记栅栏，再采样已有 pin；重叠单位保留、其他单位继续。新 pin 与栅栏登记共用短锁；树查询、B 提交和 Data IO 不在此锁内。许可拷贝共享同一生命周期，析构只修改所属 RAM 状态。
- 所有权切片、退出切片/计数和 F12 位图同一事务；已回收的旧身份不能匹配新身份。B 原 base 冲突保持原状，未自动更新；已接纳失败沿 B/F12 隔离。durable 后只填已有结果字段与解除栅栏，不再申请发布所需内存。
- Close 只排空已进入 F14 调用，不能冒充实际 Data IO 已结束；上下文重新打开前 owner 必须排空旧 IO。S7 追加/原地写、S10 PayloadRef、S11 持久共享尚未开启，不以组件许可替代它们的协议。
- 初次语法检查发现内部解码函数与记录类型 Allocation 同名，已改名 DecodeAllocation；这是编译问题，没有新增测试或生产特判来掩盖它。

方案与代码完成上述逻辑推演后才编写必要测试。以下为实际执行后的记录。

## 4. 逐个测试：目标 → 输入 → 执行 → Oracle → 失败含义

### 4.1 中间回收与身份

- **目标**：同一原分配的存活两侧不能阻止已死亡中间单位释放；旧身份不能利用物理地址相同访问新对象。
- **输入**：非零逻辑起点 `7u+137`，原 6u，替换中间 2u，左侧持有 59 字节许可；另一份预留占住其余空闲容量，确保随后另一对象实际使用被回收空间。
- **路径**：真实 Put/Replace → Reclaim → F12.Release/B → 新对象真实 Data 写 → ProtectRead/Direct 读取。没有手工伪造所有权或位图。
- **Oracle**：原输入加中间补丁生成完整预期；释放量应为 2u；旧视图取得许可必须 Stale；重复回收不产生提交且新对象正文不变。预期不由生产 Resolve 反推。
- **失败**：能区分两侧被破坏、回收过粗、身份核对缺失和重复释放。Test ReadLease 用生产寻址执行实际 IO，但比较依据仍是独立原始字节。

### 4.2 真实在途读取

- **目标**：IO 尚未完成时读到的单位必须不可复用；其他单位可以先释放。
- **输入**：`5u+73` 的 4u 正文，从第二单位内部读 37 字节；许可复制给 IO owner，销毁外部观察者。
- **路径**：在测试链接处暂停真实 pread，主线程删除对象并回收，再放行实际读取。挂起的是 F02 工作线程正在执行的 F01 调用，不是假 future。
- **Oracle**：第一次仅释放 3u、保留 u；实际读取必须等于原输入切片，完成后再释放最后 u，完整容量重新可申请。
- **失败**：提前销毁许可、按整个分配 pin、IO 完成后仍泄漏保护，都有不同断言。测试适配器明确持有许可到 batch 完成；它证明 F14 契约可正确组合，不代替未来生产 owner 的自动接入验证。

### 4.3 小范围联合、尾部与恢复

- **目标**：两次半单位退出合起来可以释放整单位；尾部未初始化字节与已退出正文一起回收，剩余归属可恢复。
- **输入**：`4u+91` 的 `2.25u` 原正文，实际分配 3u；先后替换两个半单位，再截短/扩展。
- **路径**：Replace → 两次 Reclaim → Resize → Reclaim → checkpoint → 重开真实 B/F12/F13/F14 → 读取及继续回收。
- **Oracle**：第一次半单位退出不提交；第二次释放 u；尾部有效 0.25u 退出后连同 0.75u 余量释放 u。预期正文由两个补丁、原中间单位和零填充组成；恢复后使用量 3u，最后全删可取回全部容量。
- **失败**：不合并小退出、遗失尾部、把已归还的中间范围重新当原所有权、扩展泄露旧字节或恢复重复释放。

### 4.4 预算与过期事务

- **目标**：有限许可/范围/回收预算实际生效，拒绝不得产生部分副作用；原 base 过期必须拒绝。
- **输入**：许可上限 1、范围上限 1、回收上限 u；有实际正文、跨空洞读、重叠调用与一次无关 B 提交。
- **路径**：通过正式 ProtectRead/Remove/Reclaim；不检查私有计数。过期 base 直接传入正式接口。
- **Oracle**：超限后合法许可仍可取得；第一次仅释放 u；过期事务 Conflict 后容量仍占 3u；后续三次每次释放 u；Close 后拒绝新调用。
- **失败**：许可拒绝泄漏、忽略预算、自动刷新事务版本或冲突路径部分清位图。不存在“只换参数”复制矩阵，各输入对应不同拒绝后的可观察风险。

### 4.5 提交窗口与失败恢复

- **目标**：等待持久化时禁止重叠新读取、允许非重叠读；空间不提前变为可分配；不确定结果经恢复只呈现一个完整事务。
- **输入**：3u 原数据的中间 u 被替换；其余容量被占住。成功 Flush 与注入 EIO 各一轮，输入正文均非空。
- **路径**：测试链接包装 fdatasync 暂停/报错，保留真实 Journal/B/F12 提交逻辑；重开真实存储。
- **Oracle**：暂停中重叠旧读 Busy、侧边数据正确、申请 u NoSpace；成功后旧读 Stale。失败时 B 隔离、释放量不得报告成功。重开只允许完整旧或完整新释放：退出记录、可申请容量、再次回收量须同时对应同一个状态。
- **为什么允许两个恢复结果**：Flush 返回 EIO 不能证明此前 pwrite 全未持久化；断言完整性而不伪造确定结果。不是允许任意状态，容量和待回收状态必须彼此吻合。
- **失败**：范围栅栏缺失、把 durable 前的空间暴露、恢复只更新部分所有权/退出/位图。不能据此声称覆盖真实断电、所有撕裂方式或全部并发时序。

### 4.6 真实旧格式兼容

- **目标**：新程序保持 v1 契约，不因 CreateSpace 或重开偷偷启用 v2 回收。
- **输入**：runner 从 Git `1df3ba1` 提取原 F13 头/实现，链接原实现生成磁盘样本；没有测试手写 v1 编码。
- **路径**：旧生产程序 Create/Write/Checkpoint → 新程序 Open/Read/Patch/CreateSpace/Checkpoint → 再 Open/Read。
- **Oracle**：已知 seed 产生的非零起点正文及补丁；新空间编号为 2；两次打开都明确拒绝创建 F14，原 F13 读写不受影响。
- **失败**：旧记录错误解码、字段改变、控制记录意外升级、恢复丢更新。这与 S5 的旧 Journal 格式兼容不是同一个格式或契约。

## 6. 重复与杀伤力审查

F13 验证映射发布/退出事实，F14 验证这些事实实际释放后的寿命与复用。F12 验证 caller 已证明安全时的分配器行为，F14 补的是安全依据，两者不同。没有新增位图编码、B+Tree 算法、标准库或第三方行为的单测。Flush 故障与 F12 都用原机制，但新断言要求所有权切片、退出和位图同批，不是复制原计数测试。

| 最小改坏方式 | 指定测试 / 命中断言 |
| --- | --- |
| 采样 pin 时忽略活跃读者 | Inflight：首次释放应为 3u |
| 把左侧读者扩大为整个 allocation | Partial：中间回收应存在提交 |
| 删除新读取与回收栅栏的冲突判断 | Fence：暂停窗口必须 Busy |
| 用旧 snapshot 校验当前归属 | Partial：已复用中间范围必须 Stale |
| 忽略原分配对齐尾部 | Subunit：尾单位应产生释放提交 |
| 忽略单次回收字节预算 | Bounds：首次只能释放 u |
| 提交时自动换为最新 B snapshot | Bounds：原 base 冲突必须拒绝 |
| 左侧剩余所有权错误扩展到原分配末尾 | Partial：旧视图不能重新获得中间范围 |

八个变异均编译成功，并在对应 GTest XML 中记录了指定业务断言；崩溃、超时、编译失败不算检出。兼容测试没有新增重复故意破坏编码矩阵，其真实旧生产输入与重复重开足以覆盖当前兼容改动；不因此声明测试能发现所有错误。

## 7. 稳定性与资源审查

每项使用独立真实文件与存储上下文，Image 析构删除，工作目录在仓库外。没有 sleep、未固定随机数或按时间猜测异步完成；使用条件变量等待真实 syscall 进入，10 秒只作死锁防护，runner 有有限总超时。future 前后有 RAII 放行，异常/断言退出也释放暂停点；异步任务返回前销毁自身许可。

包装器有测试进程内全局状态，但每个场景显式重新 Arm 并退出时放行，GTest 同进程串行执行；不支持在同进程并发跑这些注入场景。没有把这种测试全局状态带入生产。

环境依赖明确：Linux 支持 O_DIRECT/对齐查询的文件系统、Clang 14、CMake 和可读取基准 Git 对象。u 来自真实 allocator 配置；Direct 对齐取设备查询，测试没有把返回的对齐常数硬编码进生产。10 秒防护在极重负载机器可能触发，应作为环境/死锁待分析，不能改成假通过。此轮未做 TSAN、长时压力或物理掉电。ASan/UBSan 和全部断言通过只适用于已运行场景。

## 9. 对话覆盖与一致性复核

- 回收粒度为 u，按连续范围合并来降低事务成本；逻辑映射解决寻址，不声称消灭物理碎片。
- 剩余所有权、退出条目、位图用同一 B 事务更新；临时读者按范围保护，旧元数据 snapshot 不等于可永久访问 Data。
- 不足 u 的尾部保留在原分配，不上报全局、不生成额外任务；逻辑内容与容量分开。S7 仅查看当前尾部，安全且足够才复用，其他情况为本次追加申请新空间。
- 对象扩容由 FS F17/F18 与 F12 内部沟通；数据库只使用逻辑对象操作。这项已写入主方案及 F12/F13/F14/F15/F17/F18/F22。
