## 1. 范围、版本与实现审查

用户授权“补齐方案，然后去执行方案跑测试”，并特别强调不能假定 Direct 对齐是 4 KiB。基准提交 `d8ad4a0666640849f52f12b96ce6bb852e5c4177`，被测版本还包括本轮未提交的新源码；归档需保存源码/哈希/差异，不能只给基准号。

实现为 `src/include/storage/disk/block_device.h` 与 `src/storage/disk/block_device.cpp`，Linux 构建加入既有 `bustub_storage_disk`。复用 F00 `StorageByteRange`；保留原 DiskManager、DurableStorage 与 BufferPool，不提前接入 F02、SQL 或 Raft。新方法目前没有业务调用者：它们是本轮明确授权的设备边界，将由下一阶段 F02 消费；不把“本轮只有测试调用”隐藏成已完成业务接入，也不为此提前接通旧路径。

- 默认 Direct 存在 Options 的生产默认值中；构造参数仍必须显式传路径/Options，无默认路径。
- 已打开 fd 的 statx 返回 mask 与两个非零字段都须有效，缺失则报错；读取也采用共同严格约束。没有硬编码页/扇区大小兜底。
- 非法范围先于 IO 拒绝；容量、off_t、缓冲与对齐逐项检查。短读写保留进度；Direct 余量不对齐不能继续。系统错误码在构造诊断字符串前立即保存，避免错误来源被后续操作覆盖。
- 独立线程可并发定位 IO，析构/关闭前必须排空，范围冲突由调用者排序。
- Flush 独立调用 fdatasync、处理 EINTR、报告失败；Close 不暗中 Flush，不重试 Linux close。
- 只打开已有目标；块设备使用 O_EXCL，前后身份复核，不接管未指定的设备。固定容量期间外部不得改大小；测试主动截短用来触发损坏边界，不是正常使用方式。
- 文件与块设备能力/打开路径共用实现，裸设备未实测；WSL 文件 IO 不证明宿主机或物理掉电安全。

开源机制及本地落点见 F01 §4：Ceph 的设备职责隔离；Linux 定位 IO、能力探测和持久化契约。没有复制第三方实现或引入新依赖。

## 3. 逐项：目标 → 输入 → 路径 → Oracle → 失败含义

共同 setup：每例独立 mkdtemp/文件，直接调用系统 statx 取得约束，以内存/偏移约束的最小公倍数为 unit；容量为 256 unit，上限 64 MiB。初始内容由绝对字节位置与固定 seed 生成，不是重复零块。预置写入及独立读取绕过生产 BlockDevice，阶段之间不存在共享文件。能力不支持导致验收失败，不换 Buffered 后宣称 Direct 通过。

### 3.1 DirectRangesHaveIndependentPhysicalOracle

- 目标：精确落点及范围外不变、Direct 默认路径、精确读回。
- 输入：第 7 unit 与最后一个 unit 的不同正文，大小恰好等于探测单位；其余区域维持独立预置内容。不能全用 4 KiB 的参数掩盖硬编码错误。
- 路径：BlockDevice 构造/statx → WriteAt/pwrite → Flush/fdatasync → Close；独立 pread 核对后再新建 BlockDevice 精确读取全镜像。关闭后操作须失败。
- Oracle：初始镜像由输入计算，测试自行替换两个已知区间；完整文件用独立 pread 对照。实际 IO fd 的 O_DIRECT 由测试侧 fcntl 观察；能力用独立 statx 对照。Flush 成功观察来自实际 fdatasync 返回，重开只是内容可读证据。
- 失败：能区分能力不符、Buffered 默认、落点/邻居破坏、读回差异或关闭后错误接受。不会因生产 ReadAt 与 WriteAt 同时错偏移而自证通过。

### 3.2 InvalidRequestsCannotReachIOOrChangeNeighbors

- 目标：无效请求不能接触存储或假成功。
- 输入：越过尾部、读跨尾部、缓冲声明容量不足、分别破坏内存地址/偏移/长度对齐。若后端对应约束为 1，则该项无不对齐输入，不强造失败。
- 路径：真实 BlockDevice 验证入口；测试侧包装只观察是否下发 pread/pwrite，不让 OS 的 EINVAL 替代本项目的“先拒绝”承诺。
- Oracle：异常 + 没有下发 IO + 全镜像/长度仍等于原始输入。它不重复测试 StorageByteRange 自身的算术。
- 失败：定位为后端容量/缓冲/对齐准入缺失；即使 OS 恰巧拒绝，也能发现本项目漏检查。

### 3.3 TruncatedAllocatedRangeIsAnErrorNotZeroFill

- 目标：精确读取遇到损坏边界必须失败，保留已读进度。
- 输入：打开后将自有文件截短为 unit，再读 2 unit；随后长度变为 unit+1，触发实际非对齐 EOF。
- 路径：真实 truncate → 新后端 ReadAt → 真实 pread，未注入读结果。
- Oracle：根据实际文件长度推导应报告 EIO、成功字节分别为 unit / unit+1，不用生产计算 expected。
- 失败：说明短读被接受、补零、错误进度或不合法重试。局限：若某环境对非对齐 EOF 直接报不同错误，需分析该后端语义，不能静默跳过。

### 3.4 ConcurrentIndependentRangesDoNotCrossWire

- 目标：并发定位和缓冲隔离；不测试设备速度。
- 输入：4 个 worker，各自分配缓冲，固定不同位置，各 16 轮不同正文；共同 future 启动，无 sleep。提交前复审补上启动前预留 future 容量，避免容器扩容失败时临时 future 先阻塞析构；线程启动失败先释放启动门，再由 future 等待已启动工作结束。
- 路径：同一个生产实例，多线程 WriteAt/ReadAt；全部 join 后 Flush/Close/独立读取。
- Oracle：每轮内容与自己的输入比较，最终全镜像独立计算，未改区域仍保留。预期不依赖执行次序。
- 失败：并发串位、内容或异常传播错误。一次成功不能证明不存在所有 race，也不能证明 IO 实际吞吐线性扩展。

### 3.5 MissingAlignmentNeverFallsBackToBuffered

- 目标：默认 Direct 严格拒绝未知能力，同时保留显式兼容选择。
- 输入：分别模拟 statx 无 mask、字段为零、ENOSYS；每次默认打开必须失败。随后显式 Buffered 在字节偏移 3 写不同正文并核对全文件。
- 路径：真实打开 + 测试侧 statx 返回边界注入 → 构造；Buffered 分支执行真实普通文件 IO。
- Oracle：能力注入的明确定义、应抛异常、Buffered 的独立正文镜像。Direct 正常接受由 3.1 覆盖，避免“始终拒绝”也通过。
- 失败：默认 fallback、猜测能力、忽略字段或错误地把 Buffered 绑到 Direct 查询上。注入结果不证明测试机自身缺少能力。

### 3.6 ShortIOAndInterruptionsPreserveProgressAndErrors

- 目标：继续短操作时正确推进偏移/指针，失败进度不丢失，零进展退出。
- 输入：3 unit 不同正文；写/读先 EINTR，再把实际 syscall 长度限制到 unit，再中断；另一区间写 unit 后注入 EIO；额外零进展写和读 EIO。
- 路径：生产循环 → 测试侧 --wrap；限长部分仍调用真实 pread/pwrite，EINTR/EIO/零进展为模拟返回。
- Oracle：独立完整镜像、读结果、原范围与 unit 进度；失败后没有恢复操作补做写入。确切内容预期只适用于这里“错误返回没有额外写入”的受控注入，不能推广到真实 Direct EIO。
- 失败：重复/遗漏数据、错误偏移、丢失错误与进度、卡死或假成功。外部 timeout 只限制挂起。

### 3.7 FlushMustReachOSAndMustPropagateFailure

- 目标：不能将写完成或空 Flush 当持久化；刷新失败向上层可见。
- 输入：真实非空 Direct 写，首次刷新注入 EINTR 后调用真实 fdatasync；随后单独注入 EIO。
- 路径：生产 Flush → --wrap 观察/注入 → 正常分支真实 fdatasync。
- Oracle：至少有一次真实刷新成功返回、注入被消费、EIO 传出；不规定 batch 调用次数或设备内部实现。删除 Flush 系统调用会失败，单纯重开读回则无法抓住这一错误。
- 失败：刷新未发生、错误被吞或 EINTR 处理错误。不是物理掉电实验，无法检测设备虚假承诺持久化。

## 5. 重复与低价值审查

- 3.1/3.7 都涉及 Flush，但前者检验真实内容路径，后者检验正常读回无法发现的缺刷新与吞错误；刷新错误只在 3.7 注入，不再复制完整业务恢复测试。
- 3.2 不是 F00 算术的复刻，输入到达设备约束入口；3.3 是实际 EOF，3.6 是短操作继续/错误边界，各自不同。
- 3.4 与 3.1 内容核对部分共用方法，新增的是同实例并发串位风险；不增加不同线程数量的参数化镜像用例。
- 3.5 只为显式 Buffered 留一个非对齐正文场景，不复制 Direct 套件。
- 现有 DiskManager / DurableStorage / C/P 不经过新 BlockDevice，不能说它们已等价覆盖。它们的现有内容和入口保持原样。
- 不测试标准库/GoogleTest 功能、不约束私有线程数或锁实现、不为每个 getter 新建用例。

## 7. 稳定性、兼容及退出

- 固定内容与 seed，独立临时目录，RAII 释放 fd/缓冲；每例结束重置测试侧观察/注入状态，无执行顺序依赖。
- 并发测试用 future 关系，不 sleep；所有任务先结束，再关闭设备/独立读取。观察计数采用原子量，注入队列 thread_local，只有对应单线程用例启用。
- 环境要求 Linux STATX_DIOALIGN、文件 Direct 能力与对齐分配。缺失是环境/验收未完成，不能自动算通过；测试设备画像会写进结果。
- Sanitizer 采用与 S0 相同的临时 no-PIE 配置避免已知 WSL 启动问题，不修改项目默认配置；工具故障与项目错误分开诊断。
- 最大 64 MiB 文件、4 worker、固定 16 轮；不运行长期性能，不操作裸设备，不为测试申请 GPU。
- 风险标识和接管阶段见 F01 §7。F02 接入后核对缓冲/完成依赖；S8/S9 再用共同 C/P 内容测真实业务路径。当前归档不证明这些风险已被 E2E 接管。

### 10.1 发现与修正

发现一处测试自身的异常路径问题：`ConcurrentIndependentRangesDoNotCrossWire` 原先直接 `workers.push_back(std::async(...))`。若线程已经创建、正在等启动信号，而 vector 扩容失败，临时 async future 可能在进入 catch 之前等待线程结束；catch 因此来不及发启动信号。原有 60 秒外部超时只能终止测试，不能消除该挂起路径。

修正为在线程启动前 `workers.reserve(4)`。预留失败时还没有线程；后续四次插入不再扩容，future 移动不会抛异常。原先针对线程创建失败的释放启动门逻辑继续保留。只改阶段测试的资源安排，不改被测路径、输入、oracle 或生产代码，也不新增测试标准库内存分配行为的常驻用例。该异常路径依据控制流复审，未通过全局内存耗尽注入来制造。
