## 1. 方案落实与实际变更

- A 已由 LRU-K 切换 CLOCK-Pro；B 共用算法代码、独立维护缓存状态。移除生产 K 参数、旧专用接口及三个 benchmark 的旧头依赖。旧课程替换器只由测试目标编译，生产库仅含 CLOCK-Pro。
- B 将页版本描述与驻留正文分离；冷读取经 F05/F02/F01，核对身份、generation、LSN 和 CRC。同一位置合并加载，IO 不在全局缓存锁内等待。固定磁盘位置覆盖前保留旧视图正文；唯一脏版和不可重读旧版不能丢弃。
- F09 用每位置一个 pending 节点记录最新已提交版本；旧完成不能清掉新 pending。重启流式装入 checkpoint 并接续 WAL，普通 B 视图的查询必须在所属引擎打开期间开始。
- 前次代码复审修正 `MetadataCache::NewImage` 的双重归还：shared_ptr 控制块分配失败已调用删除器，外层不能再减一次计数。后次测试复审将 T4/T5/T7 的 expected 改为写入前输入，简化 T5 重复预热，收紧旧版重读变异的失败依据。
- **本次新增改动仅为文档和归档核验：** 修正主方案、F32 阶段表遗漏的当前进度；登记跨模块重复工作及后续归属；在原 F34 中列明下一步待确认范围。源码包不变，结果包仅更新文档快照并加入本次核验记录。

未发现阻碍本次 F32 提交的新逻辑缺陷、重复权威状态或测试专用生产接口；这不等于整个项目已完成性能验收。

## 2. 不只检查当前模块的职责去重

| 范围 / 代码入口 | 核对结论 |
| --- | --- |
| A `BufferPoolState` / B `MetadataCache` / `ClockProReplacer` | A/B 的恢复入口、版本和正文可淘汰条件不同；分别拥有状态，共用策略代码。内部 MetadataCache 是原引擎的驻留实现，不是第二个可独立部署的缓存服务。 |
| FrameArena / TranslationDirectory / PathCache | 分别拥有帧正文、临时页到帧映射、寻址路径；PathCache 不持有第二份正文或持久映射。CLOCK-Pro ghost 不保活正文或翻译组。 |
| `MetadataPageWriter::durable_` / `MetadataCache::Slot::disk_` | 前者保留扫描所需的持久版本戳，后者是磁盘版本对应 PageState 的弱关联，用于旧正文保护；弱关联消失不能使扫描丢失版本依据。不可简单删成一份弱指针。后续可测描述内存成本，但本轮没有新增另一套持久版本目录。 |
| F09 pending / F07 Journal / F27 Deferred | pending 合并 B 页落位，Journal 保存恢复事实，Deferred 处理对象正文落位；粒度、确认条件与恢复责任不同。pending 不代替 WAL，不能把三个队列机械合并。 |
| F22 / Store 退役 / F14 / F12 | `ObjectTransactionPipeline::GarbageLoop` 有界调用扫描、Store 维护及范围回收；`DistributedNode::Open/Stop` 注册、解除现有维护回调。Store 决定逻辑内容退役，F14 复核引用与 IO，F12 改可分配位图；未恢复旧 Store 周期线程或增加第二份空闲空间表。 |
| F31 总额度 / 组件局部额度 / F02 帧许可 | 真实 RAM、任务名额与固定压力分别限制。借帧不重复计算正文，组件仍负责分配和释放，不是另建中央内存分配器。 |
| F28 / F25 / Manifest / lease | 本地恢复点、传输快照、持久引用及单次使用保护分别有生产责任。Raft 接收仍由 `PrepareSnapshot` 构建一次，发布后安装该候选；未退回验证后销毁、安装时再构建的路径。 |
| F30 / 正常读取 | Data 复用 ReadValidation，B 复用 CheckDiskPage，Journal 复用自身解码器。扫描必须读取设备；正常读允许缓存，二者不是可直接删除一个的重复测试或重复服务。 |
| 文件部署 / 对象部署 / 旧替换器 | 文件部署仍有 CLI、课程和冻结基线消费者，不能作为死代码删除。旧 LRU-K 是测试兼容目标，不是当前生产 A 的备选策略；不计作 CLOCK-Pro 覆盖。 |

### 仍存在的重复工作与未完成优化

1. **解码后重新编码。** `RaftRpcCodec::Decode`、client_protocol 的请求/响应解码、command_codec 的 tuple/batch 解码和业务快照 bundle 解码仍通过 Encode 比较规范表示。额外构造确实存在，但同时承担规范性校验。协议部分归 F35，快照格式部分归 F25：先测量，再用等价的字段/编码约束检查消除重复构造；不能直接删检查。此次不改协议行为。
2. **Prepare 的扫描。** `SqlCommandPreparer::PrepareUpdate/PrepareDelete` 仍遍历表；F35 应复用绑定表达式与索引候选读取，继续核对完整谓词。Prepare 取旧值和 Apply 校验旧值承担不同正确性责任，不能把后者当重复删除。
3. **热读仍有同步。** 页寿命登记、帧 pin 与正文保护仍存在；CLOCK-Pro 减少访问历史维护，不等于已经实现不可变正文乐观短读。该协议仍归 S13/F26，不能为去重直接撤掉保护。
4. **正式部署与共同测试缺口。** C++ `DistributedNodeConfig::object_storage_` 已可组装新存储，`bustub-node` CLI 及 `test/storage_acceptance/cluster.sh` 仍只使用旧文件部署选项。原共同测试直接重跑，不能证明新对象链完成了同条件验收。下一步先接生产配置与既有测试适配器，不再复制一套测试节点。
