## P1：读取与缓存

- D1=20,000 行，4 个读客户端，全部为正式 LINEARIZABLE 整行点查。
- 两个参数点：均匀访问全表；80% 概率访问固定前 5% 键，20% 访问其余键。概率不是实测缓存命中率。
- 每个参数点使用新目录和相同初态，预热 30 秒，再测量 180 秒；预定 3 次重复，保留全部结果。
- 每次读核对完整记录，结束后全表核对。预热、装载、校验不计入正式窗口，排空尾部单独保留。
- 结果包含有效吞吐、成功/失败延迟、资源采样；包含 OS/宿主缓存影响，不称冷设备性能。

## P3：空间周转

- D1，一个写客户端，一组 20 次真实操作：14 次正文修改、3 次删除、3 次单行重插。
- 14 次修改为 7 对不同长度的互换；组内选取 17 个不同键，重插复用本组删除键。每组结束时行数与正文总字节数保持不变。
- 每轮 N 次操作，N=行数，共 10 轮。轮次表示操作量，不表示每行恰好更新一次。每轮结束检查独立预期并全表核对。
- 每轮单独计时；轮间核对不混入吞吐。记录累计操作数、时间、轮首尾实际占用和每秒采样峰值，不额外造一份空间微基准。
- 最后停发观察 60 秒，不强制 GC 或 checkpoint。
- 最后 5 个完整轮次的轮末占用与采样峰值，均要求斜率绝对值≤均值的 1%/轮、极差≤均值的 5%；稳态窗口内还须观察到至少 3 次恢复基点推进。缺少样本、轮数或推进，报告 `not_covered`，不能靠“占用没变”认定回收成功。
- 增长或波动是测量结果，不是自动当作业务正确性错误。预算耗尽时保留已经完成的轮次及操作，不能减少轮数后仍称完成。
- 当前空间适配统计节点目录的 `st_blocks`，排除测试历史、代理和报告。裸设备版本须接入实际已用空间观测，预分配容量不能冒充已用空间；未适配的空间来源不得认定稳态。

## P4：副本追赶期间的固定负载

### 到达与排队

- D1；固定 8 读/2 写操作块。4 个读工作者、2 个写客户端；两个写客户端修改互不相交的键范围，每个客户端最多一个未解决写。
- 总在途≤6，总待发≤64。队列满拒绝最新到达并记录未发出，不覆盖旧请求、不补发新身份，也不把未发出算成成功或超时。
- `--rate-source` 必须指向**旧系统已通过且业务验证成功的单客户端 P2 资格运行 result.json**。取其成功吞吐的 50%，保存来源副本与 SHA256；新版本继续使用同一个旧来源，不按新版峰值重新计算。
- 如果仅按理想到达速度累计 256 次写和两个 30 秒窗口就超过预算，启动前报告预算不匹配，不能暗中降到较小落后量。
- 为每个计划保存计划编号/时刻、读写种类、是否进入队列。真正派发时才分配生产请求号；历史保留计划编号，等待时间不会被掩盖。
- Python 的调度起点采用收到 C++ 时钟回执的时刻，保留该次往返的时间上界；计划/调用/返回的报告统一使用 C++ 时间尺度，延迟包含这段可见的调度开销。

### 故障、固定恢复点和收尾

1. 健康前台运行 30 秒，记录目标 Follower 的发布位置 L，SIGKILL 并取得退出证据。
2. 前台计划继续；目标退出后累计至少 256 次确认写，再暂停派发新写并排完在途写。读和计划继续，有界等待/过载照常记录。
3. 记录固定 K0、实际离线确认量、屏障开始、重启发出、进程启动 ACK 和恢复写派发的时刻。
4. 通过正式状态记录目标首次响应和 published≥K0；复用 C5 的有效 AppendEntries / 非 stale 完整 InstallSnapshot 配对证据。
5. K0 达成后继续观察 30 秒，同时记录目标与最近确认位置的差距。追到 K0 不表示已经追到持续变化的最新状态。
6. 停止计划后最多排空 60 秒，所有尾部保留。用已确认输入重建完整行的可达版本及最终预期，拒绝字段拼接、无依据版本或无效读；它不代替 C2/C3 的真实时间顺序检查。
7. 取得最终 K，确认目标发布到 K，再直接 STALE 核对目标全部数据，并核对 Leader 的完整业务结果。收尾不计前台延迟。

正常 P4 不隐式重试失败业务写。任何未知写都中断该次成功判定并保留身份/历史；不能跳过它后比较一个假设“没有生效”的预期。

### 输出

阶段为健康、Follower 离线、追到 K0、K0 后观察。吞吐按各阶段实际完成时刻计数；延迟按计划时刻归组，覆盖队列等待和排空尾部。同时提供计划到完成、调用到完成、计划到调用的分位数，成功与失败分开。

`overloaded`、`generator_limited`、恢复超时和正确性失败不算通过。原场景失败与报告失败分开保留，报告异常不覆盖原始问题。未发出的请求不伪造调用时间或延迟。

## 资源与验证边界

沿用三节点 3 GiB、观察程序 512 MiB、产物 10 GiB 的采样停止预算；这是观测预算，不是硬配额。资格单点最多 600 秒；P3 正式单次最多 3600 秒，P4 总计最多 600 秒。资格批次仍按约定分步安排，不能自动循环所有大矩阵。

17 项 Python 工具/内容自检已经通过。其中 C 新增 8 项保护：热点/全表访问、组边界总量、固定读写计划、空间增长判定、没有保留周期时拒绝稳态、前台整行版本匹配、排队/未发出/尾部计量、有界队列在慢发送时仍保留到达。

使用内存发送桩的那一项只验证调度器不会越界或删掉到达，不声称验证数据库。正式 P1–P4 全部仍依赖生产客户端和真实节点。
