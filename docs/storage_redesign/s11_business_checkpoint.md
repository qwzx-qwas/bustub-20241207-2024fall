# S11 / F28 一致业务 checkpoint

2026-10-06：用户授权补充方案、实施和测试。本文接续 S10，并优先于子模块中尚未冻结的历史描述。

## 1. 本轮范围与不变量

本轮先实现本地业务恢复点及其必需的共享版本保护。恢复为“一致业务版本 N + 已提交 Raft 后缀”，不新增 A 的页面 WAL，不将不同 Apply 进度的最新工作页直接当成恢复点。远端可移植快照继续使用现有协议；跨节点增量、压缩另行接续，不能把本轮本地共享误称为增量传输。

- 表内容、Catalog、Session 和页号分配边界属于同一次完整 Apply。
- 当前工作空间和 checkpoint 可以共享不可变内容；后续更新 COW。
- 内容身份固定，来源可按 S10 协议从 Journal 切换到 Data；不能查询当前业务的新版本来代替旧内容。
- 候选不是恢复权威。正文可恢复、引用持久化后才原子发布入口。
- 恢复点保留的范围不得被普通对象 GC 释放。数据归还沿用 F14/F12，不另设 bitmap 或回收数据库。
- 页号分配高水位由 F26 保存/捕获；F28 不另建独立编号器。索引先复用现有 Catalog 恢复中的重建路径。

## 2. 去重后的组织

```text
B 中的 A 恢复入口 -> 密封页空间身份
  ├─ 对象 0：checkpoint 清单（业务 index/term、Catalog、Session）
  └─ F26 描述/编号边界 + 对象 1..N
       -> F13 固定表页映射
            -> F14 持久共享保留
                 -> 原有 Data 或 Deferred 正文
```

清单不复制物理 extent 表、分配 bitmap 或完整 B 根。共享映射所需的历史寻址信息归 F13，业务清单只引用它。目录、Session 编码复用现有实现。恢复先恢复页空间/Catalog/Session，随后在开放服务前验证 Raft 边界并重放后缀；工作空间清理必须排除已发布恢复点。

恢复顺序还约束 Raft 持久状态：先以只读探测核对所选本地 checkpoint 的 index、term 与已提交历史，再推进 HardState、调整日志恢复基点或退出旧 portable snapshot。发现不匹配时拒绝恢复，不能先清理旧恢复材料再报错。工作空间的候选清理与 Raft 恢复历史的退出是两种职责，不把这条约束扩大为“恢复过程完全无写入”。

## 3. 捕获与执行

累计已应用日志触发，单节点同一时间仅一个候选；重复触发合并，失败不得推进成功边界。复用现有条数触发，字节/时间/空间压力策略在 S12 共同预算中扩展。

1. 有预算地预刷脏页，独立页复用对象批次和 F02 并发。
2. 在完整 Apply 边界捕获目录、Session、编号边界和页版本。对尚未刷出的脏内容保留有界副本；捕获后业务可继续。不能只记 index 后异步读取会变化的缓存。
3. 后台构建持久共享映射，保存捕获的脏页。每次提交遵守既有元数据和 IO 预算。
4. 原子发布小入口。旧入口退出后才能回收它独有的共享引用；旧读者/实际 IO 仍按现有许可退出。

捕获有 CPU/内存复制和短期协调成本，不承诺零阻塞。资源不足必须显式报告，不能偷偷退化为长期停写或无限积压。IO worker 不同步等待提交给同一池的新工作。

## 4. GC 与 WiredTiger 的借鉴

刷脏、缓存淘汰、记录清理、物理回收分别保留职责。当前普通 MVCC GC 为显式静止边界；Raft 记录整理/部分空页退役仍在 Apply 中；普通对象后台回收与元数据提交共用执行角色。S11 增加 checkpoint 持久引用判断；S12 才完善统一公平调度、脏页目标和前后台预算。

- [WiredTiger checkpoint](https://source.wiredtiger.com/develop/arch-checkpoint.html)：捕获前减少脏页、一致视图、旧 checkpoint 阻止块复用。内化到 F26 预刷/旧页保护、F28 捕获与 F14 引用；不复制完整 history store。
- [WiredTiger eviction](https://source.wiredtiger.com/develop/arch-eviction.html)：候选选择与 worker 执行分开。内化到 F26 与既有对象/F02 执行；统一压力策略留 S12。
- [RocksDB checkpoint](https://rocksdb.org/blog/2015/11/10/use-checkpoints-for-efficient-snapshots.html)：共享不可变 SST 与完整恢复清单。内化为共享 COW 内容；裸设备无须 POSIX hardlink。
- [PostgreSQL WAL](https://www.postgresql.org/docs/current/wal-intro.html)：checkpoint 与 REDO 配合。借鉴累计触发/预刷；本项目使用一致业务版本加 Raft 后缀，不能把逻辑命令当作任意混合页状态的恢复 WAL。

## 5. 实现顺序

1. F13/F14：固定映射与持久共享引用，来源解析复用 S10；先保证回收判断正确。
2. F26：有界预刷、脏内容捕获和页号高水位；页空间克隆复用共享内容。
3. F28：候选清单、原子发布、退出引用与启动清理。
4. Raft/节点：核对 checkpoint 的 index/term 和已提交范围，接续后缀；异步任务生命周期与错误上报。
5. 先逻辑审查，再通过真实对象存储/数据库/节点路径测试，完成八项测试设计审查和压缩归档。

## 8. 本轮具体表示与预算

- 新建对象格式 v4。共享映射保存原 owner 与 allocation，原有长度/物理偏移不重复搬到 F28 清单。旧 v1–v3 可按原路径恢复，不隐式迁移，F28 不启用。
- F14 SharedUnit 保存原 owner 的物理分配单位引用数及 allocation 校验身份；映射切片和引用数原子变化。计数按映射片段，多个片段覆盖同一单位允许大于一；只有全部退出后单位才可释放。多了共享元数据，但没有第二套空间分配事实。
- F26 专属 registry 的 control item 0 为 A 恢复根，只保存工作空间身份；其余 item 仍为工作空间登记。workspace descriptor v2 记录密封标记与 next_page；对象 0 为清单，1..N 是原页容器。清单使用 BSACKP01 校验帧，index/term 加一次 Catalog/Session 编码，上限沿用现有内存快照量级 128 MiB。
- 捕获按 TableHeap 页成员过滤，只保存表页；恢复索引定义后重新建索引。页分配高水位必须先恢复，即使有空洞也不能用存活页数替代。
- 脏页副本预算不超过本实例 arena_bytes；页成员列表也受该预算限制。源映射临时 lease 受既有 F14 预算，后台单页共享提交受 B/映射原预算；不足明确报错。当前目录遍历/共享引用事务有成本，后续可测量后优化，不能宣称常数时间 checkpoint。
- 单后台 worker 复用 F02 IO 与对象事务；预刷一次有界批次，不在本轮新增长期 eviction 调度器。当前自动 portable snapshot 触发仍存在，因此本轮先改善本地恢复，不宣称清除了 canonical snapshot 的所有开销。
