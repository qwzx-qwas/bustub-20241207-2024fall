# S6 普通对象 IO 与节点组装：执行和测试设计审查

## 1. 授权与代码前推演

用户已授权补齐方案、实现和测试。本轮先阅读 F02/F12/F13/F14/F34：既有 IOBatchData 由活动队列与 worker 保有，但自有缓冲没有携带物理保护；F14.Close 只排空函数调用；NodeStorage 仅拥有 B。因此接续通过 Prepared-only 的批次完成所有者携带 F12/F14 保护，再由节点拥有普通对象上下文。没有新 IO 线程池、WAL 或干净数据缓存。

先于新增测试，已逐项推演：

- Prepare/绑定资源/Submit 失败：局部批次及 activity 析构归还保护；未提交不执行回调，已提交由 worker 保有。
- 成员成功/失败/Flush：既有队列状态判断全部实际 IO 结束；锁外执行完成归还，再发布终态。失败不派发本批剩余成员、不释放仍被执行的空间。
- 读取：F14 同时固定映射和排除回收，按设备对齐扩大读取仍在其保护的分配单位内；结果直接按原始逻辑顺序截取/补零，不重新查映射。
- 新写入：只写 F12 真实新预留，初始化整个提交范围；单批多个 extent 共用一次 Flush，成功后显式 Publish 才调用 F13。无原地更新或隐式重试。
- 初始化：Open 失败的组件不能再 Create，必须重建；Open 不补建，InitializeObjects 才显式恢复半完成初始化。旧格式只关闭普通对象能力，不自动迁移。
- 关闭：先关闭 owner 接纳、等 API 退出，再排空对象活动 IO，随后关闭引用、分配器及 B/设备。旧写票据只保存旧 RAM 状态，不能跨打开实例发布。
- 异步错误：对象执行状态保留原异常；节点下次接纳/查询/关闭汇总时观察，不建立逐 IO 全局事件队列。成员预算复用 F02，映射范围预算复用 F14。

## 2. 测试设计（先冻结场景，再编写）

仅测试 NodeStorage→对象生产适配→F13/F14/F12→F04/F02/F01 的新组合风险。正式 SQL/Raft 接入尚未完成，不能称业务 E2E。真实 Linux Direct 文件、ASan/UBSan/LSan；暂停/错误注入只在独立测试链接包装系统调用，绝不修改 production 控制流。

1. 非零起点、多映射、空洞与恢复：数据期望值来自提交前的独立字节数组；越过映射边界、非对齐起点和 EOF，重开保持一致。
2. 读取票据放弃仍保护空间：在真实 pread 暂停期间移除对象/回收，只有在途读取单位不可回收；关闭排空后恢复可回收。
3. 保留完成结果不继续 pin：IO 完成但票据仍保有，退休范围可立即回收，已读结果仍正确。
4. 碎片写入批次：造两个不连续空闲范围，必要成员真正并行；所有正文写完成前不能 Flush/发布，完成后一次数据 Flush，正文独立比较。
5. 放弃写票据与关闭：占满 Data 区的在途预留不能被另一个写入取得；关闭等实际 IO，重开未发布内容不会成为对象。
6. 读取/写入/Flush 失败：三种失效位置；读失败不改目标缓冲，新写失败不能发布映射；错误保持可见，重开旧内容有效。
7. 显式初始化与实例隔离：元数据专用设备不被 Open 自动格式化，InitializeObjects 启用；已初始化 F12 的中间状态可续建 F13；旧写票据/快照不得用于重开的上下文。

复用 F02 八项、F34 五项等受影响原测试，不复制底层算法矩阵。数据以 S5 固定可复现生成器生成多个种子和长度，并覆盖重复读取；独立 oracle 不用生产映射推导预期正文。每场景有独立临时文件，退出释放故障门；同步等待有上限，进程有总时限。资源上限：三个 worker、8 MiB 镜像、16 MiB IO 缓冲；设备对齐真实查询，fixture 能力超出预算明确失败而非降级。

结果、八项审查、变异证据与归档检查将在执行后追加。

## 6. 重复与低价值测试审查

- 本轮七项保护对象连接后新出现的风险。F02 的掉句柄/Shutdown 只能证明执行器仍访问缓冲；不能证明 F14 单位仍不可回收或 F12 预留仍不可申请，因此两个对象寿命场景有新增覆盖。
- F34 原关闭用例围绕 B 的函数调用及恢复，不能覆盖 API 已返回、设备仍在运行的对象IO；本轮对象关闭断言有必要。
- F13 的正文检查曾使用测试侧 glue；本轮改用正式 ObjectIO，expected 模型保持输入字节比较，未复制前驱算法单元矩阵。历史F13/F14归档仅作未改算法回归，不新建同名常驻测试。
- “丢票据仍保护”与“保留完成票据不保护”保护相反的寿命边界，不能删除其一。
- 失败场景合并读、写、Flush 三种失效位置，不为同一接口每个错误码逐项增加小测试。零起点仅保留一个对照，主要样本均为非零起点及范围内部。
- 原 F02 八项测试内容原样复用：ParallelMembersDoNotSkipBarrierHoles、BudgetIncludesPreparedRunningAndRetainedResults、RejectionNeverStartsIOOrStealsPreparedBuffers、PartialFailureDrainsRunningIOAndSkipsUnstartedMembers、FlushFailureIsNotDurableAndDoesNotLoseLaterWork、DroppingHandleDoesNotCancelIOAndShutdownDrains、ExternalRoundTripReturnsPermissionsBeforePublishingCompletion、ExternalAdmissionPreservesPermissionsAndRejectsConflictingRAM。各自仍保护执行器公开的屏障、资源预算、准入和外部缓冲契约；本轮新增自有对象路径不能替代外部帧许可/分配失败检查。
- 原 F34 五项、F12/F13/F14 十八项和 S5 八项原样引用各自档案，不复制源码进入新模块包；审查沿用各自执行记录，当前重新编译验证受影响依赖。阶段测试仍退出默认测试发现，长期主线为共同生产 C/P。

## 7. 杀伤力与稳定性

实际编译并命中的七个最小变异：移除读批次物理保护、移除写批次预留保护、忽略范围内偏移、把空洞填成非零、只给单成员批次 Flush、跳过读取长度预算、在 Draining 仍报告可读。每项都核对指定测试的失败内容，见压缩结果 `mutations.json`，不是只看非零退出码。

局限：七个变异不证明所有错误都能被发现。例如原实例票据的拒绝同时受到适配身份和F12原始预留身份保护；删除单层检查可能仍被另一层挡住，不夸称单个断言能独立证明每层检查。失败新写的发布拒绝也可能先被 NodeStorage 的故障隔离拦下，不能独立证明 ObjectIO 内层每个 durable 检查；保留正常未完成时的拒绝场景及生产逻辑审查，不为绕过外层检查另开测试 API。未枚举所有资源耗尽交错，也未做真实掉电/块设备/业务线性一致性验证。

稳定性：每场景独立真实临时文件；固定生成公式和种子；无网络、GPU或随机时钟数据。故障门使用条件变量，5秒仅防挂起，20毫秒的等待只在已确认暂停真实IO后判断“尚未完成”，不计性能；没有靠 sleep 猜调度。所有退出路径释放门，进程180秒上限；测试全局包装状态在场景间 Reset，不并行运行同一可执行程序内的场景。环境需支持 O_DIRECT/实际对齐查询，能力不满足明确失败，不跳过或降级。runner 清除外部 GTEST_* 防止零用例/子集伪通过。

## 9. 方案覆盖与清理

- 主方案 S6、F02/F12/F13/F33/F34 状态同步；旧“当前只有测试适配、等待确认”的描述改为历史说明。S7/S9/S10/S11 未完成边界继续保留。
- 批次完成所有者捕获共享 Activity；不是每请求额外等待线程，不让逐IO审批成为全局瓶颈，不复制Data正文进新Journal。
- 本阶段请求限制为至多一个有界IO批次，避免无界拆分；未来一个请求多批次时可共享同一保护，但不提前实现没有当前消费者的聚合框架。
- 清理无用接续接口：未引入独立GetAllocator/GetB/裸帧getter，原F02自有及外部缓冲都有真实用途，保留。旧测试glue只存在历史压缩档案，不作为生产路径注册。
- 当前阶段测试仅保留 F02 模块最终源码包；替换旧包、删除旧结果压缩包，关联指引及校验清单更新。其他模块有效回归包继续保留。压缩结果经逐文件哈希验证后，删除本轮专用工作目录、构建、镜像和变异二进制。

### 发现并修正的测试问题

1. **辅助函数失败没有终止整个场景。** `Durable` 中的 `ASSERT` 只返回辅助函数，调用者可能继续；`Allocation` 又假定解析结果非空。现在必须提交成功、且确有映射数据，才继续使用测试 setup；失败用现有 `Require` 抛出明确异常，停止场景。`AwaitDraining` 同样不再失败后继续。
2. **异常退出时可能先等待 future，再释放故障门。** 两个关闭测试原来的清理对象早于 future 构造；若等待关闭期间抛错，future 析构等待 Close，而 Close 等被暂停的 IO。现在 future 后紧接清理对象，析构先释放门再等 Close。其他故障门也在启用之前建立清理对象，API 提交抛错时不会把全局故障状态带入下个场景。

这两类是测试失败传播/收尾缺陷，不是生产存储错误，也没有用新增 production hook 绕开问题。修改原七项场景的辅助与收尾代码，不新增重复测试。失败写入可能被节点故障隔离先拦截的判断边界已补到 §7，不能声称每层内部检查都被独立证明。
