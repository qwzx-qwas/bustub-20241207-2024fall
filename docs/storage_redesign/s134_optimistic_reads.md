# F26 / S13.4：A 索引不可变正文与乐观点查

2026-10-10，用户已授权实施及测试。本文接续 S12 已选路线 B，优先于此前待确认建议；不是新顶层模块。

## 协议与边界

- B+Tree 根据业务键选择页和RID；翻译数组把页号定位到驻留帧。两者不重复。
- A 的 BufferPoolManager 增加专用索引页入口和短读作用域。B 的 MetadataPager 模板实例继续固定 MetadataVersion，不注册 A 读者、不维护 A 的树序号。共同节点布局/查找算法保留。
- 已发布正文在短读期间不可修改。每帧两份稳定正文描述，第二份 FrameArena 槽按需申请并接入 F31，最多一份备用；总映射量同时受原 arena_bytes 和节点预算限制，淘汰后归还备用映射。正常页仍使用原槽；写者撤下发布后，无旧读者可直接复用，有旧读者则复制至安全备用槽。两槽都被旧读者使用或预算拒绝时，撤下后等待短读退出再复用，不持有目录访问保护等待，不无限分配版本。
- 短读按线程复用独立登记（每缓存最多128个并发登记，耗尽时走原路径），原子发布正文保护并重新核对发布入口后才能解引用；不用每页pin/readers/引用计数。描述符/帧保持到缓存关闭；短读作用域不跨IO、不跨线程，不允许裸指针逃逸。
- 读者退出与回收遵循同一顺序一致原子保护协议。新读者不能从已撤下入口取得可解引用的旧正文；已确认的旧读者仍保护对应槽。回收/换页/删除需撤下入口并排空保护；只归还RAM使用权，不改变设备回收语义。
- A 点查开始/结束检查树序号，写者继续原树独占锁，序号奇数覆盖全部相关页变更，最后一个写Guard发布后才变偶数。查找结果先放局部，确认稳定后才能写入输出；未找到也须验证。最多两次尝试，缺页、未发布或冲突走原共享树锁/页Guard路径。该路径同时建立未来短读所需的索引页发布入口。
- 不叠加另一套节点版本验证。树序号会因无关同树写入而使读者重试；实际代价须测量，不声称最优。正常页号映射/正文身份核对仍属内存安全职责。
- 写回继续使用原F02许可并排斥同帧写者，不在本轮引入旧版本IO/新版本写入重叠；完成只清除实际受保护版本的脏状态。关闭停新短读并等待已有作用域，普通Guard/IO原约定保留。
- 原CLOCK-Pro命中标记保留；目录登记与元数据所有权仍有成本，不宣称整个点查无原子操作/无共享写入。

## 实施及审查顺序

先审发布/回收、锁顺序、失败和关闭逻辑；再扩充F26唯一阶段包。复用原B+Tree、BufferPool、PageGuard、F32 B版本缓存、F35节点场景；不得为测试增加生产getter/hook。验证真实旧正文与新正文、结构变化点查、框复用、预算退让、重启内容和B隔离。按原约定源码/结果仅压缩，旧同模块包原位替换。

热路径对照以实际索引点查为入口，记录单核/多核延迟与吞吐及范围；不把合成页读取称为GT/完整SS/RS验收。完整跨阶段性能、设备掉电仍单独列待验收。

## 实际交接细节

`IndexBody` 描述符附着于帧，不形成第二份页号目录。读者先读取发布指针、把它写入自己的保护槽，再核对发布入口和翻译结果；通过后才读描述符和正文。撤下方清空入口并检查保护槽；全部使用同一顺序一致原子协议。页身份只在槽已安全退出后写入，不能在每次重复发布时写一次相同的非原子页号。

普通 ReadPageGuard 继续增加 pin/readers，WritePageGuard 继续独占正文；已启用索引短读的页即使通过普通 WritePage 修改，也必须经过 PrivateBody 和 Drop 发布。备用槽受 `arena_bytes` 剩余额度和 F31 两层限制。可选短读登记额度拒绝时回到原路径；真正 mmap/IO 错误不统一吞掉。

A 的共享树实例持有序号；B 的模板实例不实例化该原子序号及短读调用。根、内部页和叶页使用同一发布规则。范围迭代仍使用原 Guard，不在本轮伪装成完整无锁范围扫描。原文件页后端、对象页后端均沿原PageStorage执行，页格式/设备格式不变。

关闭先停普通和短读新入口，再排空登记/调用/任务；短读作用域不能包含设备等待。内存保护等待目前由退出方检查读者登记并让出CPU完成，不新增回收线程。持久退役失败时还须保留调用者Guard的当前正文槽；只有成功退出后才能归还备用槽。

## 来源与取舍

- [BTreeOLC公开实现](https://github.com/wangziqi2016/index-microbench/blob/master/BTreeOLC/BTreeOLC.h)借鉴读版本后验证的机制，未直接移植原地正文并发访问；本轮用树级序号配合不可变正文，不同时叠加节点版本协议。
- [PostgreSQL B-tree说明](https://github.com/postgres/postgres/blob/REL_18_STABLE/src/backend/access/nbtree/README)说明右链接/high key及页保护是另一种并发结构协议；本轮不改变磁盘节点布局来照搬。
- [RCU说明](https://docs.kernel.org/RCU/whatisRCU.html)借鉴撤下入口与真正复用分开；本轮具体采用有界、逐线程正文保护记录，未引入内核RCU或另一套缓存。

## 2026-10-10 再次复审：错误封闭与新短读准入

持久退役失败或帧身份耗尽后，普通调用和新短读登记必须同时停止接纳。已有 guard 的正文继续按其寿命保留；失败不可被短读成功掩盖。短读拒绝后，B+Tree 原路径仍抛出原错误，不返回缓存旧值冒充正常服务。已接纳的 CPU 短读按原协议退出，不强制撤销其内存保护。
