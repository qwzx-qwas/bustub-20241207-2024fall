# S12 / F26：共享零页、原子查询与翻译组回收

状态：2026-10-08 本轮已完成。[实际改动、八项测试审查及结果](s12_translation_execution_20261008.md)。属于原 F26，复用 F31 计账和现有候选 bitmap，不增加第二套页表或回收模块。本文接续并替代 S9 中“首次查询构造整组 std::atomic”的现行实现约定；日期明确的旧执行记录保留历史性质。

## 1. 合法的零页读取

私有匿名 mmap 预留叶数组虚拟地址；使用 C++23 `std::start_lifetime_as_array<uint64_t>` 开始整数数组寿命，保留零表示而不访问存储；所有条目访问统一通过 `std::atomic_ref<uint64_t>`。64 位操作必须无锁，实际地址满足 required_alignment。构建检查所需标准库能力，不允许以强转、memset 或逐项 atomic 构造替代。

只读 Lookup 真正 load 对应数组字，不以构造标志伪造“未驻留”，也不先 CAS 锁条目。匿名页第一次读取可由 Linux 共享零页提供；第一次 CAS/store 才要求私有物理页。条目仍是 frame 32 / version 24 / latch 8，帧编码为 frame_id + 1。

写访问 Access 在第一次修改前取得整 OS 页额度；额度不足就报告资源拒绝，不能先写再计账。这里按实际 OS 基础页分组，不固定 4 KiB。预算是承诺使用额度，不等同 RSS；虚拟映射、描述符、页表和私有正文分别解释。首次失败/放弃的写访问可能留下已计账空组，仍进入回收候选。

工具链：CMake 至少 3.20（开始支持 CXX_STANDARD=23）；公共头保持 C++17 可用，翻译实现目标要求 C++23 和 `__cpp_lib_start_lifetime_as >= 202207L`。原 Clang14/GCC13 标准库不能满足本路径。不得因旧工具链缺功能悄悄回退整组初始化。独立工具链只是构建选择，不改机器默认编译器。

## 2. 寿命与映射修改分开

现有 BufferPool Call 在副作用前建立 TranslationContext，预留一个可反复使用的登记节点；空闲时组指针为 null，所以跨 IO 保留的是小块登记资源，不是某个翻译组的访问权。这样一次批量调用不反复领取节点，也保证退役持久提交后的映射收尾不用新申请登记内存。嵌套查找仍取另一节点。

PathCache 是可选寻址加速：申请它的共享额度、分配缓存对象两处内存不足都应回退原多级数组；已授予的额度必须归还。已有映射和预留登记仍可完成工作。该退路不包括必需的目录/登记/组资源不足，也不吞掉 madvise 等真实错误。

组描述符在数组外，包含回收代次、慢路径锁、是否已计账和存活映射数。目录拥有稳定的访问登记节点，线程复用空闲节点；嵌套访问取得另一节点。节点数量随同时在途访问高水位增长，可由后来的线程复用，目录关闭后释放并归还额度。

读者：读偶数代次 → 在自己的登记节点发布组指针 → 再核对相同偶数代次 → load 条目。退出时清除登记。不再增减同一个组的共享计数；不持共享组锁。控制代次及访问登记使用顺序一致原子操作，先建立简单明确的交接证明，不擅自改成松散内存序。

写者也进入同一保护协议，再由组慢锁确保首次计账，最后取得条目独占 latch。只有映射修改及加载/淘汰状态交接保留独占入口。

驻留命中：Lookup 候选帧 → 帧短锁 → 核对页身份、阶段、当前条目仍指向该帧 → pin。失配则重试；Loading/Evicting 等取得已有任务，退出翻译保护后再等待。正文读写仍由 PageGuard 保护，不把映射版本当正文版本。

## 3. 回收与 PathCache

原分层候选 bitmap 只提供搜索提示：最后一个存活映射退出、失败修改留下空组时标记。纯零页读取不反复设置候选。加载及淘汰未完成仍保留映射，不能只因没有业务读者就回收。

维护者取得组慢锁，核对已计账且无存活映射，关闭入口（代次变奇数），扫描此前发布的访问登记：

- 有读/写访问：重新打开下一偶数代次，保留候选，稍后再试；不在锁内等待旧访问。
- 无访问：**再次核对存活映射数**，仍为零才执行 MADV_DONTNEED；否则重新开放入口并保留映射。第一次空组检查之后，可能有写者发布映射并退出，扫描登记时已经看不到该写者，不能据此直接打洞。成功归还后才退物理页额度，再打开下一代；OS 失败保留额度和候选，重新开放并报告真实错误。

所有旧访问都退出后才打洞，整数数组寿命继续存在；不用析构/重构或写零。条目版本归零不混淆旧访问，因为组代次隔离此前访问，帧身份/代次又由帧协议核对。目录身份隔离实例；PathCache 仅保存稳定叶描述符，命中后仍登记访问，不缓存绕过保护的条目权利。无需全局清空 PathCache。

既有批量预取继续使用真实 PID 列表与 CPU 只读提示；驻留检查改用 Lookup，无需先按 bitmap 查是否存在。候选 bitmap 管空组回收，与 F12 的设备分配 bitmap 不共用权威状态。数据设备释放、帧淘汰、翻译 RAM 归还分别保留原职责。

## 4. 检验与实现 prompt

先审 C++ 对象寿命、访问登记与回收的先后关系、首次写入计账、帧固定交接、异常退出和关闭，再写测试。验证真实生产数组的稀疏只读探测、首次写入、归还后再读取/写入、并发读写/回收及真实 BufferPool 内容路径。Linux smaps 的叶 VMA 私有内存观察与预算观察分开，不以“系统 mmap 会返回零”单独充当本项目测试。用独立预期数据验证多区间页号；不硬编码某个 PID 特例。

阶段测试按 F26 压缩归档，替换本模块旧源码包和旧结果包；其他模块有效证据保留但不冒称适用于新实现。每次写完测试按总方案八项设计审查：目标、输入、生产路径、独立 oracle、失败含义、重复/污染、最小 mutation、稳定性。共同 E2E 和 SS/RS/PL/GT 性能矩阵不由本阶段组件测量代替。

实现 prompt：代码要考虑复用性、间接性、安全性，不破坏其他模块和层次的 production 代码。接续改动完成前清理失去用途的旧同步、整组初始化和未使用接口。不要过多纠结于边界条件和防御性编程，防止问题被掩盖；先从代码逻辑分析，确认后再写测试。当遇到方案中未提到的部分时，先不要自作主张去写，而是汇报当前遇到的问题（注意先不要堆砌专有词汇，用我能看的懂的话去讲当前情况，有需要时再用专有词汇）。已授权的实现取舍直接执行。

## 5. 参考与内化

- [Calico §4.3](https://arxiv.org/html/2604.00423v1#S4.SS3)：易失翻译数组、零编码、匿名内存按需使用；内化到 F26 的真实只读 load 与空组归还。不宣称完全复现论文性能。
- [P2590R2](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2022/p2590r2.pdf)、[对象寿命规则](https://eel.is/c++draft/obj.lifetime)、[atomic_ref](https://eel.is/c++draft/atomics.ref.generic)：分别解决 mmap 上整数对象寿命和原子访问，不使用裸 cast 替代。
- [Folly Hazptr](https://github.com/facebook/folly/blob/main/folly/synchronization/Hazptr.h)：借鉴读者发布保护、回收前排除旧读者；本项目复用目录所有权，使用有界于并发高水位的短访问记录，不引入通用回收框架。
- [Linux MADV_DONTNEED](https://man7.org/linux/man-pages/man2/madvise.2.html)：匿名映射归还物理页、保留虚拟地址，之后读为零；不涉及持久设备字节擦除。
