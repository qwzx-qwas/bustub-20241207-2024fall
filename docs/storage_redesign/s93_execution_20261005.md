## 1. 本轮实际修改

| 位置 | 修改及原因 |
| --- | --- |
| `TableHeap::ReclaimEmptyPages` / `TablePage::IsEmpty` | 在原记录回收之后识别真正没有占用 slot 的页，保留首个页，最多尝试 4 个候选；前驱及空页集合随 Open 重建。不是将 MVCC 删除标记直接当成空页 |
| `TransactionManager::ReclaimDeletedTuples` | 保留现有无活跃事务/历史索引与 undo 退出条件；清理记录后调用整页维护，没有新 tombstone 时也能重试此前忙页 |
| `BusTubStateMachine::ApplyBatch` | 同一批命令全部应用后才对发生 Update/Delete 的表维护，允许更新的新记录先复用刚释放的 slot；继续持有已有 visibility 排他边界 |
| `BufferPoolManager::RetirePage` | 区分普通缓存 Delete 与持久退役；核实 victim 唯一 pin、无 IO，将新读取转为等待；先持久化前驱替换，再更新缓存/退出 victim；失败封住旧缓存，重开处理 |
| `BufferPoolState::free_` | 换成预留容量的空闲帧数组，归还帧不会在持久化成功后再分配链表节点。保持起始帧发放顺序；没有改变替换算法 |
| `ObjectPageStorage` | 批次 A 保存前驱映像和 pending；批次 B Unmap + retired 标记；Open 扫描继续 pending；真正 IO 前拒绝旧页号。工作区整体退休时也清除对应控制记录 |
| `ObjectOperation::Unmap` / Common Plan / F13 Apply | 复用既有 Cut，只解除指定逻辑范围并记录 retired ranges，保留左右映射与对象长度。没有额外 WAL、清零任务或独立回收服务 |
| 总方案、F36/F26/F13/F19/F22、S9 共同协议 | 统一“空槽复用、整页退出、物理范围再分配”三个动作；明确默认不擦除旧字节、单调 page_id、文件兼容后端边界 |

## 2. 测试前的生产逻辑检查

先阅读正常及失败路径，再编写新场景。确认如下依赖：

1. `DeletePage` 还有 B+Tree 缓存删除调用，父节点修改并未与它组成持久事务，所以不能直接赋予物理释放语义。新增退役 API 有正式 TableHeap 调用方。
2. 表页链是已有单向 next_page_id 结构。解除中间页必须保存前驱的新指向；FS 不能从“页为空”猜测业务引用已退出。
3. 前驱 Write 与 pending 同属一次 Common/B 发布；第二批才解除 victim 范围。第一批不成功，不允许复用旧空间；第一批成功第二批未完成，pending 可以恢复。
4. 元数据失效标记不能只存在数组目录，否则 RAM 回收/冷加载后旧 page_id 会复活。标记跟随工作区持久化，命中缓存不另查全局哈希表。
5. victim 持读许可、link 持写许可；entry→frame 只做短状态更新，设备等待期间不持这两种锁。其他 pin/Flush IO 阻止退役。候选读取若遇已有加载会加入等待，独立页可以继续访问。本轮不承诺 A 维护全异步。
6. durable 之后的内存发布不再申请空闲链表节点。link 的 write guard 在将本次映像记为 clean 后重置本次“已标脏”状态，后续真修改必须重新增加脏版本。
7. 二次逻辑复核将退役完成通知改为普通完成：等待中的 Flush 重新检查后跳过消失帧；普通读取重新进入后端，由持久退役记录拒绝。不能用一个异常通知误伤本可正常跳过的旧 Flush 快照。
8. F14 根据持久退役事实和实际范围保护释放完整单位；不要求清零。表页小于分配单位时，解除一个页不等于该单位已全部可用。
9. A 的旧活动索引和随时写回页不是业务恢复权威。仍通过已发布快照＋Raft 后缀重建，未偷加 A WAL，也未把此路径包装成 S11 checkpoint。

首轮编译发现缺少 `<cstring>` 显式包含，已补齐；这不是测试发现的功能问题。首轮正常测试通过后，上述 Flush 通知修正及格式整理触发最终版本复验，不将旧二进制结果当作最终证据。

## 4. 逐项：目标 → 输入 → 执行 → Oracle → 失败含义

### T1 页内整理、扫描边界与重开

输入为 48 条具有不同长度/字节模式的正文；清理首页及分散记录，扫描期间插入，再重开后重插。路径为 TableHeap/TablePage/Iterator → 数组 BufferPool → 对象页/Direct。预期存活 RID、版本和完整正文由原输入保存，扫描的 id→正文集合独立构造。原页集合只用于未执行整页退役的页内复用约定；不是固定内部 slot 顺序。失败区分正文损坏、旧扫描混入新行、重开遗失空闲摘要。

### T2 SQL/MVCC 与多页周转

真实 SQL 建表、主键/二级索引，加 Catalog 正式支持的 hash/ordered 适配器；事务读旧版本同时执行更新/删除/GC。先比较完整业务行，再通过正式索引接口确认旧 RID 已退出，防止 SQL residual predicate 隐藏悬空候选。额外 270 行跨批删除、GC、重插，输入金额按 13 + id % 7 变化，完整 270 行独立模型逐行比较。

本轮去掉旧“重插后 tail page_id 必须相同”的断言：整页释放后新页号单调增长。改为清空后首尾同为稳定首页、旧尾页不能访问、重插页号前进与业务结果正确；同时将旧 count/sum 聚合断言改为完整有序行比较，避免数量和总额相同却混淆行的错误通过。真正物理复用由 T7 接管，不能凭 page_id 宣称空间已归还。该子场景不固定清理次数为实现契约，8 次维护是超过所需工作量的有界驱动。

### T3 向量旧读者与物理退休

分别运行 HNSW/IVFFlat 真实 SQL，旧事务横跨删除/GC；通过最近邻结果和正式索引查询检查旧候选的保留/退出，随后复用记录空间。expected 来自输入向量及原事务视图，删除索引退休逻辑会暴露旧 RID。这里保留两种索引输入，是两套不同生产退休机制，不是重复换参数。

### T4 IVF 查询跨重建

空表建索引后插入八条明确向量，删除部分、GC，再做带过滤条件和 LIMIT 的多轮查询；预期结果固定为输入确定的 2、3、4。实际走 SQL → ANN 多轮消费者 → 正式索引重建；不调用测试 getter 强制重建。重置候选编号或冻结搜索预算会漏行。并发锁正确性靠代码审查，本轮 ASan 不充当 TSan。

### T5 Serializable 证据保留

两个事务制造读谓词与已提交插入的冲突，中间运行 GC。预期冲突事务 Commit 为 false，最终 SQL 结果与业务模型一致；不直接读取事务容器计数。失败定位为 GC/Serializable 验证交接失效，不能凭它证明完整 Serializable 模型。

### T6 Raft 周转与恢复

真实 Prepare、LogStore、StableStore、Apply、SnapshotStore，变长更新/删除/重插和向量候选退出；恢复后核对业务行及会话结果。正文及预期由请求构造，与磁盘编码无关。其小表页数上界针对 S9.2 页内复用；本轮保留首页，因此不是已退役页号循环复用要求。不能代替 T7 的中页释放，不能把它称为全节点 E2E。

### T7 中页/尾页与真实空间复用

四条长度 2301、2338、2375、2412 的不同正文，每条占一页且处于同一页对象；删除中页与尾页。实际 TableHeap 维护执行 A/B，再由开启的 Common 后台 GC 完成 F14/F12，测试没有直接修改 bitmap 或手工执行 Release。

Oracle 包含：独立 id→正文全集；表首尾入口；旧页读取失败；对象内部孔洞返回零；回收前后旧物理字节相同；正式新对象写入映射确实与旧单位交叠；冷重开后的同一结果。物理位置从既有 FS Resolve 接口观察，判断标准是两个不同所有者在安全时间顺序下实际复用同一区间，不是用编码器生成 expected。若所有物理地址查询都一起错误，该观测不能独自排除问题，因此同时比对正文、冷恢复和实际文件旧字节；不将它冒充独立盘格式检查器。最后删尽后保留首页并成功再插入，覆盖空表。

### T8 扫描、pin 与在途预取

四页真实数据，先删除并整理中页。活跃迭代器和外部读 guard 分别阻止维护，映射仍存在；退出后普通 DeletePage 只清缓存。通过已有 syscall wrapper 暂停真正 Direct pread，再提交预取和维护，独立页读必须完成；释放 IO 后才允许退役、拒绝旧页号且剩余内容正确。

判断基于已发生的 IO 门闩、映射存在性、读取结果及 guard 生命周期；没有在 production 添加暂停开关。超时是检测未能推进，不是正确性的排序来源。去掉表扫描保护会使映射提前消失；去掉唯一 pin 判断还会在旧 guard 归还时破坏生产 pin 不变量。

### T9 A 之前失败与 A/B 之间中断

相同非空四页输入，清理中页并先持久化已有工作页。两种故障由已有系统调用包装注入：Data pwrite 拒绝（A 未提交）；Journal 的真实 fdatasync 已成功但返回 EIO（应答丢失，A 已持久化）。断言故障确实触发、旧缓存关闭新访问，然后真实 Close/Open，不手写恢复结果。

第一种必须保留旧链并能从 Open 重建空页候选继续退役；第二种必须打开后看到新链、旧页号失效和 victim 孔洞，证明 pending 在启动中被处理。两种均比较完整业务行。它验证持久工作交接与错误传播，不模拟硬件写缓存丢失、任意扇区撕裂或真实断电。B 提交内部的原子性继续由既有 Common/B/Journal 协议及已归档测试负责，本轮不穷举 B 的每个 syscall 中断点；B 返回不确定时需要重开，不能将 pending 当成直接重试许可。

## 5. Production / 接口污染审查

新增接口均有删除测试后仍存在的生产调用：

- `TablePage::IsEmpty`：TableHeap 依据所有 slot 的实际占用判断，不是观测 getter。
- `TableHeap::ReclaimEmptyPages`：普通 GC 与 Raft Apply 共同调用。
- BufferPool `SupportsPageRetirement / RetirePage / ReclaimRetiredPages`：接收表层正式证明、保护帧、转交后端；不理解 SQL/表页格式。
- PageStorage 相应虚接口：文件后端明确不支持原子退役，对象后端实现。默认 unsupported 能力保留既有文件部署；不是为测试新增默认路径/默认大小。
- `ObjectOperation::Unmap / ObjectMutation::length_`：正式 Common 需要表达内部孔洞；不能拿 Resize/Remove 冒充。长度只对 Unmap 非零，既有调用含义不变。
- 没有新配置开关、test-only hook、为测试增加的 public 内部状态、条件编译或生产反向依赖。

测试侧 syscall wrappers、fixture、故障状态仍只在归档用例中。BPM 旧 DeletePage 虽不释放设备仍有正式 B+Tree 调用，不能为追求“删旧接口”误删；真正失去用途的空闲帧 list 和对应 include 已移除。此轮未改变默认设备路径、对齐参数、SQL/Raft API。Unmap 的 length_ 默认零表示旧操作无范围参数，服务已有生产聚合初始化，不是测试默认值。前驱替换映像使用固定页大小的只读数组，同步复制到事务，不伪装成异步借帧许可，也不使用 const_cast。

## 6. 重复性与变异审查

- T1 的页内移动、T7 的整页释放是不同所有权边界；保留。
- T2 的 MVCC/索引决定“能否清理”，T8 的实际 pin/IO 决定“此刻能否退出”；共同构成保护，不能相互替代。
- T6 的小表状态机恢复、T9 的 pending 工作交接、S8 的网络/已发布快照边界不同；不复制其下层 WAL/bitmap 场景。
- F26 九项直接复用，未复制为新测试；共同 C/P 不改。课程/向量回归属于受影响代码的复验，不宣称新增覆盖。
- T2 旧 tail 不变断言已删除；未保留旧版用例和新版用例同时执行。

定向变异共 19 个：页内偏移、Open 摘要、扫描回填、活跃事务、历史索引、Serializable 证据、ANN 候选编号/搜索预算、向量退休、Raft 回收、空值旧版本等原 14 项，以及 Unmap、持久旧页号检查、启动 pending、扫描保护、唯一 pin 五项。

`ignore-page-pins` 预期先出现映射提前释放的测试断言，再在旧 guard Drop 时因 production double-unpin 终止，不能只看到 SIGABRT 就算发现问题。其他变异要求指定单个用例的断言失败。runner 对编译、超时、测试数量、跳过和非预期返回码分别检查；不计为通过。

## 7. 稳定性与环境边界

- 每个 Harness 独立 Direct 文件与工作空间，固定输入，无随机 seed/执行顺序依赖。已封闭节点再重开；future/门闩 RAII 先释放暂停 IO 再关闭资源。
- 测试侧 wrapper 共享进程内状态，各 gtest 顺序执行；不支持把同一二进制的这些 fixture 在同进程内并行跑。
- T7 后台回收采用有期限的状态轮询（2ms 间隔、10s 上限），不以 sleep 长度推断 durable；极端机器过载可报推进超时。新分配最多 64 页、非无限填盘。
- T8 在真实 IO 已进入暂停点后验证，10s 等待用于诊断推进失败；没有要求调度器在某个微秒内调度线程。
- Direct 对齐来自 F01，fixture 明确要求当前设备能承载数据库页；失败应报告环境不满足。ASan/UBSan/LeakSanitizer 保留，TSan 本轮未执行。
- 旧无用正文不擦除按本次配置验证；未来显式引入 discard/安全擦除时须调整该策略断言，不改业务内容与新拥有者隔离承诺。

### 10.1 代码与方案核对

| 检查点 | 当前实现及结论 |
