## 3. 逐例：目标 → 输入 → 执行 → Oracle → 失败含义

所有正常 IO 都走 `test → JournalService → JournalBackend → RegionManager → IOExecutor → BlockDevice → Direct 文件`。格式损坏通过关闭写者后的测试侧独立文件描述符构造；同步/写入 EIO 和暂停在链接侧 `--wrap=pwrite/fdatasync` 实现，不绕开上层生产路径。被注入的分支不是实际硬盘掉电实验。

### T1：跨段与独立格式

- **目标：** 两种实际对齐派生的单元/段尺寸都恢复调用前保存的完整记录；旧范围不因后续追加变化。
- **输入：** 16 MiB 临时设备文件，真实查询的对齐；U 与 2U、三单元/五单元段；大于单段的确定性非重复正文，以及跟在 LAST 后的小记录、另一跨单元记录。
- **执行：** Create → TryAppend → 等 durable → Close → 独立读镜像 → 新实例 Open → 再追加。
- **Oracle：** 原始输入是独立逻辑期望；测试自行按大端解析物理段号、偏移、batch 起点/前驱及片段类型，使用测试侧逐位 CRC32C，而不调用生产 codec。比较 Journal 外全文件和旧前缀；额外确认 LAST→FULL 确实出现在同一单元，以保证输入经过需验证的解析分支；这些检查弥补编码器/解码器同时写错仍 round-trip 的缺口。
- **失败含义：** 内容失败指向分片/重组；物理字段失败指向 v1 格式；范围比较失败指向越界/旧前缀保护。不是吞吐或掉电证明。

### T2：先验证全流再恢复

- **目标：** 即使前面存在有效批次，后面的非零损坏、身份不一致或缺片也必须在任何 replay 前被发现。
- **输入：** 一批正常小记录和一批跨多单元的大记录；分别只改单位 CRC 字段（保持正文和类型合法）、段号、Journal ID、前驱、挖掉中间单元、清掉末尾 COMMIT 单元、改变批次累计 CRC。身份/序号/批次 CRC 变异会重算外层 CRC，避免只重复 CRC 检查。
- **执行：** 每个副本经真实 Open；同时核对错误身份 Open、非空区域 Create 拒绝，最后恢复原镜像再次正常 Open。
- **Oracle：** 故障由测试确定；必须抛 JournalError、回调数为零、无新增写系统调用、镜像完全不变。expected 不是扫描器自己声称的“有效范围”。
- **失败含义：** 分别定位语义校验漏项、恢复前验证不完整或擅自修复。未测试“把完整后缀全部清零仍能检测”，方案本身没有这一承诺。

### T3：组提交与空洞

- **目标：** 先完成的后方批次不能越过被暂停的前方批次，整组共用一次 Flush。
- **输入：** 三个非空批次；暂停 A，让 B/C 在 F07 队列中积累；A 放行后暂停 B 的实际写，让 C 写完。
- **执行：** 通过生产 coordinator 和三个原 F02 worker；用链接侧条件变量握手确认真实写到达指定切点，再观察公开 ticket。
- **Oracle：** A 写未放行没有 Flush；B 未完成时 B/C 均非终态且仅有 A 的一次 Flush；放行后两组共两次 Flush并全部 durable，重开后逐批正文与三组独立输入一致。计数只用于“每组一次屏障”的明确协议，不测试底层 pread 调用次数。
- **失败含义：** 连续持久化边界、等待依赖或组屏障错误。观察器完全独立于 Journal 内部的 cursor/queue 状态。

### T4：整体准入与结果寿命

- **目标：** 数据缓冲可准备但 Flush 槽不足时不得产生部分 IO或占住位置；终态仍被持有的结果不能无限累积。
- **输入：** 两个 F02 名额，测试通过正式接口占一个；F07 的结果上限为两个；真实非空记录。
- **执行：** 第一次追加 Full → 释放外部占用 → 同内容追加 → 两个终态票据保留 → 第三次 Full → 释放一个再追加；另验单条超额内容拒绝。
- **Oracle：** 拒绝期间写调用数不变；重试位置是初始追加位置、能正常 durable；第三次拒绝/释放后成功。无需私有计数 getter。
- **失败含义：** 跨 F07/F02 的预留回滚、结果占额或超额输入边界错误。原 F02 详细分配失败矩阵仍由原测试负责。

### T5：字节和磁盘容量

- **目标：** 在途容量按编码字节计，满盘返回 NoSpace，旧数据不被覆盖。
- **输入：** 四个段的区域，其中槽 0 是格式区；一次只容纳一个单元的工作预算；小而非空的不同记录。
- **执行：** 暂停第一个写 → 另一次 Full → 放行 → 填满总共九个数据单元 → 再追加。
- **Oracle：** 暂停时 Full、完成后预算可用；准确写满后 NoSpace 且无新写，先前镜像前缀字节不变。容量期望由 fixture 的显式几何推导，不读取实现的“已用字节”。
- **失败含义：** 工作字节释放/限制或无回收依据的空间覆盖。不证明 S5 GC 正确。

### T6：写错误及尚未发出的工作

- **目标：** 一个大批次的一个段 EIO，而另一个段仍在写时，批次不可提前终态；此后排队但未发出的请求不能混称为已发 IO。
- **输入：** 已 durable 小前缀；跨多个段的大批次，一段暂停、另一段 EIO；错误已到达但尚未排空时再接纳一个小批次。
- **执行：** 等测试侧确认暂停和 EIO → 公开 ticket 仍未完成 → 放行 → 等两个结果 → Close → Open。
- **Oracle：** 已发批次 Indeterminate，并保留原 EIO/物理错误范围；未发小批次 NotCommitted；新提交 Faulted，旧前缀逐字节不变；不完整尾部拒绝恢复且无回调。
- **新增同场景分支：** 将两个独立批次放在同一组，前一批 EIO，后一批的写暂停。通过正式 TryAppend 等到 Faulted，确认它在后一批放行前生效；此时两张结果票据仍非终态。放行后已发结果 Indeterminate，隔离前可能接纳但未发的请求 NotCommitted。它覆盖组间准入隔离，原分支覆盖一个跨段批次内部排空，不能互相替代。
- **失败含义：** 失败排空、错误分类、隔离或旧历史保护错误。没有把受控 EIO声称成硬件原子性证明。

### T7：Flush 错误不等于回滚

- **目标：** 不能因 fdatasync 返回 EIO 推断内容肯定不存在。
- **输入：** 大于单单元的完整批次，真实写成功后先暂停 Flush，再放行并返回 EIO。
- **执行：** 追加 → 错误票据 → 禁止新追加 → 关闭注入并新建实例 Open → 继续追加。
- **Oracle：** Flush 暂停时票据非终态；结果是 Indeterminate 且原异常必须为 fdatasync EIO，不能把“结果尚未完成”的逻辑错误混充设备错误；Open 的恢复内容等于原输入，后续可以继续。此故障切点特意保留完整字节，不要求任意错误场景一定保留或一定丢弃。
- **失败含义：** 同步完成边界、故障状态或恢复有效提交判定错误。

### T8：观察者与工作寿命分开

- **目标：** WaitFor 超时和票据释放不取消已接纳工作，Close 必须排空尚未送到 F02 的工作。
- **输入：** 两个非空不同批次、两个名额；第一条的实际写暂停，第二条留在 F07 队列；放弃两张票据。
- **执行：** 异步 Close；通过非空正式提交观察 Full → Stopped（已有两条占满名额，探测请求不能写）；确认 Close 尚未结束，再放行 IO。
- **Oracle：** Close 后新实例能恢复两批原输入。没有访问内部 closing 标志。等待只有握手 watchdog，零时等待只在确定暂停点观察状态。
- **失败含义：** 关闭未排队列、放弃观察被当取消或错误释放资源。不是 std::future 行为测试。

## 5. 重复与风险接管

- T1/T2 不同：T1 验证正确提交的内容与格式，T2 额外保护“损坏不应用/不改写”。T2 的七种镜像在本次复审后分别改变不同校验依赖，不是只换种子。
- T4/T5 不同：结果可长期保留与工作字节可提前归还是不同寿命；T5 另有满盘保护。
- T6/T7 不同：缺片故障与完整字节但屏障失败，对恢复有不同预期，不能合为一个“异常一定丢弃”的断言。
- T8 与 F02 的关闭测试在底层 IO 排空上有重叠，但新增了 **F07 尚未投递队列** 的责任；因此保留这一个完整场景，不复制 F02 八种条件矩阵。
- T3 需要经过 F02，但验证的是跨批组 Flush，原 F02 单批屏障测试不覆盖它。
- 未新增纯 codec、enum、std::vector、CRC 算法、第三方库或内部容器计数测试；测试侧 CRC 只作为 v1 磁盘格式的独立 oracle。
- 风险标识 `F07/format-chain`、`group-durable`、`admission-lifetime`、`failure-isolation`、`reopen`。S4/S5/S10 及共同 C/P 真实接入时沿标识接管；后续由真实 B/节点 E2E 覆盖的同义场景应淘汰，不永久恢复成常驻小测试。

## 7. 稳定性与执行记录

- 输入确定性生成，无随机 seed、测试顺序依赖或共用磁盘文件。每个 fixture 独立 mkstemp，析构关闭并删除；每场重置链接侧状态。仅单进程顺序执行这些注入用例，不能擅自多测试并行共享钩子。
- 条件变量握手确认切点；没有 sleep 等待“应该已经执行”。watchdog 为 10 秒、runner 为 120 秒；慢/不支持 Direct 的环境明确失败，不降级 Buffered 或静默 skip。
- 关闭测试的释放守卫在 future 析构前运行，断言失败也能解除被暂停的写。票据、服务、Bootstrap、IOExecutor、设备按逆依赖销毁。

## 10. 2026-09-25 再次方案、代码与测试复审

### 10.1 实际发现及修复

1. **生产隔离时机偏晚。** 原 Run 在整组 IO 全部排空后才设置 Faulted；已观察到某批失败时，仍可能因另一批慢 IO 而继续接纳新请求。现在 `ObserveFailure` 在投递、数据完成或 Flush 的错误被观察到时立即关闭入口；错误结果仍等所有已发 IO 排空后交付。没有增加 public API、测试 hook 或等待设备时持有队列锁。
2. **CRC 测试会被其他检查代替。** 原 T2 同时改坏 CRC 和片段类型；实际把生产单元 CRC 校验删掉，旧 T2 仍通过。现在只改 CRC 字段，保留其余内容合法。同一个变异被新断言捕获。旧用例漏检的运行日志作为诊断保留，不保留旧测试源码或旧压缩包。
3. **组恢复 oracle 太弱。** 原 T3 重开只数三批；现在逐批比较三份独立输入，能检查内容混用/遗漏等问题。
4. **Flush 完成边界补强。** T7 在测试链接侧暂停 Flush，并核对具体 EIO；删掉等待、过早读结果造成的 logic_error 不能冒充正确失败。本次实际运行捕获该变异。
5. **文档残留。** 总方案仍有“F06/S3 与 F07 待讨论”等过时总结，风险交接表也未列 F07；本轮同步状态和风险归属。历史执行条目保留其当时范围。
