1. P1/P2 共用有界窗口执行和计量；移除 P2 原本独立的重复线程编排，保留原业务序列与预处理。

3. P4 的写屏障只暂停派发，计划和读仍继续；记录屏障耗时，避免把测试侧停顿藏起来。
4. P4 以固定 K0 计算恢复时间，并持续观察相对最近确认位置的差距，最后固定 K 再核对目标全部内容。
5. P4 不能只检查读成功和不变字段：排空后重建完整可达版本，拒绝新 version 与旧 last_op 的拼接。时序线性一致仍由 C2/C3 单独检查。
6. P3 的稳定性要求最后 5 轮内有至少 3 次保留边界推进；只有占用不变不能证明回收。未适配的空间来源不作稳态判断。
7. P3 全轮历史只扫描一次生成分轮延迟，避免每一轮重新扫描整份大历史；资源峰值同次采样，不另跑重复测量。
8. 报告失败与原场景失败分别保存，后处理异常不覆盖原始正确性/超时问题。
9. P4 到达速率从冻结的旧 P2 单客户端资格结果读取并归档哈希；不允许根据新版峰值重新换算。已知预算肯定不够时提前报告。
10. 所有适配/观察变更都在 test 下；没有生产路径、API、协议或默认值的测试便利改动。
