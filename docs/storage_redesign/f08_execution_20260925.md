## 0. 交付范围与验证状态

本轮落实用户确认的两个独立运行上下文，以及固定组合键“类别编号＋所属对象编号＋条目编号/逻辑偏移”、变长值。B 不启动 SQL 系统，不改变 A 的记录组织；复用同一份 BusTub B+Tree/迭代器算法，通过独立私有页缓存、唯一 F07 Journal 和完整版本发布建立 S4 元数据事务。

**最终验证状态：通过（S4 组件范围）。** 最近一次完整运行的 6 项 F08 场景、12 项未修改的 A 回归通过；12 个独立改坏版本全部触发指定断言，正常实现未出现 ASan/UBSan 错误。完整命令/XML/日志及源码哈希见 [压缩证据](../../test-results/storage-f08-20260925/README.md)。这不是性能基线。

范围限制：S4 当前页全驻留并受页数/版本预算约束；F05 限定可寻址槽位，S4 尚不写最终元数据页。S5 的页写回、checkpoint、Journal 裁剪/复用，以及普通对象、Raft/SQL 正式接入均未完成。组件真实 Direct 文件 IO 和进程退出恢复不证明裸设备、掉电安全或三节点 E2E，也不是性能比较。

## 1. 先审生产逻辑，再确定测试

实际阅读和检查顺序：当前树/RID/事务/快照依赖 → F05/F07 接口与持久化边界 → 私有页/记录空间/编码 → 提交、发布和恢复 → 测试输入与 oracle。没有先写一套回归用例来替代代码分析。

### 生产路径

```text
MetadataEngine::Commit(base, mutations)
  → 检查 base 与输入预算
  → MetadataPager：按需复制修改页，维护记录与空闲页
  → 复用 BPlusTree：查找、插入、删除、分裂/合并
  → Prepare：FULL/PATCH + 页身份/分配/根变更
  → F07 TryAppend / Wait：唯一 Journal durable
  → Seal：填写实际批次 LSN，固定大小操作
  → 切换完整 MetadataVersion

MetadataSnapshot::Get/Scan
  → 同一树算法 + 已固定版本的页访问
  → slot 或 overflow 值

Open
  → F07 校验完整日志，再 replay
  → 校验历史/页基版本，FULL 或 PATCH 重建
  → 校验正文和引用关系
  → 开放已恢复视图
```

- 共享树算法本体经源码对照保持一致，变化是页访问类型、模板实现位置及 Create/Open。A 默认仍是 BufferPoolManager。
- 未提交页仅进入私有缓存，取消/准入拒绝不修改已发布页或最终 Metadata 区。旧读者通过不可变页引用保留旧内容。
- Journal 实际位置在结果/replay 中取得，不猜下一 LSN，不使用旧 32 位 Page::SetLSN，不增加独立 B WAL。
- 代码复核已修正持久化后 Seal 使用动态容器的风险：最终改为固定大小 trailer，发布需要的页/目录/正文缓冲在日志提交前准备。
- 代码复核发现删除后的 slot 目录尾部未缩回，可能使“许多小值 → 全删 → 一个近整页值”不断增页。已在不改变存活 RID 的前提下回收尾部空槽，并增强原空间复用场景；没有为此新建页布局微测试。
- 旧读者测试的最终新值特意与原值不同，避免修改后恰好恢复成相同内容而掩盖版本污染。
- 资源不足明确拒绝；接受后结果未知不伪装为取消。发生该类失败后停止该实例的新操作；重建上下文并 Open 后再开放。未新增静默重试、备用存储路径或测试开关。

## 3. 逐项：目标 → 输入 → 执行 → Oracle → 失败含义

### 3.1 MixedValuesSplitMergeAndReopen

- **目标：** 非空原子批次跨越多层树结构变化后，Get/Scan 与重开结果均等于输入定义的集合；空值和缺失键区分。
- **输入：** 12,000 条组合键；多类别/owner；17–127 字节小值和约 6 KiB 的溢出值，内容有重复也有差异；另含三字段全为 UINT64_MAX 的键及一个存在但值为空的条目。随后删除 11,000 条，再更新为 3 字节短值和约 9 KiB 长值。
- **路径：** 正式 Create/Commit/Read/Open → 共享树/实际 slot/overflow → F07/F06/F04/F02/F01 Direct 文件；不是手写 map 代替 production。生产容量下，两层树最多 94×97 条，12,000 条确实迫使树继续增长，无需暴露树高 getter。
- **Oracle：** 输入侧 `std::map<tuple<uint64_t,uint64_t,uint64_t>, Bytes>` 独立维护集合和排序，不调用 production 编码/比较/replay 生成 expected；同时核对数量、扫描顺序、完整字节、点查和不存在的键。
- **失败：** 能指出哪条键/值/数量不符合输入，但若 Open 直接失败，需要结合恢复错误区分结构、编码或恢复链问题，不能仅凭一个失败断言断定根因。

### 3.2 OldViewsConflictAndSpaceReuse

- **目标：** 旧视图内容不随当前修改改变；过期 base 被拒绝；旧 slot/overflow/树页可复用。
- **输入：** 页上限 32、存活版本上限 96；180 条 60 字节记录，保留原读者；80 轮全删、写入 16,013 字节和 3,999 字节值、再删、重新填入小记录。重新填入内容随轮次变化，最终新旧内容不同。
- **路径：** 同一个正式 B，反复树合并/重建、slot 整理、overflow 分配释放和代次复用；结束后真正重开。
- **Oracle：** 原输入模型固定为旧读者预期，另一个模型随成功提交更新；正常操作必须持续成功，不能用内部 free 计数器替代空间复用；过期 base 必须返回 Conflict。
- **失败：** 旧值变化表示版本污染；正确负载越来越早遇到页满表示未复用空间；过期写成功表示丢失了提交前提检查。

### 3.3 RejectedPrivateChangesDoNotLeak

- **目标：** 已经修改私有页后遇到容量不足，整批仍不能部分生效；资源回滚后可继续工作。
- **输入：** 页上限 8、版本上限 32；已有两条不同内容。批次先更新第一条，再插入 64 KiB 大值触发真实页不足；重复三次。随后持续保留旧视图并更新小值，直到版本预算拒绝，释放读者后再成功更新。
- **路径：** 正式 Commit 的真实记录分配/私有页预算，不用测试 hook 返回“假满”；最后 Open 核对持久结果。
- **Oracle：** 被拒绝批次前的独立模型必须保持；版本压力结束前最近成功模型必须保持；释放读者后合法写能成功并重开恢复。
- **失败：** 错误值表示泄漏了未提交修改；一直不拒绝表示预算无效；释放后仍拒绝表示资源没有归还。这里只约束配置的页面版本预算，不伪称测量全进程 RSS。

### 3.4 PublicationWaitsForDurabilityAndFaultsOnUnknownResult

- **目标：** 提交可见性晚于要求的 durable 边界，且多条记录同时切换；未知结果明确隔离。
- **输入：** 两条非空旧值同时更新为大/小两个新值；在测试链接侧暂停真实 `fdatasync`，握手确认进入后观察读者，再放行。下一批两条新记录在 Flush 返回 EIO。
- **路径：** 正式 engine/Journal/IO 写入；默认调用真实 fdatasync，只有指定故障阶段暂停/报错；未绕开生产提交逻辑。
- **Oracle：** 屏障暂停时 future 未完成且新取得视图仍等于旧模型；放行后整个新模型可见，旧视图仍读旧值；EIO 返回 Indeterminate、新 Read/Commit 被限制。由于此次注入只令 Flush 报错、全部 Direct 写已实际完成，重新验证/Flush 的 Open 应恢复完整批次。
- **失败：** 提前发布、部分发布、错误报告成功或故障后仍对外开放。它不证明设备在真实掉电时遵守 Flush。

### 3.5 ProcessExitReplaysConfirmedNonemptyTransactions

- **目标：** 已确认事务不能依赖正常关闭补全，恢复包含实际的插入、删除及长值更新。
- **输入：** 子进程创建 B，提交 64 条记录，再删除 12 条并把一条改成 13,013 字节；确认返回 Durable 后直接 `_exit(0)`。
- **路径：** 父进程 fork 前无 IO worker；子进程使用正式全链路，退出不执行 engine/Journal 析构；父进程检查退出状态，再重新装配生产对象并 Open。
- **Oracle：** 父进程独立生成预期，不接受子进程“成功”作为数据正确依据；逐键核对完整内容。
- **失败：** 子进程未完成约定写入、缺少恢复记录、只有 Close 才落盘等。它不能发现所有漏 Flush 情况：进程退出不清空 OS/设备缓存；屏障调用/等待由上一场景补充，真实掉电仍未测。

### 3.6 ValidJournalCannotHideWrongMetadataRedoBase

- **目标：** 完整合法 Journal 批次只是必要条件，B 还要验证页增量的基版本。
- **输入：** 正式 B 先插入并更新非空记录；关闭 B 后用正式 F07 replay 取得其真实记录。测试侧仅修改后继批次头的前一提交位置，保留旧页基版本，再经正式 F07 追加，外层 checksum 全部有效。
- **路径：** 前半段是真实 B 产生记录；故障构造走 F07，最后回到正式 B Open。不是以手写格式往返替代整个 B 测试。
- **Oracle：** 该历史故意在错误页版本上重复 redo，必须被 B 以 Corrupt 拒绝且不能开放 Read。预期来自基版本契约，既不复用 production 解码计算 expected，也不是测试 F07 的 CRC。
- **失败：** B 接受了不属于当前页历史的增量。此测试了解持久格式是为了构造损坏，不把每个无关字段偏移都做成永久测试。

## 4. Production pollution 与接口审查

| 改动 | 生产用途及删去测试后是否仍需要 | 结论 |
| --- | --- | --- |
| MetadataEngine / Snapshot / Key / Mutation / Options / Error | F08 的正式创建、事务、读取、预算和恢复入口，后续 FS 消费；当前未接节点不是测试专用接口 | 合理的新模块 API；所有预算显式传入，无测试默认路径 |
| BPlusTree 的 PageAccess 类型参数、Context/Iterator 对应适配 | A/B 复用同一树算法，隔离页访问与事务 | 默认类型保留 A 源码调用方式，不是为测试增加默认行为 |
| 显式 Create/Open 构造模式 | B 读取/重开已有树不得清空根 | 生产需要；A 原构造仍初始化新树 |
| BufferPool 的 ReadGuard/WriteGuard 类型别名 | 供共享算法的页访问契约使用 | 没有暴露内部帧、页表或统计 getter |
| leaf/internal Init 定义移到模板头文件 | 支持 B 的非 SQL 比较器实例化 | 无新行为或测试分支 |
| 测试侧 fdatasync 链接注入 | 确定性观察/失败注入 | 仅测试源码和链接参数，不进入 production |

没有新增 production test-only hook、测试配置项、`#ifdef TEST`、私有状态 getter、默认测试路径，或仅为测试转发的 wrapper。已有 F01/F02/F07 的实际持久化及默认 Direct 路径未改。

C++ 模板增加类型参数会改变重新编译后的符号，不能把新静态库当作可直接替换旧二进制的 ABI；已构建全库和相关 A 目标。A 的持久化页/网络/快照格式未因此更换。B 作为新格式独立版本化，不能读取旧 A 页当作 B。

## 5. 重复与价值检查

- Mixed 与 A 树测试共同经过树算法，但前者保护 B 的事务/编码/恢复，后者保护 A 的原 BufferPool/RID/业务快照适配；未新增另一套纯树单元测试。
- Mixed 的正常关闭重开与 ProcessExit 有不同失败模式；后者排除析构补写，仍明确无法证明真实掉电。
- OldViews 的持续可复用性与 Rejected 的真实资源耗尽/回滚不同；不再单独测试“free 链长度”或“slot 数等于某个常量”。
- Publication 检查 B 的完整视图与故障隔离，不重复 F07 的分片、段位置和组 Flush 格式套件。
- WrongRedoBase 有意维持 F07 完整性，以区分 B 的恢复责任；不重复此前损坏 CRC 即拒绝的测试。
- 不写 std::map、shared_ptr、第三方库或代码搬迁后的文件位置测试。源码对照是一次审查证据，不注册为回归套件。

## 6. 定向改坏检验

变异仅生成在隔离临时目录，不修改生产文件。每个变异要求：编译/链接成功、指定的唯一场景实际运行、退出码为 1、XML 中出现指定业务判据。编译失败、超时、零测试或其他错误不算发现了目标 bug。

| 最小变异 | 目标场景/判据 |
| --- | --- |
| 取消过期 base 检查 | OldViews：旧视图提交不能成功 |
| 忽略页容量 | Rejected：整批必须因真实容量不足被拒绝 |
| 不缩回尾部空槽目录 | OldViews：正常复用负载不应耗尽页区 |
| 忽略存活版本预算 | Rejected：旧读者长期保留必须最终触发预算拒绝 |
| Flush 完成前切换 published | Publication：观察到的内容必须仍为旧值 |
| 将未知结果报告成 Durable | Publication：结果必须是 Indeterminate |
| 未知结果后保持 ready | Publication：Read 必须拒绝 |
| 忽略 redo 基版本 | WrongRedoBase：Open 必须拒绝 |
| 跳过 PATCH 应用 | ProcessExit：不能恢复确认内容，重建页 checksum 不符 |
| 反转组合键顺序 | Mixed：独立模型的扫描顺序/结果不符 |
| 忽略 Scan 起点（本轮补强） | Mixed：独立 lower_bound 子集的键不符 |
| 忽略 Scan 上限（本轮补强） | Mixed：返回数量超过独立模型的 limit |

最终 runner 已执行这十二个变异，全部编译成功并在指定场景退出 1；XML 和预定失败信息逐项核对。失败不是崩溃、超时或编译报错，详见结果包 mutations.json 和对应日志/XML。

## 7. 稳定性、资源与清理

- 数据生成确定、无未固定随机种子；有重复内容、多类别键及不同长度，不是所有请求重复同一数据。
- 测试相互使用独立 mkstemp 文件，IO worker、Journal 和句柄按依赖逆序退出；测试进程工作目录位于仓库外。
- Flush 测试使用条件变量握手，不用 sleep 猜 IO 到了哪一步；10 秒握手和外部 watchdog 只用于发现阻塞，不是性能门槛。释放守卫在 future 析构等待之前解除暂停，失败不会卡住清理。
- runner 清除外部 GTEST_* 干扰，显式选择用例并核对 XML 数量/名称/运行状态，不接受“退出码 0 但未执行用例”。
- 测试文件逻辑容量 192 MiB，Metadata 区 8 MiB，Journal 区 128 MiB；不读取/格式化用户裸盘。默认 F01 Direct，实际设备对齐由生产查询，测试单元按查询结果构造，不假定一律 4 KiB。
- 普通场景 B 逻辑页上限 2048、存活页版本上限 8192、值上限 64 KiB、批次预算 2 MiB；F02 自有缓冲上限 32 MiB。预算压力场景单独降低限额；这些是测试资源配置，不是生产默认值或全进程峰值测量。
- 源码和证据分别按模块压缩；不保留展开测试、设备镜像、目标文件、临时变异源码或错误旧包。F08 首次归档，其他模块有效包及共同 C/P 内容不变。
